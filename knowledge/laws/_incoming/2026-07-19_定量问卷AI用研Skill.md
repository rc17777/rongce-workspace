# 我把定量问卷流程写成了两个用研 skill

最近做了两个和用户研究相关的 skill，一个是问卷设计，一个是问卷数据分析。写这两个 skill 的初衷其实很简单：想把之前做定量问卷时积累下来的一些 SOP、题库、经验沉淀下来，让之后开展调研时可以更敏捷一点。这里说的敏捷调研，主要是互联网产品里比较常见的场景：业务方想快速验证一个需求、一个功能点、一个用户偏好，或者想知道某类用户为什么没有转化/为什么流失。这个时候如果每次都从 0 开始想问卷结构、写题目、检查逻辑、再手动跑数据，其实会非常耗时间。所以这两个 skill 想解决的问题就是：在保证一定标准和规范的基础上，尽可能快地完成一份定量调研。当然，它们不是用来替代完整严谨的大型研究项目的，更像是帮助我们在日常工作里快速产出一份“够用”“可用”的问卷初稿和分析结果。今天就简单记录一下这两个 skill，以及写完之后我对AI时代用研价值的一些思考。
 为什么先做定量问卷？一开始会选择定量问卷，主要是因为它比较适合被流程化。相比访谈，问卷里有很多环节其实是相对固定的，比如：明确研究背景和目标拆解研究问题根据研究问题设计问卷题目生成问卷回收数据对数据进行清洗和统计分析这些事情以前当然也是人在做，只是每次做的时候都会散落在不同的文档、历史问卷、Excel、脑子里的经验里。写 skill 的过程，有点像把这些东西重新拎出来，变成一个可以被反复调用的工作流。我感觉这也是做 skill 很有意思的地方：它不是简单写一个Markdown，而是需要把一个人/一个团队过去做事的方式，拆成详细的流程，从步骤到规则，从参考资料到输出格式。
 Skill 1：问卷设计第一个 skill 是问卷设计。它主要解决的是：当使用者提供调研背景、调研目的和目标用户之后，如何快速设计出一份结构完整的问卷初稿。[IMG]它大概会做几件事：先追问必要信息比如这次调研到底想验证什么？目标用户是谁？是否有不同用户包？不同用户包之间是否需要对比？这里我觉得很重要的一点是：skill 不是一上来就直接写题目，而是先确认研究目标和目标人群。因为问卷最怕的不是题目写得不漂亮，而是前面目标没想清楚，后面问了一堆也不知道怎么用的数据……把研究目标拆成研究问题比如业务方说“想了解用户对某个新功能的接受度”，那这个目标可能会被拆成：用户是否知晓并理解这个功能？用户当前有没有相关需求？用户对功能价值的感知如何？用户是否愿意尝试？哪些因素会影响使用意愿？拆完之后，每个研究问题再对应到具体题组，而不是想到哪问到哪。参考历史题库生成题目这个 skill 里还有一个我觉得比较重要的部分：题库。以前团队已经做过不少问卷，这些历史问卷里其实沉淀了很多可以复用的题目，比如用户属性、使用行为、需求偏好、功能体验、满意度等。所以在做这个 skill 的时候，我也把以往问卷里的题目整理成了题库，作为 skill 可以参考的资料放了进去。这样做的好处是，后面再设计类似问卷时，它不是完全从 0 开始“凭空生成”，而是会先参考团队过去真实用过的题目，再根据这次的研究目标进行改写和组合。当然，这里也不是说历史题目一定是标准答案。反而，在 skill 里写了一些限制：如果题库里的题目和这次调研目标不匹配，就不能为了复用而硬套；如果选项需要调整，也要说明为什么改；如果题库里没有合适的题，就按问卷设计规则重新生成。这里我觉得还挺有意思的是：skill 不是只学了“问卷应该怎么设计”这种方法论，也学到了一些“我们团队以前到底是怎么问的”。因为很多时候，真正有用的经验不是写在 SOP 里的，而是藏在历史问卷里：某类问题通常怎么问、选项一般怎么分、哪些题目已经被验证过可以用。把这些题目整理进题库之后，skill 生成问卷时就会更像是在延续团队原来的工作方式，而不是完全凭空创作。根据题型规则生成题目这个 skill 里也沉淀了一些题型选择规则，比如：想知道“是否/有无” → 单选题想知道“频次” → 频次区间单选想知道“程度/态度” → 5 点量表想知道“想法” → 开放题听起来都是很基础的东西，但实际写问卷的时候，这些基础规则非常容易被忽略。比如，一个量表题只有正向选项，没有负向选项；或者题干里不小心写了很明显的引导性表达。这些问题看起来不大，但最后会直接影响数据能不能用。做质量自检我在这个 skill 里加了比较明确的风险检查，例如：引导性提问模糊措辞选项不互斥选项不穷尽量表不平衡……这些其实就是以前 review 问卷时会反复看的点。我自己觉得这个部分很像是把“mentor 帮你看一遍问卷”的经验沉淀进去了。虽然它不能保证问卷一定非常完美，但至少可以先避免一些新手很容易犯的错误。输出可以继续流转的格式这个 skill 不只是生成一份 Markdown 问卷文档，也会输出更结构化的问卷格式，比如题号、题目、选项、题型、显示逻辑、备注等。这样做的好处是：它不是只停留在“看起来像一份问卷”，而是能继续衔接后面的问卷生成及上传到平台。也就是说，前面的设计阶段需要为后面的阶段留好接口。
 Skill 2：问卷数据分析第二个 skill 是数据分析。它解决的是：问卷回收之后，如何快速识别题型、清洗数据，并输出一份可复核的分析报告。[IMG]这个 skill 里我比较在意的一点是：所有统计数字都必须由脚本算出来，而不是让 AI 直接“脑算”。因为问卷数据分析里有很多看起来很简单、但特别容易出错的地方。比如：百分比的分母到底是总样本，还是这道题的有效作答人数？多选题应该看响应率还是穿透率？跳转题因为只有一部分用户看到，所以 base 是不是明显小于总样本？交叉分析里看起来 A 比 B 高，但差异到底显不显著？这些如果只让 AI 读一眼表格然后总结，很容易出现一些“看起来很顺，但其实口径错了”的结论。所以这个 skill 的流程会更偏审计式：数据结构识别它会先识别问卷数据里有哪些题、每道题是什么题型、哪些列可能是系统字段或元数据。进行数据脱敏和清洗这一点也很重要。原始数据里可能会有手机号等隐私信息，所以不能直接把原始数据丢给模型分析。skill 会先做敏感信息检查，再根据规则进行脱敏和清洗。跑统计分析这一步包括：单选/量表题的描述统计多选题穿透率交叉分析多用户包之间的组间对比这里我觉得比较有价值的是，它会强制标注每道题的 N，也会提醒哪些结论因为样本量不足，只能参考，不能当成确定洞察。最后生成 Excel 报告报告里会包含概览、描述统计、交叉分析、对用户开放性回复的编码等内容。当然，这个报告也只是初稿，最后还是需要人来判断哪些发现真正有业务意义。但它可以先把很多重复劳动做掉，比如整理数据、计算占比、标显著性、生成表格等。
 这两个 skill 怎么配合？如果把它们串起来，大概是这样：调研背景/目的 → 问卷设计 skill 拆解研究问题、生成问卷 → 人工 review，确认后投放 → 回收问卷数据 → 数据分析 skill 做脱敏、清洗、统计和报告 → 人再去判断哪些数据能转化成 insights所以它们其实覆盖的是定量问卷里比较“执行流”的部分。以前这些事情可能会消耗很多时间：找历史题、写题、改题、检查选项、数据分析、制表等，但现在如果这些都被沉淀成 skill，之后再做类似调研时，速度就会快很多。而且更重要的是，它不只是快，而是在快的同时，遵循了一些以往调研的规范，这便是与通用大模型生成内容的差别——只是让 ChatGPT、Claude 去按调研目标生成一份问卷和进行数据分析，它们当然也可以做到。但是，它们生成的问卷内容是否延续了以往调研的团队习惯？是否遵循了以往的数据分析规范？这些都不得而知，更难以在单次交互中调试到满意，而与AI进行反复多轮交互其实也降低了效率。我想这可能是这类 skill 最大的价值：不是让 AI 随便生成一份“看起来还行”的东西，而是把团队原本认为重要的流程和红线写进去，让它可以直接按照固有流程推进。
 一点思考做完这两个 skill 之后，我其实有一点微妙的感受。以前我们会觉得，用研的很多工作是“经验活”：知道怎么问问题，知道怎么设计问卷，知道怎么分析数据，知道哪里容易出错。但当我真的开始把这些经验拆成规则、流程、脚本和检查清单时，会突然发现：好像很多执行层面的工作，确实是可以被 AI 承接住的。比如一份基础问卷的初稿，一个常规问卷的清洗和描述统计，一份格式比较固定的数据报告，这些都已经不太需要人从头手动做了，甚至在某些环节，AI 可能比人更稳定。所以我也开始想：如果“调研执行”这部分越来越容易被 AI 替代，那用研真正的核心价值到底是什么？或者说，传统的支持型岗位、辅助型岗位，真正的核心价值到底是什么？这似乎已经变成 AI 时代一个绕不过去的话题。用户研究、商业分析、数据分析这类研究型岗位，似乎都只是决策者获取信息的一环。而 AI 时代的最大特征就在于，它其实降低了一个人获取专业知识、习得专业技能的难度。这样的疑惑，在我最近进入产品岗位之后，变得更加明显。你会发现，其实调研所获知的用户需求，只是产品团队做决策的很小一部分。这并不是因为它不重要，而是因为一个决策往往就是基于多方信息的。假如你要做一个新功能，通常需要结合多方面的信息：1. 用户需求：首先考虑用户有没有这方面的需求。2. 竞对情况：要考虑竞争对手的情况，这可能需要商业分析。3. 财务与成本：需要进行成本测算，去看功能落地的投入产出比。一个真正的重大决策，往往需要结合多维度的信息。任何一个支持型岗位，它所提供的信息都是有限的。不过，不同信息在决策中的重要性是显然不同的。

或许，破局的唯一方法是“向决策者靠拢”。这当然不是说让你从现在开始就转行做产品经理，而是指：让你所产出的信息具备关键的决策价值。例如在硬件行业，由于天然的试错成本大、工业周期长，重视用户体验的公司对于人因的相关信息就会更为看重，你所输出的座椅参数、佩戴角度、振动频率，可能都会成为最终决策的关键依据，而这些是 AI 所无法替代的。而互联网行业的特点是：试错周期极短，且除用研以外还有其他信息来源渠道。比如：想要了解用户更喜欢哪个功能设计，完全不必执行调研，只需一个 AB Test，就可以在短短几天得到结论。这时候的用研，往往只起到了一个验证性的作用，甚至只是在给老板汇报时提供用户原声的、聊胜于无的角色。因此，我的浅薄建议可能是：在 AI 时代，用研工作者们更应该去做那些能直接参与决策的事情，包括但不限于：去能产出关键决策信息的岗位、转岗成为决策者，或者其他形式…当然，这只是我的一家之言，如果大家有其他想法，也欢迎在评论区里聊聊。或者有朋友同样在用研 skill/agent 的话，也可以在评论区分享～
