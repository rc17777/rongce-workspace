# 批判性评注：《标书制作的逻辑之战》

> 方法论：有用的纳入SOP，有启发的标记待验证，没用的直接丢弃。不搞全盘接收。

## ✅ 可直接采用（纳入标书制作SOP）

### 1. 一页纸四象限逻辑（★★★★★）

这是全文最有实操价值的部分。融策应在每个投标项目启动时强制生成这张纸：

```
         ┌─────────────────┐
         │   资格门槛索引    │
         │ □ 营业执照       │
         │ □ 资质证书       │
         │ □ 类似业绩       │
         │ □ 财务报告       │
         │ □ 人员证书       │
         ├────────┬────────┤
 技术得分点│  项目名称  │ 报价策略 │
 □ 方案框架 │            │ □ 下浮率 │
 □ 人员配置 │            │ □ 清单   │
 □ 方法论   │            │ □ 品牌   │
         ├────────┴────────┤
         │   废标检查清单    │
         │ □ 签字盖章       │
         │ □ 封装格式       │
         │ □ 递交时间       │
         │ □ 保证金         │
         └─────────────────┘
```

**适配融策**：政府审计服务标需调整四个象限内容——
- 资格门槛加：执业证书（会计师事务所执业许可/工程造价咨询资质）、无重大违法记录声明、中小企业声明函
- 技术得分点加：审计方案框架、人员配置表（含社保）、类似项目案例
- 废标清单加：信用中国截图、税收违法黑名单查询、联合体协议（如联合投标）

### 2. 响应性核查矩阵表（★★★★★）

五列模板可直接作为融策标书制作的强制中间产物：
```
条款编号 | 核心要求 | 响应措施 | 责任人 | 完成时间 | 复核状态
```

**操作**：把这个矩阵写入 `bid-document` skill 的 SKILL.md 作为必出中间物。

### 3. 废标红线优先级最高（★★★★★）

三遍精读法中"第一遍扫雷"的优先级排序绝对正确。融策SOP应明确：**任何投标项目，废标检查必须在所有其他工作之前完成**。

## ⚠️ 有条件采用（需适配改造）

### 4. 三遍精读法（★★★☆☆）

**原文问题**：假设一个人能通读500页招标文件三遍——不现实。

**融策适配**：
- 小型项目（招标文件<100页）：一人三遍，适用
- 大型项目（招标文件>300页）：分模块并行——资格模块+技术模块+商务模块各由一人精读，然后交叉核对
- 服务标vs工程标：服务标的"差异化要求"主要在人员配置和方法论，工程标在施工组织和报价，拆骨重点不同

### 5. "80页vs300页"的篇幅论（★★★☆☆）

**原文问题**：说法太绝对。有些政府招标文件明码要求"技术方案不少于XX页"或"包含XX附件"，你写80页反而因不响应被扣分。

**融策适配**：篇幅以"完全响应招标文件要求"为准，不多不少。重点在"删废话"而不是"削篇幅"。

### 6. 目录=得分点映射（★★★★☆）

思路正确，但原文没给具体做法。

**融策做法**（已有，本文验证了方向）：
- 把评分表（通常是Excel）转成目录大纲
- 每条评分标准至少有一个对应的章节/段落
- 用评分标准原文的关键词做标题，降低评委检索成本

## ❌ 舍弃 / 存疑

### 7. 华为案例（★☆☆☆☆）

**问题**：
- 127项标准、三年时间、字体大小——这是跨国基建/通信巨头的玩法
- 对融策这种咨询服务机构：一个投标周期通常2-4周，预算有限，照搬等于找死
- **不采用。** 仅作为"严谨的极端案例"存档。

### 8. 北交大雄安案例（★★☆☆☆）

**问题**：
- 文章只说"英文标点、多余空行、缺行"，没披露完整否决理由
- 真实情况大概率不止这些——三家企业同时犯低级错误的概率不高，更可能是技术方案实质性不满足
- 仅作为"格式检查不可忽视"的警示故事保留，不作为决策依据。

### 9. 陕煤天工48小时案例（★★☆☆☆）

**问题**：连续48小时在岗逐字审核——这是人海战术，不是方法论。融策要学的是他们的严谨态度，不是48小时连轴转的做法。

### 10. 鸡汤段落（☆☆☆☆☆）

原文后半段大量抒情（"深夜键盘的敲击声""反复推倒重来的框架""中标通知书上的名字"）——纯鸡汤，无实操价值，**直接丢弃**。
