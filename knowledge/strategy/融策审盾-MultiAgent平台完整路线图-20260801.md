## 一、两篇文章的核心洞察

### 文章1：Agent Harness Engineering（腾讯内审）

**核心命题**：通用 Agent 面对复杂任务时，「临场发挥」不可靠——需要一套工程「外骨骼」把模型能力约束在可控边界内。

| 维度 | 通用Agent的问题 | Harness Engineering的解法 |
|:--|:--|:--|
| 深度检索 | 查不全、乱编造、过程不可追溯 | 四环节控制：生成查询→来源约束→迭代检索→收敛与证据 |
| 智能分类 | 上下文不够、重复稀释信息 | 三步法：预打标(工程)→构建体系(人机)→全量分类(工程+AI复判) |
| 智能问数 | 每次都从头探索、口径不一致 | 数据理解底座：结构扫描→画像→语义→校验→沉淀，分层加载 |

**三层分工模型**（理论基石）：
- **审计师**：提出目标、定范围口径、确认歧义与结论
- **Agent**：理解任务、组织步骤、处理模糊、动态调整
- **工程链路**：批量、重复、规则明确的处理，保证稳定可复用

### 文章2：Multi-Agent 18步协作框架

**核心命题**：Multi-Agent 拼的不是模型能力，是组织能力——把一堆模型组织成一支打得赢的团队。

**七大角色**：
- 用户（甲方）
- 管理Agent（项目经理/Orchestrator）
- Planner（规划师/架构师）
- 研究Agent（情报员）
- 执行Agent（工程师/写手）
- Reviewer（质检员）
- 工具/环境（外部世界）

**18步核心流程**：
```
对齐目标(1-3) → 拆任务排依赖(4-5) → 派活(6)
  → 双线并行：研究线(7-9) ∥ 执行线(10-11)
  → 汇总中间稿(12) → Reviewer审查(13-14)
  → 虚线反馈回路(15-16) → 交付(17-18)
```

**五条原则 + 八个落地坑**已在上方原文中详述。

## 二、两篇文章的统一框架：融策·审盾「外骨骼+项目组」双引擎模型

### 2.1 为什么两篇必须一起读

**文章1（Harness Engineering）回答了「单个Agent怎么做才对」**：
- 不是让 Agent 自由发挥，而是给它搭工程脚手架
- 数据理解底座、智能分类三步法、深度检索四环节——都是「单一能力域」的工程化

**文章2（Multi-Agent）回答了「多个Agent怎么协作才对」**：
- 不是几个 GPT 互相发消息，而是像项目组一样有分工有复核
- 对齐→规划→执行→审查→迭代——是「跨能力域」的组织化

**两篇合在一起 = 完整答案**：先给每个 Agent 搭好 Harness（让它单兵作战能力可靠），再用 Multi-Agent 框架把它们组织成协同作战的项目组。

## 四、顶层设计原则（两篇文章的共同方法论）

### 原则1：按工作性质分工，不按模型能力分工

| 谁做 | 做什么 | 为什么 |
|:--|:--|:--|
| **模型/Agent** | 语义理解、模糊判断、动态调整 | 这是模型擅长的 |
| **工程链路** | 批量、重复、规则明确的处理 | 稳定、可记录、可复用 |
| **审计师** | 业务口径、关键判断、最终结论 | 专业判断不可替代 |

### 原则2：执行不打分，打分不执行

> 「让做事的人不打分，让打分的人不做事。」

- 执行Agent不评估自己的产出质量
- Reviewer不亲自下场修改
- 角色分离 = 对抗错误累积的**结构**解法，不是模型能力解法

### 原则3：闭环比单次生成更重要

> 一次性生成靠运气，带闭环的生成靠机制。

- Plan → Execute → Review → Replan 循环
- 虚线反馈回路：精准派单式返工，不整体重跑
- 必须设退出条件和最大轮次

### 原则4：复杂被藏进流程，简单是被设计出来的

- 用户只做两件事：提任务 + 收结果
- 中间全部复杂度由「Harness + Multi-Agent 框架」消化
- 过程全留痕、可回溯、可复盘

### 原则5：先 Harness，后 Multi-Agent

- 没有 Harness 的 Agent 是「裸奔」——不可控
- 没有 Multi-Agent 的 Harness 是「独狼」——不协同
- 建设顺序：先给单个 Agent 搭好外骨骼 → 再把它们组织成项目组

## 五、融策22 Agent → 7角色重映射方案

将现有22个Agent按照「7角色模型」重新编组：

| 7角色模型 | 融策Agent | 说明 |
|:--|:--|:--|
| **管理Agent** | 新建：审盾-Orchestrator | 替代 orchestrate_v3.py 的调度逻辑，升级为带目标对齐和成功标准的管理者 |
| **Planner** | 新建：审盾-Planner | 从5坐标系穿透引擎抽取任务拆解逻辑，增加依赖关系图 |
| **研究Agent** | data_scout + contract_hound + law_inspector + 会议纪要分析师 | 整合为统一研究Agent，加载深度检索Harness |
| **执行Agent** | bid_hunter + workpaper_crafter + report_writer + budget_estimator + settlement_auditor + fiscal_reviewer + performance_evaluator + 方案撰写师 + 调整分录师 | 统一工具调用接口，各保持专业Prompt |
| **Reviewer** | review_sentinel + expert_bias_detector | 整合为统一审查Agent，增加实证检查和来源校验 |
| **数据运维** | OCR预处理员 + 数据分类员 + 数据脱敏 | 归入工程链路，不作为独立Agent |
| **工具/环境** | api_gateway.py + 信源白名单 + MCP工具 | 标准化工具注册与调用层 |

**精简效果**：22 Agent → 5 核心角色 + 1 运维组 + 1 工具层 = 更清晰的分工边界
