# 审盾·指标体系 — 从复核到预警的延伸设计

> 编制时间：2026-08-04
> 依据：公众号「审计实践」文章四步构建中「指标设计」环节，审盾一期30天实验的复核指标基础
> 核心命题：复核和预警共享同一套指标定义，只在**使用时机和触发阈值**上不同

---

## 一、核心洞察

文章指出：

> "将审计专家的经验提炼为可量化的风险指标——供应商准入偏离度、价格偏离度、中标率异常、报销频次异常等。"

注意这些指标天然具有**双重属性**：
- **事后**：在已完成的事项中检查异常（复核）
- **事前/事中**：在正在发生的事项中预警风险（预警）

审盾一期做的是**事后复核**（绩效评价报告已出具），但设计指标体系时如果只看事后，就等于把"能用于事前预警的底层逻辑"浪费掉了。

---

## 二、统一指标体系架构

### 核心思想：一套指标，两个时钟

```
                    ┌──────────────┐
                    │  统一指标库   │
                    │  (Indicator  │
                    │   Registry)  │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 指标定义  │ │ 阈值配置  │ │ 证据模板  │
        │ (不变)    │ │ (可配)    │ │ (可复用)  │
        └──────────┘ └─────┬────┘ └──────────┘
                           │
              ┌────────────┼────────────┐
              ▼                         ▼
        ┌──────────┐             ┌──────────┐
        │ 复核阈值  │             │ 预警阈值  │
        │ (严)      │             │ (敏感)    │
        │          │             │          │
        │ 例：完成率│             │ 例：完成率│
        │ 低于目标 │             │ 季度偏离 │
        │ 5% 触发  │             │ 目标10%  │
        │          │             │ 触发预警  │
        └──────────┘             └──────────┘
```

### 指标元数据标准（每个指标必含字段）

```json
{
  "indicator_id": "I-P-002",
  "name": "产出指标完成率偏离度",
  "category": "performance",
  "business_line": ["绩效评价", "专项资金审计"],
  "definition": "衡量项目实际产出完成率与合同/计划约定目标之间的偏离程度",
  "formula": "abs(实际完成率 - 目标完成率) / 目标完成率",
  "data_requires": ["产出指标表", "合同约定的绩效目标表"],
  "review_threshold": {
    "trigger": "实际完成率 < 目标完成率 - 5pp",
    "severity": "P1",
    "rationale": "偏离超过5个百分点通常已超出合理业务波动范围"
  },
  "warning_threshold": {
    "trigger_early": "季度累计完成率 < 季度计划完成率 * 0.85",
    "trigger_real_time": "连续2个月完成率环比下降 > 10pp",
    "rationale": "季度偏离15%表明执行节奏严重滞后，需在年末失控前干预"
  },
  "evidence_template": "《[项目名称]绩效目标表》第X页约定完成率[N]%，实际完成率[M]%，偏离[D]个百分点。该偏离程度[超出/未超出]合理波动范围。",
  "related_indicators": ["I-P-001", "I-P-003", "I-F-005"],
  "typical_risk_types": ["资金闲置", "进度滞后", "虚报完成"],
  "agent_owner": "performance_evaluator"
}
```

## 三、四种指标类型（按数据来源）

| 类型 | 说明 | 复核可用 | 预警可用 | 例子 |
|:--|:--|:--:|:--:|:--|
| **结构指标** | 数据自身结构/格式/完整性 | ✅ | ✅ | 报表勾稽关系校验、字段完整性 |
| **阈值指标** | 单值偏离基准 | ✅ | ✅ | 报价偏离市场价、完成率低于目标 |
| **模式指标** | 多记录之间的规律/异常 | ✅ | ✅ | 供应商伴随投标、报销时间聚集 |
| **趋势指标** | 时间序列演化 | 有限 | ✅（核心） | 中标率逐月下降、资金拨付节奏异常 |

**关键发现**：趋势指标是复核的天生短板，但预警的核心武器。传统人工审计几乎不做时间序列趋势分析——这是审盾预警最大的差异化空间。

## 四、按业务线的指标密度设计

| 业务线 | 一期复核指标数（目标） | 二期预警指标数（目标） | 共享率 |
|:--|:--:|:--:|:--:|
| 绩效评价 | 30-40 | 50-60 | ~60%共享 |
| 经责审计 | 25-35 | 40-50 | ~55%共享 |
| 招投标审计 | 20-30 | 35-45 | ~65%共享 |
| 专项资金 | 20-25 | 30-40 | ~55%共享 |
| 工程竣工决算 | 15-20 | 20-25 | ~50%共享 |
| 预算执行 | 15-20 | 20-25 | ~50%共享 |

> 注：招投标审计的复核与预警共享率最高，因为23层检测体系中大部分指标天然同时适用于事前和事后。

## 五、绩效评价场景：指标延伸示例

### 一期（复核，正在做）

| 指标ID | 复核指标 | 复核阈值 |
|:--|:--|:--|
| I-P-001 | 绩效目标完整性 | 缺少任一项必设指标 |
| I-P-002 | 产出完成率偏离 | 低于目标5pp |
| I-P-003 | 资金使用率 | 低于预算80% |
| I-P-004 | 满意度达标率 | 低于目标10pp |
| I-P-005 | 时效达标率 | 超期30天以上 |

### 二期（预警，同一套ID延伸）

| 指标ID | 预警指标 | 预警阈值 | 新增数据需求 |
|:--|:--|:--|:--|
| I-P-002W | 产出进度预警 | 季度完成率 < 季度计划×0.85 | 季度产出进度表 |
| I-P-003W | 资金拨付节奏预警 | 连续2月资金拨付率 < 时间进度-15pp | 月度资金拨付台账 |
| I-P-006W | 招标采购进度预警 | 距计划开标日<30天仍未发公告 | 采购计划时间表 |
| I-P-007W | 验收计划偏离预警 | 距计划验收日<15天完成率<80% | 项目进度甘特图 |

## 六、配套工具：指标注册器

```bash
# 新增指标
python audit-blackboard/indicator_registry.py add --file indicators/performance.json

# 按业务线查询
python audit-blackboard/indicator_registry.py list --line 绩效评价

# 按Agent映射
python audit-blackboard/indicator_registry.py list --agent performance_evaluator

# 检测一期→二期延伸的共享率
python audit-blackboard/indicator_registry.py overlap --v1 indicators_v1.json --v2 indicators_v2.json
```

## 七、与审盾路线图的集成

| 路线图任务 | 本设计的贡献 |
