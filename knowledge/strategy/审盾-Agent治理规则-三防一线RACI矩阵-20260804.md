## 一、核心原则

1. **Agent 可以聪明，但不能自由** —— 能做什么、做到哪一步停、出了事找谁，全部事前定义
2. **执行不打分，打分不执行** —— 角色分离 = 对抗错误累积的结构解法（从 Multi-Agent 路线图继承）
3. **Prompt 可以被绕过，权限不能** —— 治理边界写在数据库角色权限里，不只在 Prompt 里
4. **Agent 的能力边界不是技术决定的，是治理决定的**

## 二、审盾操作分级

| 级别 | 操作类型 | 审盾场景 | 审批要求 |
|:-----|:--------|:--------|:--------|
| L0 | 只读 | 读报告、出复核建议、生成检查清单 | 免审批 |
| L1 | 低风险写 | 标注疑点、归类问题、生成底稿备注 | Agent 提交 → 审计经理 10 分钟确认 |
| L2 | 高风险写 | 修正底稿数字、调整分录、修改定性 | 业务负责人 + 质控负责人双签 |
| 🔴 | 禁止操作 | 自动写报告结论、修改金额/定性/责任 | 永久人工锁定 |

## 三、异常熔断规则

| 熔断条件 | 阈值 | 动作 |
|:--------|:-----|:-----|
| 批量操作行数 | 单次 >50 条 | 暂停 → 生成操作快照 → 通知项目负责人 |
| 敏感字段修改 | 金额/责任定性/法规条款 | 直接拦截，不进入审批 |
| 变更幅度异常 | 调整金额 > 原值 10% | 告警 → 待确认后放行 |
| 同类操作频率 | 1 小时内 >3 次 L1+ 写操作 | 暂停 Agent → 人工排障 |

## 四、审盾 RACI 责任矩阵

| 操作 | R（执行） | A（兜底）🔥 | C（咨询） | I（知悉） |
|:-----|:---------|:------------|:---------|:---------|
| AI 首次复核 | 审盾 | **审计经理** | — | 项目负责人 |
| AI 标注疑点 | 审盾 | **审计经理** | 主审会计师 | 质控部 |
| AI 归类问题发现 | 审盾 | **审计经理** | 项目负责人 | 质控部 |
| AI 生成调整建议 | 审盾 | **审计经理** | 客户 | 质控部 |
| 确认调整分录 | 审计经理 | **项目负责人** | 客户 | 质控部 |
| 修正底稿数字 | 审计经理 | **项目负责人** | 客户 | 质控部 |
| 生成复核报告 | 审盾 | **审计经理** | 质控部 | 客户 |
| 生成对外报告 | 审计经理 | **项目负责人** | 客户/质控部 | — |

> 🔥 A 列 = 出事了第一问责对象。不是 AI，是**人**。

## 五、审盾 Agent 数据库权限矩阵

```
审盾 Agent 数据库账号：rongce_agent_ro（命名即只读标识）

✅ SELECT（只读）：
  - 审计底稿库.底稿明细表
  - 审计底稿库.取证单表
  - 审计底稿库.报告草稿表
  - 财务数据仓库.科目余额表
  - 财务数据仓库.序时账

⚠️ INSERT（有条件写，需审批）：
  - 复核意见库.疑点标注表
  - 复核意见库.复核清单表
  - 复核意见库.Agent操作日志表（强制全量记录）

🔴 DENY（禁止）：
  - 审计底稿库（所有写操作）
  - 生产报告库（所有操作）
  - 财务数据仓库（所有写操作）
  - 任何 DROP/TRUNCATE/ALTER 权限
```

## 六、操作日志与审计追踪

Agent 每次写操作**强制记录**到 `Agent操作日志表`：

| 字段 | 说明 |
|:-----|:-----|
| 操作时间 | 精确到毫秒 |
| 操作类型 | L0/L1/L2 分级 |
| 操作对象 | 表名.字段名 |
| 修改前值 / 修改后值 | 完整快照 |
| 触发原因 | 自动/人工指令 |
| 审批记录 | 审批人 + 审批时间 + 审批意见 |
| 回滚信息 | 可回滚标记 + 回滚 SQL |

## 七、事故分级与响应

| 等级 | 定义 | 响应 | 责任人 |
|:-----|:-----|:-----|:------|
| P0 严重 | 影响对外报告结论/定性/金额 | 30 分钟内回滚 + 通知质控部 | 项目负责人 |
| P1 重要 | 影响底稿/疑点标注（内部可见） | 2 小时内修复 + 通知审计经理 | 审计经理 |
| P2 一般 | 格式/归类/非关键字段 | 当日修复 | 审计经理 |
