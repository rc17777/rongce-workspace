## 概述

截至2026年5月，Obsidian社区插件已超过2700个。文章将11个核心插件按四个梯队分层介绍。

---

## 第一梯队：AI 对话与知识库问答

这是让 AI 能"读懂你的笔记"的基础设施。

### 1. Copilot —— 功能最全面的 AI 对话入口

- Obsidian 安装量最大的 AI 插件
- 集对话、Vault QA、内联编辑、自定义 Prompt 于一体
- 不内置模型，需接入 API（OpenAI、Anthropic、Google）或本地模型（Ollama、LM Studio）
- **核心模式 Vault QA**：笔记全量向量化索引 → 自然语言提问 → 语义检索相关片段 → 带引用回答
- **配置要点**：对话模型和 Embedding 模型必须分别配置。本地隐私方案：LM Studio/Ollama 跑 DeepSeek 7B 做对话 + `nomic-embed-text` 做嵌入，Base URL 填 `http://localhost:1234/v1`

### 2. Khoj —— 完全本地的开源 AI 知识库助手

- 2026年最受关注的本地优先 AI 知识库方案
- 支持语义搜索、对话式问答、自定义 Agent
- 检索 Markdown、PDF、图片、Word 等多种格式
- **所有数据留在本地**：自托管 + Ollama 本地模型
- **与 Copilot 的核心区别**：Copilot 是"AI 对话界面"，Khoj 更进一步——能创建自定义 Agent，让 AI 主动帮你整理知识
- **选择建议**：日常快速问答用 Copilot（轻量、集成度高），深度知识库检索和 AI 主动整理用 Khoj

## 第二梯队：语义关联与知识图谱

AI 能回答你的问题之后，下一步是让知识自己找到知识。

### 3. Smart Connections —— 零配置的语义关联引擎

- Obsidian 最成熟的本地语义关联插件
- **最大亮点**：无需 API Key 就能做语义检索——安装后自动用本地嵌入模型索引笔记
- 打开任意一篇，右侧面板自动显示语义最相关的其他笔记
- **Smart Context 新功能**：把多篇语义相关的笔记打包成干净的可复用上下文，直接喂给 ChatGPT、Claude 等外部 AI 工具，大幅减少 Prompt 的 Token 消耗

### 4. OpenGem —— 把代码库变成可查询的知识图谱

- 2026年4月上线，连接 OpenCode 和 Obsidian 的 AI 插件
- 用 tree-sitter 解析 15+ 种编程语言源码 → 自动构建函数/类/模块之间的调用图和导入关系
- 存储在本地 `.opengem/` 目录
- AI 助手不需要反复扫描整个代码库——一次查询，直接走图遍历
- **分工**：Smart Connections 负责"笔记之间的语义关联"，OpenGem 负责"代码与文档之间的结构化关联"

## 第三梯队：AI 深度集成与知识库自动化

让 AI 帮你管理知识库。

### 5. Claudian —— 把 Claude Code 搬进 Obsidian

- 把 Claude Code 完整搬进 Obsidian
- 支持 Claude Code 的完整 Skills 技能体系、内联编辑、重构内容、调用 Skills
- 可在 Obsidian 里直接对 Claude Code 说："帮我重写这一段，把逻辑理清楚"，或"扫描我这周的笔记，找出有矛盾的观点"
- 需手动安装：GitHub Releases 下载 main.js、manifest.json、styles.css → `.obsidian/plugins/claudian/`

### 6. mindloom —— Karpathy LLM Wiki 的一键实现

- 社区开发者 @jupiterthewarlock 对 Karpathy LLM Wiki 思路的完整工程实现
- 极简操作：贴链接或丢 PDF → Claude Code 自动抓取内容 → 存入 `raw/` → 编译成 `wiki/` 知识页面 → 建立双向链接 → 标注矛盾 → 更新索引和日志
- 命令行操作：
  - `loom init ~/my-wiki` — 初始化 Vault
  - `loom add "URL" -t "标签" -v ~/my-wiki` — 添加文章
  - `loom ask "问题" -v ~/my-wiki` — 直接提问
- 每次操作自动记录 `log.md`，生成可追溯的全量审计日志

### 7. vault-memory —— 把 Obsidian 变成 AI Agent 的原生记忆层

- 2026年5月发布1.0稳定版
- 本地 MCP 服务器，把 Obsidian Vault 直接变成 Claude Code 等 AI Agent 的原生记忆系统
- **23 个 MCP 工具**：混合语义搜索（BM25 + 向量）、双向链接图分析、Frontmatter 查询、原子写入（带并发锁）
- AI Agent 可像操作数据库一样操作知识库——读笔记、搜索、分析链接图谱、修改笔记
- 所有数据不离开机器

## 第四梯队：结构化与非 AI 基石插件

AI 再强，也需要一套结构化的知识底盘来承载。这三款非 AI 插件是所有 AI 插件能高效运转的地基。

### 8. Dataview —— 把笔记变成可查询的数据库

- Obsidian 插件生态中最经典的数据查询引擎
- 把 Markdown 文件索引为实时更新的数据库
- 类 SQL 语法查询笔记元数据（标签、日期、状态、项目名）→ 动态表格/列表/日历视图
- **对 AI 知识库的价值**：把分散在几百篇笔记里的结构化信息聚合到一个视图，让 AI 有清晰的"数据入口"
- 类比：知识库的 SQL 层——没有它，AI 检索笔记就像在没有索引的数据库里做全表扫描

### 9. Templater —— 让重复性笔记工作自动化

- Obsidian 生态中最强大的模板引擎
- 支持变量、JavaScript 代码、逻辑判断、外部 API 调用
- 核心价值：把"每次创建笔记都要手动填日期、写标题、加标签"的重复劳动全自动化
- **对 AI 知识库的价值**：统一的 Frontmatter 格式是 AI 语义检索准确率的基础。为不同类型笔记（读书笔记、项目复盘、会议纪要）创建标准化 YAML 模板

### 10. Tasks —— 把知识库里的待办事项管起来

- 全库 Markdown 文件中自动识别任务（`- [ ]` 格式）
- 支持截止日期、优先级、标签、重复规则
- 查询语法生成动态任务列表
- **对 AI 知识库的价值**：AI 对话中产生的行动项被 Tasks 自动捕捉 → 按项目/日期/优先级汇总到仪表盘 → "对话→任务→执行"完整闭环

### 11. Excalidraw —— 在 Obsidian 里画架构图、思维导图、流程图

- 把 Excalidraw 的完整手绘风格绘图引擎集成进 Obsidian
- 支持与笔记之间的双向链接和联动
- **对 AI 知识库的价值**：把复杂的系统架构、数据流、决策逻辑用可视化方式呈现。对于需要 AI 辅助分析复杂逻辑链的场景，Excalidraw 是唯一能把这些"非文本知识"结构化的工具

## 最佳组合：按角色推荐

### 内容创作者/研究者
**Copilot + Smart Connections + Claudian**
- Copilot：日常问答和写作辅助
- Smart Connections：发现笔记之间的隐藏关联
- Claudian：Claude Code 深度整理和重构

### 开发者/技术团队
**Copilot + Smart Connections + OpenGem + vault-memory**
- Smart Connections：零配置语义关联
- OpenGem：代码库解析为知识图谱
- vault-memory：整个 Vault 暴露为 AI Agent 原生记忆系统

### Karpathy LLM Wiki 实践者
**mindloom + Dataview + Templater**
- mindloom：最省心——贴链接，AI 全自动编译
- Dataview：数据查询和仪表盘
- Templater：模板自动化
- Khoj：可选，日常问答辅助入口

## 融策关联分析

1. **与 "LLM Wiki 知识库设计"（MEMORY 2026-05-22）的呼应**：之前我们基于 Karpathy LLM Wiki 设计了融策 Wiki 知识库结构（6类页面/两大主题域/CLAUDE.md规则框架），这篇文章给出了完整的工具链方案——mindloom 是 Karpathy 理念的一键实现，Dataview + Templater 是结构化底盘。

2. **vault-memory 与 audit-plugin 的潜在结合点**：vault-memory 提供 23 个 MCP 工具让 AI Agent 程序化操作知识库。如果融策的 audit-plugin 能通过 MCP 直接读写审计知识库（政策法规/案例/方法）——那就是 audit-plugin 的"原生记忆层"。

3. **Smart Context 的实用价值**：把多篇语义相关的笔记打包为干净可复用的上下文 → 直接喂给 AI。对审计场景：把相关法规 + 相似案例 + 审计方法打包成一个上下文块，大幅减少 Prompt 体积。

4. **Obsidian 引入的可行性**：融策目前没有 Obsidian 体系。如果引入，建议从"创作者/研究者"组合开始（Copilot + Smart Connections + Claudian），配合已有 Wiki 知识库设计逐步落地。
