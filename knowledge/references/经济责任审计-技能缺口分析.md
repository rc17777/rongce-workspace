## 一、经济责任审计的完整工作流

```
进场 → 政策解读 → 实施方案 → 取证分析 → 量化评分 → 责任认定 → 报告撰写
  │        │          │          │          │          │          │
  │    policy-    implementation- multi-    【缺口】  【缺口】  report-
  │    digest     plan           source-                       writer
  │                              analysis                     【需增强】
  │                              
  └── 无经责专用的进场面试/资料清单模板
```

### 现有技能覆盖情况

| 工作流环节 | 现有技能 | 覆盖度 | 缺口 |
|:----------|:--------|:------|:-----|
| 进场准备 | 无 | 0% | 无经责专用资料清单、访谈提纲 |
| 政策解读 | policy-digest ✅ | 70% | 缺少经责审计特有的法规库（党政主要领导干部和国有企业领导人员经济责任审计规定等） |
| 实施方案 | implementation-plan ✅ | 50% | 无经责审计专用模板，无量化评价方案 |
| 取证分析 | multi-source-analysis ✅ | 60% | 5大维度各自的数据源和取证方法未定义 |
| **量化评分** | **无** | **0%** | **5维×22指标的自动化打分框架完全缺失** |
| **责任认定** | **无** | **0%** | **直接/领导/免责三类区分无技能支撑** |
| 报告撰写 | report-writer ⚠️ | 40% | 无经责报告专用章节（履职评价章），无撰写红线检查 |
| 问题发现 | finding-generator ⚠️ | 50% | 四层递进框架可用，但无经责专用的严重度分级（需关联责任类型） |
| 建议生成 | recommendation-engine ✅ | 60% | 通用框架可用，但缺少经责特有的整改建议模板 |

## 二、核心缺口详解

### 缺口1：量化评分引擎（最优先）

**缺失能力**：将审计发现自动映射到5大维度指标体系并打分。

**需要的原子技能**：

| 原子技能 | 功能 | 优先级 |
|:--------|:----|:------|
| `eval-dimension-scorer` | 按5大维度对审计发现归类，自动匹配到17项二级指标 | 🔴 P0 |
| `eval-weight-calculator` | 根据指标权重计算加权总分，自动生成评分雷达图 | 🔴 P0 |
| `eval-threshold-config` | 按项目类型/规模配置差异化扣分阈值 | 🟡 P1 |
| `eval-cross-validation` | 交叉验证：问题严重度 → 责任等级 → 评分区间的一致性检查 | 🟡 P1 |

**技术方案**：

```yaml
# 理想调用流程
1. multi-source-analysis → 输出结构化发现列表（已实现）
2. eval-dimension-scorer → 每条发现匹配到 [A-E] 维度 + [1-17] 指标
3. eval-weight-calculator → 计算各维度得分 + 总分
4. finding-generator → 对扣分项做四层递进分析（已实现）
5. responsibility-classifier → 责任认定
6. report-writer → 嵌入评分结果生成经责报告
```

### 缺口2：责任认定引擎

**缺失能力**：根据审计发现自动判定直接/领导/免责。

**需要的原子技能**：

| 原子技能 | 功能 | 优先级 |
|:--------|:----|:------|
| `resp-classifier` | 根据发现特征自动判定责任类型 | 🔴 P0 |
| `resp-evidence-mapper` | 每种责任类型需要的证据链清单 | 🟡 P1 |
| `resp-cross-check` | 多源交叉验证：同一问题的不同责任人之间的责任分配 | 🟢 P2 |

**判定逻辑**（可编码为规则引擎）：

```
IF 发现含"个人签字/授意/直接操作/明知故犯" → 直接责任
ELIF 发现含"制度缺失/系统性/普遍性/分管领域" → 领导责任
ELIF 发现含"历史遗留/政策变更/不可抗力/程序到位" → 无责任/免责
ELSE → 标记为"需人工判断"
```

### 缺口3：经责报告模板增强

**现有 report-writer 覆盖**：通用政府专项审计报告（审计概况→基本情况→发现问题→审计评价→审计建议）

**缺少**：经济责任审计报告特有的章节——

```markdown
## 第X章 履职评价（经责审计特有，通用报告无此章）

### X.1 量化评分总览
| 维度 | 权重 | 得分 | 得分率 | 等级 |
|------|------|------|--------|------|
| 重大经济决策 | 30% | 24/30 | 80% | 良好 |
| 工程管控 | 25% | 20/25 | 80% | 良好 |
| 资金资产绩效 | 25% | 18/25 | 72% | 合格 |
| 合规风控 | 12% | 10/12 | 83% | 良好 |
| 廉洁自律 | 8% | 8/8 | 100% | 优秀 |
| **合计** | **100%** | **80/100** | **80%** | **良好** |

### X.2 五大维度分别评价
（每个维度含：得分、主要成效、存在不足、具体事实）

### X.3 责任认定
| 问题编号 | 问题描述 | 责任类型 | 责任主体 | 依据 |
|----------|---------|---------|---------|------|

### X.4 综合评价
（遵循5条撰写红线的话术规范）
```

### 缺口4：撰写红线自动检查

**缺失能力**：报告初稿生成后，自动扫描5条红线违规：

| 红线 | 检查方式 | 实现难度 |
|:----|:--------|:-------|
| 绝对化表述 | 正则匹配："完全合规""毫无问题""履职完美""百分之百" → 标记替换建议 | 低 |
| 责任夸大/弱化 | 语义分析：检查责任认定措辞是否匹配责任等级 | 中 |
| 无数据支撑 | 检测"总体较好""较为规范"→ 检查前后文是否有具体数字 | 中 |
| 问题评价脱节 | 交叉比对：发现清单 vs 评价段落中的问题引用 | 中 |
| 廉洁定性过重 | 正则匹配："存在廉洁问题""有廉政风险"→ 警告替换 | 低 |
