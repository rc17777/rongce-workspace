## 一、场景

某中学校长经济责任审计 → 食堂消费数据→ 甄别未纳入资助的困难学生 → 发现**12名**学生餐均消费远低于平均水平且未享受补助。

## 二、SQL分析流程

```
食堂数据表 + 建档立卡困难人口表 + 助学金表
  ↓ JOIN on 身份证号
标记字段: '助学金人员' / '建档立卡人员' / NULL
  ↓ 聚焦午餐+晚餐（排除波动大的早餐）
  ↓ GROUP BY 学生 → COUNT(用餐次数) + AVG(消费金额)
  ↓ HAVING: 剔除用餐次数<全校均值一半的学生
  ↓ 按男女生分别设定餐均消费阈值
  ↓ ORDER BY → 定量排序
  ↓ 定性核实（家访、镇村核实）
  → 确认12人均符合资助条件
```

## 三、可借鉴思路

### 异常检测的"多源交叉验证"模式

| 文章做法 | 融策招投标审计对应 |
|:--------|:-----------------|
| 食堂数据 ↔ 助学金名单 ↔ 建档立卡表 | 投标文件数据 ↔ 工商数据 ↔ 社保数据 |
| JOIN on 身份证号 | JOIN on 统一社会信用代码 |
| 消费行为异常 → 政策执行漏洞 | 投标行为异常 → 采购制度漏洞 |
| 定量筛选 + 定性核实 | L1-L12定量 + P0/P1核查清单定性 |

### SQL在审计中的应用模式

文章中使用的SQL技巧可直接迁移到招投标数据分析：
- `ALTER TABLE` 标记字段 → 标记"异常投标人"
- `GROUP BY + HAVING` 过滤 → 过滤TF-IDF低于阈值的对
- 多表JOIN交叉 → 投标人+工商+社保+历史异常标记库
