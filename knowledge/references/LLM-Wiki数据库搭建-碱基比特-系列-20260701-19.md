# LLM-Wiki 数据库搭建系列（四部分全）

作者：碱基比特。核心介绍了 Andrej Karpathy 提出的 LLM Wiki 范式。

## 核心理念：LLM Wiki ≠ RAG

RAG：每次查询时从原始文档中检索 → 拼进 Prompt → 生成。文档被切碎、向量化，每次查询都要重新"阅读"原文。

**LLM Wiki**：放弃查询时检索原始文档。让 LLM 逐步构建和维护一个持久化的 wiki——一组结构化、相互链接的 Markdown 文件，作为原始资料和查询之间的中间层。

| 维度 | RAG | LLM Wiki |
|:--|:--|:--|
| 知识形态 | 向量库中的碎片 | 结构化的相互链接的 markdown 文件 |
| 处理时机 | 查询时检索 | 离线预编译 |
| 知识关联 | 无显式关联 | 双向链接，知识联网 |
| 持续演进 | 需要重新索引 | 渐进式更新，越用越厚 |
| 来源追溯 | 可追溯（文档片段） | 可追溯（wiki 页面引用来源） |
| 适合场景 | 文档量大、更新频繁 | 知识体量适中、需深度理解 |

## 三层架构
1. **原始资料源（Raw Sources）**：只读的源文档集合。LLM 从中读取但绝不修改。
2. **Wiki**：LLM 生成的 Markdown 文件目录。摘要、实体页面、概念页面、对比分析、概览。LLM 创建页面、更新页面、维护交叉引用。
3. **Schema（模式定义）**：配置文档（如 CLAUDE.md / AGENTS.md），定义 wiki 结构、约定、工作流。

## 操作逻辑
- 摄入（Ingest）：新资料放进原始资料集 → LLM 阅读 → 提取关键信息 → 整合进现有 wiki → 更新实体页面 → 修订主题摘要 → 标注新数据与旧结论的矛盾之处
- 查询：直接查已编译的 wiki 页面，无需实时检索

## QMD 搜索引擎
- 本地 Markdown 文件搜索引擎
- 支持 BM25/向量混合搜索 + LLM 重排序
- 全部本地运行
- MCP 接口可集成到 Claude Code
- 命令：`qmd search`, `qmd vsearch`, `qmd query`, `qmd get`

## 对审盾的价值
LLM Wiki 的"知识预编译"思路对审盾二期有重要参考价值：
- 审盾一期（当前）：RAG 向量检索 → 实时检索原始文档
- 审盾二期方向：将高频使用的法规、常见问题类型、整改建议预编译为结构化 wiki 页面，查询时直接读取 wiki 而非实时检索

但**审计场景不适合完全放弃 RAG**，因为：
1. 法规政策更新频繁（每月都有新文件）
2. 审计需要精确溯源（"根据 XX 号文件第 X 条"）
3. 项目经验库需要持续积累

**建议方案：RAG + LLM Wiki 混合**——高频稳定知识走 wiki 预编译，动态更新知识走 RAG 实时检索。
