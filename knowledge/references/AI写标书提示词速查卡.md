# AI写标书·提示词速查卡

> 来源：公众号「每天用Ai解决一个问题」 | 提取：2026-07-30
> 用途：技术方案撰写 + 项目背景分析

---

## 一、技术方案撰写（四步法）

### 提示词 1：生成对标评分标准的大纲

```
你是一名【XX行业】的资深技术顾问。请根据以下招标文件中的技术要求和评分标准，生成一份技术方案大纲。

【招标文件技术部分】

（粘贴技术要求、技术评分标准等内容）

要求：
1. 大纲的每个一级标题必须对应技术评分标准中的一项评分点
2. 在每个一级标题后标注对应的评分点编号和满分值，格式如："一、项目整体方案（对应评分点T1，15分）"
3. 每个一级标题下展开3-5个二级标题，覆盖该评分点的所有要求
4. 大纲末尾附一个"评分点覆盖检查表"，确认所有技术评分点都已被大纲覆盖

输出格式：层级编号的大纲 + 评分点覆盖检查表
```

> 🔑 关键：评分点→大纲的逆向映射，专家怎么打分你就怎么组织章节。

---

### 提示词 2：逐章生成初稿

```
请撰写技术方案中【章节名称】的初稿。

【本章大纲】
（粘贴该章节的二级标题和三级要点）

【相关招标要求】
（粘贴招标文件中与该章节相关的技术要求原文）

【公司技术能力】
（列出你们公司在该领域的技术积累、产品参数、成功案例）

写作要求：
1. 每个二级标题展开为800-1200字
2. 所有技术参数必须来自【公司技术能力】，不要编造
3. 每涉及一个招标要求，用"（响应招标文件第X章第X条）"标注
4. 实施步骤用"第1步→第2步→第3步"的格式
5. 避免以下表述："先进的""领先的""一流的"——用具体参数代替形容词
6. 段落不超过6行，超过则拆分
```

> 🔑 关键：逐章生成不要一次全文（后半部分质量会明显下降）；逐条标注招标条款响应。

---

### 提示词 3：技术选型论证（翻车教训补救）

```
每个技术选型决策，必须附带200字以上的选型理由，包括：
- 候选方案对比（至少2个方案）
- 每个方案的优劣
- 最终选择的取舍依据
```

> 🔑 关键：AI方案不缺内容，缺的是"为什么选这个不选那个"的论证过程。

## 二、项目背景分析（10分钟速成法）

### 前置：3分钟填项目信息卡

| 信息维度 | 要填的内容 |
|:---------|:-----------|
| 项目名称 | 完整项目名称 |
| 采购单位 | 单位全称 + 所属行业 |
| 项目核心目标 | 一句话说清这个项目要解决什么问题 |
| 政策依据 | 2-3个最相关的国家/地方政策（写文件全名） |
| 行业痛点 | 采购单位当前具体面临什么困难（2-3条） |
| 我方优势 | 你们公司在这个领域有什么独特能力 |
| 关键数据 | 跟项目相关的行业数据、增长趋势等 |

---

### 提示词 1：生成写作框架

```
你是一名有10年投标经验的技术顾问。请根据以下招标文件摘要和项目信息，帮我生成一份项目背景分析的写作框架。

【招标文件摘要】
（粘贴招标文件中项目概况/采购需求章节的内容）

【项目信息卡】
（粘贴上一步整理的项目信息卡）

要求：
1. 框架至少包含5个维度，如政策环境、行业现状、项目痛点、技术趋势、实施必要性等
2. 每个维度下列出3-5个具体的写作要点，每个要点一句话说清楚要写什么
3. 标注每个维度建议引用的具体政策文件或数据来源
4. 框架结构遵循"宏观→行业→项目→必要性"的递进逻辑

输出格式：按层级列出框架，每层用编号标注
```

> 🔑 关键：不让AI写正文，只出框架。骨架对了肉才好填。

---

### 提示词 2：逐节生成正文

```
请根据以下框架要点，撰写"项目背景分析"中【XX维度】部分的正文。

【写作要点】
（粘贴框架中该维度的写作要点）

【项目信息卡】
（再次粘贴项目信息卡，确保AI不偏离）

写作要求：
1. 每个写作要点展开为一个自然段，150-250字
2. 政策引用必须标注文件全称，避免"有关文件指出"这类模糊表述
3. 行业数据必须说明来源和时间，如"根据XX研究院2024年报告"
4. 每个自然段末尾用一句话关联本项目
5. 语气正式但不空洞，每句话都要有信息量
6. 严禁使用"随着经济发展""在新时代背景下"等套话开头
```

> 🔑 关键：每引用一个政策，后面必须跟一句"本项目中的XX内容正是落实这一要求"。

---

## 三、通用去AI味检查清单

- [ ] 术语一致性：同一概念全文用同一个词
- [ ] 删除重复内容：不同章节不要重复"公司介绍""技术优势"
- [ ] 强化逻辑链：需求分析提出的问题 → 技术方案都有对应解决
- [ ] 政策-项目关联：每引一个政策 → 必须跟一句"本项目如何落实"
- [ ] 数字核实：AI生成的数字全部回原始来源核实，没来源的删除
- [ ] 补充独家信息：同类项目经验数据、对采购方的具体了解、行业案例
- [ ] 禁止套话开头："随着经济发展""在新时代背景下""先进的""一流的"

---

## 四、避坑清单

| 坑 | 后果 | 正确做法 |
|:---|:-----|:---------|
| AI一次生成全文 | 框架扁平、衔接生硬、篇幅失控 | 框架先行→逐节生成→人工组装 |
| 不核实AI引用的政策 | AI会编造看似真实实际不存在的政策文件名 | 每条政策去官网核实 |
| 背景分析写3000字技术方案写800字 | 喧宾夺主 | 背景1500-2000字，省下时间做技术方案 |
| 技术选型只写结果不写理由 | 专家评"缺乏论证过程" | 每个决策附200字以上选型理由 |
| 安全/实施方案写通用模板 | 缺乏行业针对性 | 结合具体行业合规要求定制 |

---

## 五、绩效拉满的5个提分细节

1. **写失败预案**：实施计划里加"风险识别与应对措施"，列3-5个可能出问题的环节
2. **用对账表响应**：方案末尾加"招标要求响应一览表"（左：要求原文 / 右：方案章节+页码）
3. **关键岗位放真实简历**：项目经理、技术负责人放脱敏真实简历
4. **技术指标用承诺值**：不是"≤3秒"而是"我方承诺≤1.5秒（XX项目实测1.2秒）"
5. **附增值建议**：超出招标要求但能创造额外价值的1-2条建议（标注"建议但不必须"）
