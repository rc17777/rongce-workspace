# 审计现场管理SOP·AI工具嵌入指南

> 依据：《审计现场管理图解》（中国时代经济出版社）｜编制：融策·审盾 2026-07-29
> 用途：每个审计项目的标准化操作流程 + AI辅助工具调用节点

---

## 总流程图

```
审计组组成 → 审前准备 → 现场实施 → 形成报告+整改跟踪
   │              │           │              │
   │  AI: 人员    │  AI: RAG  │  AI: OCR    │  AI: 审盾复核器
   │  专业匹配    │  法规检索  │  Agent取证  │  四维输出+整改追踪
   │              │  历史案例  │  规则引擎   │
   └──────────────┴───────────┴──────────────┘
```

## 第一阶段：审计组组成

### 1.1 人员架构

| 角色 | 职责 | 配置标准 |
|:-----|:-----|:-----|
| 审计组组长 | 全面负责、审定方案与报告 | 1人，由审计机关/事务所指定 |
| 主审 | 组织实施现场审计、复核底稿 | 1人 |
| 审计组成员 | 按专业分工执行审计程序 | ≥2人（财务/工程/IT/法律按需） |
| 廉政监督员 | 独立监督审计纪律 | 1人（可与组员兼任） |

### 1.2 操作步骤

| 步骤 | 动作 | 产出物 |
|:-----|:-----|:-----|
| 1.1 | 明确审计项目类型与范围 | 审计任务书 |
| 1.2 | 匹配专业领域，选定组长与主审 | 人员名单 |
| 1.3 | 按需配置组员（财务至少1人+业务对口1人） | 审计组成员表 |
| 1.4 | 指定廉政监督员 | 廉政监督承诺书 |
| 1.5 | 组长召开进驻前碰头会，明确分工与时间表 | 会议纪要 |

### 🤖 AI嵌入点

| 节点 | AI工具 | 作用 |
|:-----|:-----|:-----|
| 1.2 选组长/主审 | Agent路由（agent_router.py） | 根据项目类型自动推荐22 Agent中最匹配的专业方向 |
| 1.3 配置组员 | 专业匹配 | 根据审计类型（经责/绩效/招投标等12线）建议人员配比 |
| 1.5 碰头会 | 会议纪要分析Agent | 自动生成结构化会议纪要+待办事项 |

## 第二阶段：审前准备

### 2.1 调查了解

| 步骤 | 动作 | 产出物 | 时限 |
|:-----|:-----|:-----|:-----|
| 2.1.1 | 收集被审计单位基本情况 | 基本信息表 | 1-2天 |
| 2.1.2 | 收集行业特点及相关政策法规 | 法规清单 | 同步 |
| 2.1.3 | 了解内控制度建立及执行情况 | 内控评价底稿 | 1-2天 |
| 2.1.4 | 分析财务数据及业务数据，确定审计重点 | 数据初筛报告 | 1-2天 |
| 2.1.5 | 汇总调查结论，形成审前调查报告 | 审前调查报告 | 合计≤5天 |

### 2.2 编制审计实施方案

| 步骤 | 动作 | 关键要素 |
|:-----|:-----|:-----|
| 2.2.1 | 明确审计目标 | 回答「审什么、为什么审」 |
| 2.2.2 | 确定审计范围 | 时间范围+机构范围+资金范围 |
| 2.2.3 | 确定审计内容与重点 | 具体事项清单+优先级 |
| 2.2.4 | 确定审计步骤与方法 | 取证方法+抽样策略 |
| 2.2.5 | 人员分工与时间安排 | 甘特图/进度表 |
| 2.2.6 | 审批方案 | 组长签批→业务部门备案 |

### 2.3 下达审计通知书 & 审前培训

| 步骤 | 动作 | 时限 |
|:-----|:-----|:-----|
| 2.3.1 | 编制审计通知书（列明范围/时间/人员/资料清单） | — |
| 2.3.2 | 提前3天送达被审计单位（特殊情况除外） | ≥3天 |
| 2.3.3 | 组织审前培训（法规+行业+标准统一） | 0.5-1天 |

### 🤖 AI嵌入点

| 节点 | AI工具 | 作用 |
|:-----|:-----|:-----|
| 2.1.2 法规收集 | **智析v2.0 RAG** (`/api/rag/query`) | 按审计类型自动检索适用法规+政策+审计要点 |
| 2.1.2 法规收集 | RAG知识库 (13,706 chunks) | 补充历史案例库中相似项目的法规适用 |
| 2.1.3 内控评价 | 数据侦察兵 Agent | 自动分析内控自评报告，标注薄弱环节 |
| 2.1.4 数据初筛 | **Benford定律** (financial-fraud-detection) | 金额字段分布异常初筛 |
| 2.1.4 数据初筛 | **数据侦察兵 Agent** | 财务数据趋势分析+异常标注 |
| 2.1.5 审前调查报告 | **方案撰写师 Agent** | 根据调查结果自动生成审前调查报告框架 |
| 2.2.1-2.2.6 方案编制 | **方案撰写师 Agent** | 根据项目类型+调查结论，生成审计实施方案初稿（含审计重点/抽样策略/人员分工/时间表） |
| 2.3.1 审计通知书 | 模板引擎 | 按审计类型自动填充通知书模板 |
| 2.3.3 审前培训 | RAG知识库 | 自动生成培训材料：法规要点+行业特征+历史常见问题 |

## 第三阶段：现场实施

### 3.1 审计取证

| 步骤 | 动作 | 取证方法 | 关键要求 |
|:-----|:-----|:-----|:-----|
| 3.1.1 | 进点会谈 | 询问 | 形成会谈纪要，被审计单位确认 |
| 3.1.2 | 收集财务资料 | 检查 | 建立资料交接清单，双方签字 |
| 3.1.3 | 实质性测试（凭证/账簿/报表） | 检查+重新计算 | 抽样或全量，覆盖审计重点 |
| 3.1.4 | 实地盘点/勘察 | 观察+检查 | 拍照留证、制作盘点表 |
| 3.1.5 | 外部函证 | 函证 | 银行/往来单位/关联方 |
| 3.1.6 | 数据分析比对 | 分析程序 | 趋势/比率/合理性分析 |
| 3.1.7 | 编制取证单 | — | **逐份由被审计单位签字确认** |

### 3.2 编制审计工作底稿

| 步骤 | 动作 | 标准 |
|:-----|:-----|:-----|
| 3.2.1 | 逐事项编制底稿（事项/过程/结论/依据） | 内容完整、记录清晰 |
| 3.2.2 | **主审复核**（第一级） | 检查底稿完整性、逻辑性 |
| 3.2.3 | **组长复核**（第二级） | 检查问题定性、证据充分性 |
| 3.2.4 | 修改完善底稿 | 如有问题返回修改 |

### 3.3 沟通反馈与退场

| 步骤 | 动作 | 时限 |
|:-----|:-----|:-----|
| 3.3.1 | 重大问题随时沟通、一般问题阶段性沟通 | 过程中 |
| 3.3.2 | 退场前：清点归还资料、整理归档底稿 | 退场当天 |
| 3.3.3 | 编写审计组工作报告 | 退场后1-3天 |
| 3.3.4 | 审计组撤离 | — |

### 🤖 AI嵌入点

| 节点 | AI工具 | 作用 |
|:-----|:-----|:-----|
| 3.1.1 进点会谈 | 会议纪要分析Agent | 录音→转写→结构化纪要→待核实事项清单 |
| 3.1.2 资料收集 | OCR预处理Agent | 纸质资料→OCR→结构化数据 |
| 3.1.3 凭证测试 | **调整分录生成师 Agent** | 发现差异后自动生成调整分录建议 |
| 3.1.3 凭证测试 | 数据侦察兵 Agent | 批量比对：金额/日期/科目/摘要一致性 |
| 3.1.5 外部函证 | 自动化函证模板 | 按往来单位自动生成函证格式 |
| 3.1.6 数据分析 | **Apriori关联规则** (apriori-audit) | 多维关联挖掘（供应商/科目/时段异常组合） |
| 3.1.6 数据分析 | **Benford定律** | 金额首位数字分布检测 |
| 3.1.6 数据分析 | **FP-growth伴随投标** | 招投标审计：多项目联合检测围标模式 |
| 3.1.6 数据分析 | **13维关联方识别** | Agent自动比对工商/股权/人员/地址等13维度 |
| 3.1.7 取证单 | 规则引擎 | 格式校验+关键字段不缺项检查 |
| 3.2.1 底稿编制 | **底稿工匠 Agent** | 根据取证单自动填充底稿模板，生成初稿 |
| 3.2.2-3.2.3 三级复核 | **审盾复核器** | 辅助一级复核：格式/逻辑/法规引用自动检查 |
| 3.3.2 资料清点 | 资料清单比对 | OCR扫描后自动比对借出/归还清单 |
| 3.3.3 审计组报告 | 报告笔杆子 Agent | 汇总底稿→生成审计组工作报告初稿 |

## 第四阶段：形成报告 + 整改跟踪

### 4.1 审计报告征求意见

| 步骤 | 动作 | 时限 |
|:-----|:-----|:-----|
| 4.1.1 | 审计组起草审计报告（征求意见稿） | 退场后3-7天 |
| 4.1.2 | 送达被审计单位征求意见 | 当面送达或挂号邮寄 |
| 4.1.3 | 被审计单位书面反馈意见 | **10日内** |
| 4.1.4 | 审计组研究反馈意见，采纳合理意见 | 收到反馈后2-3天 |
| 4.1.5 | 不采纳的必须书面说明理由 | 同步 |

### 4.2 审计报告审理（五审五查）

| 审理维度 | 检查内容 |
|:-----|:-----|
| ①审计程序 | 是否按规定程序执行 |
| ②审计证据 | 是否充分、适当、形成证据链 |
| ③问题定性 | 是否准确、依据是否充分 |
| ④处理处罚 | 适用法律是否正确、幅度是否恰当 |
| ⑤审计评价 | 是否客观、与问题是否矛盾 |

### 4.3 报告出具与送达

| 步骤 | 动作 |
|:-----|:-----|
| 4.3.1 | 审计机关召开**审计业务会议**，集体审定报告 |
| 4.3.2 | 出具正式审计报告 + 审计决定书 |
| 4.3.3 | 送达被审计单位 + 相关主管部门 |
| 4.3.4 | 按规定范围公布审计结果 |

### 4.4 整改跟踪

| 步骤 | 动作 | 时限 |
|:-----|:-----|:-----|
| 4.4.1 | 被审计单位报送整改情况 | **60日内** |
| 4.4.2 | 审计机关跟踪检查整改进展 | 持续 |
| 4.4.3 | 建立整改台账，动态管理 | — |
| 4.4.4 | 整改情况作为后续审计的参考 | — |

### 🤖 AI嵌入点

| 节点 | AI工具 | 作用 |
|:-----|:-----|:-----|
| 4.1.1 报告起草 | **报告笔杆子 Agent** | 汇总审计发现→生成报告初稿（含问题/依据/建议完整段落） |
| 4.1.3 反馈意见处理 | **审盾复核器** | 筛选反馈意见中的合理性，标注需要回应的核心争议 |
| **4.2 审理** | **⭐审盾复核器（核心定位）** | **15维全面复核**：10维正文+5维交叉比对 |
| 4.2 审理 | 法规检察官 Agent | 逐条验证法规引用是否现行有效、适用正确 |
| 4.2 审理 | 复核哨兵 Agent | 终审级零容错检查（≤2次/项目触发opus） |
| 4.3.1 业务会议 | 会议纪要分析Agent | 会议决议结构化记录+决议事项追踪 |
| 4.4 整改跟踪 | **整改台账自动比对** | 上传的整改材料OCR→自动比对审计决定事项→标记是否已覆盖 |
| 4.4 整改跟踪 | 时效预警 | 距60日截止≤7天时自动提醒 |

## ⚠️ AI使用红线（守拙老师四条规矩映射）

| 规矩 | SOP中的体现 | 违规示例 |
|:-----|:-----|:-----|
| **①每个判断标明来源** | 所有AI输出的法规引用必须注明制度名称+条款号，无原文标注"待核实" | AI自行补全不存在的法规条文 |
| **②事实/风险/待核实分层** | 审盾复核器输出强制四分类标签 | 把推测的风险当作已确认事实 |
| **③无整改证据不判有效** | 4.4整改跟踪中AI只做「已提交/未提交」状态标注，不做有效性判断 | 看到整改报告就标"整改完成" |
| **④历史匹配标为线索** | RAG相似案例输出前加「历史相似线索，非本项目已确认事实」标签 | 把旧案例直接当作当前项目问题 |
