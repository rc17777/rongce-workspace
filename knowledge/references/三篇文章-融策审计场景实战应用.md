## 文章一实战：「守拙四条规矩」→ 审计报告质控复核

### 场景 A：经责审计报告质控（最高频场景）

**触发条件**：经责审计报告（征求意见稿）完成后，提交审理前

**操作**：
```bash
python scripts/report_review_workflow.py --file "经责审计报告-征求意见稿.docx" --deep
```

**四分类输出改造（新增）**：

AI复核报告不再输出扁平列表，而是强制四分类：

```
=== 已确认事实（有证据链支撑） ===
1. 差旅费报销单缺少出差审批单（取证单D-12，已签字确认）
2. "三重一大"会议纪要缺失2023年第3次（取证单D-05）
   → 依据：中央《关于进一步推进国有企业贯彻落实"三重一大"决策制度的意见》

=== 风险提示（根据现有资料推测，需进一步核实） ===
3. 2023年招待费同比增长87%，远超营收增速12%
   → 注意：业务扩展可能导致招待费增加，非必然违规
4. 某供应商与子公司注册地址同一栋楼（非同一层）
   → 注意：同地址不一定等于关联关系

=== 待核实事项（证据不足） ===
5. 部分固定资产未贴标签（现场只抽查30%，需扩大样本）
6. 合同台账与财务账务存在3笔金额差异（待被审计单位提供解释）
   → 证据状态：差异已记录，原因待确认

=== 历史相似线索（非本项目已确认事实） ===
7. [相似案例#2019-经责-07] 国有企业领导人违规兼职取酬
   → 提示方向：检查领导班子成员是否在关联企业兼职
8. [相似案例#2022-工程-03] 在建工程长期挂账不转固
   → 提示方向：审查在建工程转固时点是否合理
```

**人工确认三步**：
- 回到原始依据：核对法规版本是否现行有效
- 回到本项目证据：核实四类分类是否准确
- 回到多级质控：组长/业务会议最终裁定

**触发条件**：绩效评价报告定稿前

**特别适配**：绩效评价的「事实/风险/待核实」分类需增加绩效维度——

| 标准分类 | 绩效评价专属子维度 |
|:-----|:-----|
| 已确认事实 | 指标完成值（有佐证材料）/ 资金使用率（有银行流水） |
| 风险提示 | 指标数据来源不一致 / 自评分数与复核分数偏差>10% |
| 待核实事项 | 满意度调查样本量不足 / 佐证材料未覆盖全部指标 |
| 历史相似线索 | 同类项目常见问题：指标设置不科学 / 资金沉淀 / 自评虚高 |

## 文章二实战：「三Agent审计科大讯飞」→ 融策审计Agent工作流

### 场景 D：国企审计·隐性关联方识别（对标 Agent 01）

**13维结构化比对实战版**：

| 维度 | 高风险(权重3) | 辅助(权重1) | 数据源 |
|:-----|:-----|:-----|:-----|
| ①实际控制人 | 控制人相同或亲属关系 | — | 天眼查/企查查 |
| ②股权穿透 | 持股≥20%或重大影响 | 持股<20% | 工商登记 |
| ③董监高交叉 | 双方高管互相任职 | 曾在同一企业任职 | 工商变更记录 |
| ④人员重叠 | 社保同月同一人出现在两家 | — | 社保数据 |
| ⑤注册地址 | 同一门牌号/同一栋楼同一层 | 同一栋楼不同层/同一街道 | 工商登记 |
| ⑥联系方式 | 相同电话/邮箱/网站域名 | — | 企业年报 |
| ⑦IP/MAC地址 | 投标IP同C段/MAC同厂 | — | 投标系统日志 |
| ⑧银行账户 | 同开户行+相近时间开户 | 同开户行 | 银行流水 |
| ⑨历史交易 | 3+项目同时出现 | 1-2次 | 历史招投标台账 |
| ⑩资金往来 | 大额无商业实质 | 少量往来 | 财务数据 |
| ⑪中标模式 | 轮流中标+异常报价分布 | 偶尔竞争 | 3年+招投标数据 |
| ⑫文件指纹 | 电子指纹八项(L18) | — | 投标文件 |
| ⑬注册变更 | 同一时间注册/变更 | 邻近时间 | 工商信息 |

**操作命令**：
```bash
python launch.py "XX国企经责审计" --type 国企
# → 自动触发 contract_hound + bid_hunter Agent
# → 13维关联方比对结果 → findings/ 目录
```

**人工确认点**：
- 维度①-④(人员/控制) ≥ 2个 → 🔴高置信度，建议深入
- 维度⑤-⑦(地址/IP) ≥ 2个 → 🟡中置信度，需排除合理巧合
- 仅有维度⑤且属普通写字楼 → ⬜低置信度，标注但不下结论

### 场景 E：研发密集型企业审计·研发支出穿透（对标 Agent 02）

**适用业务线**：①国企审计 ②成本效益审计 ③专项资金审计（科技类）

**三程序框架（动机→合规→实质）**：

```
第一层：资本化率与利润敏感度（查动机）
──────────────────────────────
输入：年度研发投入总额、资本化金额、净利润
计算：
  资本化率 = 资本化金额 / 研发投入总额 × 100%
  利润敏感度 = 资本化金额 / 净利润 × 100%

判断标准：
  - 资本化率同比变动 >10个百分点 → 异常，查资本化政策是否变更
  - 利润敏感度 >30% → 高敏感，企业有操纵利润动机
  - 利润敏感度 >50% → 严重关注，资本化政策直接影响盈亏

第二层：高企资质与研发人员合规（查合规）
──────────────────────────────
输入：研发人员名单、薪酬明细、学历、工时分配
检查项：
  ① 研发人员占比 ≥10%（高企认定标准）
  ② 研发费用占销售收入比例 ≥3%/4%/5%（按收入档）
  ③ 研发人员平均薪酬 vs 同业 vs 公司整体水平，异常偏离关注
  ④ 硕博占比 vs 研发性质匹配度
  ⑤ 是否存在非研发人员薪酬计入研发费用

第三层：资本化项目实质与减值（查实质）
──────────────────────────────
输入：资本化项目清单（含立项时间/预算/进度/验收）
检查项：
  ① 是否存在超3年未完工的"僵尸项目"→ 减值测试
  ② 本期新增资本化项目是否满足5条件（技术可行性等）
  ③ 已完工项目是否及时转入无形资产并摊销
  ④ 是否存在研发失败项目未及时费用化
  ⑤ 是否存在"为资本化而立项"的可疑小额项目
```

**操作命令**：
```bash
python launch.py "XX科技国企审计" --type 成本
# → 自动触发 budget_estimator + data_scout Agent
# → 三程序研发支出分析 → findings/ 目录
```

**人工确认点**：
- 第一层自动计算可直接采用，但资本化率变动原因需人工核实会计政策变更公告
- 第二层硕博占比不是硬性指标，仅作合理性参考
- 第三层项目实质判断必须人工核对项目文档

### 场景 F：通用·费用交叉验证三规则（对标 Agent 03）

**适用业务线**：全部12条业务线

**三条规则直接吸收进规则引擎（零LLM成本）**：

```
规则1：薪酬-员工匹配
──────────────────
条件：ABS(管理费用-薪酬 / 平均员工人数 - 上年同期值) / 上年同期值 > 30%
且 ABS(员工人数 - 上年同期值) / 上年同期值 < 10%
→ 输出：薪酬总额异常增长但员工人数未变，可能虚列人头/非正常加薪
→ 需核实：工资表中是否有离职人员/编外人员/一人多岗重复计薪

规则2：办公费-规模联动
──────────────────
条件：ABS(办公费 / 不含税营收 - 上年同期值) / 上年同期值 > 50%
且 ABS(不含税营收 - 上年同期值) / 上年同期值 < 10%
→ 输出：营收未显著增长但办公费暴涨，可能虚列费用
→ 需核实：检查办公费大额报销凭证的真实性

规则3：在建工程-转固时点
──────────────────
条件：在建工程科目余额/本期增加额 > 2（余额是当年增加的2倍以上）
且 在建工程-本期减少额 = 0（当年无转固）
→ 输出：在建工程长期挂账不转固，可能虚增资产/规避折旧
→ 需核实：实地查看项目是否已完工投入使用
```

**实现方式**：直接写进 `perf-audit-checklist` 或规则引擎的JSON配置，不调LLM，用纯Python校验。

**操作命令**：
```bash
# 规则1-2（财务数据）
python scripts/rule_engine.py --type cross_validation --data "项目财务数据.xlsx"

# 规则3（工程数据）
python scripts/rule_engine.py --type construction --data "在建工程台账.xlsx"
```
