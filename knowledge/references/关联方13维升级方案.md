> 来源：文章2-Agent01（南望侦探·科大讯飞案例）
> 升级范围：L8（工商关联穿透）→ 13维结构化比对
> 升级日期：2026-07-29

---

## 升级概览

| 维度 | 原L8覆盖 | 13维新增 |
|:-----|:-----|:-----|
| 覆盖维度 | 2维 | 13维 |
| 权重体系 | 无 | 高风险(3分)+辅助(1分) |
| 假阳性抑制 | 无 | 每维有排除规则 |
| 关联强度评分 | 无 | 累计评分→三档置信度 |

---

## 13维定义

### 🔴 高风险维度（权重=3）

| # | 维度 | 数据源 | 判定标准 | 排除规则 |
|:--|:-----|:-----|:-----|:-----|
| 1 | **实际控制人** | 天眼查/企查查股权穿透 | 同一自然人控制·或亲属关系·或同一国企实控且交叉任职 | 国企集团内部正常关联（需排除）·工会持股 |
| 2 | **股权穿透** | 工商登记·股东名册 | 持股≥20%·或可施加重大影响（董事会席位） | 财务投资无董事会席位 |
| 3 | **董监高交叉** | 工商变更记录·年报 | 当前同时在双方任职·或12个月内存在交叉 | 独立董事在不同企业任职（正常） |
| 4 | **人员重叠** | 社保缴纳记录 | 同一自然人在同一月份出现在两家企业社保缴纳记录中 | 兼职（需核实是否违反竞业禁止） |
| 5 | **联系方式相同** | 企业年报·官网 | 相同电话号码/邮箱/网站域名 | 使用平台统一客服（如淘宝商家统一热线） |
| 6 | **IP/MAC地址** | 投标系统日志 | 投标IP同C段·MAC同厂·或同一设备 | 同一写字楼共享网络（弱信号） |
| 7 | **银行账户关联** | 银行流水·开户信息 | 同开户行+相近时间开户·且资金往来≥3笔 | 同区域正常业务·小额往来 |

### 🟡 辅助维度（权重=1）

| # | 维度 | 数据源 | 判定标准 | 排除规则 |
|:--|:-----|:-----|:-----|:-----|
| 8 | **注册地址** | 工商登记 | 同一门牌号·同一栋楼同一层 | 同一栋写字楼不同层（正常）·虚拟地址集群 |
| 9 | **历史交易模式** | 历史招投标台账 | ≥3个项目同时出现·或轮流中标模式 | 充分竞争行业的正常参与者 |
| 10 | **资金往来** | 银行流水 | 大额无商业实质的往来·或往来频率异常 | 正常购销·小额代付 |
| 11 | **中标模式** | 3年+招投标数据 | FP-growth检出≥2次伴随·或报价呈阶梯分布 | 公开招标正常竞争 |
| 12 | **文件电子指纹** | 投标文件 | L18八项（CPU/硬盘/主板/机器码/文件GUID/图片哈希等）任意≥2匹配 | 使用相同模板或WPS默认设置 |
| 13 | **注册变更时间** | 工商信息 | 同一日期注册·同一日期变更经营范围·变更后经营范围趋同 | 政策驱动行业集体变更（如资质审批） |

## 评分规则

```python
# 评分标准
SCORE_HIGH = 3    # 高风险维度命中
SCORE_AUX = 1     # 辅助维度命中

# 置信度阈值
THRESHOLD_HIGH = 6     # ≥6分 → 🔴 高置信度关联
THRESHOLD_MEDIUM = 3   # ≥3分 → 🟡 中置信度关联
THRESHOLD_LOW = 1      # ≥1分 → 🟢 低置信度关联
```

### 判定示例

| 发现组合 | 评分计算 | 得分 | 置信度 |
|:-----|:-----|:-----|:-----|
| 控制人相同(3)+人员重叠(3)+历史伴随(1) | 3+3+1 | 7 | 🔴 高 |
| 同IP/MAC(3)+注册地址近(1) | 3+1 | 4 | 🟡 中 |
| 仅注册地址近(1) | 1 | 1 | 🟢 低 |
| 仅同开户行(3) | 3 | 3 | 🟡 中 |
| 联系人相同(3)+股权穿透(3)+中标模式(1)+资金往来(1)+文件指纹(3) | 3+3+1+1+3 | 11 | 🔴 高（几乎铁证）|

## 实施路径

### Step 1: 修改 Agent Spec

更新 `audit-blackboard/agent_specs/bid_hunter.json`：

```json
{
  "related_party_detection": {
    "version": "2.0",
    "dimensions": 13,
    "scoring": {
      "high_risk_weight": 3,
      "aux_weight": 1,
      "high_confidence_threshold": 6,
      "medium_confidence_threshold": 3
    },
    "false_positive_rules": [
      "同地址但位于普通写字楼 → 降权处理",
      "独立董事交叉任职 → 排除",
      "国企集团内部正常关联 → 需人工标注排除",
      "WPS默认设置导致元数据相同 → 降权处理",
      "同一网络运营商导致的IP相似 → 需结合其他维度"
    ]
  }
}
```

### Step 2: 数据采集要求

| 维度 | 采集方式 | 优先级 |
|:-----|:-----|:-----|
| 1-5 实际控制/股权/人员/联系 | 天眼查API/工商批量导出 | P0 |
| 6 IP/MAC | 代理机构后台·投标系统日志 | P1（需配合） |
| 7 银行账户 | 银行流水 | P1 |
| 8 注册地址 | 工商批量导出 | P0 |
| 9-11 历史交易/资金/中标 | 3年+招投标台账+财务数据 | P0 |
| 12 文件指纹 | 投标文件PDF/DOCX | P0 |
| 13 注册变更 | 工商批量导出 | P1 |

### Step 3: 集成到检测流水线

```bash
# 融策现有命令（升级后自动使用13维）
python launch.py "XX项目" --type 招投标
# → bid_hunter Agent 自动执行13维比对
# → 输出: findings/related_parties_13dim.json + 关联关系矩阵.xlsx
```

## 验收标准

- [ ] 13维全量覆盖率≥90%（即≥12维有数据可用）
- [ ] 假阳性率≤30%（对比人工标注结果）
- [ ] 高置信度关联（≥6分）的人工确认采纳率≥80%
- [ ] 处理速度：100家投标人×13维 ≤ 5分钟
