# 审计平台开发_第一性原理分析（技能蒸馏版）

> 来源: 田川不是四川（原创），2026-05-18
> 领域: 审计平台架构设计 / 第一性原理

## 审计的第一性原理

### 本质定义

```
审计 = 独立第三方对财务信息的可靠性发表意见
```

### 六原子要素

| 要素 | 定义 | 自动化 | 融策工具对应 |
|:------|:-----|:------|:----------|
| 信息收集 | 获取财务数据、制度文件、交易记录 | ✅ 可自动化 | API/OCR/RAG |
| 风险评估 | 识别哪些地方可能出错 | △ 半自动化 | procurement-audit-models |
| 证据获取 | 收集证明财务信息可靠的证据 | △ 半自动化 | audit_finding_processor |
| 证据评价 | 判断证据是否充分、适当 | ✗ 需专业判断 | Human-in-the-loop |
| 结论形成 | 基于证据发表审计意见 | ✗ 需专业判断 | Human-in-the-loop |
| 工作记录 | 记录做了什么、发现了什么 | ✅ 可自动化 | report-writer/底稿生成 |

### 关键洞察

**信息收集和记录占60-70%时间，但恰恰是自动化最优的部分。真正创造价值的专业判断，却被繁琐文书工作挤占。**

## 审计底稿的原子分解

```
底稿 = 证据链 + 工作记录 + 复核轨迹
```

| 传统类比方式 | 第一性原理重构 |
|:----------|:----------|
| "底稿长这样→数字化" | 证据链: 自动生成证据索引+追溯 |
| "模板E2130→按模板填" | 工作记录: 自动填充+人工补判断 |
| "手工签字→电子签" | 复核轨迹: 区块式记录+不可篡改 |

## 三层架构

```
数据层 → 自动化 (API/OCR/RAG)
判断层 → AI辅助 + Human-in-the-loop
交互层 → 自然语言/可视化/AI对话
```

## 核心原则

1. **自动化第一问**：这个步骤的本质是什么？需要人的什么判断？
2. **不该自动化的别强制自动化**：证据评价和结论形成需要职业怀疑，AI只能辅助
3. **自动化什么取决于数据获取成本**：信息收集和数据标准化是自动化的前提
4. **底稿不是目的，证据链才是**：底稿格式不重要，证据追溯链是核心
