# RAG 与知识图谱在根因分析中的协同

## 核心观点

企业 AI 落地中，根因分析（RCA）有两条技术路线：RAG（擅长非结构化文本、接入快、推理弱）与知识图谱（多跳推理强、可解释、构建贵）。二者不是二选一，而是流水线协同。

## 两类实体（对审盾知识图谱设计直接有用）

- **运行态实体（Operational Entities）**：可被定位、可测量的物理对象——设备、服务、机房、人员；制造业中产线、机台、物料批次。回答"谁/什么东西出了问题"。
- **知识态实体（Knowledge Entities）**：诊断经验与规程——故障现象、故障模式、可能原因、修复方案。回答"出了什么问题、为什么、怎么修、怎么防"。

> 知识态实体是"引擎"，运行态实体是"机架"。只照抄 CMDB 建图谱的团队只建了机架，没有诊断能力。

## 三种协同架构

1. **RAG-first**：用户描述模糊（无明确实体）→ 先向量检索 → 实体抽取 → 图谱多跳推理 → 融合生成。风险在实体抽取错误导致方向跑偏。
2. **KG-first**：提问已含明确实体 → 直接图谱遍历 → RAG 补细节。可解释性最强、幻觉率最低。
3. **Hybrid 并行**：双通道同时检索 + RRF/置信度加权/LLM 重排序融合。鲁棒性最强但成本翻倍；无实体时自动降级为 RAG-first。

## 三种深度集成

- **KG-enhanced RAG**：用图谱邻居扩展检索 Query，提升召回精准度。
- **RAG-backed KG**：图谱路径中断时用 RAG 挖文档补边，标注为"推断边"，图谱随使用自我完善。
- **GraphRAG**：离线用 LLM 抽实体建图 + 社区检测 + 社区摘要；局部问题走实体遍历，全局问题走社区摘要。离线成本极高，适合知识体量适中、更新频率低的场景。

## 工程落地四条铁律

1. **不要一开始追求完美图谱**：从 RAG 切入快速验证，再从高频实体逐步抽知识态实体，覆盖度上来后再切 Hybrid。
2. **推理路径加置信度**：候选根因附（置信度 + 路径长度 + 完整推理链），路径越短越可能是直接原因。
3. **RAG 检索后去噪**：LLM 二分类过滤"相关但不充分"的片段，过滤 Prompt 要含已知实体/时间范围/故障现象。
4. **防幻觉边**：边分"确认边"（人工校验/权威来源）与"推断边"（LLM 抽取），推断边默认置信度 0.5；两个以上独立来源交叉验证才升级；推理优先走确认边，走推断边必须在报告中标注。
