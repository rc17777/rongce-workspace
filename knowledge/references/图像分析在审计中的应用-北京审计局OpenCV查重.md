# 图像分析在审计中的应用 — 北京市审计局OpenCV查重实践

- **作者**：北京市审计局 邹远志
- **项目背景**：助残帮扶专项审计 — 入户帮扶图像查重
- **存入日期**：2026-05-27
- **关联技能**：procurement-audit-models (L4-图片哈希)

## 一、审计背景与问题

某市第三方机构入户助残帮扶 → 拍摄照片/视频 → 申请财政补贴。业务部门无力逐一审核23762张图片真实性 → 可能存在重复使用、冒用图片骗取补贴。

## 二、三种弄虚作假场景

1. **同一对象不同时间使用相同图像** — 多次帮扶用同一张照片
2. **不同对象不同时间使用相同图像** — 张三的照片给李四用
3. **不同对象相同时间使用相同图像** — 集体照代替入户照

→ 本质是**图像查重问题**

## 三、技术方法

### 技术栈
- OpenCV-Python（计算机视觉库）
- 图像特征提取：彩色→灰度→DCT变换+Radon变换
- 特征数据库：128bit二进制特征 + 属性标注（Tuple→txt）
- 相似度判定：哈明距离（Hamming Distance）
- 匹配阈值：≥0.8（基于Nova标准图像库统计学习确定）

### 流程
```
原始图像(23762张) 
  → 归一化至64×64像素
  → DCT块变换 → 128bit特征
  → 构建图像特征库(txt)
  → 哈明距离匹配
  → 阈值≥0.8 → 标记疑点
```

### 成果
- 23762张中检出疑点**1994张**
- 涉及帮扶对象**997人次**
- 发现问题：集中帮扶代入户、集体照替代、事后补拍

## 四、对招投标审计的启示（L4升级方向）

### 当前做法 vs 升级方向

| | 当前（MD5/SHA256） | 升级（感知哈希pHash） |
|:--|:---|:---|
| 原理 | byte-level精确比对 | DCT+Hamming视觉相似 |
| 能检测 | 完全相同的文件 | 同一图像的不同扫描/压缩版本 |
| 局限 | 同一张纸重新扫描→哈希完全不同 | 需要调整阈值 |
| 适用 | .docx解压word/media的嵌入图片 | PDF扫描件中的图片比对 |

### 文章三场景 ↔ 招投标L4

| 文章场景 | 招投标对应 | 检测价值 |
|:--------|:---------|:-------|
| 同一对象不同时间用相同图像 | 同一公司多项目用相同资质扫描件 | 正常（可能是同一张扫描件复用） |
| **不同对象**用相同图像 | **不同投标人使用同一张资质/印章图片** | 🔴串标铁证 |
| 不同对象相同时间用相同图像 | 多家投标人同批次制作→共用图片素材 | 🔴串标信号 |

### 实施建议

```
L4升级路径：
  Phase 1（已实现）: MD5/SHA256精确哈希 → 检测完全相同的嵌入图片
  Phase 2（待实现）: 感知哈希(pHash/DCT) → 检测视觉相似但文件不同的图片
  Phase 3（远期）: 图像特征数据库 → 跨项目图片追踪（某张资质图在多个项目中反复出现）
```
