## 一、核心案例

某鞋服品牌部署 DataAgent 做商品主数据日常维护。Agent 发现 200 个 SKU 的 category_code 为空，根据商品名称推断类目编码自动写回——但它用的是**去年的旧版编码体系**，今年运营刚做完类目重构。200 条数据从源表 → 查询层 → 指标中心 → 前端推荐，全链路写错。男士运动鞋出现在女士凉鞋区。

事后数据团队、运营、安全三方扯皮 2 天，没人说得清谁负责。

## 二、根因：3 个"没人管"

| # | 缺口 | 表现 | 代价 |
|:--|:-----|:-----|:-----|
| 1 | **权限没人管** | Agent 拿到全库写权限（万能钥匙），没有表级/字段级分级 | 一条错误覆盖全链路 |
| 2 | **审批没人管** | Agent 发现空值→自动补全→直接写生产表，零人工确认 | 200 条错误无阻拦 |
| 3 | **责任没人管** | 事前没有定义"Agent 事故责任主体"，事后 CTO 拍桌追认 | 2 天扯皮，追责无据 |

> 核心判断：不是 Agent 闯的祸，是**治理空白**闯的祸。Agent 只是把这个空白暴露了。

## 三、三道防线

### 第一道：操作分级审批

| 级别 | 操作类型 | 审批要求 |
|:-----|:--------|:--------|
| L0 只读 | 查表、出报告、统计分析 | 免审批，随时跑 |
| L1 低风险写 | 补全非关键字段、更新元数据 | 提交建议 → 数据负责人 10 分钟内确认 |
| L2 高风险写 | 改业务主数据、改财务字段、批量超 50 条 | DataWorks 审批流 → 业务负责人 + 数据负责人双签 |

### 第二道：异常自动熔断

| 熔断条件 | 阈值 | 动作 |
|:--------|:-----|:-----|
| 影响行数 | 单次修改 >100 行 | 暂停 Agent → 生成操作快照 → 通知数据负责人 |
| 字段敏感度 | 涉及金额/库存/会员标识等 | 直接拦截，不进入审批 |
| 变更幅度 | 单字段值变化 >历史值 3 倍 | 触发告警，待确认后放行 |

### 第三道：RACI 责任矩阵

| 角色 | 含义 | 举例（Agent修改主数据） |
|:-----|:-----|:---------------------|
| R | Responsible 执行人 | Agent |
| A | Accountable 最终负责人 | **数据负责人**（出事了第一问责） |
| C | Consulted 被咨询方 | 运营负责人 |
| I | Informed 被通知方 | 安全/合规 |

> RACI 矩阵写进数据治理制度、CTO 签字确认。不是走形式。

## 四、对融策审盾的映射

### 审盾当前阶段（一期：AI复核）

审盾一期 AI 只做**只读操作**（读报告 → 出复核建议）→ 属 L0 级，风险可控。

### 审盾后续阶段（Agent 开始"写"）

| 审盾场景 | 对应防线 | 实施建议 |
|---------|---------|---------|
| AI 自动标注疑点（在底稿上） | L1 写操作 | 标疑点→审计经理确认→生效 |
| AI 修正底稿数字（调整分录） | L2 高风险写 | 双签：审计经理 + 项目负责人 |
| AI 自动分类问题发现 | RACI 矩阵 | R=AI, A=审计经理, C=项目负责人 |
| AI 起草报告结论 | 🔴 禁止自动写 | 只能出草稿，人签字才生效 |
| AI 批量标记（>50条） | 熔断 | 超阈值→暂停+快照+人工审核 |
| AI 修改金额/定性/责任 | 🔴 禁止 | 永远不自动修改，永久人工锁定 |

### 审盾 Agent 权限分级建议

```
审盾 Agent 账号权限：
├── 审计底稿库：只读（不可改）
├── 取证单库：只读
├── 报告草稿库：只读
├── 复核意见库：可写（L1审批）
├── 疑点标注库：可写（L1审批）
├── 财务数据明细表：只读
└── 生产报告库：🔴 禁止访问
```

### 审盾 RACI 矩阵（草案）

| 操作 | R | A | C | I |
|:-----|:--|:--|:--|:--|
| 首次复核（读报告→出建议） | 审盾AI | 审计经理 | — | 项目负责人 |
| 标注疑点 | 审盾AI | 审计经理 | 主审会计师 | 质控部 |
| 修正底稿数字 | 审计经理 | **项目负责人** 🔴 | 客户 | 质控部 |
| 生成复核报告 | 审盾AI | 审计经理 | 质控部 | 客户 |
| 自动归档 | 审盾AI | 质控部 | — | 档案管理员 |
