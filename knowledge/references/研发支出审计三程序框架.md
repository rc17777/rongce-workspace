## 程序一：资本化率与利润敏感度分析（查动机）

### 目标
判断企业是否存在通过调节研发支出资本化率来操纵利润的**动机和空间**。

### 所需数据

| 字段 | 来源 | 期间 |
|:-----|:-----|:-----|
| 年度研发投入总额 | 研发支出明细账/辅助账 | 近3年 |
| 研发支出资本化金额 | 研发支出明细账 | 近3年 |
| 研发支出费用化金额 | 研发支出明细账 | 近3年 |
| 净利润 | 利润表 | 近3年 |
| 研发支出会计政策 | 年度报告附注/会计制度文件 | 当期 |

### 计算指标

```
指标1：资本化率 = 本期资本化金额 / 本期研发投入总额 × 100%
指标2：利润敏感度 = 本期资本化金额 / 本期净利润 × 100%
指标3：资本化率同比变动 = 本年资本化率 - 上年资本化率
指标4：资本化率行业对标 = 本企业资本化率 vs 同业均值
```

### 判断矩阵

| 利润敏感度 | 资本化率同比变动 | 风险等级 | 操作 |
|:-----|:-----|:-----|:-----|
| < 10% | < 5pp | 🟢 低 | 常规检查 |
| 10%-30% | 5-10pp | 🟡 中 | 关注会计政策变更原因 |
| 30%-50% | 10-20pp | 🟠 高 | 重点审查资本化条件满足情况 |
| > 50% | > 20pp | 🔴 严重 | 逐项检查资本化项目，质疑会计政策合理性 |

### 审计程序

```
1. 获取近3年研发支出明细，计算资本化率和利润敏感度
2. 对比行业平均水平（软件/硬件/互联网行业资本化率差异大）
3. 访谈财务负责人：资本化政策是否有变更？变更原因？
4. 检查本年是否出现异常大额单笔资本化
5. 分析：如果不做资本化（全部费用化），净利润会变成多少？
```

### 常见红灯

- 资本化率在同行业处于极端高位（top 10%）
- 利润敏感度 > 50%——资本化是保持盈利的关键
- 研发投入总额同比下降但资本化率上升
- 从一个没有资本化的年份突然开始大额资本化

## 程序二：高企资质与研发人员合规性（查合规）

### 目标
验证企业高企资质保持条件，以及研发人员薪酬的真实性和合规性。

### 所需数据

| 字段 | 来源 | 验证要点 |
|:-----|:-----|:-----|
| 研发人员名单（含学历/岗位/工时） | 人力资源 | 人数统计口径 |
| 研发人员薪酬明细（按月/按人） | 工资表 | 是否包含非研发人员 |
| 销售收入总额（近1年） | 利润表 | 高企比例分母 |
| 研发费用总额 | 研发辅助账 | 高企比例分子 |
| 高新技术企业认定证书 | 科技部门 | 有效期 |

### 检查清单

```
□ ① 研发人员占比 ≥ 10%
    公式：研究开发人员/职工总数
    注意：兼职研发人员按实际工时折算

□ ② 研发费用占销售收入比例达标
    收入<5千万 → ≥5%
    收入5千万-2亿 → ≥4%
    收入>2亿 → ≥3%
    注：此处为近三个会计年度的合计比例，不是单年

□ ③ 境内研发费用占比 ≥ 60%（高企认定）

□ ④ 研发人员平均薪酬 vs 公司整体人均薪酬
    偏差>30% → 需解释
    研发人员薪酬显著偏低 → 可能是非研发人员被计入

□ ⑤ 研发人员学历结构匹配度
    硕博占比与研发性质是否匹配
    基础研究/算法类→硕博比例应较高
    应用开发/测试类→本科为主合理

□ ⑥ 是否存在非研发人员薪酬计入研发费用
    核对：研发人员名单 vs 工资表签字名单
    关注：行政/销售/高管工资列入研发费用

□ ⑦ 研发设备折旧/材料费归集准确性
    共用设备折旧分配方法是否合理
    材料领用是否可追溯到具体研发项目
```

### 常见红灯

- 研发人员占比刚好≥10%（疑似凑数）
- 研发人员名单包含大量行政/管理层
- 研发人员平均薪酬异常低于公司平均水平
- 高企有效期即将届满且目前条件不完全满足
- 研发费用辅助账与财务账不一致

## 程序三：资本化项目实质与减值测试（查实质）

### 目标
穿透到具体项目层面，判断资本化处理是否有**真实的项目**支撑，已完成项目是否及时摊销。

### 所需数据

| 字段 | 来源 | 
|:-----|:-----|
| 资本化项目清单（含立项/预算/进度/验收） | 研发项目管理台账 |
| 各项目资本化金额、起始时间 | 研发支出明细账 |
| 各项目完工情况（开发完成/未完成/已终止） | 研发管理部门 |
| 已完工项目转入无形资产记录 | 无形资产明细账 |
| 无形资产摊销记录 | 累计摊销明细 |
| 各项目技术可行性报告/立项书 | 研发档案 |

### 检查清单

```
□ ① 识别"僵尸项目"
    条件：立项超过3年仍未完成 + 仍有资本化金额
    → 减值测试：是否仍有使用价值？技术是否已被淘汰？

□ ② 新立项项目资本化条件核查
    条件：本期新增/首年资本化的项目
    逐项检查是否同时满足5个条件：
    ① 完成该无形资产以使其能够使用或出售在技术上具有可行性 ✓
    ② 具有完成该无形资产并使用或出售的意图 ✓
    ③ 无形资产产生经济利益的方式 ✓
    ④ 有足够的技术/财务资源支持 ✓
    ⑤ 归属于该无形资产开发阶段的支出能够可靠计量 ✓

□ ③ 已完工项目转固/转无形及时性
    条件：项目状态="已完成"但尚未转入无形资产
    检查：完工验收报告日期 vs 会计处理日期
    延迟转入 → 可能为规避摊销

□ ④ 研发失败项目是否及时费用化
    条件：项目状态="已终止/失败"
    检查：相关资本化金额是否已转费用化
    未及时处理 → 资产虚增

□ ⑤ 疑似"为资本化而立项"的小额项目
    条件：单个项目资本化金额 < 5万元
    检查：项目的技术实质和商业合理性

□ ⑥ 转无形后的摊销复核
    检查：摊销年限是否与受益期匹配
    检查：是否存在已无使用价值的无形资产仍在摊销（摊销年限过长）
```

### 判断输出格式

```
项目：XX研发项目
├── 状态：开发中（已36个月）
├── 累计资本化：850万元
├── 本期增加：200万元
├── ⚠️ 超3年未完工 → 列为"需减值测试"
├── 技术可行性：最近一次评估报告日期为2023年（已过时）
└── 建议：获取最新技术评估，判断是否需计提减值
```

## 三程序串联工作流

```
输入：企业名称 + 审计期间
  │
  ├── 程序一（动机）
  │   ├── 计算资本化率 + 利润敏感度
  │   ├── 同行业对标
  │   └── 输出：🔴🟡🟢 风险等级
  │
  ├── 程序二（合规）  
  │   ├── 高企资质七项检查
  │   ├── 薪酬结构与人员比对
  │   └── 输出：合规检查清单 + 异常项
  │
  └── 程序三（实质）
      ├── 逐项目进展检查
      ├── 减值信号识别
      └── 输出：项目级判断 + 需要减值测试清单
          │
          ▼
      汇总审计发现 → 底稿工匠 Agent → 审计底稿
```

## 人工确认点（不可跳过的检查）

- [ ] 资本化率变动原因是否已向企业获取书面解释？
- [ ] 资本化的5个条件是否逐项验证？（不能只问"是否满足"，要拿到证据）
- [ ] 研发人员名单是否与社保名单做过交叉比对？
- [ ] 已完工项目是否实地查看过？
- [ ] 僵尸项目的技术可行性评估是否获取了第三方或者独立技术意见？
- [ ] 高企资质有效期是否在审计期间内？

> ⚠️ AI可以完成数据计算和模式识别，但资本化条件判断（尤其是"技术可行性"和"使用意图"）依赖人的专业判断。不要因为AI算出了风险等级就跳过人工核实。
