## 二、通用选型原则（全场景适用）

- 凭证/单据数量＜50条、需要深度业务判断、临时抽查：优先**人工操作**
- 单据批量大、页面永久固定、无弹窗/登录超时等干扰：选用**传统RPA**
- 大批量作业、页面动态变化、频繁出现登录超时/异常弹窗、要求高准确率：首选**Claude Computer Use 2.0**
- 补充技巧：使用Claude CU长期执行任务时，本地新建**工作日志文档**，每批次任务结束自动记录：完成时间、单据总量、异常数量、异常原因，便于复盘优化。

## 三、五大审计场景分方案操作指南+指令模板

### 场景一：供应商应付账款凭证翻查

**业务说明**：从ERP系统调取凭证，逐页检查发票、入库单、付款单三单完整性，截图存档，在Excel登记检查结果。

#### 方案1：人工操作（适配少量单据）
- 操作流程：登录ERP→打开凭证详情→核对三单→截图→Excel登记结果→依次完成所有单据
- 注意事项：连续作业建议每小时休息，避免视觉疲劳导致漏检。

#### 方案2：传统RPA（适配固定页面、大批量单据）
- 配置步骤：① 打开RPA工具，手动录制ERP登录、凭证打开、截图、Excel录入全流程；② 设置循环规则，配置单据读取顺序；③ 反复调试页面坐标，确认无偏移后正式运行。
- 风险提示：ERP弹出会话过期、弹窗提示时，RPA会持续空跑，需专人实时值守。

#### 方案3：Claude Computer Use 2.0（推荐，全量大批量单据）

**通用指令模板（直接复制使用）**：

```
你现在模拟人工完成ERP系统供应商应付账款凭证翻查任务，执行规则如下：
1. 依次打开所有凭证详情页，逐笔检查发票、入库单、付款单三单是否齐全；
2. 每完成1条凭证，对详情页进行截图保存；
3. 将检查结果（单据齐全/单据缺失）录入指定Excel表格；
4. 遇到会话过期、系统弹窗等异常，自动点击保持登录、关闭弹窗，恢复正常操作；
5. 仅遇到验证码时暂停操作，等待人工协助；
6. 任务结束后，在本地工作日志中记录：任务完成时间、凭证总数量、异常凭证数量、异常原因。
当前待查凭证共：【填写数量】条
```

### 场景二：审计函证匹配

**业务说明**：整理银行/往来单位询证函，核对回函信息、账面数据、系统数据三者一致性，标记差异项，分类归档。

#### 方案1：人工操作
逐份比对函证原件、系统账面数据，手动标注差异，分类整理归档，适合函证数量少、涉及复杂业务判定的场景。

#### 方案2：传统RPA
仅适配函证格式、页面布局完全统一的场景，提前录制数据读取、比对、标注流程；函证格式微调会导致匹配失败。

#### 方案3：Claude Computer Use 2.0（推荐）

**指令模板**：

```
请完成审计函证匹配核对工作，具体要求：
1. 调取系统账面数据、已收回询证函，逐项比对金额、往来单位、业务日期等核心信息；
2. 信息一致标注"匹配无误"，存在差异详细标注差异内容；
3. 按"正常函证、差异函证"两类进行分类归档；
4. 遇到系统登录超时、页面加载异常自动修复；
5. 任务完成后更新工作日志，记录函证总数、差异数量、主要差异类型。
```

### 场景三：银行对账

**业务说明**：比对企业银行日记账、银行流水回单、网银交易记录，核对交易金额、收支时间、摘要，筛查未达账项、异常流水。

#### 方案1：人工操作
逐笔勾稽流水与账目，手动编制银行余额调节表，适合账户少、流水量小的企业。

#### 方案2：传统RPA
仅支持固定版式网银页面与Excel台账，银行页面改版、流水格式变更后需重新录制流程。

#### 方案3：Claude Computer Use 2.0（推荐）

**指令模板**：

```
执行银行对账全流程操作，规则如下：
1. 登录企业网银，导出本期全部银行交易流水；
2. 将流水与企业银行日记账逐笔核对，标记未达账项、金额异常、摘要不符的流水；
3. 自动整理未达账项明细，编制简易银行余额调节表；
4. 识别网银登录超时、安全提示弹窗并自主处理；
5. 全程保留操作记录，任务结束更新工作日志，统计流水总数、异常流水数量。
```

### 场景四：合同审查

**业务说明**：调取业务合同，核对合同主体、金额、履约期限、付款条款、合规条款，筛查风险条款，登记审查结果。

#### 方案1：人工操作
适用于重大合同、特殊框架合同，需要结合法务、业务经验做深度风险判断。

#### 方案2：传统RPA
仅能抓取固定位置的文字内容，无法识别条款逻辑、风险点，仅可做基础信息摘抄。

#### 方案3：Claude Computer Use 2.0（批量常规合同首选）

**指令模板**：

```
请批量完成常规业务合同审查，执行要求：
1. 提取每份合同的主体信息、合同金额、履约周期、付款节点四大核心内容；
2. 对照审计合规要求，筛查违规条款、不合理付款条款、缺失关键约定等风险点；
3. 将审查结果录入指定表格，区分"合规合同、风险合同"并标注风险位置；
4. 打开合同文件、切换文件夹时遇到页面卡顿、弹窗自动处理；
5. 任务完成后在工作日志记录合同总数、风险合同数量、高频风险类型。
```

### 场景五：审计底稿归档

**业务说明**：整理审计工作底稿、凭证附件、函证、对账表等资料，按项目分类命名、分区存储，核对资料完整性，建立归档目录。

#### 方案1：人工操作
项目资料零散、格式多样、需人工分类判定时使用。

#### 方案2：传统RPA
适合文件命名规则、存储路径完全固定的归档场景，文件名称/格式变动则无法正常分类。

#### 方案3：Claude Computer Use 2.0（大批量底稿归档首选）

**指令模板**：

```
完成审计工作底稿批量归档工作，要求如下：
1. 按照【项目名称-资料类型-日期】规则统一重命名所有底稿文件；
2. 根据资料类型（凭证、函证、对账表、审查报告）分类存入对应文件夹；
3. 逐一核对项目全套资料，标记缺失的底稿文件；
4. 处理文件打开、文件夹切换过程中的系统弹窗、登录提醒；
5. 自动生成归档目录表格，任务结束更新工作日志，统计归档文件总数、缺失文件数量。
```

## 五、补充避坑指南

1. Claude Computer Use 2.0依赖屏幕视觉识别，运行时**请勿最小化窗口、遮挡页面**，否则会中断任务；
2. 传统RPA上线前，务必预留30分钟以上调试时间，重点测试弹窗、页面跳转等边界场景；
3. 无论使用哪种工具，**高风险审计事项（大额合同、大额流水）最终必须人工二次复核**；
4. 若原始单据、数据本身存在错误，任何自动化工具都无法修正，需提前人工梳理基础资料。

## 融策适用性评估

### 与现有能力对标

| 场景 | 融策现有能力 | Claude CU能补充什么 |
|------|------------|-------------------|
| 凭证翻查 | 融策Agent数据分析 | 屏幕操作层自动化（ERP系统内直接操作截图） |
| 函证匹配 | Python数据分析比对 | 多源数据视觉识别+自动截屏归档 |
| 银行对账 | 数据分析Agent | 网银登录+流水导出+弹窗处理（端到端） |
| 合同审查 | audit-text-mining | 条款视觉识别+页面交互级操作 |
| 底稿归档 | 人工/脚本 | 自动分类重命名+完整性检查 |

### 建议
- **立即可用**：五大场景的指令模板可直接套用（调整业务系统名称即可）
- **配套建设**：工作日志模板→可集成到融策Agent的审计底稿模块
- **注意红线**：高风险事项（大额合同/流水）必须人工二次复核——与融策11层串标检测体系的L11意思联络原则一致
