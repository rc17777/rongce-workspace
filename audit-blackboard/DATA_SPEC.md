# 融策多Agent审计平台 — 取数规范与范围

> v1.0 | 2026-06-21 | 12业务线全覆盖

---

## 一、通用取数原则

### 1.1 数据格式要求

| 数据类别 | 首选格式 | 备选格式 | 最低要求 |
|----------|:--------:|:--------:|----------|
| 财务数据 | .xlsx (CSV导出) | .csv | 必须含科目编码+金额+日期 |
| 合同台账 | .xlsx | .csv | 必须含合同编号+金额+签订日期 |
| 投标文件 | .docx | .pdf | 至少含报价+技术方案 |
| 制度文件 | .pdf / .docx | 扫描件 | 可OCR的文字版优先 |
| 工商信息 | .xlsx | .csv | 含统一社会信用代码 |
| 项目资料 | .pdf | .docx | 立项/可研/批复三件套 |

### 1.2 文件存放规范

```
projects/<项目名>/raw_data/
├── 财务/          ← 序时账、科目余额表、辅助账、报表
├── 合同/          ← 合同台账、验收单、付款凭证
├── 招投标/        ← 招标文件、各投标人投标文件、开标记录
├── 制度/          ← 内控制度、审批权限、管理办法
├── 工商/          ← 工商信息、股权结构、关联方
├── 项目/          ← 立项、可研、批复、中标通知书
├── 绩效/          ← 绩效目标表、自评报告、佐证材料（绩效评价专用）
├── 资产/          ← 资产台账、盘点表、处置审批（资产清查专用）
├── 往来/          ← 往来明细账、账龄分析、函证（往来款清理专用）
└── 工程/          ← 概算、预算、结算、变更签证（工程审计专用）
```

### 1.3 列名规范（Agent兼容）

Agent用列别名自动识别，但优先使用以下标准列名：

**序时账标准列：**
`日期 | 凭证号 | 摘要 | 科目编码 | 科目名称 | 借方金额 | 贷方金额 | 余额 | 辅助核算`

**合同台账标准列：**
`合同编号 | 合同名称 | 供应商 | 签订日期 | 合同金额 | 已付金额 | 未付金额 | 履约状态 | 验收日期`

**投标数据标准列：**
`投标人 | 报价 | 技术得分 | 商务得分 | 是否中标 | 投标日期`

## 四、取数优先级（实战经验）

收到审计任务后，**先要这四件套**，有了就能跑第一轮Agent：

```
第一轮（Day 0-1）:
  ✅ 序时账（.xlsx）
  ✅ 科目余额表（.xlsx）  
  ✅ 合同台账（.xlsx）
  ✅ 内控制度/法规文件（.pdf）

第二轮（Day 2-3）:
  ⬜ 投标文件（.docx，如涉及招标）
  ⬜ 银行流水（.xlsx）
  ⬜ 项目批复/实施方案（.pdf）

第三轮（Day 4-5）:
  ⬜ 工商信息/关联方
  ⬜ 专项材料（绩效目标/资产台账/能耗数据）
```

**原因：** 序时账+科目余额+合同台账三样数据侦察兵和合同猎犬就能产出第一轮发现，先跑起来，第二轮补充招投标数据后切入深度分析。

|--------|------|-------------|
| 序时账含摘要 | 100%凭证必须有摘要 | 退回被审计单位补全 |
| 合同编号唯一 | 同一编号不出现在两个合同 | Agent合并打标记 |
| 日期格式统一 | YYYY-MM-DD | 自动解析但降低置信度 |
| 金额字段为数值 | 不含千分位逗号/单位文字 | 自动清洗 |
| 供应商名称一致 | 全量表统一用全称 | 模糊匹配但打标记 |
| 投标文件.docx | 非PDF扫描件 | L3-L6分析不可用，仅L1+L7 |
