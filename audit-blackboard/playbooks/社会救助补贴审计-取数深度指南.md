# 社会救助/补贴审计 — 取数深度指南

> 融策多Agent审计平台 | 2026-07-22 | 场景拆解第2篇
> 依据：《社会救助法》（2026年7月1日施行）| 来源：广安审计局大数据审计实践

---

## 一、先搞清楚审计对象

社会救助补贴审计的核心问题是：**钱发给了不该发的人**（资格不符/死亡冒领/重复享受），以及**该发的人没发到**（漏发/截留）。

### 审计类型

| 类型 | 说明 | 适用模型 |
|------|------|:--------:|
| 低保审计 | 城乡居民最低生活保障资金 | 死亡超领+资产比对+重复享受 |
| 特困供养审计 | 特困人员救助供养资金 | 死亡超领+资产比对 |
| 高龄津贴审计 | 80岁以上老人高龄补贴 | 死亡超领 |
| 养老保险审计 | 城乡居民/企业职工基本养老金 | 死亡超领 |
| 养老服务补贴 | 居家养老/社区养老服务补贴 | 死亡超领+资格审核 |
| 医疗救助审计 | 大病医疗救助资金 | 资格审核+重复享受 |
| 临时救助审计 | 突发困难临时救助 | 资格审核+重复享受 |
| 教育/住房/就业救助 | 其他专项救助 | 按需取数 |

### 审计前必须确认的四件事

1. **补贴政策文件**（最新版本，含发放标准、资格条件、审批流程）
2. **补贴对象范围**（低保/特困/高龄/养老——不同补贴类型数据源不同）
3. **数据覆盖范围**（区县级/市级/省级——决定数据整合难度）
4. **系统数据质量**（电子化程度、数据字段完整性、历史数据可追溯性）

### 2.1 必须获取（第一轮）

| 数据 | 来源 | 关键字段 | 用途 |
|------|------|---------|:----:|
| 补贴发放明细 | 民政局/社保局系统 | 身份证号+姓名+补贴类型+金额+发放日期+发放状态 | 所有模型的核心 |
| 公安户籍信息 | 公安局 | 身份证号+姓名+户籍地址+户籍状态+注销日期 | 死亡超领+资格审核 |

| 车辆登记数据 | 车管所 | 车主身份证号+姓名+车牌号+车辆类型+登记日期 | 资产比对模型 |
| 房产登记数据 | 不动产登记中心 | 产权人身份证号+姓名+房产地址+面积+登记日期 | 资产比对模型 |

## 三、三个大数据比对模型（即用）

### 模型一：死亡超领模型

**适用场景：** 低保、特困供养、高龄津贴、养老金

**原理：**
```
殡葬火化数据（死亡人员）→ LEFT JOIN → 补贴发放名单（在领人员）
        ↓
匹配成功 = 疑似死亡超领
        ↓
核实实际死亡时间 → 计算违规发放金额 → 追回
```

**SQL逻辑（伪代码）：**
```sql
SELECT 
    p.身份证号, p.姓名, p.补贴类型, p.每月金额,
    d.死亡日期, d.火化日期,
    DATEDIFF(MONTH, d.死亡日期, GETDATE()) * p.每月金额 AS 违规金额
FROM 补贴发放明细 p
LEFT JOIN 殡葬火化数据 d ON p.身份证号 = d.身份证号
WHERE d.死亡日期 IS NOT NULL
  AND p.发放状态 = '正常发放'
```

**核查要点：**
- 核实实际死亡时间（殡葬日期 vs 死亡证明日期 vs 家属申报日期）
- 计算从死亡日期到停发日期之间的违规发放金额
- 确认是否涉及伪造死亡证明（如随州案例）
- 延伸核查：死亡后医保仍在报销？死亡后仍在进行资格认证？

**数据要求：** 殡葬火化数据必须完整连续，含死亡日期和火化日期

---

### 模型二：资产比对模型

**适用场景：** 低保、特困救助

**原理：**
```
补贴对象名单 → LEFT JOIN → 车辆/房产/工商登记数据
        ↓
名下拥有车辆（非营运性残疾车）→ 标红
名下拥有房产（非唯一住房）→ 标红
名下注册企业 → 标红
        ↓
同时还在领救助金 = 疑似资格不符
```

**SQL逻辑（伪代码）：**
```sql
-- 车辆比对
SELECT p.身份证号, p.姓名, c.车牌号, c.车辆类型, c.登记日期
FROM 补贴发放明细 p
LEFT JOIN 车辆登记数据 c ON p.身份证号 = c.车主身份证号
WHERE c.车辆类型 NOT IN ('残疾人专用车', '营运性残疾车')

-- 房产比对
SELECT p.身份证号, p.姓名, r.房产地址, r.面积
FROM 补贴发放明细 p
LEFT JOIN (
    SELECT 产权人身份证号, COUNT(*) AS 房产数量
    FROM 房产登记数据
    GROUP BY 产权人身份证号
    HAVING COUNT(*) > 1
) r ON p.身份证号 = r.产权人身份证号

-- 工商比对
SELECT p.身份证号, p.姓名, b.企业名称, b.注册资本
FROM 补贴发放明细 p
LEFT JOIN 工商登记数据 b ON p.身份证号 = b.法人身份证号 
    OR p.身份证号 = b.股东身份证号
```

**核查要点：**
- 核实资产取得时间与救助申请时间的关系（先买车后申请？还是先申请后买车？）
- 区分"临时困难"（如因病致贫，名下仍有资产但正在治疗）和"长期不符合条件"
- 车辆：区分营运性车辆（如残疾人代步车）和非营运性车辆
- 房产：区分唯一住房和多套房产，关注出租收入
- 工商：关注注册资本规模和经营状态（正常经营 vs 停业）
- 注意：家庭财产共有人制度——配偶/子女的资产也需纳入核查

**数据要求：** 车辆/房产/工商数据必须能关联到身份证号

### 模型三：重复享受模型

**适用场景：** 所有救助类型（低保、特困、高龄津贴、医疗救助等）

**原理：**
```
不同地区/不同系统的救助发放数据 → FULL JOIN → 同一身份证号
        ↓
同一身份证号在不同地方同时领 → 标红
同一身份证号在不同系统领同类补贴 → 标红
        ↓
核实是否故意隐瞒
```

**SQL逻辑（伪代码）：**
```sql
-- 跨地区重复享受
SELECT a.身份证号, a.姓名, a.补贴类型, a.发放地区 AS 地区1, 
       b.发放地区 AS 地区2, a.每月金额 + b.每月金额 AS 合计金额
FROM 补贴发放明细 a
JOIN 补贴发放明细 b ON a.身份证号 = b.身份证号
    AND a.发放地区 <> b.发放地区
    AND a.补贴类型 = b.补贴类型
    AND a.发放状态 = '正常发放'
    AND b.发放状态 = '正常发放'

-- 跨系统重复享受（同一人在不同系统领同类型补贴）
SELECT p.身份证号, p.姓名, 
       p.补贴类型, p.补贴系统, p.每月金额,
       q.补贴类型, q.补贴系统, q.每月金额
FROM 系统A_发放明细 p
JOIN 系统B_发放明细 q ON p.身份证号 = q.身份证号
    AND p.补贴类型 = q.补贴类型
```

**核查要点：**
- 核实本人是否知晓（有些是系统错误导致的重复发放）
- 是否故意隐瞒（跨区县重复申请）
- 重复领取的资金去向（是否已使用）
- 区分"临时性重复"（如系统切换期间的数据迁移重复）和"恶意重复"
- 注意：不同补贴类型可以同时享受（如低保+高龄津贴不算重复），只有同类型重复才算

**数据要求：** 跨区域数据整合——区县级别数据壁垒最高，需要市级/省级统一数据平台

## 四、广安"五步核查法"操作流程

### 第一步：数据破壁（Day 0-1）
整合15类数据：一卡通发放数据、公安户籍、车辆登记、房产登记、社保缴费、工商登记、殡葬数据、医保数据等。

**输出：** 统一数据仓库（含所有补贴对象的全维度信息）

### 第二步：模型筛查（Day 1-2）
运行120个模型（含上述三个核心模型），每个模型针对一种异常模式。

**输出：** 疑点数据清单（含异常类型、置信度、涉及金额）

### 第三步：疑点核实（Day 2-5）
模型筛出的疑点推送到一线核查，**不是直接定性**。广安筛出近110万条疑点——每条都要核查，但不是每条都有问题。

**输出：** 已核实疑点清单（确认/排除/待进一步调查）

### 第四步：问题定性（Day 5-7）
- **不符合条件** → 清退
- **虚报冒领** → 追回资金
- **涉嫌犯罪** → 移送司法机关

**输出：** 审计发现问题汇总表（含定性依据+金额+责任人）

### 第五步：推动整改（Day 7+）
- 推动建立**补贴对象生存状态月核验制度**
- 建立**部门数据实时校验机制**
- 完善**审批流程和审核标准**

**输出：** 审计整改建议书（含制度建设建议+整改时限）

## 五、派生疑点模型（延伸）

### 5.1 收入异常模型
**原理：** 银行流水/社保缴费基数显示大额进账，但低保申报表填"无收入"

**数据：** 银行流水 + 社保缴费基数 + 补贴申报表

### 5.2 资格认证异常模型
**原理：** 长期未完成资格认证但仍在发放补贴

**数据：** 资格认证记录 + 补贴发放明细

### 5.3 集中发放异常模型
**原理：** 同一IP/同一经办人批量操作大量补贴发放

**数据：** 系统操作日志 + 发放明细

### 5.4 跨部门信息比对模型
**原理：** 医保住院记录显示正在治疗，但补贴发放显示已死亡

**数据：** 医保结算 + 殡葬数据 + 补贴发放明细

## 八、典型违规模式速查

| 违规模式 | 核心模型 | 证据链 | 处理方式 |
|---------|:--------:|-------|:--------:|
| 死亡超领 | 死亡超领模型 | 殡葬记录+发放记录 | 追回+责令家属退还 |
| 伪造死亡证明 | 死亡超领模型+延伸核查 | 原始死亡证明+医院记录+公安户籍 | 追回+移送司法 |
| 有车有房享受低保 | 资产比对模型 | 车辆/房产登记+低保申请材料 | 清退+追回 |
| 注册企业领低保 | 资产比对模型 | 工商登记+低保申请材料 | 清退+追回 |
| 跨区重复享受 | 重复享受模型 | 两地区发放记录+身份证信息 | 清退其一+追回 |
| 跨系统重复享受 | 重复享受模型 | 两个系统发放记录 | 系统合并+追回 |
| 隐瞒收入申请低保 | 收入异常模型 | 银行流水+社保缴费记录 | 清退+追回 |
| 经办人虚报冒领 | 集中发放异常模型 | 操作日志+发放记录+经办人信息 | 追回+移送司法 |

## 九、实战案例参考

### 案例1：四川广安大数据全覆盖审计
- **规模：** 全市城乡低保、特困救助、养老服务等民生资金
- **数据：** 15类数据整合，120个分析模型
- **结果：** 疑点110万条，清退493人，追回54.05万元
- **制度成果：** 建立补贴对象生存状态月核验制度、部门数据实时校验机制

### 案例2：湖北随州死亡冒领
- **手法：** 家属隐瞒死亡时间2年，后伪造死亡证明
- **发现：** 社保资格认证核查+公安户籍+医保住院记录交叉比对
- **金额：** 冒领养老金3.24万元

### 案例3：江西东乡违规领取高龄补贴
- **手法：** 户口已迁出但仍领取高龄补贴
- **发现：** 纪委监委大数据监督平台数据碰撞
- **金额：** 违规领取5000余元
