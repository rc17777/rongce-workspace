## 一、项目概况

### 审计背景

医疗保险基金审计是专项资金审计中**数据量最大、风险点最密集、违规手法最隐蔽**的类型之一。典型违规包括：虚报参保人数套取财政补助、定点医疗机构骗保（虚假住院/分解住院/过度医疗/串换药品）、医保经办机构审核不严、重复报销（跨制度/跨地区）。

若尔盖县属高原藏区，参保人群以城乡居民医保为主，辖区内有县级医院、乡镇卫生院、村卫生室三级医疗网络，异地就医比例较高（高原特殊病种转院至成都等地）。

### 审计目标

1. 医保基金收支是否真实完整，有无截留、挪用
2. 参保人数是否真实，财政补助是否足额到位
3. 定点医疗机构是否存在骗取医保基金行为
4. 医保经办机构审核、拨付是否合规
5. 异地就医报销是否真实、合规

## 四、现场实施·核心分析模型

### 4.1 模型一：参保人数真实性核查

```
输入：参保名单 + 户籍底册 + 死亡人口数据
逻辑：
  ① 参保但无户籍记录 → 疑似虚报
  ② 参保但已死亡 → 冒领财政补助
  ③ 同一身份证号重复参保（跨县/跨制度）→ 重复参保
  ④ 参保人数同比增长率 > 户籍人口自然增长率+5% → 异常

输出：虚报参保人数清单 + 虚报金额 = 虚报人数 × 人均财政补助标准
```

```bash
python launch.py "若尔盖医保" --agent data_scout
# → 自动执行参保人数真实性分析
```

### 4.2 模型二：分解住院识别

```python
# 条件：
# - 同一患者（身份证号）
# - 同一医院
# - 7天内再次入院（出院日期→再入院日期 ≤ 7天）
# - 且两次住院总费用超过同等DRG正常单次住院费用

输入：住院结算明细3年
输出：疑似分解住院清单 + 涉及金额
```

**融入规则引擎**：
```bash
python scripts/rule_engine.py --data "住院结算明细.csv" --type cross_validation
# 规则引擎自动检测：
# R12: 7天内同患者同院再入院率
# R13: 住院天数分布异常（大量<3天住院）
```

### 4.3 模型三：虚假住院·时空碰撞

```
输入：住院记录 + 门诊记录
逻辑：
  ① 住院期间有门诊就诊记录 → 疑似虚假住院（人不可能同时在病房和门诊）
  ② 同一天在不同医院有住院记录 → 必然虚假
  ③ 住院天数与费用结构不匹配（长期住院但无床位费/护理费）

输出：疑似虚假住院清单
```

### 4.4 模型四：过度医疗·费用离群

```
输入：住院结算明细（按DRG分组）
逻辑：
  ① 同一DRG组内，费用超过均值+2σ → 疑似过度医疗
  ② 同一DRG组内，费用低于均值-2σ → 疑似服务不足
  ③ 药占比（药品费/总费用）异常 → 医院级别×科室对比

输出：过度医疗/服务不足病例清单
```

### 4.5 模型五：串换药品/项目

```
输入：医保结算用药/项目明细 + 医院HIS药品库存
逻辑：
  ① 医保结算使用A药品，但同期医院采购入库无A → 疑似串换
  ② A药品医保结算量 > A药品采购入库量+期初库存 → 不可能
  ③ 高价药品/耗材结算量异常增长 → 利益驱动

输出：疑似串换项目清单
```

### 4.6 模型六：定点机构异常分析

```
输入：各定点医疗机构结算数据
逻辑：
  ① 次均费用离群（>全县均值+2σ）
  ② 就诊人次/费用年增长率离群
  ③ 门诊住院比异常（正常约10%-20%转住院，某机构>50%）
  ④ 某机构申报的病种集中度异常（例如某乡卫生院"专治"某种高价慢病）

输出：异常机构清单 + 重点现场复核名单
```

## 六、若尔盖特殊场景

| 特殊场景 | 应对方案 |
|:-----|:-----|
| 牧区参保人信息不完整（部分无身份证号） | 按姓名+出生日期+乡镇模糊匹配·人工核实 |
| 异地就医比例高（转院至成都等地） | 异地结算数据单独分析·核实转诊审批真实性 |
| 乡镇卫生院信息化程度低 | 优先抽取县级医院数据·乡镇级以抽查为主 |
| 藏区特殊用药/藏医药 | 藏医药报销政策与非藏区不同·需单独核实政策适用性 |
| 城乡居民医保为主·职工医保占比小 | 以城乡居民医保为重点·职工医保常规检查 |
| 数据量：百万级住院+千万级门诊 | sqlite/duckdb本地分析·不依赖RAG·纯规则引擎+统计分析 |
