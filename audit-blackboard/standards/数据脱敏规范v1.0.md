# 融策审计数据脱敏规范 v1.0

> 四川融策会计师事务所 / 四川融策工程咨询公司  
> 适用：所有政府审计、国企审计、绩效评价项目  
> 生效日期：2026-06-24  
> 责任人：项目主审 + 数据专员双重确认

---

## 一、为什么必须脱敏

1. **法律合规**：《个人信息保护法》《数据安全法》要求处理敏感数据必须脱敏  
2. **政府审计特殊性**：被审计单位数据含公民个人信息、财政敏感信息、企业商业机密  
3. **AI工具使用风险**：在线API（DeepSeek/Kimi等）传输数据存在泄露风险，脱敏是底线  
4. **底稿归档**：审计底稿长期保存，脱敏后方可入库存档

---

## 二、数据分级（四级）

| 级别 | 名称 | 示例 | 处理要求 |
|:---:|:---|:---|:---|
| **L1** | 公开级 | 法律法规、政策文件、已公开预算 | 无需脱敏，可直接使用 |
| **L2** | 内部级 | 被审计单位名称、项目概况、非敏感财务汇总 | 轻度脱敏，可保留内部使用 |
| **L3** | 机密级 | 个人身份信息、详细财务数据、合同金额、供应商信息 | **必须脱敏**后才能上传AI/共享 |
| **L4** | 绝密级 | 涉密项目信息、国家安全相关数据、纪检移送线索 | **禁止数字化**，纸质流转，双人双锁 |

**判断原则**：不确定就高不就低。L3级数据默认识别为脱敏对象。

| 手机号 | 13800138000 | 保留前3位+后4位 | 138****8000 |

### 3.3 财务/金额信息

| 字段 | 示例 | 脱敏规则 | 脱敏后示例 |
|:---|:---|:---|:---|
| 单笔金额 | ¥1,234,567.89 | 按金额区间化（见3.4） | 100-200万 |
| 合同金额 | ¥5,000,000.00 | 按金额区间化 | 500-1000万 |
| 支付金额 | ¥89,320.00 | 按金额区间化 | 5-10万 |
| 绩效目标金额 | ¥10,000,000 | 精确到百万级或按区间 | 1000万（精确到百万） |

### 3.4 金额区间化规则（审计专用）

```
区间划分（适用于脱敏后的统计分析）:
├── 5万以下      → "5万以下"
├── 5-10万       → "5-10万"
├── 10-50万      → "10-50万"
├── 50-100万     → "50-100万"
├── 100-500万    → "100-500万"
├── 500-1000万   → "500-1000万"
├── 1000-5000万  → "1000-5000万"
├── 5000万-1亿   → "5000万-1亿"
└── 1亿以上      → "1亿以上"

注意：区间化后仍可用于异常检测（如"大额支付""拆分支付"），
      但无法精确计算总金额。如需精确计算，应在本地安全环境完成，
      脱敏仅用于上传AI/共享/归档。
```

### 3.6 审计工作底稿特有信息

| 字段 | 脱敏规则 |
|:---|:---|
| 审计发现问题涉及的具体人名 | 替换为"某人员""某负责人" |

## 四、脱敏操作原则

### 4.1 操作顺序（必须遵守）

```
Step 1: 数据分级 → 判断L3/L4
Step 2: 本地备份原始数据（加密存储）
Step 3: 脱敏处理（脚本或人工）
Step 4: 脱敏验证（抽查10%数据）
Step 5: 脱敏后数据方可上传AI/共享/入知识库
Step 6: 原始数据与脱敏数据分离存储，原始数据禁止上传云端
```

### 4.2 双重确认机制

| 场景 | 确认人 | 确认方式 |
|:---|:---|:---|
| 常规脱敏（脚本自动） | 项目主审 + 数据专员 | 抽查签字 |
| 敏感项目（纪检/涉密） | 项目合伙人 + 技术负责人 | 逐条确认 + 书面记录 |
| AI上传前最终检查 | 数据专员独立复核 | 上传清单签字 |

### 4.3 禁止行为（红线）

- ❌ 未经脱敏，直接将原始数据粘贴到在线AI对话框
- ❌ 将L3/L4级数据通过邮件、微信传输
- ❌ 脱敏后未验证，直接作为底稿归档
- ❌ 同一份数据，脱敏版和原始版混放在同一目录
- ❌ 使用未经验证的第三方脱敏工具（可能存在后门）

## 五、脱敏脚本使用

### 5.1 Excel自动脱敏

```bash
python audit-blackboard/standards/scripts/desensitize_excel.py \
  --input "原始数据/校服采购支付明细.xlsx" \
  --output "脱敏数据/校服采购支付明细_脱敏.xlsx" \
  --config "audit-blackboard/standards/脱敏规则配置.json"
```

### 5.2 字段级脱敏（Python）

```python
from audit_blackboard.standards.scripts.desensitize_excel import desensitize_field

# 身份证号脱敏
desensitize_field("51010719850315001X", "id_card")  # → "510107****001X"

# 金额脱敏
desensitize_field(1234567.89, "amount")  # → "100-200万"

# 姓名脱敏
desensitize_field("张三", "name")  # → "张**"
```

## 六、审计场景脱敏速查表

| 审计类型 | 重点脱敏字段 | 特殊注意 |
|:---|:---|:---|
| **经济责任审计** | 被审计领导姓名、亲属信息、个人财产 | 涉及干部隐私，脱敏级别最高 |
| **专项资金审计** | 受益人名单、身份证号、银行卡号、发放金额 | 社保/营养餐等涉及大量公民信息 |
| **招投标审计** | 投标企业名称、报价明细、专家姓名 | 专家姓名脱敏，但评标过程需保留 |
| **工程审计** | 合同金额、分包商信息、工程地址 | 金额区间化后仍可分析异常 |
| **绩效评价** | 被评价单位敏感数据、受访者信息 | 访谈记录需人名替换为"受访者A/B" |
| **国企审计** | 商业机密、未公开财务数据、关联交易 | 涉及商业秘密，脱敏+保密协议 |
| **往来款清理** | 欠款单位名称、金额、联系人 | 联系人信息必须脱敏 |

## 七、脱敏质量检查清单

每批次脱敏数据上传AI前，数据专员必须勾选：

- [ ] 已确认数据分级（L3/L4）
- [ ] 原始数据已本地备份（加密）
- [ ] 脱敏脚本已运行，输出文件已生成
- [ ] 抽查10%数据，脱敏结果正确
- [ ] 未发现原始数据残留（如Excel隐藏sheet、PDF元数据）
- [ ] 脱敏文件命名已加"_脱敏"后缀
- [ ] 上传AI前已再次确认无敏感信息
- [ ] 项目主审已签字确认

## 八、违规处理

| 违规级别 | 情形 | 处理 |
|:---|:---|:---|
| 一级 | 未脱敏数据泄露（外部） | 立即报告合伙人，启动应急预案，书面报告监管机构 |
| 二级 | 未脱敏数据误传AI/云端 | 删除云端数据，更换API密钥，内部通报 |
| 三级 | 脱敏不彻底（抽查发现） | 重新脱敏，责任人书面说明，纳入考核 |
