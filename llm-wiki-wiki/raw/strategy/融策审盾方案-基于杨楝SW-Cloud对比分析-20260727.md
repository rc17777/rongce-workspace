> 制定日期：2026-07-27

## 一、核心定位：我们不做SW-Cloud，我们做"审盾"

杨楝的SW-Cloud是**管理流程平台**，覆盖项目/人事/客户/财务/知识的全生命周期管理。融策审盾的定位完全不同：

```
        SW-Cloud                          审盾
      ┌─────────┐                    ┌──────────┐
      │ 怎么干活 │ ←── 管理流程 ──→  │ 活干得怎样 │
      └─────────┘                    └──────────┘
      项目+HR+客户+财务              AI复核+质量智能
      通用流程（横向）              政府审计专精（纵向）
      传统软件（开发团队）           AI驱动（大模型+RAG）
      替代OA/CRM                    嵌入现有流程的质量插座
```

**一句话定位：融策·审盾 = 政府审计报告的AI质量守门人。让审计报告敢签字。**

不跟SW-Cloud比功能覆盖，比在"报告质量保障"这一个点上的AI深度。

## 二、三阶段路线图

### 第一阶段：审盾一期 —— 单点突破验证（30天，2026年7-8月）

> 此即为7月19日已确定的第一阶段，仅更新细化。

**唯一目标：** 验证AI在绩效评价报告复核中，能否达到或超过融策审计经理平均水平。

**不做什么：**
- ❌ 不做系统平台
- ❌ 不涉及项目管理/HR/客户模块
- ❌ 不对外宣传
- ❌ 不养开发团队

**做三件事：**

| 周 | 任务 | 产出物 |
|:--|:--|:--|
| 第1周 | 选人（最懂绩效评价的业务骨干）、选10份高质量报告、形成《绩效评价报告AI复核检查清单v1.0》 | 检查清单+报告集 |
| 第2-3周 | 构建最小复核器：上传报告→AI复核→输出复核意见清单。RAG知识库匹配+智析v2.0+15维检查 | 可运行的最小复核器 |
| 第4周 | 业务骨干逐条校验AI输出：命中率/误报率/漏报率/采纳率/耗时变化 | 验证数据 |
| 第5周 | AI复核 vs 3位审计经理人工复核盲测 | 盲测报告 |
| 第6周 | 形成《融策·审盾一期验证报告》 | 验证报告 |

**通过标准（不变）：**
- AI发现问题数量 ≥ 人工平均水平80%
- 误报率 ≤ 20%
- 重大错误漏检 = 0
- 报告复核时间减少 ≥ 30%
- 有效建议采纳率 ≥ 30%
- 项目经理愿意继续用 ≥ 2/3

**第一期投入：** 1个业务骨干全职30天 + DeepSeek API费用（预估¥200-500）

---

### 第二阶段：审盾二期 —— 嵌入业务流（3个月，2026年9-11月）

> 第一期验证通过后启动。核心：把AI复核从"事后补刀"变成"流程内嵌"。

**目标：** 让AI复核成为融策内部所有政府审计报告出报告的必经节点。

**三大升级：**

#### 升级1：从绩效评价扩展到+2条业务线

审盾一期只覆盖绩效评价。二期新增：
- **专项资金审计报告**复核模型（社保、营养餐等）
- **经济责任审计报告**复核模型（任中/离任）

每条线的扩展成本：约2周/条（主要是检查清单定制+案例库扩充+验证）

#### 升级2：从"报告后复核"到"三节点内嵌"

学习杨楝"合规嵌入流程"的思路——

```
传统流程：底稿 → 报告初稿 → 报告终稿 → 【AI事后复核】
               ↑ 问题发现太晚！

审盾流程：底稿 → 报告初稿 → 【AI初核节点①】→ 修改 → 【AI复核节点②】→ 报告终稿 → 【AI终审节点③】→ 签发
               ↑ 三节点逐层把关
```

三个节点的AI角色不同：
- **节点① 初核（底稿→初稿阶段）：** 检查数据来源是否完整、取证是否到位。角色：数据完整性哨兵。
- **节点② 复核（初稿修改后）：** 15维深度检查。角色：全文质量审计师。
- **节点③ 终审（签发前）：** 金额合计校验+法规适用性+责任归因合理性。角色：终审守卫。

#### 升级3：输出物标准化

```
审盾二期输出（每次复核自动生成）：
├── 复核意见清单（P0/P1/P2分级）
├── 数据追溯链（疑点→数据源→参考法规→建议修改）
├── 版本差异报告（新版 vs 旧版改动点清单）
└── 质量评分卡（含各维度得分+趋势+历史对比）
```

**二期投入：** 2个业务骨干各50%投入3个月 + 1个兼职技术协调人

### 第三阶段：审盾·Pro —— 行业赋能（2027年起）

> 二期稳定运行6个月后评估是否启动。

**目标：** 把融策内部的AI复核能力，变成可以对外输出的服务产品。

**三种输出形态：**

| 形态 | 说明 | 目标客户 | 定价逻辑 |
|:--|:--|:--|:--|
| **审盾·SaaS** | 在线平台，上传报告→自动复核→返回意见清单 | 其他中小事务所 | 按报告数量/按月订阅 |
| **审盾·嵌入** | API/SDK嵌入客户现有系统 | 有自建系统的机构 | 按调用量+年费 |
| **审盾·服务** | 融策团队+AI辅助的人工复核服务 | 政府客户/委托方 | 按项目收费 |

**优先推：审盾·服务。** 
- 原因：融策做政府审计出身，直接面向政府客户有信任基础
- 模式：政府客户委托融策做"报告质量审查"，融策用AI辅助内部效率，对外输出人工+AI双重保障
- 比SaaS好推：不用说服客户换系统，只是卖一种新服务

**与SW-Cloud的互补可能性：**
- 如果SW-Cloud未来走向市场化，审盾可以作为SW-Cloud的质量模块嵌入
- 如果SW-Cloud面向的事务所客户同时有报告质量需求，可以形成渠道合作
- 但目前不主动推动，等三期有稳定产品后再议

## 三、与杨楝SW-Cloud的战略差异（四个"不跟"）

### 1. 不做平台，做"质量插座"

SW-Cloud是独立的管理系统，替代OA/CRM。用户要换系统才能用。

审盾是"质量插座"——**嵌入用户现有流程，不需要换系统**。用户用什么工具做项目都行（Excel/金蝶/用友/手工），只在上传报告那一刻触发AI复核。

**优势：** 零迁移成本，零培训成本，上线即用。

### 2. 不养开发团队，养"提示词工程师"

SW-Cloud靠代码迭代，需要开发团队。

审盾靠提示词+知识库迭代，需要的是：
- 懂审计业务的"提示词工程师"（审计经理转型）
- 懂知识管理的"知识库架构师"（现有RAG维护者）
- 不需要专业程序员（AI编码足够处理辅助脚本）

**成本差异：** 一个开发团队年薪20万+ → 零。一个审计经理50%精力投入 → 已有。

### 3. 不面向全行业，只做政府审计

SW-Cloud面向所有专业服务机构（审计+咨询+评估）。

审盾只做政府审计→只做报告质量复核→先从绩效评价做起。

"窄"才是壁垒。当你在一个点上积累的案例库、检查清单、AI模型是别人的10倍深，别人就没法追。

### 4. 不做"好看的系统"，做"好用的工具"

杨楝的惨痛教训："超过84%的使用者认为系统是累赘。"

审盾的产品哲学：
- 一线审计员：少填一个表就成功一半。AI复核自动运行，不需要手动触发。
- 报告复核人：打开报告→一键运行审盾→拿到意见清单→逐条确认/修改→闭环。
- 管理层：看到质量评分卡和趋势图即可，不用进系统。

**产品形态：** 不是网页系统，而是一个"上传报告→返回意见"的简单流程。可以做成企业微信机器人、网页上传、文件拖拽——形式不重要，重要的是"看不见但一直在"。

## 四、行业发声策略（对标杨楝的信息化委员会通路）

杨楝在省注协信息化委员会有话语权，文章发在《四川注册会计师》。融策目前没有这个通路，但不需要复制——有自己的路径：

### 路径1：省注协信息化委员会（现成渠道）

审盾一期验证报告出来后：
- 整理成一份《政府审计报告AI质量复核：融策实践验证报告》
- 通过省注协信息化委员会渠道提交/分享
- 切入点："十五五规划强调数智化，我们做了一次务实的AI在政府审计质量保障中的验证"

**时效：** 审盾一期完成后（2026年8月底前）即可启动。

### 路径2：省注协三项指引（搭便车）

省注协2026年要出台经责报告模板/社会组织换届审计/司法会计鉴定三项指引。
- 融策对应的12业务线标准化指引手册中，AI复核可以作为"质量标准"独立章节
- 对外发布时，审盾=标准落地的AI工具

### 路径3：客户口碑驱动（最牢固）

政府审计的甲方圈子很小——财政局/审计局/各委办局的财务处。质量好的报告他们会互相推荐。
- 融策出的一份带"审盾AI复核"标记的报告，本身就是最好的广告
- 比任何PPT、论文、协会演讲都管用

### 路径4：文章发表（对标杨楝）

审盾一期验证完成后，可以写一篇技术文章投《四川注册会计师》：
- 主题："AI辅助绩效评价报告复核——一个中小事务所的实践"
- 风格：不吹牛，讲真话（失败了几个维度、哪些效果显著、哪些还在挣扎）
- 这种务实风格反而能打动同行

## 六、三句话总结（对外话术）

**对同行：** 融策·审盾不是一套系统，是一个AI驱动的审计报告质量保障机制。先做好我们自己的质量，再帮助更多的同行。

**对客户：** 每一份融策出具的审计报告，都经过了"AI+人工"双重复核。AI把能自动检查的跑完，审计师把需要专业判断的深入分析。让您更敢采纳审计结论。

**对协会：** 十五五规划提出数智化转型。我们选择了一条最务实的路——不是在PPT上讲AI，而是在审计报告复核这个最基础的环节，用AI做出可测量的质量提升。

## 附录：审盾一期检查清单（待业务骨干共建）

此清单为一期核心产出物，需由选定的业务骨干与AI团队共同制定。初步框架：

### A. 数据一致性检查（6项）
- [ ] 报告正文金额 vs 附表金额是否一致
- [ ] 合计/小计/汇总是否准确
- [ ] 跨表引用数据是否一致
- [ ] 期间数据 vs 基准数据是否匹配
- [ ] 百分比计算结果是否准确
- [ ] 金额单位是否统一（元/万元/亿元）

### B. 合规性检查（5项）
- [ ] 法规引用是否准确、有效
- [ ] 审计程序是否完整覆盖必要节点
- [ ] 审计证据是否充分支撑结论
- [ ] 报告要素是否完整（标题/文号/落款/日期/签章）
- [ ] 术语使用是否规范

### C. 逻辑性检查（4项）
- [ ] 问题描述 → 原因分析 → 结论的逻辑链是否完整
- [ ] 指标设置 → 评价标准 → 评分是否合理
- [ ] 问题定性是否与问题严重程度匹配
- [ ] 建议是否针对问题根因而非表面

### D. 格式规范性检查（4项）
- [ ] 错别字/语病/标点错误
- [ ] 段落格式/编号连续性
- [ ] 表格格式是否规范
- [ ] 字体/字号/行距是否符合标准

### E. 交叉比对（3项）
- [ ] 报告问题 ↔ 取证单是否一一对应
- [ ] 评价指标 ↔ 评分表 ↔ 结论是否一致
- [ ] 上期整改 ↔ 本期再发现问题是否标记
