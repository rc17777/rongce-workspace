# 大数据赋能巡察：四类模型实战手册

> 提炼自：公众号「巡风笔记」| 入库：2026-07-19
> 适用业务线：监督检查（4号）、预算执行审计（3号）、专项资金审计（4号）
> 关键词：大数据审计、巡察模型、数据比对、智慧监督

---

## 一、三个基础条件

在审计/巡察中引入大数据方法，以下三者缺一不可：

### 1.1 数据

| 数据来源部门 | 可获取数据 | 审计价值 |
|:--|:--|:--|
| 财政局 | 预算指标、国库支付、政府采购台账 | 资金流向追踪 |
| 人社局 | 社保发放、养老金领取、医保结算 | 民生资金比对 |
| 民政局 | 殡葬数据、低保名单、残疾证 | 死亡/违规领取交叉比对 |
| 公安局 | 户籍信息、车辆登记 | 身份核验 |
| 市场监管局 | 工商登记、股权结构 | 关联关系穿透 |
| 住建局 | 工程项目审批、施工许可 | 工程全流程追踪 |

**取数策略**：
- 建立制度化数据共享机制（不是一次性的，是常态化的）
- 巡前统一发出数据需求函，明确目录、格式、时限
- 设立专职数据联络员——可将调取时间从几天缩短到2小时内

### 1.2 平台

| 平台 | 功能 | 审计映射 |
|:--|:--|:--|
| 网络平台（云端） | 数据归集、上下贯通 | 相当于我们的RAG知识库+项目管理 |
| 单机系统（本地） | 巡中实时录入、数据分析 | 相当于审计现场的数据分析工具 |

工作流：巡前网络平台归集 → 巡中单机系统比对 → 巡后数据回传入库

### 1.3 组织保障

- 设立专门的数据分析岗位（不是兼职）
- 配置专业人员（不是临时抽调）
- 持续推动（不是一次性项目）

## 二、四类已过实战检验的比对模型

### 模型一：民生资金比对模型 🟢 最简单、见效最快

**核心逻辑**：跨部门名单交叉比对

| 比对组合 | 数据A | 数据B | 发现的问题 |
|:--|:--|:--|:--|
| 死亡人员领养老金 | 民政局殡葬数据 | 人社局养老金发放表 | 死亡后继续领取（冒领） |
| 不符合条件领低保 | 民政局低保名单 | 公安局户籍+车辆登记 | 有车有房吃低保 |
| 惠农补贴违规 | 农业局补贴名单 | 户籍+土地确权 | 非农户领取农业补贴 |
| 重复享受救助 | 民政局救助名单 | 人社局失业金名单 | 同一人多渠道领取 |

**操作难度**：★★☆☆☆ | **审计效果**：★★★★★

**实操要点**：
- 身份证号是最可靠的关联键
- 注意时间窗口（死亡日期 vs 最后一次发放日期）
- 必须保留手工复核环节（同名同姓≠同一人）

### 模型二：工程项目分析模型 🟡 适合住建/交通/水利领域

**核心逻辑**：项目全流程数据串联，找异常

| 分析维度 | 数据来源 | 异常信号 |
|:--|:--|:--|
| 中标价格异常 | 招标控制价 + 中标价 + 标底 | 中标价远低于第二名（恶意低价）/ 所有报价接近控制价（可能围标） |
| 合同金额频繁变更 | 原始合同 + 补充协议 | 变更金额超过合同价10%未重新招标 |
| 工程量虚增 | 结算工程量 vs 设计工程量 | 结算量>设计量150%且无签证变更支撑 |
| 超概算 | 批复概算 vs 结算金额 | 超概10%未履行调概程序 |
| 工期异常 | 合同工期 vs 实际工期 | 验收日期早于开工日期 / 工期压缩50%以上 |

**操作难度**：★★★☆☆ | **审计效果**：★★★★☆

### 模型三：招投标关联模型 🔴 营商环境专项必用

**核心逻辑**：投标人之间的多维关联分析

| 关联维度 | 检测方法 | 信号强度 |
|:--|:--|:--:|
| 法人代表交叉 | 多个投标人法人相同 | 🔴 铁证 |
| 股东重叠 | 同一人在多家投标企业持股 | 🔴 铁证 |
| 联系人/代理人同一 | 不同投标人授权同一人投标 | 🔴 铁证 |
| IP地址相同 | 上传/解密标书的出口IP一致 | 🔴 铁证 |
| 注册地址相近 | 同一写字楼/同一门牌号 | 🟡 强信号 |
| 联系电话相同 | 投标文件中留的电话相同 | 🔴 铁证 |

> ⚠️ 详细检测方法参见 `融策电子招投标审计SOP-v1.0.md` 和 `procurement-audit-models` 技能

### 模型四：12345热线分析模型 🟢 群众获得感导向

**核心逻辑**：从投诉数据中锁定审计重点

| 分析维度 | 方法 | 审计输出 |
|:--|:--|:--|
| 投诉量集中领域 | 按分类统计投诉数量TOP10 | 确定审计重点方向 |
| 重复投诉 | 同一事项被多次投诉 | 整改不到位的线索 |
| 投诉解决率 | 办结率 vs 满意率 | 主管部门履职情况 |
| 地理分布 | 投诉热力图 | 问题集中的乡镇/街道 |
| 物业管理匹配度 | 投诉量/小区数量 | 推动物业费下调的依据 |

**案例**：某地通过分析数万条投诉数据，建立物业管理匹配度分析模型，推动了一批物业企业下调服务费。

## 三、三个关键环节

### 环节一：数据清洗（最耗时但最关键）

```
原始数据 → 统一编码（身份证号/统一社会信用代码）→ 去重 → 格式标准化 → 缺失值处理 → 入库
```

**常见坑**：
- 同一人在不同系统里名字写法不同（简繁体、空格）
- 金额单位不一致（元/万元/亿元）
- 日期格式不统一（2024-01-01 / 2024.1.1 / 2024年1月1日）
- 编码体系不同（老行政区划代码 vs 新代码）

### 环节二：疑点核查（数据结论≠审计结论）

| 疑点类型 | 核查方式 | 证据形式 |
|:--|:--|:--|
| 数据比对发现的差异 | 实地核查+走访群众+谈话了解 | 取证单+访谈记录+现场照片 |
| 规律性异常 | 调取原始凭证逐笔核实 | 凭证复印件+情况说明 |
| 跨部门数据矛盾 | 向两个部门分别核实 | 双方书面回复 |

> 核心原则：数据告诉你有疑点，但疑点背后是不是真问题，还得靠人去看、去问、去核实。

### 环节三：整改推动（不止于个案）

- 个案整改 → 制度漏洞分析 → 推动出台管理办法
- 示例：村级项目违规发包频发 → 数据分析发现监管制度不健全 → 推动出台《村级工程项目管理办法》

## 四、最大难点：人才融合

| 问题 | 症状 | 解决方案 |
|:--|:--|:--|
| 技术人员不懂业务 | 建出来的模型用不上 | 业务人员+数据人员搭配组队 |
| 业务人员不懂技术 | 不知道哪些数据可以建模 | 编制模型操作手册，固定成熟模型 |
| 人员流动 | 换人模型就废了 | 标准化模块 + 分级分类培训 |

**融策对应策略**：
1. 培养既懂审计业务又懂数据分析的复合型人才
2. 建立可复用的标准化模型模板库
3. 新来的人员照着操作手册就能上手
