# 满意度与投入关联分析 — 聚类模型

## 审计问题
用户满意度是否与资金投入正相关？是否存在"高投入低满意"的异常项目？

## 核心逻辑
正常情况下投入越高的项目满意度应该越高。将项目按"投入金额+满意度"二维聚类，找出"高投入低满意"的异常群。

## 数据需求

| 字段 | 说明 | 来源 |
|------|------|------|
| 项目名称 | 被评价项目 | 项目库 |
| 总投资 | 项目总投入 | 决算 |
| 满意度得分 | 满意度调查得分（0-100或1-5） | 满意度调查报告 |
| 项目类型 | 基建/服务/补贴等 | 项目分类 |
| 受益人数 | 受益人次 | 验收/台账 |

## 检测逻辑

```
Step 1: 标准化：投入金额 → Z-Score
       满意度得分 → Z-Score
Step 2: K-Means聚类（k=4）：
  群1: 高投入-高满意 → 效率正常
  群2: 低投入-高满意 → 优秀（值得推广）
  群3: 低投入-低满意 → 投入不足
  群4: 高投入-低满意 → 🔴 重点审计对象
Step 3: 对群4项目逐项分析原因：
  - 资金被挪用？质量差？选址错误？需求不匹配？
```

## 阈值/参数
- 聚类数 k=4
- 投入和满意度标准化后聚类
- 群4（高投入低满意）自动标记为异常

## 典型发现
- 某市民公园投资5000万，满意度仅2.1/5 → 群4异常，经查选址偏远无人使用
- 某培训项目投资仅20万，满意度4.8/5 → 群2标杆，经验可复制

## 局限性
- 满意度数据主观性强，调查方法影响结果
- 投入大小需考虑项目类型差异（基建天然高投入）
- 建议同类型项目内部分组聚类，避免基建和培训混比
