# everything-claude-code 使用指南

> **来源**：「硬核科技屋」公众号  
> **日期**：2026年4月20日  
> **类型**：AI开发工具  

---

## 核心定位

不是给 Claude Code 加几个命令的简单插件，而是一套**工程流程增强工具箱**（skills/agents/hooks/rules/工作流配置），让 Claude Code 从"写代码的助手"升级为"参与项目流程的工程搭子"。

## 核心理念：从"命令式"到"任务式"

| 旧方式 | 新方式 |
|--------|--------|
| "帮我写一个登录功能" | "先帮我规划登录功能的实现路径，分析风险，再拆解开发步骤" |
| 局部快、整体不稳 | 先理解上下文→再执行→整体可控 |

## 四大核心用法

| 类型 | 场景 | 价值 |
|------|------|------|
| **规划类** | 新功能/大改造前先出方案、拆任务、列风险 | 避免一头扎进代码 |
| **调研类** | 接手陌生项目/大代码库，先梳理结构、依赖、调用链 | 减少误改和返工 |
| **审查类** | 写完后让AI从reviewer角度检查结构/边界/命名/异常 | 提前暴露隐藏问题 |
| **安全验证类** | 检查权限绕过/数据泄露/注入风险，做验证闭环 | 比单次生成更接近真实开发 |

## 正确使用姿势

**把需求表达成完整任务**，而非零散指令：

❌ "帮我改一下认证模块"  
✅ "请先梳理当前项目里的认证模块实现方式，找出登录、鉴权、权限判断相关代码，再给出重构方案，最后按步骤完成改造"

## 嵌入流程的四个节点

1. 需求刚来 → 先拆解
2. 动手之前 → 先摸清结构
3. 编码过程 → 查漏补缺
4. 完成之后 → 审查+安全检查

## 常见踩坑

- 装完不熟悉规则和hooks就直接上 → 体验不稳
- 一上来就丢超大需求 → 从小功能/审查/梳理开始
- 当"万能替代品" → 架构判断/上线把关/安全决策仍需人来定
