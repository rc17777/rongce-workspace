## 三、场景化Prompt模板

### 3.1 科目余额异常检测

**适用**：经责审计、收支审计、预算执行审计、国企审计

```
## 审计任务
科目余额异常检测 — 找出期末余额方向异常或金额异常的科目

## 数据表结构
表名: gl_balance（科目余额表）
字段:
- company_code (VARCHAR) — 公司代码
- account_code (VARCHAR) — 科目编码（4位=一级科目）
- account_name (VARCHAR) — 科目名称
- period (VARCHAR) — 期间，格式YYYY-MM
- begin_debit (DECIMAL) — 期初借方余额
- begin_credit (DECIMAL) — 期初贷方余额
- period_debit (DECIMAL) — 本期借方发生额
- period_credit (DECIMAL) — 本期贷方发生额
- end_debit (DECIMAL) — 期末借方余额
- end_credit (DECIMAL) — 期末贷方余额
数据粒度: 科目级（按月汇总）
金额单位: 元
数据库类型: [按实际情况填写]

## 疑点条件
1. 资产类科目（编码1开头）出现贷方余额且金额>100万
2. 负债类科目（编码2开头）出现借方余额且金额>100万
3. 期末余额为负数且金额>100万的科目（绝对值降序）
4. 期末余额为0但本期有发生额的科目（可能被冲销）

## 输出要求
- 分别输出4个疑点清单，各按金额绝对值降序排列
- 包含：公司代码、科目编码、科目名称、期末余额、疑点类型
```

### 3.2 往来款账龄自动分层

**适用**：往来款清理、经责审计

```
## 审计任务
往来款账龄分层 — 按客户汇总未回款金额并按账龄分层统计

## 数据表结构
表名: ar_detail（应收账款明细表）
字段:
- company_code (VARCHAR) — 公司代码
- customer_id (VARCHAR) — 客户ID
- customer_name (VARCHAR) — 客户名称
- invoice_no (VARCHAR) — 发票号
- invoice_date (DATE) — 开票日期
- invoice_amount (DECIMAL) — 开票金额
- received_amount (DECIMAL) — 已回款金额
- balance_date (DATE) — 截止日期
数据粒度: 发票明细级
金额单位: 元
数据库类型: [按实际情况]

## 疑点条件
1. 按客户汇总未回款金额（invoice_amount - received_amount > 0）
2. 账龄分层标准：0-90天 / 91-180天 / 181-365天 / 1年以上
3. 基准日期：balance_date = '[填写截止日期，如2026-06-30]'
4. 重点关注：账龄1年以上且金额>50万的客户

## 输出要求
- 按总未回款金额降序排列
- 包含：客户名称、各账龄段金额、总未回款金额
- 额外标注：1年以上账龄占比>50%的客户标红
```

### 3.3 关联方交易识别与汇总

**适用**：经责审计、国企审计、往来款清理

```
## 审计任务
关联方交易识别与汇总 — 识别并汇总被审计单位与关联方之间的交易

## 数据表结构
表1: voucher_detail（凭证明细表）
字段:
- voucher_id (VARCHAR) — 凭证ID
- company_code (VARCHAR) — 公司代码
- counterparty (VARCHAR) — 对方单位名称
- dr_amt (DECIMAL) — 借方金额
- cr_amt (DECIMAL) — 贷方金额
- summary (VARCHAR) — 摘要
- posting_date (DATE) — 记账日期

表2: related_party（关联方清单）
字段:
- party_name (VARCHAR) — 关联方名称
- relation_type (VARCHAR) — 关联关系类型（母子公司/同一控制/关键管理人员...）

数据粒度: 凭证明细级
金额单位: 元
数据库类型: [按实际情况]

## 疑点条件
1. 筛选期间：[填写期间，如2026-01-01至2026-06-30]
2. 关联方匹配：counterparty IN (SELECT party_name FROM related_party)
3. 借贷不平异常：ABS(SUM(dr_amt) - SUM(cr_amt)) > 0
4. 无商业实质交易：摘要含"往来""暂借""周转"且金额>100万

## 输出要求
- 按交易净额降序排列
- 包含：公司代码、关联方名称、关联类型、凭证笔数、借方总额、贷方总额、净额
- 额外输出：借贷不平的交易清单（单独sheet）
```

### 3.4 审计抽样（MUS/分层抽样）

**适用**：各类审计的凭证抽样

```
## 审计任务
凭证分层抽样 — 按金额分层抽取样本凭证

## 数据表结构
表名: voucher_header（凭证主表）
字段:
- voucher_id (VARCHAR) — 凭证ID
- voucher_no (VARCHAR) — 凭证号
- amount (DECIMAL) — 凭证金额
- posting_date (DATE) — 记账日期
- created_by (VARCHAR) — 制单人
- approved_by (VARCHAR) — 审核人
- summary (VARCHAR) — 摘要
数据粒度: 凭证级
金额单位: 元
数据库类型: [按实际情况]

## 疑点条件（分层+抽样）
1. 金额分层：
   - 小额：< 1万元 → 每层抽5笔
   - 中额：1-10万元 → 每层抽8笔
   - 大额：10-100万元 → 每层抽10笔
   - 超大额：>100万元 → 全查
2. 期间：posting_date BETWEEN '[开始]' AND '[结束]'
3. 额外关注：制单人=审核人的凭证 100%抽样

## 输出要求
- 分层抽样结果：每层按金额降序，随机抽取指定笔数
- 额外输出：制单人=审核人凭证清单
```

```
- project_id (VARCHAR) — 项目编号
```

### 3.8 通用异常检测（持续审计监控）

**适用**：所有业务线，作为月度常规监控

```
## 审计任务
月度持续审计监控 — 批量扫描以下异常模式

## 数据表结构
[根据被审计单位系统填写]

## 监控项清单（可一次让AI全部生成SQL）
1. 大额整数凭证（金额末位≥3个0，可能人为凑整）
2. 摘要含"调整""冲销""补记""更正"等关键词的凭证
3. 非工作时间录入的凭证（周末/节假日/22:00-06:00）
4. 同一凭证制单人与审核人为同一人
5. 同一制单人连续录入多张金额相同的凭证

7. 本期无发生额但期末余额变动的科目

9. 凭证日期晚于制单日期（后补凭证）
10. 借方金额=贷方金额但跨科目的分录（疑似资金腾挪）

## 输出要求
- 每个监控项一个独立SQL
- 所有查询按金额/数量降序输出
```

## 五、黄金验证流程（必读）

> ⚠️ AI写的SQL必须经过验证才能用于审计底稿！

```
第1步：AI生成初版SQL
  ↓
第2步：人工校验逻辑
  - 借贷方向是否正确？
  - 科目范围是否完整？
  - 期间口径是否准确？
  - 金额单位是否匹配？
  ↓
第3步：抽样验证
  - 先用一个已知结果的子科目/小期间跑一遍
  - 结果与财务系统余额表核对
  ↓
第4步：全量执行
  - 验证通过后扩大到全部数据
  ↓
第5步：结果复核
  - 与财务系统总账余额交叉比对
  - 标记偏离>5%的结果重新检查SQL
```

## 六、常见陷阱速查

| 风险点 | 表现 | 应对 |
|--------|------|------|
| 科目编码理解偏差 | AI把应收账款和应收票据混为一谈 | Prompt中明确科目编码范围 |
| 借贷方向搞反 | 不同科目余额方向不同，AI未必知道 | 说明科目属性（资产/负债/权益） |
| 辅助核算遗漏 | 审计常需按部门/项目/客户交叉分析 | 明确列出所有辅助核算字段 |
| 口径不一致 | 多公司合并时期间、币种不同 | 逐一确认口径后再提问 |
| 金额单位幻觉 | AI默认"元"，实际是"分"或"万元" | Prompt中明确金额单位 |
| JOIN键错误 | 表关联用了错误的字段 | 说明主键-外键关系 |
| NULL值处理 | 未回款金额可能为NULL | 要求使用COALESCE/NVL |
