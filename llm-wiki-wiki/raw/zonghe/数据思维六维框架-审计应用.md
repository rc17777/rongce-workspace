# 数据思维六维框架：审计应用指南

> 提炼自：本·琼斯《会说话的数据：人人都需要的数据思维》（2024）书评
> 来源：公众号「言言的留白」| 入库：2026-07-19
> 用途：为审计人员提供一个结构化的数据思维检查清单

---

## 概述

本书提出了理解数据思维的六大方面，将其映射到审计实务后，形成了一套可操作的"数据思维自查框架"——在审计分析启动前、分析过程中、报告撰写前各阶段均可使用。

---

## 一、数据素养 → 审计中的数据基本功

| 素养要素 | 审计映射 | 常见陷阱 |
|:--|:--|:--|
| 理解数字含义 | 能区分"万元"和"元"，识别金额单位不一致 | 决算报表以万元列示，合同以元列示，直接比较得出错误结论 |
| 识别数据的普遍性 | 知道哪些业务环节会产生可审计的数据 | 只查账本，忽略业务系统日志、审批记录、GPS轨迹等非财务数据 |
| 掌握分析基本原则 | 了解抽样、趋势、比率、回归等基本方法 | 拿Excel透视表当数据分析 |

**审计自查项**：报告中的每一个数字，我能说出它的含义和来源吗？

---

## 二、数据直觉 → 审计怀疑能力的结构化

书中提出直觉在分析中的5个作用，映射到审计：

| 直觉作用 | 审计映射 |
|:--|:--|
| 知道数据说了什么和没说什么 | 看出报表中"不该缺的缺了"（如某类支出完全没有） |
| 知道下一步该去哪里 | 发现异常后知道要查哪个辅助账、哪份合同 |
| 知道何时停止寻找并采取行动 | "收益递减"原则——查到第三层证据还不够就换个方向 |
| 知道听众是谁 | 报告写给财政局看 vs 写给纪委看，重点完全不同 |
| 知道事情为什么重要 | 一个0.3%的偏差在万亿资金盘子里意味着什么 |

**卡尼曼三问（判断直觉是否可靠）**：
1. 这个领域是否有规律可循？→ 政府资金的流向通常是有规律的
2. 我在这个领域是否有足够经验？→ 审计年限和项目数量
3. 我过去是否收到过及时反馈？→ 审计报告被采纳/驳回的记录

## 三、五种数据分析方法 → 审计分析的标准阶梯

| 方法 | 审计问题 | 典型工具 |
|:--|:--|:--|
| **描述性分析** | 发生了什么？ | 收支明细统计、预算执行率 |
| **推理性分析** | 其他的是什么？ | 同行业比较、同地区横向对比 |
| **诊断性分析** | 为什么发生？ | 下钻分析：超支→具体科目→具体合同→具体凭证 |
| **预测性分析** | 接下来会发生什么？ | 基于历史趋势预测年末预算执行率 |
| **推导性分析** | 应该做什么？ | 审计建议的量化依据 |

**审计中的典型使用顺序**：
```
描述 → 发现异常 → 诊断（下钻找原因）→ 推理（同行业对照确认严重性）→ 推导（形成建议）
```

## 四、八个提前问的问题 → 审计取数前必问

| 问题 | 审计场景 |
|:--|:--|
| **Why** — 为什么我需要这份数据？ | 明确审计目标，避免"数据越多越好"的取数膨胀 |
| **Where** — 数据来自哪里？ | 财政局导出 vs 单位自报 → 可信度完全不同 |
| **Who** — 谁拥有和更新数据？ | 数据提供方的动机：可能是被审计单位自己 |
| **When** — 上次更新是什么时候？ | 2024年决算数据 ≠ 2026年的真实财务状况 |
| **Which** — 哪些变量最重要？ | 不要取100个字段，先锁定关键的10个 |
| **What** — 重要变量怎么定义的？ | "三公经费"在不同单位可能口径不同 |
| **How** — 数据如何测试、收集、存储？ | 手工录入的数据 vs 系统自动采集的数据 |
| **How much** — 我有多少时间？ | 3天出报告 vs 3周出报告，分析深度完全不同 |

## 五、消费数据时的意识 → 审计证据审视

| 审视维度 | 审计场景 |
|:--|:--|
| 信息来源可信度 | 被审计单位提供的自查报告 vs 第三方数据交叉验证 |
| 数据转换方式 | 单位上报数据是否经过"加工美化"？ |
| 上下文背景充分性 | 只看今年数据不够，要看近3-5年趋势 |
| 展现详细程度 | 汇总数据掩盖了什么？需要下钻到原始凭证 |
| 展现方式 | 对方选的图表类型是否有意引导结论？ |

## 六、数据素养的17个关键特征 → 审计团队能力评估

| 维度 | 特征 | 审计团队对应能力 |
|:--|:--|:--|
| **知识** | 识别数据普遍性 | 知道各部门/各业务系统有哪些可用数据 |
| | 理解数据生命周期 | 从原始凭证→记账→报表→审计取数的完整链路 |
| | 掌握分析原则 | 7大审计分析方法 |
| | 熟悉可视化规则 | 选对图表类型传达审计发现 |
| | 了解AI能力 | 知道RAG/SQL生成/OCR能做什么、不能做什么 |
| **技能** | 数据整理 | 能从PDF/Excel/数据库多源数据清洗入库 |
| | 处理与分析 | SQL + Python + Excel三件套 |
| | 阅读可视化 | 不被对方报表的"漂亮图表"误导 |
| | 比较分析 | 跨部门/跨年度/跨地区多维度比较 |
| | 理解背景与历史 | 知道这笔资金的历史沿革 |
| **态度** | 开放但批判 | 相信数据但不迷信数据 |
| | 质疑精神 | "这个数字为什么是这个数字？" |
| | 伦理意识 | 审计中获取的数据不用于审计目标之外 |
| | 包容自信 | 技术分析结果≠审计结论，要结合业务判断 |
| **行为** | 用数据解决问题 | 不只发现问题，能量化问题的严重程度 |
| | 沟通洞察 | 把技术分析结果翻译成管理者听得懂的语言 |
| | 持续学习 | 每个项目总结新的分析思路 |

## 审计场景速查

| 审计阶段 | 适用维度 | 核心问题 |
|:--|:--|:--|
| 审前调查 | 四（8问）+ 五（数据意识） | 该取什么数据？从哪取？可信吗？ |
| 数据分析 | 三（5方法）+ 二（直觉） | 先描述→再诊断→怀疑什么查什么 |
| 疑点排查 | 二（直觉）+ 五（意识） | 数据结论合理吗？还需要佐证吗？ |
| 报告撰写 | 六（17特征-沟通）+ 一（素养） | 数字含义清晰吗？读者能理解吗？ |
