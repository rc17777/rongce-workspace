# 北京智能体新政 × 融策·审盾 战略对标分析

> 分析日期：2026-07-23
> 依据：北京市《关于加快智能体引领发展的若干措施》10条 + 融策审盾战略 + 十五五战略分析
> 对标框架：7个核心概念逐一映射审盾现状、差距、机会

---

## 一、总判断

**这份政策不是"AI行业利好"，是给审盾发了一份官方背书的战略路线图。** 文件里 Harness Engineering、RaaS、OPC、需求智能、Token经济五大概念，恰好对应审盾从技术架构到商业模式到组织形态的五个关键维度。审盾的战略方向不需要调整——需要的是用这些概念把现有思路讲得更清楚、卖得更贵。

## 二、七大概念逐一对标

### 2.1 Harness Engineering（驾驭层工程）↔ 审盾技术架构

**政策原文**："上下文工程优化、任务持久化、多智能体协作、系统可扩展"

**审盾现状**：

审盾本质上就是一个审计领域的 Harness 系统。把审盾架构拆开看：

| Harness 组件 | 政策概念 | 审盾对应物 | 成熟度 |
|:--|:--|:--|:--:|
| 上下文管理 | 上下文工程优化 | RAG知识库（17,933 chunks）+ 法规匹配 | ✅ 已建 |
| 工具调用 | 工具编排 | RAG查询→法规匹配→金额核验→逻辑检查 | ✅ 部分 |
| 任务拆解 | 任务持久化 | 15维度复核检查清单 | ✅ 已建 |
| 权限控制 | 安全治理 | 人工确认制度（5类必确认） | ✅ 已建 |
| 状态保存 | 长期记忆 | 项目闭环沉淀 + 留痕导出 | ✅ 已建 |
| 失败重试 | 任务持久化 | 模型fallback链（14层） | ✅ 已建 |
| 结果验证 | 结果评测 | 业务骨干逐条校验（30天实验） | 🔄 进行中 |
| Agent观测 | 可观测系统 | AI输出留痕制度 | ✅ 已建 |
| 跨模型路由 | 多模型协同 | 14模型路由体系 | ✅ 已建 |
| 多Agent编排 | 多智能体协作 | 22 Agent + 黑板模式 + H-packet交接 | ✅ 已建 |

**核心发现**：审盾的 Harness 层在审计行业已经非常厚实。政策里提到的 Harness 组件，审盾几乎全有对应物。问题不在于"有没有"，而在于"有没有产品化包装"。

**战略启示**：

> 论文《Agentic Harness Engineering》验证：不改模型，只优化 Harness，10轮迭代后 Pass@1 从 69.7%→77.0%。审盾的护城河不在模型，在 Harness——这跟政策判断完全一致。

**行动建议**：
1. 审盾对外宣传时，主动使用"驾驭层工程"概念，把15维复核+RAG+留痕+路由包装成"审计领域 Harness 系统"
2. 审盾一期验证报告里增加一章："Harness 层对复核准确率的独立贡献"（对比裸模型 vs Harness增强的差异）
3. 投标材料里引用政策原文"实施驾驭层工程（Harness Engineering）"，建立政策合规性背书

### 2.2 RaaS（结果即服务）↔ 审盾商业模式

**政策原文**："鼓励创新主体从Token消耗量计费转向价值计费" → TaaS → AaaS → RaaS

**审盾三层对应**：

| 层级 | 定义 | 审盾阶段 | 定价逻辑 |
|:--|:--|:--|:--|
| **TaaS** | 卖Token/推理 | ❌ 不碰 | 这不是融策的局 |
| **AaaS** | 卖Agent能力 | 审盾二期→三期 | 按报告类型/业务线订阅 |
| **RaaS** | 卖审计结果 | 审盾终局 | "让你敢签字" = 按复核结果收费 |

**关键洞察**：政策里那句"供应商要承担任务失败、重复执行、成本波动、质量验收、结果归因和赔偿责任"——这恰恰是审盾一期在做的验证。在没验证完成率之前，绝对不敢对外卖RaaS。一期的30天实验，本质上是在测 **Cost per Successful Task**。

**审盾应该盯的核心指标**（来自政策启示）：

```
Cost per Successful Task（每次成功复核的真实成本）
= 模型推理 + 工具调用 + 失败重跑 + 人工接管 + 延迟损失 + 错误风险
```

而不是：
```
Cost per Token（每百万Token价格）← 这是模型厂的指标，不是审盾的
```

**战略启示**：

> 政策的 TaaS→AaaS→RaaS 升级路径，就是审盾的商业化路线图。审盾一期验证 AaaS 可行性（能力是否达标），二期在外部试点 AaaS（订阅模式），三期冲刺 RaaS（按结果收费，但风险自负）。

**定价策略预判**：

| 阶段 | 模式 | 定价锚点 | 风险 |
|:--|:--|:--|:--|
| 内部工具 | 成本中心 | 节省的人工成本 | 无 |
| AaaS（外部） | 按报告/按月 | 人工复核市场价的50-70% | 中等 |
| RaaS（终局） | 按结果/按保险 | 报告出错的风险溢价 | 高 |

### 2.3 OPC（一人公司）↔ 审盾组织形态

**政策原文**："支持以 OPC（一人公司）为代表的创新创业新模式"

**审盾对应**：审盾一期本质上就是一个 OPC 实验——

> 一个业务骨干 + 一套Agent系统 = 一个人完成原来3个审计经理的复核工作量

科斯的公司边界理论在这里被直接验证：Agent压低了执行成本和协调成本，企业最小可行规模下降。

**审盾一期与 OPC 的精确映射**：

| OPC 要素 | 审盾一期 |
|:--|:--|
| 个人能力 | 最懂绩效评价的业务骨干 |
| Agent系统 | 15维复核 + RAG + 法规匹配 |
| 可复用资产 | 复核检查清单 + 采纳率数据 + 轨迹沉淀 |
| 基础设施 | 14模型路由 + 22 Agent + 知识库 |
| 结果交付 | 复核意见清单（可独立对客户交付） |

**战略启示**：

> 政策提 OPC 不只是"一个人开公司"，它背后是**企业边界正在被Agent改写**。审盾的秘密武器不是让10个人更高效，是让1个人能干10个人的活——这是比"提效30%"性感得多的话术。

**行动建议**：
1. 审盾一期验证报告标题建议："OPC模式下的绩效评价报告AI复核——1人+AI=3位审计经理？"
2. 投标时用 OPC 概念包装："融策审盾实现了审计领域的OPC模式，一人+AI系统完成传统3-5人的复核工作量"
3. 申请"专精特新"时，把审盾定位为"审计OPC基础设施"

### 2.4 需求智能 ↔ 审盾 UX 范式

**政策原文**："以需求智能为核心驱动的原生AI软件和超级软件"

**三层智能演进与审盾对应**：

| 层级 | 定义 | 审盾对应 | 状态 |
|:--|:--|:--|:--|
| 功能智能 | AI负责某个节点 | RAG单次查询 | ✅ |
| 流程智能 | AI串起多个步骤 | 15维自动复核流程 | ✅ |
| **需求智能** | 用户只表达结果，系统负责全过程 | "上传报告→告诉我有什么问题" | 🎯 目标 |

**审盾已经在做需求智能**："上传报告→输出复核意见清单"——用户不需要点15个按钮、不需要选法规库、不需要手动查金额。这正是政策的"需求智能"范式。

**超级软件视角**：

审盾如果只做"报告复核工具"，那它只是一个功能软件。但如果它跨过报告复核→法规查询→问题定性→整改建议→底稿管理→质量留痕这些边界，统一理解审计需求，把分散能力编排起来——那就是审计领域的"超级软件"。

> 政策原文的"UI可能被Skill吞掉"——对应审盾：审计助理不用学15个菜单，只需要对审盾说"复核这份绩效报告"。

### 2.5 Token经济 ↔ 审盾价值度量

**政策核心**："从Token消耗量计费转向价值计费"

**审盾的价值度量重构**：

旧思维（模型厂视角）：
```
这次复核花了多少Token？→ 降Prompt长度、选便宜模型
```

新思维（审盾视角，政策对齐）：
```
这次复核为客户创造了多少价值？
= 避免了多少金额的错误 × 错误被发现的概率
+ 节省了多少人工复核时间 × 人工时薪
+ 提升了多少报告质量（客户续约率）
```

**审盾应该建立的三层指标体系**：

| 指标层 | 指标 | 当前状态 |
|:--|:--|:--|
| Token层 | 每次复核Token消耗 | 可追踪（token_tracker.py） |
| 任务层 | Cost per Successful Task | 审盾一期应测量 |
| 价值层 | Value per Successful Task | 审盾二期应建立 |

**Token券/服务券机会**：政策提出"探索Token券和智能体服务券"——如果落地，审盾可以申请政府服务券补贴客户使用成本，这是直接的价格竞争力。

### 2.6 安全治理 ↔ 审盾质控体系

**政策框架**：Agent 安全五个问题

| 政策安全问题 | 审盾对应机制 | 状态 |
|:--|:--|:--:|
| 目标理解错了 | 人工确认"问题定性" | ✅ |
| 权限越界了 | AI输出必须人工采纳 | ✅ |
| 提示词注入操控 | 输入文件脱敏 | ⚠️ 待建 |
| 长期记忆被污染 | 知识入库质控制度 | ✅ |
| 多Agent连锁放大 | 15维框架作为容隔离 | ✅ 部分 |

**关键机会**：政策提出"分级分类监管"——低风险任务自测上线，高风险任务严格检测+人类确认。审盾可以主动对标这套框架，在投标时引用：**"审盾的安全治理体系对齐北京市智能体安全分级标准"**。

### 2.7 银河算廊 + FDE ↔ 审盾实施路径

**银河算廊**：云边端协同算力调度。

对审盾的现实意义：审盾不需要自己的GPU集群，但需要稳定的推理供给。当前14模型路由 + fallback链就是一套轻量级"算力路由"——哪个模型便宜用哪个、哪个挂了切哪个。

**FDE（前沿部署工程师）**：

> 政策："进入客户现场，跟业务人员一起拆流程、接系统、清数据，把新问题带回产品里"

这就是审盾一期的业务骨干角色！他不只是"验证AI"，他本质上是融策的第一个 FDE——

- 拆流程：把绩效评价复核拆成15维
- 接系统：把RAG、模型路由、复核清单接起来
- 清数据：脱敏10份历史报告
- 带回问题：统计误报/漏报，迭代规则

**FDE 路径的产品化逻辑**：

```
服务1个客户 → 沉淀一套轨迹
服务10个客户 → 找出共性结构
共性足够稳定 → 服务变成产品
```

这就是审盾从内部工具→外部产品的标准路径。

## 四、战略叙事升级建议

### 4.1 旧叙事 vs 新叙事

| 维度 | 旧叙事 | 新叙事（政策对齐） |

| 技术定位 | AI辅助审计工具 | **审计领域 Harness 工程系统** |
| 价值主张 | 让复核更快更准 | **审计领域的 RaaS——让你敢签字** |

### 4.2 一句话电梯演讲

> 融策·审盾是政府审计领域的 Harness 工程系统——我们不卖模型，我们卖的是"让你敢签字"的结果。1个审计师 + 审盾 = 传统3-5人的复核产能。这是审计OPC模式的中国首批验证。

## 六、风险与注意事项

1. **概念泡沫风险**：Harness、RaaS、OPC 这些词很新，客户可能听不懂。对内用真概念做架构，对外用"AI复核系统"做沟通。不要炫概念吓跑客户。

2. **RaaS 责任风险**：政策明确说RaaS供应商要承担"结果归因和赔偿责任"。审盾在对外承诺"让你敢签字"之前，必须有法律条款限定责任范围。

3. **OPC 不等于不雇人**：OPC是效率杠杆，不是裁员工具。对外讲"1人+AI=3人产能"比"用AI替代审计师"安全一百倍。
