# Agentic RAG 从入门到实战：让 RAG 拥有"自我纠错"能力

## 核心观点

传统 RAG 的"死穴"：一锤子买卖，没有质量把关环节。有研究发现，在医学临床文本生成中，传统 RAG 反而让大模型幻觉率从 5.0% 飙升至 43.6%。原因是它只找到"看起来相关"的资料，而非循证证据。

Agentic RAG 的解法：在流程中插入检查点——智能体先判断要不要检索；检索完有评分环节确认相关性；不相关就重写查询再试；循环直到拿到合格上下文或重试次数耗尽。

## RAG 三代进化

| 代际 | 方案 | 核心机制 | 核心问题 | 适合场景 |
|:--|:--|:--|:--|:--|
| 第一代 | Vector RAG | 向量检索 → 拼接 → LLM 生成 | 检索跑偏了没人知道 | 简单 FAQ、单文档问答 |
| 第二代 | Graph RAG | 实体抽取 → 知识图谱 → 社区摘要 | 构建和维护成本极高 | 跨文档推理、实体关系理解 |
| 第三代 | Agentic RAG | 智能体 → 检索 → 评分 → 重写循环 | 工程复杂度高 | 复杂查询、多知识源、高准确率要求 |

## 核心机制：三个组件

1. **智能体节点**：判断是否需要外部知识；需要就调检索器，不需要直出答案。
2. **评分节点（质量关卡）**：逐个审视返回文档——相关不相关？能不能帮忙？相关→走生成，不相关→触发查询改写。**这是整个系统最关键的质量关卡**。
3. **重写节点**：把原始问题改写为更适合检索的形式（口语化→关键词化、补充上下文），改写后重新发起检索。

## 关键数据

- 2026 Q1 企业采用混合检索意向从 10.3% 飙升至 33.3%
- GraphRAG 在复杂多跳推理场景仍有不可替代优势，但离线成本极高
- 文章提供完整 LangGraph 实现代码

## 对审盾的直接价值

1. 审盾一期当前是"传统 Vector RAG + 规则引擎"，Agentic RAG 的自纠错机制是二期方向
2. 评分节点 = 审盾的复核规则引擎升级版：不只是规则检查，还能判断检索结果相关性
3. 重写节点 = 当审计人员提问模糊时（"看看这个项目有什么问题"），系统自动改写为更精确的检索查询
4. 三代的演进路径和审盾的架构设计（一页纸）一致：一期 RAG → 二期 KG-enhanced RAG → 三期 Agentic/GraphRAG
