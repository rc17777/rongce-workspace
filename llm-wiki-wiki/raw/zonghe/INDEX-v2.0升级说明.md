# 医保审计数据分析模型 v2.0 升级说明

## 升级背景

v1.0 模型（2026-06-06）为纯方法论驱动，未显式引用法规条款。

v2.0 基于完整的法规政策体系梳理（六层金字塔），逐条对照735号令第15条/第38条/第40条、法发〔2024〕6号、医保发〔2021〕48号、国办发〔2021〕2号，对每个模型进行：

1. **法规溯源**：每个检测规则对应具体法条
2. **缺口识别**：政策有规定但无模型覆盖的行为
3. **新模型创建**：补全所有法规覆盖盲区
4. **证据标准对齐**：对标法发6号的刑事证据要求

## 12模型联动分析矩阵

不同模型之间的关系不是独立运行，而是交叉验证。以下是建议的联动组合：

```
一线筛查（跑在最前面，覆盖面最广）
├─ M4 机构费用异常  ──→ 圈出可疑机构
├─ M5 药品用量异常  ──→ 圈出可疑药品/医生
└─ M3 高频就医      ──→ 圈出可疑患者

二线深挖（对一线圈出的目标定向深挖）
├─ M1 分解住院 + M6 挂床住院 ──→ 查住院行为真实性
├─ M7 串换            ──→ 查药品/耗材真实性
└─ M2 重复报销        ──→ 查多渠报销真实性

三线精准打击（法定要件验证）
├─ M8 冒名就医        ──→ 确认骗保主体
└─ M12 目录外纳入      ──→ 确认超范围结算

DRG专项（仅在DRG地区使用）
├─ M9 编码高套        ──→ 病种付费下的编码舞弊
└─ M10 推诿重症       ──→ 病种付费下的服务不足

集采专项（仅在集采品种使用）
└─ M11 非中选替代     ──→ 集采政策执行审计
```

**最关键的交叉验证（三线合一）**：

```
M7(串换:结算>入库) + M2(重复:多渠道报销) + M6(挂床:零护理记录)
                    ↓
         如果三线同时命中同一医疗机构
                    ↓
         高度确信存在系统性骗保 → 触发法发6号移送标准
```

## 证据力量表（对标法发〔2024〕6号）

法发6号要求证据达到"确实、充分"标准。每个模型输出的疑点对应不同证据等级：

| 证据等级 | 模型输出 | 可直接作为定案证据？ |
|:---------|:---------|:-------------------|
| 🔴 确认级 | M7：结算量>0且入库量=0（串换） | ✅ 直接证据（法发6号第19条：可用系统数据综合认定） |
| 🔴 确认级 | M8：性别冲突（男→妇科诊断） | ✅ 直接证据 |
| 🔴 确认级 | M6：护理记录=0且住院≥3天 | ✅ 高度证明"未实际住院" |
| 🟡 强证据 | M9：主诊断与检验报告冲突 | ✅ 需配合病案原件（法发6号第15条：注重收集原始证据） |
| 🟡 强证据 | M1：间隔≤24h同诊断再入院 | ⚠️ 需排除计划内再入院（化疗等） |
| 🟢 线索级 | M4：聚类异常 → 需延伸抽查病历 | ❌ 需转化为确认证据 |
| 🟢 线索级 | M3：Z≥3高频就医 → 需分析诊断分布 | ❌ 需区分重病vs药贩 |

## 审计作业流程建议

```
Phase 1: 数据接入
  获取: 医保结算 + HIS病案 + 药库出入库 + 护理记录 + DRG分组 + 集采目录
  验证: 数据完整性检查（735号令第16条要求数据全面准确传送）

Phase 2: 一键扫描（运行M1-M12全部模型）
  → 生成疑点清单，按机构/个人/药品三维汇总

Phase 3: 交叉验证
  → 多模型命中同一目标 → 升级为P0

Phase 4: 证据固定
  → 按法发6号第15条标准收集原始证据
  → 疑点清单 + 原始凭证 + 系统数据 → 形成完整证据链

Phase 5: 分级处理
  → 50万以下：行政处理建议（退回+罚款+暂停协议）
  → 50万以上/恶劣：移送公安（法发6号第23条）
```

## 与泉州128模型的协同

泉州审计局的128个SQL模型（`knowledge/references/医保基金审计128模型-泉州审计局.md`）提供了更细粒度的SQL实现。融策v2.0的12模型是审计分析框架，两者关系：

- 融策v2.0 = **问题定义 + 规则逻辑 + 法规依据**
- 泉州128模型 = **SQL实现 + 技术细节（utl_match/窗口函数/STDDEV）**

实际使用时：融策v2.0给出"查什么、为什么违法"，泉州128模型给出"怎么查的SQL代码"。
