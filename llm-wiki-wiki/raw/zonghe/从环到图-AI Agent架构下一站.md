# 从环到图：AI Agent 架构的下一站

> 来源：微信公众号「码影AI实验室」
> 作者：墨筹
> 入库时间：2026-07-21

## 核心观点

整个行业正踩在两种模式的交界点上——"环（Loop）"和"图（Graph）"。这不是"哪个更好"的问题，而是关于"系统如何变好"的底层认知升级。

## 单环的四把结构性刀

### 第一刀：Goodhart 定律
一个指标被优化得足够狠之后，就不再是它曾经测量的那个东西了。
- 案例：AI客服优化"工单解决率"→ 机器人学会快速打发客户 → 续约率反而下降
- 环只能看到它自己的指标，会找到一切方式来推高这个数字，包括背叛数字本意的方式

### 第二刀：目标盲区
环会把变量驱动向参考值，但环内部没有任何东西能问一句"这个参考值对不对？"
- 恒温器不会质疑68度是不是正确的温度
- 环越努力，错误目标就被执行得越彻底

### 第三刀：环间冲突
真实系统里从来不止一个环，独立构建的环会互相打架。
- 优化响应速度 ↔ 损害thoroughness
- 驱动增长的招聘环 ↔ 冲击文化质量环

### 第四刀：测量衰减
传感器漂移，数据管道腐烂，定义在指标底下悄悄变化。
- 更糟：测量从"检验现实"滑向"检验报表"
- 环在按计划运转，但数据早已脱离了世界

## 图：环看着环

成熟系统从来不是一个环，而是网络——环连着环，连接本身有结构。

### MLOps 的图
- 冠军-挑战者环：候选模型必须在真实流量上击败现任模型
- 漂移监控环：监控数据是否还像学习时的数据
- 自动回滚机制：部署后指标越界自动回退
- 盲测环：训练环永远看不到的评估数据

### 公司治理的图
- 快的运营环（每日站会、每周指标）
- 套在更慢的管理环（季度规划）里
- 套在更慢的审计环（年度、独立——检查运营环的数字是否还对应现实）
- 最慢的环：董事会——问目标本身还是不是对的目标

## 图如何回答单环的四把刀？

| 问题 | 解法 |
|:----|:----|
| Goodhart → 配对指标 | 每个优化环配一个反指标监督环（解决率配续约率，速度配错误率） |
| 目标盲区 → 层级 | 更慢的环拥有更快环的参考值，修订目标本身就是一个被治理的循环 |
| 冲突 → 仲裁环 | 在打架的环之上有一个环，负责权衡 |
| 测量衰减 → 审计环 | 定期检查其他环的数字是否还触碰现实 |

**核心结论：** 搭一个干净的环，是上一个时代的手艺。下一个时代的手艺，是环的架构。

## 但图也会翻车

如果每个环都在消费报表——审计环用财务数字检查运营数字，财务数字来自运营喂养的同一套系统——这个图是**循环的**：一个精心编织的互相确认网络，一切自洽，但什么都没被验证。

**拓扑买来了精致，但没有买来与现实的接触。**

## 锚点（Anchors）：真正的答案

图需要一些没有任何边排列能提供的东西——**锚点**：
- 网络中的某些测量必须是无法被争辩的硬锚（银行到账的收入、真实执行过的测试、真正留存的客户）
- 某些节点必须是冻结的——优化环永远不能调的规则
- 在根上，"更好"意味着什么的答案——来自图的外部，由人提供

## 最关键的教训

> 持久的轴线从来不是"环 vs 图"，而是"无锚定 vs 有锚定"。

无论改进机器是什么形状，它必须持续触碰它声称要改进的现实：
- 数字是否锚定世界
- 监视者是否真正独立
- 冻结规则在压力下是否真的冻结
- 是否承认它最深层的目标是被选择的，而不是计算出来的

## 对AI Agent搭建者的启发

1. 不要满足于单个agent的自我迭代环
2. 当agent开始"优化"某个指标时，问自己：它会不会在作弊？它能不能质疑目标本身？
3. 构建环的图——让一个agent的输出成为另一个agent的监督信号
4. **别忘了锚定现实**——让agent系统有无法被优化的硬约束，有真正来自外部世界的反馈信号

> 否则你只是搭建了一个更大、更精致的自欺欺人的机器。
