# 医保重复报销检测 — 关联规则

## 法规依据
- **社会保险法第30条**：明确四类费用不纳入医保支付
- **735号令第41条**：重复享受医疗保障待遇 → 退回+暂停联网3-12月；以骗保为目的的 → 2-5倍罚款
- **法发〔2024〕6号第6条**：重复享受医疗保障待遇 → 以诈骗罪定罪处罚

## 审计问题
是否存在同一笔医疗费用在多个渠道重复报销、套取医保基金的问题？

## 核心逻辑
同一患者、同一日期、同一诊疗项目，如果在医保、大病保险、医疗救助等多个渠道同时出现，即为重复报销。关联规则挖掘多源数据中的重复模式。

## 数据需求

| 字段 | 说明 | 来源 |
|------|------|------|
| 身份证号 | 患者唯一标识 | 医保结算系统 |
| 就诊日期 | 就诊日期 | 结算数据 |
| 项目编码 | 诊疗/药品项目编码 | 结算数据 |
| 费用金额 | 单次费用 | 结算数据 |
| 报销渠道 | 医保/大病/救助/商保 | 结算系统 |
| 医疗机构 | 就诊机构 | 结算数据 |

## 检测逻辑

```
Step 1: 构建关联规则 — 定义重复报销特征
  规则1: 同一身份证 + 同日期 + 同项目编码 → 在多个报销渠道出现 → 疑似重复报销

Step 2: 交叉匹配 — 三表JOIN
  医保报销表 vs 大病保险表 vs 医疗救助表
  三表按(身份证,日期,项目编码) JOIN
  规则2: JOIN结果行数 > 1 → 触发标记

Step 3: 金额验证
  规则3: 多渠报销总和 > 实际费用 → 超额报销 → P0（直接确认）
  规则4: 多渠报销总和 = 实际费用（刚好100%）→ 仍需确认是否符合政策

Step 4: 机构层面汇总
  规则5: 同一机构重复报销率 > 2% → 系统性套取 → P1
  规则6: 同一机构重复报销人数 > 50人/年 → 重点延伸
```

## 阈值/参数
- JOIN结果行数 > 1 → 触发标记
- 超额报销 > 0元 → P0（直接确认）
- 同一机构重复率 > 2% → P1（重点排查）
- 同一机构重复人数 > 50人/年 → P1

## 典型发现
- 某患者同一次住院同时在医保和大病保险报销，多报3.2万
- 某医院全年重复报销率5.8% → 系统性套取
- 审计署2017-1号公告：全国查实5124人重复报销1346.91万元

## 局限性
- 需多数据源打通（医保/大病/救助），数据孤岛是最大障碍
- 身份证号可能录入错误导致误匹配
- 跨省重复报销（在A省和B省同时报销）需全国联网数据，省级审计难以覆盖
