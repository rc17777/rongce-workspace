# audit-plugin v3.0：AI原生升级设计

> **对应五大基石之三**：从硬编码逻辑到构建推理大脑，探索AI原生开发
>
> **设计日期**：2026-05-26
> **当前版本**：v2.0（政府专项审计模式）

---

## v2.0 → v3.0：核心范式转移

```
v2.0（当前）                         v3.0（目标）
─────────────────────────────────────────────────────
人触发 → Skill执行                   上下文感知 → 自动触发
"帮我分析政策"                      新政策文件入库 → 自动解读+推送
"帮我分析数据"                      数据更新 → 自动异常检测+标记

串上下文不串流程                     串上下文 + 主动感知上下文变化
每个Skill独立执行                    Orchestrator协调多Skill编排

确定性：输入→处理→输出              概率性：输入→自主推理→概率输出
                                     带有置信度标注
```

## 架构变化

### v2.0 架构

```
CLAUDE.md（共享上下文）
    ↓ 人触发
┌───────┼───────┼───────┐
│ skill1 │ skill2 │ skill3 │  ...  独立执行
└───────┴───────┴───────┘
```

### v3.0 架构

```
CLAUDE.md（共享上下文 + 项目状态）
    ↓
┌─────────────────────────────┐
│       Orchestrator           │  ← 新增：上下文感知调度中枢
│  - 上下文变化感知             │
│  - 触发条件匹配               │
│  - Skill编排与调度            │
│  - 输出路由                   │
└──────────┬──────────────────┘
           │ 自动触发
    ┌──────┼──────┐
    ↓      ↓      ↓
  skill1 skill2 skill3 ...
    │      │      │
    └──────┴──────┘
           ↓
    输出路由（推送/标注/看板更新/静默记录）
```

## 改造清单

### 改造1：每个Skill增加触发条件声明

在每个Skill的SKILL.md（或独立trigger.yaml）中声明：

```yaml
# skill: policy-digest
triggers:
  - type: file_arrival
    pattern: "政策文件/**/*.{pdf,docx}"
    description: "新政策文件入库时自动解读"
    auto_execute: true
    
  - type: manual
    command: "/audit:policy-digest"
    
output_routing:
  default: push_summary      # 推送摘要
  auto: silent_update        # 自动执行时静默更新CLAUDE.md
```

```yaml
# skill: multi-source-analysis
triggers:
  - type: data_refresh
    source: "审计数据仓库"
    description: "数据更新时自动执行异常检测"
    auto_execute: true
    schedule: "on_data_change"
    
  - type: milestone
    milestone: "data_collection_complete"
    description: "数据收集完毕后自动启动分析"
    auto_execute: false      # 需确认
    
output_routing:
  auto: dashboard_update     # 更新数据看板
  alert: push_notification   # 异常时推送
```

### 改造2：新增 orchestrator Skill

**功能**：
- 监控项目状态（数据更新/文件变更/阶段切换）
- 匹配各Skill的触发条件
- 编排多Skill协同（如：policy-digest → multi-source-analysis → finding-generator）
- 管理输出路由（静默更新/主动推送/标注/看板）

**核心逻辑**：
```
1. 轮询/监听项目上下文变化
2. 匹配触发条件 → 确定需要执行的Skill
3. 检查依赖关系 → 排序执行
4. 收集输出 → 按路由规则分发
5. 记录轨迹 → project-trajectory-recorder
```

### 改造3：CLAUDE.md 升级为动态状态文件

```
CLAUDE.md v2.0:
  - 政策知识库（静态）
  - 审计方案（静态）
  
CLAUDE.md v3.0:
  - 政策知识库（静态 + AI自动更新）
  - 审计方案（静态 + 执行进度标记）
  + 项目状态（阶段/进度/当前焦点）
  + 数据状态（最后更新/数据质量评分/异常数量）
  + 待确认事项队列
  + Agent活动日志
```

### 改造4：输出升级为概率性标注

```
v2.0:
  "发现3处违规" → 确定性结论

v3.0:
  "发现3处高风险异常（置信度：2处高/1处中），
   建议优先核查第1、2项，第3项可能与政策解读偏差有关"
   → 概率性建议 + 人工判断空间
```

## 分阶段实施

### Phase 1：上下文感知基础（1-2周）
- [ ] 每个Skill添加触发条件声明（trigger.yaml）
- [ ] CLAUDE.md增加项目状态追踪字段
- [ ] 手动验证：文件变更 → Agent识别 → 提示可执行操作

### Phase 2：Orchestrator原型（2-3周）
- [ ] 新建 orchestrator skill
- [ ] 实现基础的事件→触发匹配→Skill调度
- [ ] 实现输出路由（静默/推送/标注）
- [ ] 灰盒测试：用历史项目数据模拟验证

### Phase 3：全链路打通（3-4周）
- [ ] 端到端测试：数据入库 → 自动分析 → 发现推送
- [ ] 人工Gate机制验证（哪些环节需要确认）
- [ ] 输出概率性标注（置信度+不确定说明）

### Phase 4：生产化（4-6周）
- [ ] 与融策现有审计作业系统对接方案设计
- [ ] 安全边界确认（Agent不能自主定性/不能对外交互）
- [ ] 团队培训：从"使用工具"到"与Agent协作"

## 安全边界（红线）

```
✅ Agent可以做的                     ❌ Agent不能做的
─────────────────────────────────────────────────
自动提取文档内容                     自动定性审计问题
自动对照政策标记疑似违规              自动生成最终报告结论
自动异常检测并标注                   自动发送外部函证
推荐审计重点和方法                   自动与被审计单位交互
自动填充底稿模板                     覆盖人工已确认的判断
推送风险提示                         绕过人工Gate直接对外输出
```
