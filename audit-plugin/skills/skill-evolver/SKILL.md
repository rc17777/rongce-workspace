# 技能进化器 (Skill Evolver)

## 元数据

- **类型**：reflective（反思式）
- **命令**：`/audit:evolve`
- **核心价值**：解决"审计技能装完就不再变化，经验和踩坑无法沉淀回技能库"的痛点
- **输入**：项目轨迹聚合数据 + 当前技能定义
- **输出**：技能更新建议（Refine / Create / Skip）+ 版本对比 + 部署决策
- **理论来源**：SkillClaw（阿里 DreamX）+ Graph of Skills（GoS 依赖图更新）

---

## 目标

让 audit-plugin 的审计技能**像活的东西一样，随项目经验的积累而持续进化**。

不是一次性造一个完美的技能，而是建立一个**持续改进的正反馈循环**：

```
更多项目执行 → 更多轨迹数据 → 更好的进化素材 → 更好的技能 → 更好的项目交付
```

---

## 工作流程

### 第一步：加载证据 → 准备分析

**命令**：
```
/audit:evolve --prepare
/audit:evolve --prepare --projects PSJX-2026-001,PSJX-2026-002,PSJX-2026-003
```

从 `project-trajectory-recorder` 积累的轨迹中，提取各技能的「证据组」：

```
skill: finding-generator
├── 成功案例（n=5）
│   ├── PSJX-001: 政策标准明确、数据完备 → 问题发现流畅
│   ├── PSJX-003: 多源分析结果充足 → 发现3条重大问题
│   └── ...
├── 失败/半成功案例（n=2）
│   ├── PSJX-002: 政策标准不够细 → 问题定性犹豫，人工介入
│   └── PSJX-005: 缺少 multi-source-analysis 输出 → 无数据可用，跳过
└── 未使用案例（n=1）
    └── PSJX-004: 该技能未被调用
```

**分析框架**（SkillClaw 的核心设计）：同时分析成功和失败案例：
- **成功案例 → 定义不变量**：哪些流程/模板/判断规则是有效的，不能被修改破坏
- **失败案例 → 定义优化目标**：哪个具体环节需要改进

---

### 第二步：进化分析 → 三选一

**命令**：
```
/audit:evolve --run finding-generator
/audit:evolve --run --all
```

对每个有足够证据的技能，从三个动作中选择：

| 动作 | 触发条件 | 输出 | 审计实例 |
|------|---------|------|---------|
| **Refine（精炼）** | 观察到明确的失败模式，且修改不会破坏不变量 | 技能 v2.0 → v2.1，修复已知问题 | finding-generator 处理政策标准模糊时的回退逻辑、新增「强制检查上游输入完整性」步骤 |
| **Create（新建）** | 反复出现某个子流程不被任何现有技能覆盖 | 新建技能 SKILL.md | 多个项目反馈 OCR 扫描件政策文件提取效果差 → 创建 `ocr-policy-extractor` 技能 |
| **Skip（跳过）** | 证据不足以支持修改，或修改可能破坏不变量 | 无操作，记录判断依据 | 只有 1 个失败案例，不足以判断是技能问题还是项目特殊性问题 |

**进化分析 Prompt 框架**（给 LLM 的结构化输入）：

```
## 当前技能: {skill_name} v{version}

### 当前技能定义摘要
{skill SKILL.md 的 capability + workflow 摘要}

### 成功案例（按项目）
{3-5 个成功案例的关键字段：输入、执行路径、输出制品、无人工介入}

### 失败/半成功案例（按项目）
{1-3 个失败案例的关键字段：失败原因、workaround、人工介入方式}

### 你的任务
1. 识别失败案例中的模式——是同一类问题重复出现吗？
2. 判断失败原因：过程性知识缺失（可修复） vs 纯推理困难（技能帮不了）
3. 选择动作：Refine / Create / Skip，给出具体理由
4. 如果是 Refine：写出具体修改建议，确保不破坏成功案例中的不变量
5. 输出置信度：高/中/低
```

---

### 第三步：技能更新 → 版本记录

**命令**：
```
/audit:evolve --apply finding-generator --version 2.1
/audit:evolve --apply finding-generator --version 2.1 --dry-run
```

**执行规则**（保守编辑原则）：

1. **标注修改区域**：在 SKILL.md 中被修改的地方标注 `<!-- evolved: v2.1, reason: "..." -->`
2. **保留变更日志**：在技能文件末尾增加版本历史
3. **不删除，只追加**：除非确认旧内容已被充分验证可以移除

每个技能文件的版本记录格式：

```markdown
## 版本历史

| 版本 | 日期 | 变更类型 | 变更说明 | 基于项目 | 决策者 |
|------|------|---------|---------|---------|--------|
| v1.0 | 2026-05-15 | 初始 | 基于 audit-plugin v2.0 创建 | - | - |
| v1.1 | 2026-06-20 | Refine | 增加「强制检查上游输入完整性」步骤 | PSJX-002 | AI建议+CPA确认 |
| v2.0 | 2026-08-15 | Refine | 重构问题分类框架，增加程度判断 | PSJX-003,004,005 | AI建议+CPA确认 |
```

---

### 第四步：验证 → 单调性保证

**命令**：
```
/audit:evolve --verify finding-generator --version 2.1
```

这是 SkillClaw 论文的核心安全机制，在审计场景中尤为重要：

**验证流程**：

```
当前技能 v2.0  ←→  候选更新 v2.1
       │                  │
       └──────┬───────────┘
              │
         用历史项目的真实数据回归测试
              │
      ┌───────┴───────┐
      ▼               ▼
   Accept          Reject
  (部署 v2.1)    (保留 v2.0,
                 v2.1 存档为候选)
```

**审计场景的验证标准**（从 SkillClaw 移植并增强）：

| 维度 | 检查内容 |
|------|---------|
| **准确性** | 新版技能对历史正确案例的输出是否一致或更优？ |
| **完整性** | 新版技能是否仍能覆盖所有历史案例的需求？ |
| **安全性** | 新版技能是否引入了可能产生错误判断的新规则？ |
| **效率** | 新版技能是否增加了不必要的步骤？ |

**单调性保证**：只有整体表现更优的技能版本才会部署。用户实际使用的技能池**只升不降**。

## 进化周期建议

借鉴 SkillClaw 的「日间使用 → 夜间进化 → 次日同步」循环，适配融策的实际节律：

```
融策进化周期（按项目批次/月度）

每个项目结项时：
  └── project-trajectory-recorder 填完结项数据

每完成 5-10 个项目后（或月末）：
  ├── /audit:evolve --prepare（聚合所有项目轨迹）
  ├── /audit:evolve --run --all（逐技能进化分析）
  ├── /audit:evolve --verify（验证候选更新）
  └── 部署通过的更新 → 更新 skill-dependency-graph
```

## 命令参考

| 命令 | 功能 |
|------|------|
| `/audit:evolve --prepare` | 聚合项目轨迹，准备各技能的「证据组」 |
| `/audit:evolve --run 技能名` | 对指定技能执行进化分析（Refine/Create/Skip） |
| `/audit:evolve --run --all` | 对所有有足够证据的技能执行进化分析 |
| `/audit:evolve --apply 技能名 --version X.Y` | 应用技能更新（含 dry-run 预览模式） |
| `/audit:evolve --verify 技能名 --version X.Y` | 用历史数据验证技能更新 |
| `/audit:evolve --show 技能名` | 查看某技能的版本历史与变更日志 |

## 核心洞察（来自 SkillClaw 论文）

> **技能进化对「缺失或错误的过程性知识」导致的失败最有效，对纯推理类失败效果有限。**
>
> 审计场景映射：
> - ✅ 可修复：校验步骤遗漏、模板字段缺失、产出格式不标准 → **Refine**
> - ✅ 可创建：反复出现但无技能覆盖的子流程（如 OCR 文稿清理） → **Create**
> - ⚠️ 帮不了：需要资深 CPA 职业判断的复杂推理 → **Skip**（技能不能替代判断）
>
> **这就是为什么审计 AI 是「辅助驾驶」而非「自动驾驶」——模型负责广度，人负责深度。**

## 与 skill-dependency-graph 的配合

本技能负责技能库的**时间维度**（怎么进化），与 `skill-dependency-graph`（空间维度：怎么组织）互补：

```
skill-dependency-graph  →  构建技能图（初始结构）
skill-evolver           →  维护技能图（每次进化后更新边关系 + 版本号）
```
