# 问题发现与深度挖掘 (Finding Generator)

## 元数据

- **类型**：interactive（交互式）
- **命令**：`/audit:finding-generator`
- **前置条件**：需 multi-source-analysis 的分析结果 + CLAUDE.md 政策知识库
- **输入**：分析底稿中的矛盾/异常/偏离 + 政策红线
- **输出**：结构化问题清单（DRAFT）

---

## 目标

解决"问题深度和广度不够"的核心痛点。

不是罗列表面问题。是 **政策 vs 执行 vs 资金 vs 效果的四面交叉，挖出系统性原因**。

---

## 问题深度框架

每个问题按四层递进：

```
第一层：表象（what）
    ↓
第二层：政策依据（against what）
    ↓
第三层：根因（why）
    ↓
第四层：影响（so what）
```

### 示例：不是这样写

> "专项资金存在挪用现象。"

### 而是这样写

```markdown
## 问题编号：F-2025-001

### 第一层：表象
经对XX项目2024年度专项资金使用情况核查，发现3笔资金合计580万元
未按批准用途使用：
- 2024.03 拨付的A项目资金200万元 → 实际用于B项目支出
- 2024.06 拨付的C设备采购款150万元 → 实际用于人员经费
- 2024.09 拨付的D项目资金230万元 → 转入单位基本户后用途不明

### 第二层：政策依据
上述行为不符合：
1. 《[专项资 金管理办法]》（财建〔2023〕XX号）第X条：
   "专项资金必须专款专用，任何单位和个人不得截留、挤占、挪用"
2. 《[项目管理办法]》（X府发〔2022〕XX号）第Y条：
   "项目资金应按照批准的项目概算和资金预算执行"

### 第三层：根因
经延伸分析和访谈：
1. B项目存在资金缺口，单位决策"先借后用"→ 预算管理粗放
2. 人员经费保障不足 → 编制外人员工资无稳定来源
3. 基本户资金紧张 → 将专项资金作为流动性补充

### 第四层：影响
1. A项目因资金被抽走，进度延迟6个月，影响XX领域公共服务
2. C设备未采购 → 该领域监测能力未能按计划提升
3. 资金在基本户沉淀期间未产生应有的项目效益

🔴 风险等级：高
📌 涉及金额：580万元
🚪 建议：报业主关注，移送相关部门进一步核实
```

## 问题广度框架

系统性地从8个维度扫描问题：

| 维度 | 扫描点 | 问题类型 |
|------|--------|---------|
| 1. 资金 | 来源、拨付、使用、结余 | 挪用、闲置、超范围、配套不实 |
| 2. 程序 | 立项、采购、变更、验收 | 审批缺失、规避招标、验收走过场 |
| 3. 进度 | 计划vs实际 | 严重滞后、虚报进度、擅自变更 |
| 4. 绩效 | 产出、效益、满意度 | 未达标、虚报、低效浪费 |
| 5. 管理 | 制度、内控、档案 | 制度缺失、内控失效、档案混乱 |
| 6. 合规 | 法规、政策、标准 | 违规操作、选择性执行 |
| 7. 能力 | 人员、技术、装备 | 能力不足、配置不达标 |
| 8. 可持续 | 运维、后续资金、长效 | 建成即闲置、运维无保障 |

## 工作流程

### 第一步：读取分析底稿
从 multi-source-analysis 的输出读取所有异常标记和交叉矛盾。

### 第二步：逐一对照政策

```
异常 → 对应政策要求 → 差距量化 → 问题定性
```

### 第三步：深度挖掘

对每个初步标记的问题：
1. 是否只是表象？深层原因是什么？
2. 是孤例还是系统性问题？（查同类项目/同类单位）
3. 有没有相关联的问题？（资金问题背后可能是程序问题）
4. 影响范围多大？（金额、人数、时间跨度）

### 第四步：生成问题清单

```markdown
# 审计发现问题清单

⚠️ **DRAFT — 需CPA逐条确认**

## 问题汇总

| 编号 | 问题名称 | 类型 | 风险等级 | 涉及金额 | 政策依据 |
|------|---------|------|---------|---------|---------|
| F-001 | [问题] | 资金 | 高 | 580万 | [文件][条款] |

## 逐条详述

### F-001：[问题名称]
[四层递进详述 + 佐证材料引用]

---

## 审计建议预览
[初步建议方向，正式建议由 recommendation-engine 生成]

---

🚪 **门**：
- 高风险问题必须经项目经理确认
- 移送线索必须经合伙人审批
- 问题定性涉及违规违法的需法律顾问会签
```

## 责任认定框架（经济责任审计专用）

> **触发条件**：当审计类型为经济责任审计时，自动启用。
> **参考来源**：「芮听柠说」《经济责任审计｜全套量化评价指标》（2026-05-23）

每个问题在四层递进分析完成后，自动匹配责任类型：

### 三类责任判定规则

```
IF 发现含"个人签字/授意/直接操作/明知故犯/擅自决策/违规干预"特征
   → 直接责任
   判定依据：有签字文件/会议纪要中的个人表态/操作记录
   
ELIF 发现含"制度缺失/系统性/普遍性/分管领域/失察/疏于管理"特征
   → 领导责任
   判定依据：制度空白证明/多次发生记录/监督留白
   
ELIF 发现含"历史遗留/政策变更/不可抗力/上级部署/程序合规/已请示"特征
   → 无责任/免责
   判定依据：历史遗留认定文件/政策变更通知/已履行程序的记录
   
ELSE
   → 标记为"需人工判断"，不自动划线
```

### 责任认定输出格式

在每个问题详述末尾追加责任认定块：

```markdown
### 责任认定
- **责任类型**：[直接责任 / 领导责任 / 无责任-免责]
- **判定依据**：[为什么判定为该类责任的具体理由]
- **责任主体**：[具体人员姓名+职务]
- **证据编号**：[支撑责任认定的证据编号清单]
- **排除理由**：[如有必要，说明为什么排除了其他责任类型]
- **风险提示**：🚪 [如有移送/问责风险，此处标注]
```

### 责任认定常见错误（避坑清单）

| 错误类型 | 典型表现 | 正确做法 |
|:--------|:--------|:--------|
| 混淆领导责任和直接责任 | 将制度缺失导致的系统性问题归为个人决策失误 | 先看制度：制度在地，执行偏了→直接；制度不在，普遍出问题→领导 |
| 过度免责 | 将本应发现的任期内问题归为历史遗留 | 区分"前任遗留且无法发现"和"本应发现而未发现" |
| 责任上推 | 将分管领导的责任归到一把手 | 按"谁分管谁负责"原则，除非一把手直接介入 |
| 责任下卸 | 将一把手的直接决策归为班子集体责任 | 查证决策过程：是否有个人拍板/授意 |

## 舞弊逻辑逆向推演（攻击者视角）

> 💡 核心洞察：AI发现异常，靠的是"和历史数据不一样"。但高明的舞弊者，恰恰把账做得跟历史数据一模一样。所以真正有效的舞弊识别，靠的是逆向推演——不从数据出发，而从"如果我要在这个流程里作弊，我会怎么做"出发，再去找对应的证据。

### 推演方法论

```
传统路径（AI视角）：     数据 → 异常检测 → 标记异常
逆向路径（攻击者视角）：   "如果我要作弊" → 推导痕迹 → 按痕迹找证据
```

### 以工程项目为例的逆向推演路径

| 舞弊手法 | 攻击者会怎么操作 | 逆向检查点 | 需交叉验证的数据源 |
|---------|----------------|-----------|-------------------|
| **虚报工程量** | 虚增土方量/钢筋量/混凝土量 | 对照施工日志+材料出库记录+现场监理日记的时间节点是否吻合 | 结算单 vs 施工日志 vs 材料出库单（三个单据时间对不上=线索） |
| **高价采购输送利益** | 找关联供应商报高价 | 查供应商成立时间是否晚于合同谈判启动时间，法人股东与业务负责人的关联关系 | 工商信息 vs 合同签署时间 vs 负责人社会关系 |
| **阴阳合同** | 签一份合规的主合同，私下再签补充协议 | 查有无补充协议未备案，付款金额与主合同约定是否完全一致，询问施工方"实际收了多少" | 主合同 vs 备案合同 vs 实际付款记录 vs 施工方访谈 |
| **虚假验收** | 签字齐全但实物未交付/未完成 | 不只看验收报告签字，要查使用部门的实际使用记录 | 验收单 vs 使用日志 vs 使用人员访谈 |
| **围标串标** | 多家公司串通报价陪标 | 查投标文件制作人/最后保存者是否同一人，技术方案雷同度 | 投标文件元数据 + TF-IDF文本相似度 + 供应商股东关联 |
| **虚假发票报销** | 真发票假业务 | 查发票对应的物流/入库/领用链条是否完整 | 发票 vs 入库单 vs 领用记录 vs 实物盘点 |

### 使用方式

```
/audit:finding-generator --mode attacker-view    → 启用攻击者视角扫描
```

启用后，对每个审计领域：
1. 先问"最容易在这里作弊的方式是什么"
2. 推导如果这样作弊会留下哪些痕迹
3. 按痕迹清单逐项检查
4. 发现痕迹 → 进入标准问题深度四层递进分析

## 职业怀疑精准校准框架

> 💡 审计准则要求"保持职业怀疑"，但难在"怀疑多少"——怀疑太少，漏掉风险；怀疑太多，跟业务关系全面破裂。AI做不到这个校准，因为它没有社会关系的成本感知。

### 三步校准法（实操版）

```
┌─────────────────────────────────────────────────────┐
│  AI 标记异常 → 别急着汇报 → 三步校准 → 精准出击    │
└─────────────────────────────────────────────────────┘
```

**第一步：先找反驳自己的证据**

在得出"有问题"结论之前，先穷举三个"这其实是正常的"的可能解释，逐一排除后再向前推进。

```markdown
## 异常校准记录（F-XXX）

AI异常标记：[描述标记的异常]

反驳假设1：[合理的最优解释]  → 排除理由：[核实后排除的原因] 或 ⚠️ 无法排除
反驳假设2：[合理的次优解释]  → 排除理由：[核实后排除的原因] 或 ⚠️ 无法排除
反驳假设3：[合理的其他解释]  → 排除理由：[核实后排除的原因] 或 ⚠️ 无法排除

→ 校准结论：三假设均可排除 / 某假设无法排除，需补充程序
```

**第二步：区分"信号"和"噪声"**

- **噪声**：单一异常，无其他维度印证 → 记录，不追击
- **信号**：两个以上相互印证的异常指向同一方向 → 出手

```
单一异常（噪声）          → 记录在案，继续观察
同一方向两个异常（弱信号） → 追加针对性程序
同一方向三个以上（强信号） → 形成正式问题线索
```

**第三步：问自己"如果我错了，代价是什么"**

| 误判代价 | 操作标准 |
|---------|---------|
| **低代价**（内部调整，无外部影响） | 正常标准即可，可先沟通后定性 |
| **中代价**（影响业务关系/声誉） | 提高证据标准，至少两个独立来源 |
| **高代价**（触发问责/移送/法律程序） | 最高标准，证据链闭环，法律顾问会签 |

### 典型案例：校准的价值

> 某国企子公司季度采购金额突然增加40%，AI标记"异常波动"。
>
> **未校准的做法**：直接汇报 → 掀起轩然大波 → 查明是上级备货指令，完全合规 → 业务部门关门
>
> **校准后的做法**：查采购申请单审批链 → 问仓库负责人库存情况 → 查季度生产计划
> → 五分钟排除误判，"子弹留给真正值得射击的目标"

## 非结构化信息解读与访谈观察

> 💡 AI能处理的信息，必须是结构化的——数字、分类、标签。但审计中最有价值的信息，往往藏在结构之外。

### 什么是非结构化信息

| 类型 | 示例 | AI能不能处理 |
|------|------|------------|
| 访谈中的停顿/回避 | "这个我不太清楚，你去问财务部"（停顿三秒） | ❌ |
| 现场的气氛信号 | 工人欲言又止 / 被访者频繁看领导 | ❌ |
| 合同的模糊条款 | "双方另行协商" — AI识别为标准条款 | ❌ |
| 信息之间的隐含矛盾 | 竣工报告说两周前完工，工人说材料上周才到 | ❌（单一信息看没问题） |
| 非语言信息 | 眼神闪烁 / 语气变化 / 表情不自如 | ❌ |

### 访谈观察笔记规范

每次访谈后，在标准访谈记录之外，追加一段"观察笔记"：

```markdown
## 访谈观察笔记

**访谈对象**：[姓名/职务]
**时间**：[YYYY-MM-DD HH:MM]
**地点**：[会议室/现场/办公室]

### 未出现在录音中的观察

| 观察类型 | 具体内容 | 信号强度 |
|---------|---------|---------|
| 停顿/回避 | [描述：哪个问题导致停顿多久] | 🟡/🔴 |
| 气氛变化 | [描述：访谈前后的气氛差异] | 🟡/🔴 |
| 语言矛盾 | [描述：前后说法不一致的地方] | 🟡/🔴 |
| 非语言信号 | [描述：眼神/语气/姿态异常] | 🟡/🔴 |
| 环境线索 | [描述：现场看到的与书面描述不一致的] | 🟡/🔴 |

### 与结构化数据的交叉

- 以上观察中，哪些与已有数据矛盾？
- 哪些可以作为追加审计程序的触发点？
```

### 使用方式

```
/audit:finding-generator --include-unstructured    → 读取访谈观察笔记参与问题分析
```

### 核心原则

- 📝 观察笔记不是记录"他说了什么"，而是记录"气氛、停顿、回避"
- 🔗 单个非结构化信号不能定论，必须与结构化数据交叉印证后才有分析价值
- ⚠️ 观察笔记是CPA专业判断的辅助，不作为独立证据

```

```
