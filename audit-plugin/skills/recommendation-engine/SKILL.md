# 可落地建议生成 (Recommendation Engine)

## 元数据

- **类型**：interactive（交互式）
- **命令**：`/audit:recommendation-engine`
- **前置条件**：需 finding-generator 的问题清单
- **输入**：结构化问题清单
- **输出**：分类分级的可落地建议方案（DRAFT）

---

## 目标

解决"建议不可落地"的痛点。

不是写"加强管理""完善制度"这类废话。是 **告诉对方具体怎么做、谁来做、什么时候完成、做不到怎么办**。

---

## 建议质量框架

### 不可落地的建议（反面教材）

> "建议加强专项资金管理，完善内部控制制度。"
> 
> 问题：谁加强？怎么加强？什么标准算加强？不可考核。

### 可落地的建议（正面案例）

```markdown
## 建议编号 R-2025-001（对应问题 F-2025-001）

### 一、立即整改事项（15日内）

1. **退回挪用资金**
   - 责任单位：XX局
   - 具体动作：将挪用的580万元于X月X日前退回原项目专户
   - 依据：《专项资金管理办法》第X条
   - 验证方式：查看专户银行回单

2. **追补缺失审批**
   - 责任单位：XX局财务科
   - 具体动作：对3笔资金调整事项补办审批手续
   - 依据：《预算管理办法》第Y条
   - 验证方式：查看补充审批文件

### 二、制度整改事项（30日内）

1. **建立专项资金台账制度**
   - 建议：XX局建立专项资金"一项目一专账"，逐笔登记来源和使用
   - 模板：附《专项资金台账模板》（见附件）
   - 监管：每季度报主管部门备案

2. **分离岗位职责**
   - 建议：将资金审批岗与支付岗分离，设立专户对账人
   - 具体：由财务科A负责审批、B负责支付、C负责对账

### 三、长效机制建议（3-6个月）

1. **预算编制改革**
   - 建议：将编外人员经费纳入下年度部门预算
   - 路径：XX局向财政局报送人员经费缺口报告
   - 时间窗口：在2026年部门预算编制时同步调整

2. **内部审计常态化**
   - 建议：每半年开展一次专项资金内部审计
   - 方式：可联合第三方机构执行
```

## 建议分类框架

| 类型 | 时限 | 特征 | 示例 |
|------|------|------|------|
| **立即整改** | 15-30天 | 明确违规，限期纠正 | 退回资金、补办审批 |
| **制度整改** | 30-90天 | 系统性缺陷，建制度 | 出台管理办法、分离岗位 |
| **长效机制** | 3-12个月 | 需要多部门协同 | 预算改革、信息化建设 |
| **移送处理** | 按程序 | 涉嫌违纪违法 | 移送纪检监察/司法机关 |

---

## 可落地性检查清单

每条建议必须通过以下检查：

```
□ 明确了责任主体（哪个单位、哪个科室、谁）
□ 给出了具体动作（做什么、怎么做）
□ 标注了时间要求（什么时间前完成）
□ 说明了政策依据（为什么这么做）
□ 提供了验证方式（怎么检查是否做到）
□ 考虑了实施障碍（有没有阻力？如何克服？）
□ 给出了不执行的后果
```

## 工作流程

### 第一步：读取问题清单
从 finding-generator 输出读取所有问题。

### 第二步：问题→建议映射

```
问题类型      → 建议方向         → 具体建议
─────────────────────────────────────────────
资金挪用      → 退回+制度+追责    → [具体方案]
程序违规      → 纠正+补程序+防再犯 → [具体方案]
进度滞后      → 赶工+调整+问责    → [具体方案]
绩效不达标    → 整改+监测+考核    → [具体方案]
内控缺失      → 建制度+分岗位+审计 → [具体方案]
能力不足      → 培训+引进+外包    → [具体方案]
```

### 第三步：考虑实施约束

建议时自动考虑以下现实约束：
- 📅 **财政预算周期**：涉及资金调整的建议需对齐预算编制窗口
- 🏛️ **行政层级**：超出被审计单位权限的建议标注"建议上级统筹"
- 👥 **人员能力**：考虑单位实际可调配的人力资源
- ⚖️ **法规空间**：建议必须在现有法规框架内
- 🔄 **多部门协调**：需要多部门配合的建议明确牵头单位和配合单位

### 第四步：生成建议方案

```markdown
# 审计建议方案

⚠️ **DRAFT — 需CPA逐条确认**

## 一、立即整改类（X条）
[R-001 ~ R-XXX]
[每条含：动作、责任、时限、依据、验证]

## 二、制度整改类（X条）
[R-XXX ~ R-XXX]

## 三、长效机制类（X条）
[R-XXX ~ R-XXX]

## 四、移送处理类（如有）
[移送建议、依据、路径]

## 五、建议落实路线图

| 序号 | 建议 | 责任单位 | 时限 | 前置条件 | 验证节点 |
|------|------|---------|------|---------|---------|

## 六、被审计单位可能提出的异议及应对
[预判对方的辩解和应对策略]
```

---

## 参数

```
/audit:recommendation-engine                       → 基于问题清单生成
/audit:recommendation-engine --urgent-only          → 只生成立即整改类
/audit:recommendation-engine --full                 → 含落实路线图和异议应对
```

---

## 质量标注

- 📌 每条建议标注对应的政策依据和问题来源
- 🔍 可行性评估标注置信度（高=有成功先例/低=创新建议）
- ⚠️ 整体 DRAFT — 建议是否采纳由业主决定
- 🚪 移送处理类建议必须经合伙人和法律顾问审批
