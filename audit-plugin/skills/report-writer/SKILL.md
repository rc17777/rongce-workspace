# 报告与汇报材料生成 (Report Writer)

## 元数据

- **类型**：interactive（交互式）
- **命令**：`/audit:report-writer`
- **前置条件**：需完整的底稿和问题清单
- **输入**：所有底稿 + 问题清单 + 建议方案 + CLAUDE.md
- **输出**：审计报告 + 汇报材料

---

## 目标

将审计发现和建议转化为专业的审计报告和汇报材料。

报告三要素：
1. **事实清楚**：基于底稿，每个判断有据可查
2. **依据充分**：每个问题定性引用具体政策条款
3. **建议可行**：每条建议可落地、可考核

---


## 汇报材料生成

### PPT 大纲

```markdown
# 审计汇报 PPT 大纲

## 第1页：封面
- 项目名称 + 汇报单位 + 日期

## 第2页：审计概况
- 审计背景与目的（1-2句话）
- 审计范围（时间/范围/资金）
- 审计方法与实施情况

## 第3页：总体评价
- 总体判断（1-2句话）
- 分维度评分（资金/程序/绩效/管理）

## 第4-8页：主要问题
- 每个问题1页：事实+数据+政策依据+影响
- 用图表展示（金额占比、趋势、对比）

## 第9-11页：审计建议
- 分类展示：立即整改 / 制度整改 / 长效机制
- 标注责任单位和时限

## 第12页：总结与后续
- 关键风险提示
- 后续建议工作安排
```

### 汇报话术生成

```markdown
## 汇报要点提示

### 开场（1分钟）
[自动生成开场白：审计背景+核心结论]

### 问题汇报要点
- 最严重的问题先说（按风险等级排序）
- 每个问题用"是什么→为什么→怎么办"结构
- 关键数据要口头重复强调

### 应对预判
- 对方可能反驳的点 + 准备好的回应
- 对方可能推卸责任的点 + 准备好的追问
```

## 经济责任审计报告专用模板

> **类型**：`--type econ-responsibility`，用于国企/事业单位工程领域经济责任审计。
> **参考来源**：「芮听柠说」《经济责任审计｜全套量化评价指标》（2026-05-23）

经济责任审计报告在标准框架基础上，新增第五章「履职评价」，是经责审计区别于其他审计类型的核心章节。

### 经责审计报告框架

除标准报告的第一至六章外，新增/调整如下：

```markdown
# XX同志任期经济责任审计报告

⚠️ **DRAFT — 需CPA复核确认**

## 一、审计概况
（同标准框架，增加：被审计人姓名/职务/任职期间/分管领域）

## 二、被审计单位基本情况
（同标准框架）

## 三、审计评价（替换标准框架的第三章）

### 3.1 量化评分总览

| 维度 | 编码 | 权重 | 得分 | 得分率 | 等级 |
|------|------|------|------|--------|------|
| 重大经济决策履职 | A | 30% | XX/30 | XX% | [优秀/良好/合格/不合格] |
| 工程管控履职 | B | 25% | XX/25 | XX% | [等级] |
| 资金资产绩效 | C | 25% | XX/25 | XX% | [等级] |
| 合规风控及整改 | D | 12% | XX/12 | XX% | [等级] |
| 廉洁自律履职 | E | 8% | XX/8 | XX% | [等级] |
| **合计** | — | **100%** | **XX/100** | **XX%** | **[等级]** |

> 等级标准：≥90优秀 | 75-89良好 | 60-74合格 | <60不合格

### 3.2 重大经济决策履职评价（权重30%）

**得分：XX/30 | 等级：[等级]**

**主要成效：**
- [从底稿提取的正面事实]

**存在不足：**
- [对应扣分项，含具体事实/金额/数据]

### 3.3 工程管控履职评价（权重25%）
[同上结构]

### 3.4 资金资产绩效评价（权重25%）
[同上结构]

### 3.5 合规风控及整改评价（权重12%）
[同上结构]

### 3.6 廉洁自律履职评价（权重8%）

⚠️ **撰写红线**：无确凿线索不随意定性廉洁问题。

[标准表述]："本次审计未发现XX同志在……方面存在以权谋私、违规插手干预工程项目等行为。"

### 3.7 综合评价

[不超200字的总结段，遵循5条撰写红线]

## 四、审计发现的问题

### 4.1 问题与责任认定对照表

| 编号 | 问题名称 | 严重度 | 对应指标 | 责任类型 | 责任人 |
|------|---------|--------|---------|---------|--------|
| F-001 | [问题] | 严重 | 招投标管理(B) | 直接责任 | XX |
| F-002 | [问题] | 一般 | 内控制度(E) | 领导责任 | XX |

### 4.2 直接责任问题详述
[从 finding-generator 提取，含四层递进]

### 4.3 领导责任问题详述
[同上]

### 4.4 免责事项说明
[如有免责情形，在此说明]

## 五、审计建议
（同标准框架，增加责任单位/责任人/整改时限）

## 六、被审计人意见
[被审计人签署意见]

## 附件
- 附件1：经济责任审计量化评分表
- 附件2：审计发现问题汇总表
- 附件3：责任认定汇总表
- 附件4：政策依据索引表
```

### 撰写红线自动检查（Post-generation Lint）

报告生成后，自动扫描以下5条红线：

| 红线 | 检查规则 | 处理方式 |
|:----|:--------|:--------|
| 1. 绝对化表述 | 匹配："完全合规""毫无问题""履职完美""百分之百到位" | ⚠️ 自动替换为"总体合规""基本到位""整体良好" |
| 2. 责任夸大/弱化 | 责任类型措辞与责任等级一致性校验 | ⚠️ 标记需人工复核 |
| 3. 无数据支撑 | 检测"总体较好""较为规范"后2句内无数字 | ⚠️ 提示补充数据 |
| 4. 问题评价脱节 | 发现清单ID vs 评价段落引用交叉比对 | 🛑 发现未引用问题，自动插入 |
| 5. 廉洁定性过重 | 匹配："存在廉洁问题""有廉政风险""涉嫌违纪违法" | 🛑 自动替换为"未发现个人违规违纪线索" |

## 参数

```
/audit:report-writer                         → 生成完整审计报告
/audit:report-writer --type econ-responsibility → 生成经济责任审计报告（含履职评价章节）
/audit:report-writer --format ppt            → 生成汇报PPT大纲
/audit:report-writer --script                → 生成汇报话术
/audit:report-writer --draft                 → 征求意见稿
/audit:report-writer --final                 → 正式稿（合并征求意见回复）
/audit:report-writer --summary               → 摘要版（1-2页）
/audit:report-writer --lint                  → 撰写红线自动检查
```

## 报告质量标准

- 📌 每个问题定性必须引用对应底稿编号（可追溯到分析来源）
- 📌 每个判断必须引用政策依据（文件+文号+条款）
- 🔍 数字和金额必须与底稿一致
- ⚠️ 报告标注 DRAFT — 意见类型和最终结论需CPA确认
- 🚪 **门**：审计结论、移送建议需经合伙人和法律顾问审批

## 签字前结论可靠性检验（四问自检）

> 💡 AI可以给你一份分析报告，但它不能在报告上签字。它不能承担"我判断这是重大风险"这句话后面的职业责任。审计意见的本质，是一个有资质的人，用自己的职业声誉为一个判断背书——这件事不可以外包给机器。

在签字或出具意见前，对自己问四个问题：

### 自检清单

```markdown
## 结论可靠性自检

### 问1：我的结论，能用证据链完整支撑吗？
- [ ] 每一个关键判断，都有独立的、可核实的证据支持
- [ ] 证据不是来自单一来源——至少两个独立来源指向同一方向
- [ ] 证据链的每个环节都有对应的底稿编号可追溯

### 问2：我考虑过最强的反对意见了吗？
- [ ] 如果有人要反驳我，他们最有力的论据是什么？
- [ ] 我能回应这个论据吗？（不能 → 补充证据或调整结论）
- [ ] 我对"这其实是正常的"的可能解释逐一核查并排除了吗？

### 问3：我的结论受到了外部压力的影响吗？
- [ ] 领导的态度有没有影响我的判断？
- [ ] 业务部门的情绪有没有让我回避某些问题？
- [ ] 项目进度的紧迫感有没有让我降低证据标准？
- [ ] 如果没有任何外部压力，我的结论会一样吗？

### 问4：如果三年后被复查，我的结论和过程经得起检验吗？
- [ ] 三年后有人翻出这份报告，我能说得清当时为什么这样判断吗？
- [ ] 当时的证据是否都妥善归档保存？
- [ ] 如果三年后的事实证明我当时判断有误，我的审计过程本身有没有过失？
```

### 使用方式

```
/audit:report-writer --self-check    → 生成报告后自动触发四问自检
```

### 核心原则

- 📝 这不是形式——是签字的后果。如果你签了字出了事，这四问的答案就是你的"尽职免责"依据
- 🔗 四问全部通过后，报告从 DRAFT → READY FOR SIGNATURE
- 🚪 任何一问答不上来 → 回到 upstream（finding-generator / multi-source-analysis）补充程序

## 依赖技能

- `multi-source-analysis` — 提供分析底稿（含五维交叉验证结果）
- `finding-generator` — 提供结构化问题清单（含逆向推演+校准结果）
- `recommendation-engine` — 提供建议方案
- `economic-responsibility-evaluator` — 经责审计专用（可选）
- `policy-digest` — 提供政策依据库
