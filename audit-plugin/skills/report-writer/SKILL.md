# 报告与汇报材料生成 (Report Writer)

## 元数据

- **类型**：interactive（交互式）
- **命令**：`/audit:report-writer`
- **前置条件**：需完整的底稿和问题清单
- **输入**：所有底稿 + 问题清单 + 建议方案 + CLAUDE.md
- **输出**：审计报告 + 汇报材料

---

## 目标

将审计发现和建议转化为专业的审计报告和汇报材料。

报告三要素：
1. **事实清楚**：基于底稿，每个判断有据可查
2. **依据充分**：每个问题定性引用具体政策条款
3. **建议可行**：每条建议可落地、可考核

---

## 报告结构

### 标准政府专项审计报告框架

```markdown
# XX项目审计报告

⚠️ **DRAFT — 需CPA复核确认**

## 一、审计概况

### 1.1 审计依据
[政策文件依据 + 委托依据]

### 1.2 审计范围
[时间范围/单位范围/资金范围]

### 1.3 审计方法
[采用的方法组合]

### 1.4 审计实施情况
[现场工作时间/查阅资料数量/访谈人数/核查金额等]

## 二、被审计项目基本情况

### 2.1 项目概况
[从 CLAUDE.md 和查阅资料提取]

### 2.2 资金来源与到位情况
[从 multi-source-analysis 提取]

### 2.3 项目实施情况
[从 multi-source-analysis 提取]

## 三、审计评价

[对整体情况的评价，分维度打分或定性]

## 四、审计发现的问题

### 4.1 [问题领域1]
[逐条详述，每条含：事实+依据+影响]

### 4.2 [问题领域2]
[可配图表辅助说明]

## 五、审计建议

### 5.1 立即整改事项
[从 recommendation-engine 提取]

### 5.2 制度完善建议
[从 recommendation-engine 提取]

### 5.3 长效机制建议
[从 recommendation-engine 提取]

## 六、被审计单位意见
[征求意见稿回复情况]

## 附件
- 附件1：审计发现问题汇总表
- 附件2：政策依据索引表
- 附件3：[其他]
```

## 汇报材料生成

### PPT 大纲

```markdown
# 审计汇报 PPT 大纲

## 第1页：封面
- 项目名称 + 汇报单位 + 日期

## 第2页：审计概况
- 审计背景与目的（1-2句话）
- 审计范围（时间/范围/资金）
- 审计方法与实施情况

## 第3页：总体评价
- 总体判断（1-2句话）
- 分维度评分（资金/程序/绩效/管理）

## 第4-8页：主要问题
- 每个问题1页：事实+数据+政策依据+影响
- 用图表展示（金额占比、趋势、对比）

## 第9-11页：审计建议
- 分类展示：立即整改 / 制度整改 / 长效机制
- 标注责任单位和时限

## 第12页：总结与后续
- 关键风险提示
- 后续建议工作安排
```

### 汇报话术生成

```markdown
## 汇报要点提示

### 开场（1分钟）
[自动生成开场白：审计背景+核心结论]

### 问题汇报要点
- 最严重的问题先说（按风险等级排序）
- 每个问题用"是什么→为什么→怎么办"结构
- 关键数据要口头重复强调

### 应对预判
- 对方可能反驳的点 + 准备好的回应
- 对方可能推卸责任的点 + 准备好的追问
```

---

## 参数

```
/audit:report-writer                     → 生成完整审计报告
/audit:report-writer --format ppt        → 生成汇报PPT大纲
/audit:report-writer --script            → 生成汇报话术
/audit:report-writer --draft             → 征求意见稿
/audit:report-writer --final             → 正式稿（合并征求意见回复）
/audit:report-writer --summary           → 摘要版（1-2页）
```

---

## 报告质量标准

- 📌 每个问题定性必须引用对应底稿编号（可追溯到分析来源）
- 📌 每个判断必须引用政策依据（文件+文号+条款）
- 🔍 数字和金额必须与底稿一致
- ⚠️ 报告标注 DRAFT — 意见类型和最终结论需CPA确认
- 🚪 **门**：审计结论、移送建议需经合伙人和法律顾问审批
