# 审计底稿生成 (Work Paper Generator)

## 元数据

- **类型**：interactive（交互式）
- **命令**：`/audit:work-paper`
- **前置条件**：需 multi-source-analysis 的分析结果 + finding-generator 的问题清单
- **输入**：所有前置分析结果
- **输出**：标准化审计底稿（DRAFT）

---

## 目标

将分析过程和结论转化为规范的审计底稿。

底稿是审计报告的基础——必须做到：**别人拿了底稿能复现你的分析过程**。

---

## 底稿结构标准

按照审计底稿的"三要素"标准：

```
1. 程序执行记录（做了什么、怎么做、什么时候做）
2. 检查发现（发现了什么、金额多少、问题性质）
3. 审计结论（结论是什么、依据是什么）
```

---

## 底稿类型

| 类型 | 内容 | 对应分析 |
|------|------|---------|
| **综合类底稿** | 审计方案、重要性判断 | implementation-plan |
| **分析类底稿** | 财务分析、数据分析 | multi-source-analysis |
| **检查类底稿** | 凭证抽查、合同查阅 | multi-source-analysis |
| **访谈类底稿** | 访谈记录、要点提取 | multi-source-analysis |
| **实地类底稿** | 现场勘查记录、照片 | multi-source-analysis |
| **问题类底稿** | 问题汇总、定性依据 | finding-generator |
| **建议类底稿** | 管理建议、整改方案 | recommendation-engine |

---

## 工作流程

### 第一步：读取所有前置分析结果

从 CLAUDE.md 和各 skill 输出读取：
- 审计方案 → 综合类底稿基础
- 分析底稿 → 分析类/检查类底稿基础
- 问题清单 → 问题类底稿基础
- 建议方案 → 建议类底稿基础

### 第二步：逐类生成底稿

```markdown
# 审计底稿

⚠️ **DRAFT — 需CPA逐份复核**

---

## 底稿索引

| 编号 | 名称 | 类型 | 页数 | 编制人 | 复核人 | 日期 |
|------|------|------|------|--------|--------|------|

---

## WP-A-001：审计方案

### 审计程序
[从 implementation-plan 提取]

### 方案调整
[如有调整，记录调整原因和审批]

### 审计结论
方案已按程序审批，外勤工作按方案执行。

编制人：AI Agent | 复核人：[项目经理]

---

## WP-B-001：财务数据分析

### 审计程序
1. 获取科目余额表及明细账
2. 执行趋势分析和比率分析
3. 识别异常波动的科目
4. 对异常科目追加检查程序

📌 数据来源：[文件路径]，数据期间：[期间]

### 分析过程
[从 multi-source-analysis 提取]

### 异常发现
[列表]

### 审计结论
[结论]

编制人：AI Agent | 复核人：[CPA]

---

## WP-C-001 ~ WP-C-XXX：问题类底稿

### 问题编号 F-XXX

#### 审计程序
[为发现此问题执行的程序步骤]

#### 事实描述
[从 finding-generator 提取]

#### 判断依据
📌 [政策文件+条款]

#### 审计结论
[问题定性]

编制人：AI Agent | 复核人：[项目经理]

---

*每个底稿独立成页，含交叉索引，便于复核人追踪分析链条。*
```

### 第三步：交叉索引

自动建立底稿间的引用关系：

```
WP-B-001 分析底稿 → 标记异常 → WP-C-001 问题底稿 → 引用 WP-B-001
WP-C-001 问题底稿 → 提出建议 → WP-D-001 建议底稿 → 引用 WP-C-001
```

---

## 参数

```
/audit:work-paper                        → 生成全部底稿
/audit:work-paper --type 问题             → 只生成问题类底稿
/audit:work-paper --index WP-C-001       → 只生成指定编号底稿
/audit:work-paper --format excel          → 生成Excel格式底稿
```

---

## 底稿质量标注

- 📌 每个底稿标注程序执行时间、数据来源、分析工具
- 🔍 AI 判断标注置信度，CPA 复核确认后签字
- ⚠️ 每个底稿标注编制人（AI Agent）和复核人（留空待签）
