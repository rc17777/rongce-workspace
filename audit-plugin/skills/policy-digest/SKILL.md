# 政策文件解读 (Policy Digest)

## 元数据

- **类型**：interactive（交互式）
- **命令**：`/audit:policy-digest`
- **核心价值**：解决"政策文件吃不透"的痛点
- **输入**：政策文件（PDF/Word/网页/扫描件）
- **输出**：结构化政策知识库 → 写入 CLAUDE.md

---

## 目标

将一堆政策文件转化为结构化、可检索、可用于审计判断的"政策知识库"。

不是简单的文件摘要。是 **提取审计可用信息**——即能够用于判断"是否合规"的标准和红线。

---

## 工作流程

### 第一步：文件摄入

```
/audit:policy-digest D:\项目\政策文件\
/audit:policy-digest 文件1.pdf, 文件2.pdf           → 指定文件
/audit:policy-digest --append 新文件.pdf             → 增量追加
```

支持格式：PDF、Word、扫描件（OCR）、网页链接

### 第二步：结构化提取

对每个文件逐层提取：

#### 第一层：文件基本信息
- 文件名称、文号、发文机关、发文日期、生效日期
- 是否现行有效
- 文件层级（法律/行政法规/部门规章/规范性文件/地方文件）

#### 第二层：关键条款提取（审计视角）

| 提取维度 | 提取内容 | 为什么审计需要 |
|---------|---------|--------------|
| **资金管理** | 资金来源、配套比例、拨付流程、使用范围、禁止事项、结余处理 | 判断资金使用合规性 |
| **项目程序** | 立项审批、招投标门槛、变更程序、验收标准 | 判断程序合规性 |
| **时间节点** | 各环节时限要求、截止日期 | 判断进度合规性 |
| **绩效指标** | 产出指标、效益指标、满意度 | 判断绩效达标情况 |
| **禁止/红线** | 明确禁止的行为和后果 | 零容忍问题清单 |
| **罚则** | 违规后果和处罚措施 | 问题定性和建议依据 |

#### 第三层：交叉关联
- 同一事项在不同文件中的规定是否一致
- 上位法和下位法的关系
- 新旧文件的替代/补充关系
- 不同部门文件的要求是否存在冲突

### 第三步：生成政策知识库

输出到 CLAUDE.md 的"政策知识库"部分：

```markdown
## 一、政策知识库

### 1.1 核心政策文件清单
[自动生成文件清单表]

### 1.2 关键政策要求提取
[按维度结构化提取]

### 1.3 政策红线
[零容忍问题清单，每条标注来源]

### 1.4 政策引用索引
[问题+依据的快速检索]
```

### 第四步：生成检查清单

基于政策要求，自动生成审计检查清单：

```markdown
## 审计检查清单（自动生成）

### 资金类
- [ ] 配套资金是否按时足额到位？ 依据：[文件][条款]
- [ ] 资金使用是否在允许范围内？ 依据：[文件][条款]
- [ ] 拨付是否在规定时限内？ 依据：[文件][条款]
- [ ] 结余资金是否按规定处理？ 依据：[文件][条款]

### 程序类
- [ ] 立项审批程序是否完整？ 依据：[文件][条款]
- [ ] 招投标程序是否合规？ 依据：[文件][条款]
- [ ] 项目变更是否按程序报批？ 依据：[文件][条款]
- [ ] 验收是否按标准执行？ 依据：[文件][条款]

### 绩效类
- [ ] 产出指标是否完成？ 依据：[文件][条款]
- [ ] 效益指标是否达到？ 依据：[文件][条款]
```

---

## 关键能力

### 1. 政策对比
```
/audit:policy-digest --compare 新旧文件
```
自动对比新旧政策差异，标注变化点。

### 2. 跨文件矛盾标注
如果两个文件对同一事项有不同要求，自动标注并提示风险。

### 3. 增量更新
```
/audit:policy-digest --update
```
新文件加入后只分析新增/变化内容，不重读已有文件。

---

## 输出质量标注

- 所有提取内容标注：📌 来源：[文件名][第X条]
- 置信度标注：🔍 高（原文明确）/ 中（理解推断）/ 低（需人工确认）
- 不确定的地方标注：[待确认] 供CPA确认
