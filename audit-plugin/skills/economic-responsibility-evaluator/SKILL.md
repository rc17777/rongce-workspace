# 经济责任审计量化评价 (Economic Responsibility Evaluator) v2.0

## 元数据

- **版本**：v2.0（整合版）
- **类型**：interactive（交互式）
- **命令**：`/audit:econ-responsibility`
- **前置条件**：需 multi-source-analysis 的分析结果 + finding-generator 的问题清单
- **输入**：结构化审计发现列表 + 被审计人基本信息
- **输出**：量化评分卡 + 责任认定表 + 履职评价初稿 + 报告片段

## 目标

将经济责任审计从"凭经验定性"变为"标准化量化评价"。

核心能力：
1. **被审计对象分类**：7+1类（工程/行政事业/商业竞争/公益功能/特定功能/金融/科技创新 + 自定义）
2. **自动评分**：根据对象类型自动选择指标体系，映射发现到指标并计算加权总分
3. **责任认定**：自动区分直接责任/主管责任/领导责任（三级）+ 免责排除
4. **撰写合规**：生成履职评价初稿，5条红线自动检查
5. **报告集成**：输出完整七段式经责审计报告，可直接嵌入 report-writer

## 工作流程

### 第零步：被审计对象分类（强制步骤 ★）

在评分前，必须先确定被审计对象的类型，自动选择对应的指标体系。

**七种对象类型 + 自定义**：

| 类型编码 | 对象类型 | 核心权重维度 | 最高权重项 | 指标数 |
|:--------|:--------|:-----------|:---------|:-----:|
| `project` | 工程项目负责人 | 决策履职30% | 立项/招投标合规率各8% | 17项 |
| `gov` | 行政事业单位 | 决策25%+财务25% | 三重一大执行率8% | 19项 |
| `commercial` | 商业竞争类 | 盈利能力35% | 净资产收益率15% | 12项 |
| `welfare` | 公益功能类 | 服务效能35% | 服务覆盖率15% | 12项 |
| `functional` | 特定功能类 | 任务完成度30% | 重大项目按期完成率15% | 12项 |
| `financial` | 金融类 | 资产质量30% | 不良资产率12% | 13项 |
| `innovation` | 科技创新类 | 创新产出30% | 专利+成果转化各10% | 12项 |
| `custom` | 自定义 | 手动配比 | — | 自定义 |

完整决策树、各类型指标体系详情 → `knowledge/references/经济责任审计-融策整合模板v2.0.md`

### 第一步：读取审计发现

从 finding-generator 的问题清单读取所有已发现的审计问题，提取：
- 问题编号 / 问题名称
- 严重度（红线/严重/一般/关注）
- 涉及金额
- 问题领域

### 第二步：维度映射

根据第零步确定的类型编码，自动加载对应指标体系，将每条审计发现映射到具体的二级/三级指标。

### 第三步：计算评分

**统一评分规则**（所有类型适用）：
- 基准分+加减分：达标准则满分，有问题按评分标准扣分（最低0分）
- **一票否决6种情形**：重大国有资产流失 / 重大安全生产事故 / 重大违法违纪 / 财务造假 / 个人廉洁违规 / 小金库
- 等级：≥90优秀 | 75-89良好 | 60-74合格 | <60不合格
- 定量指标≥总分70%
- 定性评分区分四类调整因素：历史遗留 / 不可抗力 / 战略调整 / 特殊使命

### 第四步：责任认定（三级制 ★v2.0更新）

```
判定规则链（按顺序执行，先排除→再判定→兜底）：

0. 免责排除检查（四条同时满足）：
   IF 问题属于历史遗留（前任任职期间形成）
      AND 本人已履行正常程序且留痕
      AND 不存在失职渎职行为
      AND 本人已积极采取措施推动解决
   → 无责任/免责

1. 直接责任判定：
   IF 本人签字批准/直接操作/授意/明知故犯 → 直接责任
   IF 本人违规干预/擅自决策 → 直接责任

2. 主管责任判定（★v2.0新增）：
   IF 对分管领域未能有效监管/制度建设有缺陷/审批把关流于形式 → 主管责任
   IF 问题属于分管领域 AND 非直接操作 AND 非主观故意 → 主管责任

3. 领导责任判定：
   IF 作为单位主要负责人 AND 系统性/普遍性问题 → 领导责任
   IF 宏观层面履职不到位 → 领导责任

4. 兜底：
   → 标记为"需人工判断"
```

### 第五步：生成履职评价初稿

按以下结构输出：

```markdown
## 履职评价（DRAFT — 需CPA复核确认）

### 量化评分总览
[评分表格]

### 分维度评价
[5段，每段含：得分/主要成效/存在不足/具体事实]

### 责任认定汇总
[责任认定对照表，含三级责任+免责排除说明]

### 综合评价
[遵循5条红线的总结段，≤200字]
```

### 第六步：撰写红线自动检查

```python
REDLINE_RULES = [
    {"id": 1, "name": "绝对化表述",
     "pattern": r"完全合规|毫无问题|履职完美|百分之百|零问题",
     "fix": "替换为'总体合规/基本到位/整体良好/基本达标'",
     "method": "regex"},
    {"id": 2, "name": "责任夸大/弱化",
     "check": "语义交叉比对：问题性质→责任措辞，是否匹配三级标准",
     "fix": "严格匹配直接/主管/领导三级责任判定标准",
     "method": "semantic"},
    {"id": 3, "name": "无数据支撑",
```

## 完整报告框架（七段式 v2.0）

参考 `knowledge/references/经济责任审计-融策整合模板v2.0.md` Layer 1：

一、基本情况 → 二、主要经济指标完成情况 → 三、审计发现的主要问题 → **四、定量评价(核心)** → 五、审计评价意见 → 六、审计处理处罚建议 → 七、审计整改要求 + 6个附件

## 参数

```
/audit:econ-responsibility                        → 基于已有发现生成完整评价
/audit:econ-responsibility --type <code>           → 指定对象类型(A/B/C/D/E/F/G/H)
/audit:econ-responsibility --score-only            → 只输出量化评分卡
/audit:econ-responsibility --responsibility-only   → 只输出责任认定表
/audit:econ-responsibility --evaluation-draft      → 只输出履职评价初稿
/audit:econ-responsibility --lint                  → 对已有评价文本做撰写红线检查
/audit:econ-responsibility --export-excel           → 导出评分表到Excel
/audit:econ-responsibility --full-report            → v2.0新增：生成完整七段式报告
```

## 质量要求

- 📌 每个扣分点必须绑定对应的审计发现编号
- 📌 每个责任认定必须标注判定依据 + 排除理由
- 🔍 评计算需输出计算过程（不只有结果）
- ⚠️ 整体标注 DRAFT — 最终等级和定性需CPA确认
- 🚪 不合格/一票否决/移送建议设门
