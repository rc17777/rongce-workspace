## 核心问题分析

### 工作区配置自动生成机制

**触发条件（推测）**：
- UI 切换模型操作
- Gateway 启动/重启
- 某些配置读取失败时的fallback机制
- 桌面端应用启动

**生成内容**：
```json
{
  "providers": {
    "deepseek": {
      "apiKey": "DEEPSEEK_API_KEY",  // ← 环境变量引用，不是硬编码
      "baseUrl": "https://api.deepseek.com/v1",
      ...
    }
  }
}
```

**问题**：
1. 自动生成频率极高（今晚10次）
2. 默认使用环境变量引用而非硬编码
3. 覆盖主配置的正确设置
4. 无法通过常规方法禁用

### 配置优先级

```
工作区配置 (models.json) > 主配置 (openclaw.json)
```

这导致即使主配置正确，工作区配置一旦出现就会覆盖。

### 环境变量的陷阱

**问题链**：
```
工作区配置引用 DEEPSEEK_API_KEY
  ↓
OpenClaw 进程启动时环境变量不存在
  ↓
apiKey 获取到 null 或空字符串
  ↓
HTTP 401 Authentication Fails
```

**为什么设置环境变量后仍失败**：
- Gateway restart 不刷新进程环境变量
- 必须完全重启 OneClaw 应用（退出 + 重新启动）

### 只读锁定的失败

**设想**：设置配置文件为只读，防止被自动覆盖

**现实**：
- OpenClaw 需要写入配置文件（临时文件 → 重命名）
- 只读权限阻止了所有写入操作
- 导致 EPERM 错误，影响正常功能

## 🎓 核心教训与最佳实践

### 教训 1：顺应设计，不要对抗

**错误思路**：
- OpenClaw 用环境变量 → 我们改成硬编码
- 工作区配置自动生成 → 我们反复删除/锁定

**正确思路**：
- OpenClaw 设计用环境变量 → 我们就设置环境变量
- 进程需要重启才能读取新环境 → 我们就完全重启应用

### 教训 2：环境变量的生命周期

```
环境变量设置
  ↓
进程启动时读取（一次性）
  ↓
进程运行期间不更新
  ↓
需要重启进程才能读取新值
```

**关键区别**：
- 配置文件：可以热重载（gateway restart）
- 环境变量：必须冷启动（应用重启）

### 教训 3：配置层级与优先级

```
工作区配置 (D:\openclaw-workspace\models.json)
  ↓ 覆盖
主配置 (C:\Users\scrccpa\.openclaw\openclaw.json)
```

工作区配置会自动生成，优先级更高，无法轻易禁用。

### 教训 4：Gateway restart ≠ 应用重启

| 操作 | 效果 | 适用场景 |
|-----|------|---------|
| gateway restart | 热重载配置文件 | 配置文件修改 |
| 应用完全重启 | 冷启动，重新读取环境 | 环境变量修改 |

**今晚的致命错误**：设置了环境变量，但只执行 gateway restart，没有完全重启应用。

### 教训 5：baseUrl 格式要求

OpenAI 兼容 API 的 baseUrl 必须以 `/v1` 结尾：

```json
❌ "baseUrl": "https://api.deepseek.com"
✅ "baseUrl": "https://api.deepseek.com/v1"
```

这是第4轮才发现的隐藏问题，不在常规 HTTP 401 排查清单中。

### 教训 6：只读锁定的危险

**设想**：锁定配置文件防止被覆盖
**现实**：导致 EPERM 错误，影响正常功能

OpenClaw 需要写入配置文件（临时文件→重命名），只读权限会破坏这个流程。

## 🎓 核心教训（13条）

### 配置管理

**1. 配置有层级，优先级要清楚**
```
工作区配置 > 主配置
```

**2. 工作区配置会自动生成**
- 触发条件：UI切换模型、应用启动等
- 频率：今晚13次
- 内容：默认使用环境变量引用

**3. 删除 > 修改**
- 修改工作区配置会被还原
- 删除后强制使用主配置更可靠

### 环境变量

**4. 环境变量的生命周期**
```
进程启动时读取 → 运行期间不更新 → 需要重启进程
```

**5. Gateway restart ≠ 应用重启**
- Gateway restart：热重载配置
- 应用重启：冷启动，重新读取环境

**6. 用户级环境变量可能无效**
- OneClaw进程可能无法读取用户级环境变量
- 可能需要系统级环境变量（需管理员权限）
- 硬编码密钥更可靠

### API配置

**7. baseUrl格式要求**
```
OpenAI兼容API必须以/v1结尾
```

**8. 独立测试API很重要**
- 用Python/curl直接调用API
- 排除OpenClaw配置问题
- 快速定位问题所在

### 模型切换

**9. 当前会话的模型不会中途改变**（⚠️ 关键）
- 切换模型后，当前对话仍用旧模型
- 必须新开对话或刷新页面
- 第11轮失败就是因为这个

**10. 切换不报错 ≠ 真的在用**
- 没有401错误只说明认证通过
- 要看实际回复才能确认模型

### 故障排查

**11. 不要只看表面错误**
- 401错误有多种原因：配置覆盖、baseUrl错误、环境变量失效
- 要系统排查所有可能的配置层级

**12. 不要对抗系统设计**
- OpenClaw设计用环境变量→不要强行改硬编码（前期错误思路）
- 工作区配置会自动生成→不要试图锁定（第10轮失败）
- 顺应设计更容易成功

**13. 持续失败时要换思路**
- 前10轮都在对抗工作区配置
- 第13轮换思路：删除工作区配置+用主配置硬编码
- 结合了两种方案的优点
