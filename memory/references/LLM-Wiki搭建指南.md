# LLM Wiki：手把手搭建自我生长的知识库

> 来源: 公众号「能力进化笔记」 | 抓取日期: 2026-05-22
> 核心参考: Karpathy LLM Wiki Gist

## 核心理念

**LLM Wiki ≠ RAG**：RAG是检索已有文档拼答案，LLM Wiki是编译知识、建关联页面。

| 对比维度 | RAG | LLM Wiki |
|---------|-----|----------|
| 工作方式 | 检索→拼接 | 摄入→理解→创建跨主题关联 |
| 知识状态 | 文档孤岛 | 有链接、有图谱、有演化 |
| 更新机制 | 人工维护 | AI主动健检，提示矛盾/过时 |

## 四类典型场景

| 场景 | 痛点 | Wiki 解法 |
|------|------|----------|
| 多项目管理 | 信息散落在周报/会议/微信/人脑 | 摄入周报→识别人员/技术依赖/供应商→跨项目关联 |
| 内容创作 | 收藏几百篇，写的时候找不到 | 按话题跨来源综合回答 |
| 持续学习 | 零散输入，不成体系 | 每次摄入让系统更完整，三个月后自动浮现答案 |
| 快变领域跟踪 | 认知过时不自知 | 健检主动提示矛盾、过时内容 |

## 技术栈

- **Claude Code**（或 Codex CLI / kimi-cli）
- **Obsidian**（浏览界面 + 关系图谱）
- **CLAUDE.md**（系统规则文件，定义摄入/查询/健检规范）

## 目录结构

```
MyWiki/
├── raw/           ← 原始资料（只读）
│   ├── topic-a/
│   ├── topic-b/
│   └── ...
├── wiki/          ← LLM维护的知识页面
│   ├── topic-a/
│   ├── topic-b/
│   ├── index.md   ← 目录
│   └── log.md     ← 操作日志
└── CLAUDE.md      ← 系统规则
```

## 7步搭建流程

1. **安装 Claude Code**
2. **建目录结构**（raw/ + wiki/ + CLAUDE.md）
3. **生成 CLAUDE.md**：定义主题域、页面类型、摄入/查询/健检规范
4. **初始化 index.md + log.md**
5. **第一次摄入**：放资料→AI建议生成页面→确认→自动创建+更新索引
6. **第二次摄入**：观察跨页面关联更新（复利效应）
7. **Obsidian 看关系图谱**（Graph View）

## 三个持续习惯

1. **遇到好内容当天放进去**，别攒——攒着是知识库死亡的第一原因
2. **问了好问题，把答案存回 wiki**——每次探索都在给知识库加料
3. **每 20 个页面做一次健检**——查矛盾/孤立/过时，小错误传播很快

## 关键设计原则

- 每个 wiki 页面只写一个概念（单概念页面产生更好的链接）
- 摄入时先给概述等确认再创建
- 每次新会话先说"读取 CLAUDE.md + index.md + log.md"快速定位状态
- Obsidian Web Clipper 一键把网页转 markdown 存入
