### 三个致命教训

#### 教训1：OCR 脚本 HTTP 超时必须设 read timeout
- `OpenAI(timeout=120)` 只设了整体超时，但流式响应中途断流时 httpx 不一定会触发
- **正确做法**：`httpx.Timeout(180, connect=30, read=180, write=60)` 精确控制每阶段
- 线程级硬超时（threading.Thread.join(timeout)）在 Windows 下不稳定，容易导致整个进程崩溃

#### 教训2：temp_ocr 目录凭空消失的诡异事件
- 搜索了 C 盘、D 盘、workspace 所有可能路径，均不存在
- 怀疑：kill PID 时可能触发了某种文件系统异常（NTFS journal？杀毒软件？）
- **防御措施**：
  1. OCR 结果应同步备份到 OneDrive（已加入 TOOLS.md 备份规则）
  2. output_new 目录应加入 git（当前在 .gitignore 外？需确认）
  3. 下次出问题时先用 `robocopy` 镜像一把再杀进程

#### 教训3：Windows Python 多线程坑
- daemon Thread + subprocess + fitz 的组合在 Windows 下不稳定
- 线程崩溃时静默退出（stderr 不重定向到日志），排查困难
- **原则**：OCR 这种 I/O 密集型任务用简单串行更稳，不要自作聪明加线程
