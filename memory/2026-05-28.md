### 技能管理与密钥管理优化

**背景：** 阅读了公众号「One的AI工具箱」文章《很多人没看懂 OpenClaw：真正拉开 Agent 差距的，不是模型，而是 workspace》，其中强调了两点：
1. `.secrets/` 文件夹绝对不能上传 GitHub 或分享给他人
2. Skills 技能管理需要规范化

**执行的操作：**

1. **新建 `.secrets/` 目录**
   - `~/.openclaw/workspace/.secrets/`
   - 子目录：`api-keys/`、`credentials/`
   - 各目录均有 README.md 说明用途和命名规范

2. **新建 `.gitignore`**
   ```
   .secrets/          ← 密钥目录
   memory/            ← 日志目录
   state/             ← 状态文件
   *.log / logs/      ← 日志文件
   *.pem / *.key      ← 密钥文件
   .env               ← 环境变量
   ```
   目的：防止意外 commit 敏感信息

3. **重构 `TOOLS.md`**
   - 新增「Secrets 管理」章节（绝对禁止事项、命名规范、使用方式）
   - 新增「Skills 技能管理」章节（安装流程、已安装技能清单、路径速查）
   - 新增「本地环境信息」章节（工作目录、Skills 目录、Secrets 目录）
   - 添加快速参考命令

4. **更新 `AGENTS.md`**
   - 新增「Secrets & Keys Security Rules」红色底线规则
   - 新增「Skills 技能管理原则」章节，引用 TOOLS.md
   - 强调密钥禁止写入共享文件

**核心原则（写入 AGENTS.md）：**
- `.secrets/` 内容禁止 commit、禁止上传 GitHub、禁止分享
- 密钥统一存放 `.secrets/api-keys/`（纯文本 .txt）
- SKILL.md 只注路径，不写内容
