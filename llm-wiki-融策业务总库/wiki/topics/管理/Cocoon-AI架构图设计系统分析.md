## 一、Cocoon-AI 设计系统拆解

### 1.1 六色语义配色体系

Cocoon-AI 为技术架构定义了7种语义色，每种对应一个技术层：

| 层级 | 颜色 | 色系 | 典型组件 |
|:----|:----|:----|:--------|
| 前端/客户端 | 🔵 青色 | Cyan | React、移动端、边缘设备 |
| 后端/服务 | 🟢 翠绿 | Emerald | API、微服务、业务逻辑 |
| 数据库/存储 | 🟣 紫色 | Purple | PostgreSQL、Redis、对象存储 |
| 云/AWS | 🟡 琥珀 | Amber | CDN、负载均衡、云服务 |
| 安全/认证 | 🔴 玫瑰 | Rose | 防火墙、加密、安全组 |
| 消息队列 | 🟠 橙色 | Orange | Kafka、RabbitMQ |
| 外部/通用 | ⚪ 石板灰 | Slate Gray | 第三方API、终端用户 |

**核心设计理念**：颜色不是装饰，是信息——看色识层。

### 1.2 输出形式

- **HTML渲染**（而非 draw.io XML 或 SVG）
- 暗色主题 + 网格背景（40px subtle grid）
- 等宽字体 JetBrains Mono
- 标题旁脉冲呼吸灯动画

### 1.3 技术亮点

| 特性 | 实现 | 效果 |
|:----|:----|:----|
| 箭头层级 | 先画箭头→再画组件（组件垫不透明背景） | 箭头不穿透组件，视觉干净 |
| 等宽字体 | 全图使用 JetBrains Mono | 技术感统一，阅读一致 |
| 网格背景 | 40px间距 subtle grid | 一眼识别为专业架构图 |
| 脉冲动画 | 标题旁呼吸灯 CSS animation | 图表"活"起来 |

### 1.4 交互模式

- **描述即所得**：自然语言 → 完整HTML图
- **对话式迭代**："把数据库改成集群""加上Redis"
- **一键导出**：PNG高清截图 / PDF / 复制到剪贴板

## 三、可借鉴改进项

### 🔴 高优先级（直接落地，效果明显）

#### 3.1 建立审计语义配色体系

Cocoon-AI 的"看色识层"理念对审计场景高度适用。需要建立的是**审计专用**的语义配色，而非照搬技术架构的配色。

**审计语义配色方案（8色）：**

| 审计概念 | 颜色 | 色值 | 适用场景 |
|:--------|:----|:----|:--------|
| **资金流/拨款** | 🟢 资金绿 | #27AE60 | 资金注入、拨付、支出、结余 |
| **问题/风险** | 🔴 风险红 | #E74C3C | 问题发现、风险点、红线、违规 |
| **整改/措施** | 🟠 整改橙 | #E67E22 | 整改建议、行动措施、追回 |
| **合规/制度** | 🔵 制度蓝 | #2980B9 | 制度要求、法规依据、政策条款 |
| **流程/程序** | 🟣 流程紫 | #8E44AD | 审计程序、业务流程、审批环节 |
| **组织/单位** | ⚪ 组织灰 | #7F8C8D | 被审计单位、部门、岗位 |
| **决策/审批** | 🟡 决策金 | #F39C12 | 决策节点、审批流程、三重一大 |
| **数据/证据** | 🟦 证据青 | #1ABC9C | 数据源、佐证材料、信息流 |

#### 3.2 引入箭头层级控制

**问题**：当前 drawio 生成的 XML 中，箭头的 mxGeometry 没有不透明背景垫层，导致大箭头可能穿透组件标签。

**改进**：
- 在 XML 中将所有 edge 节点的 `id` 集中写在 vertex 节点之前
- drawio 按 XML 中顺序渲染，先渲染的在后渲染的"下面"
- 或者：为需要避免穿透的 edge 添加 `opacity="100"` 的填充层

#### 3.3 添加网格背景

**drawio 实现**：在 mxGraphModel 层面设置 grid 属性
```xml
<mxGraphModel grid="1" gridSize="10" guides="1" ...>
```

**arch-diagrammer 实现**：在 Canvas 中添加 40px 间距的 subtle 网格（#2C3E50, opacity 0.05）

#### 3.4 等宽字体规范

**drawio**：所有 `value` 使用 Consolas（Windows 自带等宽字体，替代 JetBrains Mono）
**arch-diagrammer**：标签使用 `'Consolas, "Microsoft YaHei", monospace'`

### 🟡 中优先级（需要一定开发工作）

#### 3.5 dark/light 双主题

Cocoon-AI 的暗色主题给图表带来专业感。drawio 支持 theme 切换。

#### 3.6 对话式迭代增强

当前 drawio 的 Critic Mode 已经实现了审查→修改循环（max 3 round），但缺少"自然语言修改"的交互体验——需要用户明确说"修改节点X的背景色"，而不是"把数据库改成集群"这种自然语言。

**改进**：Critic Mode 中增加自然语言解析步骤，将用户的修改意图映射到具体的 XML 修改操作。

### 🟢 低优先级（长期考虑）

#### 3.7 HTML渲染输出方案

Cocoon-AI 的 HTML 渲染输出比 drawio XML 更轻量、渲染更快。但对于 audit-plugin 场景，drawio XML 的可编辑性是刚需（CPA 需要手动微调），不宜替换。

**策略**：保持 drawio 为主力，HTML 渲染作为快速原型/讨论用选项。

## 五、核心结论

Cocoon-AI 给融策的最大启发不是技术栈（它是HTML，我们是drawio XML，各有用处），而是两个设计思想：

1. **"看色识意"的语义配色体系** — 颜色是信息载体，不是装饰。这个思想可以直接移植到审计场景（资金绿/风险红/整改橙/制度蓝/流程紫/组织灰/决策金/证据青），让融策产出的审计图表一眼就能读懂。

2. **"描述即所得"的零摩擦交互** — 用户只需要说"在资金流中加上专项债券的流程"，不需要知道怎么操作。这个思想可以增强 drawio Critic Mode 的自然语言解析能力。
