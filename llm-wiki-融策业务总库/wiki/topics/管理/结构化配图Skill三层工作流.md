# 从「凭感觉出图」到「结构化配图」：一个图片 Skill就能解决

## 核心要点（融策适用）

1. **核心理念**：配图前先判断「这段内容应该画成什么结构」，而不是直接堆风格词
2. **7种视觉结构**：Cycle循环 / Pipeline流程 / Hub-and-spoke中心辐射 / Before-after对比 / Layer-stack分层 / Data-first数据场景 / Scientific-mechanism机制图
3. **三层出图工作流**：概念拆解Skill（画什么结构）→ 视觉规范Skill（尺寸/配色/排版统一）→ imagegen（生成）
4. **图内文字规则**：中文标签2-5字，不超6字；文字只做标记，讲道理交给正文
5. **Skill本质论**：把反复做、反复解释、反复纠正的事变成可复用的判断——不是让AI变聪明，而是让AI少忘事

## 对融策的启发

- **标书/宣传册配图**可套用同样三层：先判断结构（流程图/对比图/分层图）→ 融策品牌规范（深蓝#0A1F3F+铜金#C5955C）→ 生成
- **审计报告可视化**：审计发现天然适合Before/after（整改前后）、Pipeline（资金流向）、Hub-and-spoke（关联方网络）
- **对应现有工具**：drawio（结构图）/ huashu-design（品牌视觉）/ gpt-image-2（生图）正好构成同样的三层
- **技能治理呼应**：与2026-07-14 Skill体系三件套（场景路由/过程追踪/异步化）同一理念——判断层与执行层分离

最近我在整理自己的公众号写作流程，越来越确定一件事：真正拖慢一篇文章的，往往不是正文，而是配图。正文明明写清楚了，图一加进去，味道反而散了——有的图太像装饰，有的图太像 PPT，有的图风格不错却和文章没什么关系。最尴尬的是，它看起来很「AI」，却没有帮读者多理解一点东西。所以我给自己找了一套图片 Skill。你可以先把它理解成一个「配图前的判断框架」：它不是简单帮我画一张好看的图，而是先帮我判断——这段内容，究竟应该被画成什么结构？
这句话很关键。因为很多人第一次用 AI 做公众号配图，都会卡在同一个地方：我知道这里需要一张图，但不知道这张图应该长什么样。 于是最后写出的提示词往往很宽泛：帮我生成一张科技感的公众号配图，主题是 AI 工作流。
模型也会很配合：蓝紫渐变、发光线条、漂浮界面、一个看起来很忙但不知道在忙什么的人。看起来不差，但放进文章里没什么信息量——它只是在装饰文章，不是在解释文章。为什么还要单独做一个图片 Skill？之前我其实已经做过一个公众号配图相关的 Skill，重点是让一篇文章里的所有图片保持统一风格。比如它会规定：图放在文章哪里尺寸是 900×500 还是 900×380一张图最多出现几处中文背景、描边、配色、留白怎么统一这张图是流程图、对比图、便签卡，还是总结图它更像一个「公众号视觉规范」，解决的问题是：这篇文章需要一整套配图，怎样让它们看起来像同一个栏目？而这次这套图片 Skill，解决的是更靠前的问题：这段内容里，哪些概念值得被画出来？它应该画成流程、循环、分层、对比，还是图表？也就是说，之前那个 Skill 偏「风格统一」，这次这个偏「概念可视化」——一个管外观是否统一，一个管结构是否成立。这两个问题经常被混在一起，但实际做内容的时候最好分开，因为一张图如果结构选错了，风格再统一也只是统一地没用。它到底做了什么我看了一下这套 Skill 的说明，它的工作方式大概分三步：先读文章、截图、数据或产品概念；再判断哪些地方值得配图；最后给每个概念选择合适的视觉结构。它内置了一些常用结构，比如：Cycle：适合表达循环、反馈、迭代Pipeline：适合表达流程、步骤、转化Hub-and-spoke：适合表达一个中心连接多个分支Before/after：适合表达升级前后、变化前后Layer stack：适合表达架构、层级、依赖关系Data-first scene：适合把数据图表放进更具体的场景Scientific mechanism：适合解释科学机制、结构、反应过程这些词听起来有点抽象，但实际很有用。因为 AI 出图最难的往往不是写风格词——不是「3D」「极简」「材质感」「柔和光影」这些词不够，真正难的是，你要先知道这张图承担什么信息任务。比如同样是写「Skill」：如果想解释 Skill 怎么运行，更适合用 Pipeline：用户需求 -> 匹配 Skill -> 读取规则 -> 执行任务 -> 检查结果

这才是配图真正的价值。它不是让文章更花，而是让读者少花 10 秒理解你在说什么。我现在会把出图分成三层以前我做配图，脑子里只有一个问题：这张图好不好看？现在我会把它拆成三层。第一层是imagegen，负责真正生成图片。你给它提示词，它把图画出来——它像一台能力很强的打印机，但前提是你得给它一份靠谱的图纸。第二层是我之前做的公众号配图 Prompt Skill，负责把一篇文章包装成统一视觉系统。它会关心图片尺寸、中文数量、构图、安全边距、公众号里的阅读节奏——它像一个视觉编辑，确保整篇文章不要东一张西一张。第三层就是这次这套图片 Skill，负责判断内容应该被画成什么结构。它不只是问「好不好看」，而是先问：这个概念应该怎样被看懂？它更像一个信息设计师。这三层组合起来，工作流就变得很清楚：文章内容

三层工作流：概念拆解、配图规范、图片生成这样出图就不再像凭感觉抽卡，而是先有内容判断，再有风格规范，最后才进入图像生成。一个具体例子假设我写一篇文章，标题叫《我给自己做了一个公众号写作 Skill》。如果直接让 AI 出图，提示词可能会变成：生成一张关于 AI 写公众号文章的插画，风格简洁，适合公众号。
这大概率会得到一张很常见的图：一个人在电脑前写文章，旁边漂着 AI 图标。不是不能用，只是太泛了，没有把这篇文章真正想说的东西画出来。如果换成这套图片 Skill 的思路，它会先把文章概念拆开：·痛点：每次写文章都要重新讲风格
·方法：把写作经验沉淀成 Skill
·变化：从临时指令变成可复用工作流
·结果：选题、结构、语气、交付变稳定
然后它会判断，这里最适合做的是 Before/after 或 Layer stack。比如 Before/after 可以这样画：左边：临时提示词堆在一起，文章风格忽高忽低
右边：写作 Skill 作为中枢，把选题、标题、结构、语气、排版串起来
以前是装饰图，现在是解释图这个画面就比「一个人在电脑前写文章」更有信息量，因为它把文章的核心观点画出来了：Skill 的价值不是替你写一次，而是把你反复需要的判断固化下来。
我最喜欢的一条规则这套 Skill 里有一条规则我很喜欢：图里的文字要短。 它建议中文标签最好 2-5 个字，通常不要超过 6 个字。这和我自己做公众号配图时的感受完全一致。很多 AI 配图失败，不是因为画得丑，而是因为图里塞了太多字——一张图如果出现五六段解释文字，那它就已经不是图了，只是把文章换了个背景重新贴了一遍。真正好的配图，应该让读者一眼知道：哪个是中心、哪个是输入、哪个是输出、哪个是变化、哪些东西互相连接。文字只做标记，不负责讲完所有道理——讲道理这件事交给正文，图片只负责把结构照亮。它适合哪些内容我觉得这套图片 Skill 特别适合四类内容。第一类是工具教程，比如 Codex、Cursor、Claude Code、n8n、Dify、Coze 这类工具型内容。工具教程里经常有流程、角色分工、输入输出，很适合做成 Pipeline 或 Layer stack。第二类是方法论文章，比如「如何搭建自己的 AI 工作流」「如何把提示词变成 Skill」「如何让 AI 输出更稳定」。这类内容如果只用文字写，很容易显得虚；一旦画成 Before/after、循环图、中心辐射图，读者就更容易抓住重点。第三类是数据和报告。 它的说明里专门提到，可以处理图表截图、表格、指标、benchmark 结果，重点不是照抄原图的颜色和样式，而是提取数据关系，再重新做成更适合传播的图。这点很重要，因为很多报告截图本来是给电脑屏幕看的，不是给手机公众号看的——公众号里的图，必须更克制、更大字、更少元素。第四类是科普和教育内容，比如生物、化学、物理机制，或者小学课文、人文历史类内容。这类内容最怕两种极端：要么太抽象，要么太花哨。一个好的图片 Skill，应该能帮你在中间找到平衡：既有画面，又不乱编。我会怎么用它以后我要给一篇文章做配图，大概率不会一上来就让 AI 直接画，而是分三步走。第一步，让这个新 Skill 先读文章，告诉我这篇文章最值得画的 4-6 个概念是什么，每个概念适合什么图形结构。第二步，再用我之前的公众号配图 Prompt Skill，把这些图统一成一套公众号尺寸和风格——比如封面图、节内说明图、流程图、总结图分别怎么排。第三步，最后才调用imagegen。这时候给它的就不是一句模糊需求，而是一份更具体的图纸，比如：为公众号文章生成一张 900×420 横版 Before/after 对比插画。
主题：装图片 Skill 前后，AI 配图从随机装饰变成结构化解释。
左侧标题「凭感觉出图」，表现为零散提示词、风格不统一、图片只做装饰。
右侧标题「结构化配图」，表现为文章内容进入 Skill，被拆成流程图、分层图、对比图，再输出统一插画。

这和一句「帮我画张科技感配图」完全不是一个级别。前者是在描述一个信息结构，后者只是在描述一种气氛。再看一下新旧风格的区别为了让这个区别更直观，我又用之前那个公众号配图 Skill 的风格，把其中两个主题重新生成了一组。这里不再额外增加新的对比图，只把旧风格和新风格放在同一行里看。你会发现，它们不是「哪个好看、哪个不好看」的关系，而是两种不同的表达语言：旧风格更像「手绘知识笔记」——轻、亲切、有随手整理的温度，适合经验分享和轻教程；新风格更像「材质感解释图」——更立体、更模块化，更适合工具拆解、流程说明和方法论表达。第一组：从笔记感到结构感

这一组讲的是三层工作流：旧版本更像把自己的经验摊开给读者看，有笔记感，也更像一个创作者在边做边整理；新版本则更像一个已经被产品化的流程——每一层都有边界，每一步都有产物，适合解释「我现在是怎么系统化做配图的」。所以它们不是谁替代谁，只是文章要表达的重心变了，配图风格也要跟着变。但它也不是万能的我也要说一句实话：这套图片 Skill 目前还不是一个全自动的素材工厂，它更像一套配图前的判断框架。它能帮我判断这段内容适合做流程图、对比图、分层图还是数据图，但具体到每张图，还是需要继续打磨提示词、控制文字数量、检查画面有没有跑偏。如果真要稳定用于公众号，我可能还会继续补几类规则：公众号封面图规则小节配图规则中文标签失败后的重试规则多张图的统一配色规则生成后如何质检和返工不过这也正是 Skill 好玩的地方，它不是一次写完就结束，更像一块可以持续打磨的工作台：用一次，发现一个问题，补一条规则；再用一次，再补一条。最后它就慢慢变成你自己的生产习惯。我现在对 Skill 的理解又变了一点一开始我把 Skill 理解成「让 Codex 多一种能力」，现在觉得这个说法还不够准确。Skill 更像是：把你反复做、反复解释、反复纠正的事情，变成一套可复用的判断。
写作 Skill 是这样，图片 Skill 也是这样。它们不是让 AI 突然变聪明，而是让 AI 少忘事、少走弯路、少在每一次新任务里重新摸索你的偏好。对内容创作者来说，这件事很重要，因为我们真正想要的不是一张临时好看的图，而是一个可持续的内容系统：选题能积累标题能迭代文章有稳定语气图片有统一表达排版不用每次重来经验能沉淀成工具这也是我为什么会继续折腾 Skill——不是为了把工作变复杂，恰恰相反，是为了把那些看不见的复杂，提前收进规则里。然后下一次开始写的时候，我只需要说一句：按我的公众号写作和配图工作流来。
AI 就知道该往哪个方向走。这才是我觉得 Skill 最有价值的地方。如果你也想要这套图片 Skill，可以私聊我，我整理好之后发你。
