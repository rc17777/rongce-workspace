## FS-LDM模型

Teradata 1996年发布的金融服务逻辑数据模型（Financial Services Logical Data Model），第三范式，囊括银行约80%业务数据，已被全球多家金融机构仓库系统使用。

四个级别：主题域 → 概念 → 细节 → 逻辑视图。数字化审计中掌握主题域即可快速认知数据。

## 十大主题

| 主题 | 内容 |
|------|------|
| **当事人** Party | 服务对象和分析对象（个人/公司客户、员工、分行等） |
| **产品** Product | 可营销的交易品种集合 |
| **协议** Agreement | 与当事人之间的契约关系（账户/合同） |
| **事件** Event | 交易活动（存取款/收费/计息/查询等） |
| **资产** Asset | 客户资产/负债信息（担保品/抵质押品） |
| **财务** Finance | 总账信息/科目组织/内部核算 |
| **内部组织** Internal Org | 机构的业务单元（分行/网点/部门） |
| **地域** Location | 地址信息（国家/城市/区县+电子地址） |
| **营销** Campaign | 营销活动的策略/行为/反馈 |
| **渠道** Channel | 交互手段（柜面/网银/手机/ATM等） |

## 对审计的价值

拿到全新数据时，按这十大主题归类，思考就有了方向。核心是**结构化思维**。非金融领域（如政府数据）同样可以借鉴这个逻辑框架。

> "数据按照主题进行归并了，思考也就有了方向。"
