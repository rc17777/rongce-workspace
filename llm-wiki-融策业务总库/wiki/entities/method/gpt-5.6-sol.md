# Review: gpt-5.6-sol

Status: success

---

## 量化评审结论

**严谨度：5/10。** 架构合理，但阈值主要是经验设定，缺少标注集、基准实验、置信区间和成本回测；LLM 的 `confidence`、`high/medium/low` 尚未校准，不能直接作为概率使用。

### 1. 阈值是否合理

| 当前阈值 | 评价 | 建议初始值 |
|---|---|---|
| 孵化证据数 = 3 | 偏低。3篇转载同一上位文件并非3个独立证据 | **≥4个独立证据**，且至少2个独立发布主体、1个中央/省级权威源；采用加权证据分 |
| novelty confidence < 0.6 | 无校准依据；LLM自报置信度通常失真 | 初始进入队列 **≥0.70**；自动通知/晋级 **≥0.85**，最终仍人工确认 |
| 提案相似度 > 0.7 | 未指定嵌入模型、距离度量和文本字段，不可复现；可能误合并 | 使用“名称+描述+关键词”综合相似度；**>0.82自动合并，0.65–0.82人工复核，<0.65新建** |
| 180天窗口 | 文档中未明确出现；若用于证据聚合，统一窗口不合理 | 快变领域 **90天**，一般政策 **365天**；或采用指数衰减，半衰期180天 |
| secondary关键词 ≥2 | 可能因重复/共现造成假阳性 | 用验证集调权；建议加标题命中、词距和否定语境，阈值取使 precision≥0.9 的点 |
| ≥3条业务线为 low 触发R3 | `low` 易受模型偏置影响，且“不确定时标medium”会破坏该条件 | 改为新颖度/OOD分数或多次推理一致性；不要以弱标签数量单独触发 |
| 标题含“管理办法”等即触发 | 召回高、精度预计很低 | 增加权威来源、正文新概念/OOD、与现有分类低相似度等联合条件 |

另有逻辑不一致：R3描述为“R1+R2均无high/medium”，条件A却是“R1零命中且R2无high”，此时有 `medium` 也会触发，应统一。

### 2. 更好的校准方式

1. 建立分层金标准集：按来源、年份、文档长度、12条业务线抽样，建议先标注 **500–1,000篇**；每篇双人标注并仲裁。  
2. 时间切分回测：旧政策训练/调参，新政策测试，避免同系列文件泄漏。  
3. 分别校准各阶段：  
   - R1：每条线绘制 PR 曲线，按业务成本选择阈值，不采用统一规则。  
   - R2：将 high/medium/low 改为连续相关分，使用 temperature scaling、isotonic regression 校准。  
   - R3：评估候选级 precision@k、proposal recall；LLM自报 confidence 只作为特征。  
4. 相似度阈值用“同一候选/不同候选”配对集确定，报告 ROC/PR、误合并率和漏合并率。  
5. 用期望损失选阈值：  
   \[
   \text{阈值}=\arg\min(C_{FP}FP+C_{FN}FN+C_{review}N_{review})
   \]
6. 先 shadow run 4–8周，再锁定阈值；按月监控漂移并重校准。

### 3. 成本估算准确性与隐藏成本

“flash约500 tokens/篇、pro约1500 tokens/篇”明显偏乐观：Prompt已包含12条业务线，且要求12项JSON输出；加上正文，实际应同时核算**输入与输出token**。R3“全文”可能远超1500 tokens。

建议成本公式：

\[
C=N(C_{OCR}+C_{parse})+N(T_{in}P_{in}+T_{out}P_{out})
+Nq_3C_{pro}+C_{retry}+C_{review}+C_{storage}
\]

隐藏成本包括：

- PDF解析、OCR、表格/附件处理；
- 摘要模型或长上下文费用；
- JSON失败重试、限流、超时与模型版本切换；
- 向量嵌入、相似度检索、索引更新；
- 人工标注、孵化审核、争议仲裁；
- `radiation_signals` 无限增长导致的存储和YAML写入冲突；
- 规则维护、回归测试、监控与安全合规；
- 误分类造成的下游检索/SOP更新成本。

应报告 **每千篇总成本、P50/P95单篇成本、R3触发率、人工分钟/篇**，并做低/中/高三种情景预算。

### 4. 如何持续衡量分类准确率

采用滚动时间评估：

- 每周随机抽样，并对“零命中、低置信度、新来源、新主题”过采样；
- 双人标注，报告 Cohen’s κ 或 Krippendorff’s α；
- R1/R2是多标签分类，跟踪：micro/macro precision、recall、F1、每业务线PR-AUC、Hamming loss、subset accuracy；
- R2另跟踪相关等级的加权κ、校准误差 ECE/Brier score；
- R3跟踪：候选 precision、发现召回率、误提案率、人工接受率、发现延迟；
- 按来源、业务线、季度、模型版本切片；
- 使用30/90天滚动窗口和控制图，指标显著下降时告警；
- 保存不可变测试集，同时增加“未来时间窗”测试集以识别概念漂移。

### 5. “演化”与“积累”的区分指标

**积累**仅代表数量增加：

- 文档数、辐射次数、证据数；
- 去重后独立来源数；
- 加权证据量：\(\sum w_{source}e^{-\lambda age}\)。

**演化**应体现结构或语义发生变化：

- 新增/合并/拆分业务线率；
- 新关键词占比、主题新颖度/OOD分数；
- 业务线关键词或嵌入质心的时间漂移；
- 来源、客户、审计对象分布的 Jensen–Shannon divergence；
- 辐射网络边新增率、边权变化、模块度变化；
- 新候选晋级率和从首次信号到确认的时间；
- SOP/方法/法律依据发生实质更新的比例。

建议设立 **Evolution Score**，而不是以“被辐射N次”代替演化：

\[
E=0.3\,SemanticDrift+0.25\,StructuralChange+
0.25\,Novelty+0.2\,IndependentSourceGrowth
\]

所有分量先归一化，并通过历史人工确认事件回测权重。总体上，应将固定阈值改为**分来源、分业务线、可校准的阈值体系**。
