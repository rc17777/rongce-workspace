# Prompt 记录格式规范

## 完整 Schema

```yaml
# === 必填字段 ===
id: prompt-NNN                           # 唯一标识
标题: "简短描述这个Prompt做什么"          # 用于列表展示
场景: "绩效评价|资产清查|专项资金审计|采购审计|工程审计|财务审计|通用"
具体环节: "更细的环节描述"
标签: [标签1, 标签2, 标签3]              # 用于检索

prompt: |                                # Prompt全文（多行）
  完整的提示词内容...

# === 评分与使用 ===
效果评分: 4.5                            # 1-5分，支持小数
使用次数: 23
提交人: "姓名或代号"
提交日期: "YYYY-MM-DD"
最后使用: "YYYY-MM-DD"

# === 版本管理 ===
当前版本: "v2.1"
版本历史:
  - version: "v1.0"
    date: "2026-05-01"
    changes: "初始版本"
    rating: 3.5
  - version: "v2.0"
    date: "2026-05-15"
    changes: "增加嵌套判断逻辑处理"
    rating: 4.2
  - version: "v2.1"
    date: "2026-05-26"
    changes: "修复嵌套判断遗漏case"
    rating: 4.5

# === 可选字段 ===
模型适配:
  deepseek-v4-pro: "✅ 效果好"
  deepseek-chat: "⚠️ 有时遗漏细节"
  gemini-flash: "❌ 不推荐，理解偏差大"

使用注意事项: "需要配合合同台账和付款凭证一起使用"
前置条件: "需要先执行 policy-digest 建立政策知识库"
关联技能: [cot-capture, policy-digest]

输出格式: "JSON|Markdown表格|自然语言|结构化报告"
输出示例: |                              # 可选的输出样例
  一个典型的输出片段...
```

## 评分标准

| 分数 | 含义 | 标准 |
|------|------|------|
| 5 | 完美 | 在所有测试案例中表现优异，可直接用于生产环境 |
| 4 | 优秀 | 大部分场景表现好，偶有边界case需要人工修正 |
| 3 | 可用 | 基本满足需求，但需要较多人工干预或后处理 |
| 2 | 勉强 | 经常出错或遗漏，可能需要重新设计 |
| 1 | 不可用 | 输出质量差，建议废弃 |

## 标签体系

### 审计类型标签
`绩效评价` `资产清查` `专项资金` `采购审计` `工程审计` `财务审计` `经济责任审计` `内控审计`

### 审计环节标签
`政策解读` `方案编制` `数据提取` `数据分析` `疑点排查` `底稿生成` `报告撰写` `问题定性` `建议生成`

### 方法标签
`查阅法` `数据分析` `访谈` `实地考察` `函证` `穿行测试` `财务核查` `对比分析` `复核计算` `异常检测` `文本分析`

### 质量标签
`生产可用` `需人工复核` `实验性` `已废弃`

## 示例：一条完整的Prompt记录

```yaml
id: prompt-001
标题: 绩效评价-专项资金使用合规性检查
场景: 绩效评价
具体环节: 专项资金使用合规性-付款时间异常检查
标签: [绩效评价, 资金合规, 专项资金, 合规检查, 数据分析, 生产可用]

prompt: |
  你是一位政府审计专家，具有10年以上财政专项资金审计经验。
  
  ## 任务
  分析以下资金使用记录，重点检查付款时间的合规性。
  
  ## 检查要点
  1. 逐笔核对付款日期是否在合同约定的付款期限内
  2. 关注验收日期与付款日期的间隔是否异常短
  3. 关注年底（11-12月）大额集中付款
  4. 对比同一供应商的历史付款节奏
  
  ## 输出格式
  对每一笔可疑付款，输出：
  - 付款编号 | 付款日期 | 验收日期 | 间隔天数 | 合同约定天数 | 偏离度 | 风险等级
  
  ## 输入数据
  [粘贴资金使用明细]

效果评分: 4.5
使用次数: 23
提交人: 张三
提交日期: 2026-05-01
最后使用: 2026-06-15
当前版本: v2.1

版本历史:
  - version: v1.0
    date: 2026-05-01
    changes: 初始版本，基础付款时间对比
    rating: 3.5
  - version: v2.0
    date: 2026-05-15
    changes: 增加同一供应商历史付款节奏对比
    rating: 4.2
  - version: v2.1
    date: 2026-05-26
    changes: 增加年底集中付款标记，优化输出格式
    rating: 4.5

模型适配:
  deepseek-v4-pro: "✅ 效果好，嵌套判断准确"
  deepseek-chat: "⚠️ 复杂嵌套判断有时遗漏细节"

使用注意事项: |
  1. 需要合同台账（含付款条款）和付款凭证
  2. 如果被审计单位资金量很大，建议分批次输入（每批不超过200条）
  3. 输出中的风险等级是初步判断，需人工确认

关联技能: [cot-capture, policy-digest]
输出格式: Markdown表格
```
