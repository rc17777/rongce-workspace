# 审计作业流AI嵌入分析 (Workflow Embedder)

分析审计作业流程，找到AI"无感嵌入"的最佳节点——让AI像水电一样融入日常，而非一个需要主动打开的工具。

## 核心理念

> 文章五大基石之一：真正的智能化不应增加用户的决策成本。AI能力必须实现向审计日常行为链、工作流的无感嵌入。呼之即来挥之即去。

**目标**：审计人员不需要"切换到AI对话框"——AI在正确的时间、正确的上下文中自动触发并提供洞察。

## 工作流

### 1. 梳理作业流

```
/workflow:map [审计项目类型]
```

输出当前作业流的标准步骤，每个步骤包含：
- 输入/输出
- 执行人/角色
- 耗时/频次
- 痛点/瓶颈

### 2. 识别嵌入点

对每个步骤评估AI嵌入可行性：

| 维度 | 评估标准 |
|------|---------|
| 触发确定性 | AI能否从上下文中判断"现在该做什么"？ |
| 输入可获取性 | AI需要的数据是否已在系统中/可自动获取？ |
| 输出即用性 | AI的输出是否能直接呈现在审计人员的作业界面上？ |
| 人工确认需求 | 该环节是否需要人类确认/Gate？ |

### 3. 设计嵌入方案

对每个高可行性嵌入点，设计：
- **触发方式**：事件触发 / 定时触发 / 上下文感知触发
- **Agent/Skill链**：调用哪些能力
- **输出形态**：高亮批注 / 侧边栏提示 / 数据看板更新 / 自动填充
- **人工交互**：全自动 / 推荐+确认 / 仅提示

详见 [embedding-patterns.md](references/embedding-patterns.md)。

## 输出：嵌入方案报告

```markdown
## XX项目审计作业流AI嵌入方案

### 作业流全景
[流程图]

### 嵌入点1：收到资料 → 自动预处理
- **当前状态**：人工下载→手工分类→逐份阅读→发现问题
- **嵌入后**：Agent自动提取+分类+对照政策库高亮疑点
- **触发方式**：文件系统监控（新文件到达）
- **输出形态**：原文件旁高亮批注+疑点摘要卡片
- **涉及Skill**：policy-digest, multi-source-analysis
- **人工Gate**：不需要（仅标注，不自动定性）

### 嵌入点2：数据分析 → 异常自动标记
- **当前状态**：审计人员手工跑SQL/Python→人工判断异常
- **嵌入后**：数据更新时Agent自动跑异常检测→标记可疑记录
- **触发方式**：数据刷新触发
- **输出形态**：数据看板红色高亮+异常理由
- **涉及Skill**：data-analysis-methods, finding-generator
- **人工Gate**：不需要（标记为"待确认"）

### 嵌入点3：底稿编写 → 关键字段自动填充
...
```

## 嵌入点分类

### 🟢 全自动嵌入（无需人工Gate）
- 数据预处理/格式检查
- 政策条款自动匹配
- 异常数据标记（仅标记，不定性）
- 报告格式/排版检查

### 🟡 推荐+确认（需人工Gate）
- 问题发现建议
- 审计重点推荐
- 方法选择建议
- 底稿模板选择

### 🔴 仅提示（需人工发起）
- 问题最终定性
- 处罚建议
- 报告结论
- 与外部系统交互（发函证等）

## 与现有体系的对应

| 审计环节 | 嵌入时机 | 对应Skill |
|---------|---------|-----------|
| 政策学习 | 新政策文件入库 | policy-digest 自动触发 |
| 方案编制 | 项目创建 | implementation-plan 推荐方案 |
| 数据分析 | 数据源更新 | multi-source-analysis + data-analysis-methods |
| 问题发现 | 分析过程中 | finding-generator 自动标注 |
| 底稿编制 | 问题确认后 | work-paper 自动填充 |
| 报告撰写 | 底稿完成后 | report-writer 生成草稿 |
