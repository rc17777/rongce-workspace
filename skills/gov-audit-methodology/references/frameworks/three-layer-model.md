# 业务穿透三层模型

> 来源：#49「业务是数字化审计之本」

## 核心原理

> "全流程业务梳理的目的就是穿透业务，到达数据底层，这样才能有效地进行数字化审计。"

数字化审计的核心前提不是技术，是对业务的透彻理解。两个常见错误：
1. 一头扎进数据茫然无措 → "有吓人的线索，无落地的问题"
2. 盲人摸象新瓶装旧酒 → "隔墙扔砖头，砸到谁算谁"

## 三层穿透操作指南

### 第一层：制度流程层 → "要查什么"

目标：了解业务的基本情况、规章制度和操作流程

收集四类材料：
- **基本规范**：国标/行业标准/术语定义
- **业务手册**：产品定义/准入要求/操作流程
- **制度体系**：章程/管理制度/流程/细则
- **考核体系**：指标/权重/指标计算说明

本层输出：**政策法规清单 + 制度流程图**

### 第二层：业务环节层 → "怎么操作的"

目标：将业务按工作流分解为环节，了解每个环节的四个要素

| 要素 | 内容 | 示例（专项债申报） |
|------|------|------------------|
| 人 | 涉及的岗位 | 申报人/审核人/审批人/财政专员 |
| 信息 | 需要提供什么资料 | 可研报告/实施方案/财务评估 |
| 流程 | 具体操作步骤 | 编制→初审→专家论证→财政局报送 |
| 系统 | 使用的IT系统 | 地方政府债务管理系统 |

本层输出：**业务环节分解表（人/信息/流程/系统）**

### 第三层：业务操作层 → "数据在哪"

目标：搞清楚系统功能界面由外到里的信息

- 调用的**交易码/功能码**
- 涉及的**科目/分类**
- 产生的**数据字段**
- 数据的**存储位置**（表名/文件路径/数据库）

本层输出：**数据字典/字段映射表**

## 实战示例：绩效评价项目的三层穿透

| 层 | 内容 |
|:--|:-----|
| 制度流程 | 资金管理办法、项目管理办法、绩效考核办法、年度目标 |
| 业务环节 | 项目申报→资金拨付→项目实施→验收评估→绩效自评 |
| 业务操作 | 财政一体化系统→指标下达表→支付数据→项目台账 |

## 与三维视角的衔接

三层穿透完成后 → 用三维视角评价：
- 穿透后的流程 → 形式维度（制度是否齐全？流程是否合规？）
- 穿透后的执行数据 → 事实维度（进度如何？资金使用如何？）
- 穿透后的产出 → 价值维度（效果如何？群众满意吗？）
