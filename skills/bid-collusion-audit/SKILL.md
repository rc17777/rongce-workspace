# 政府采购串标围标审计

## ⏸️ 关键检查点（执行前必须确认）

| 步骤 | 检查点 | 确认内容 |
|------|--------|---------|
| 第二步前 | ⏸️ 数据齐全？ | 确认已拿到所有投标公司的全部标书PDF，缺一则后续分析不完整 |
| 第五步前 | ⏸️ PDF可读？ | 确认PDF有文本层还是扫描件（决定用PyMuPDF还是OCR） |
| 第七步前 | ⏸️ 调取授权？ | 需向采购中心/代理机构调取IP/CA记录，确认是否有权限获取 |
| 第九步前 | ⏸️ 证据核实？ | 铁证级发现是否已排除误报？（如同一Author可能因共用办公电脑） |

## 触发条件

当用户需要分析招投标数据、排查串标围标线索时使用。典型信号：
- "这些投标文件有没有串标嫌疑"
- "帮我看下这几家公司的投标有没有关联"
- "分析一下围标串标的可能性"

## 审计流程（九步法）

每一步标注：📥 输入 → 🔧 操作 → 📤 输出

### 第一步：项目概览梳理
- 📥 输入：招标公告、中标公告、投标人名单
- 🔧 操作：列出采购项目→列出参与公司→制作矩阵表
- 📤 输出：项目概览表 + 项目-公司矩阵

### 第二步：人员交叉匹配（铁证优先级最高）
- 📥 输入：所有标书全文文本
- 🔧 操作：提取身份证号→手机号→邮箱→跨公司交叉匹配
- 📤 输出：人员×公司交叉匹配表
- ⚠️ 身份证号相同 = 铁证（同一人代表不同公司投标）

### 第三步：籍贯/地域关系网络
- 📥 输入：第二步提取的身份证号列表
- 🔧 操作：提取身份证前6位→比对出生年月→发现同乡同年龄段聚集
- 📤 输出：嫌疑人关系图谱（籍贯+年龄维度）

### 第四步：报价分析
- 📥 输入：各公司报价表
- 🔧 操作：横向对比→偏离度计算→排序一致性检测→陪标特征识别
- 📤 输出：报价对比表+偏离度分析

### 第五步：投标文件制作痕迹比对（数字指纹）
- 📥 输入：所有PDF投标文件
- 🔧 操作：
  - ⭐ PDF元数据提取（Author、Creator、Producer、CreationDate）
  - ⭐ Author字段跨公司交叉比对（同Author做不同公司标书 = 铁证）
  - 制作时间线分析（各文件创建/修改时间的先后关系）
  - PDF制作工具链比对（WPS文字 vs Office、Chromium版本）
  - 文档属性中的公司名/作者名残留检查
- 📤 输出：Author交叉对比表 + 制作工具链比对表

### 第六步：文本内容相似度分析
- 📥 输入：投标文件服务方案、商务应答表文本
- 🔧 操作：内容相似度比对→格式雷同检测→错别字一致性比对
- 📤 输出：相似度矩阵 + 雷同特征清单
- ⚠️ 招标文件固定格式不算雷同，只比较投标人自行填写的内容

### 第七步：设备指纹追踪（如可行）
- 📥 输入：（需外部调取）招投标平台后台数据
- 🔧 操作：调取上传IP→CA数字证书记录→原始Word文档docProps→浏览器指纹
- 📤 输出：设备指纹对比表（如数据可获取）
- ⚠️ PDF元数据不含MAC/CPU/硬盘序列号，需向采购中心/代理机构调取

### 第八步：时间线重构
- 📥 输入：所有文件CreationDate/ModDate + 招标流程节点
- 🔧 操作：报名→购买标书→制作→提交→开标，按时间排列，标异常点
- 📤 输出：时间线图表

### 第九步：证据链汇总与审计建议
- 📥 输入：前八步的所有发现
- 🔧 操作：按证据强度分级（铁证>强证据>线索>异常）→输出结构化报告
- 📤 输出：审计报告Excel（6个工作表）

## 注意事项

1. **先读文件再下结论** — 不能扫一眼文件名就做判断，必须实际提取文本内容
2. **模板化 vs 雷同要区分** — 招标文件固定格式的雷同不是证据
3. **时间戳要注意时区** — PDF时间有+08'00'和+00'00'的区别
4. **Chromium生成的PDF无Author** — 这是浏览器打印PDF的特征，不是异常
5. **Windows GBK终端** — Python输出中文需要 `sys.stdout.reconfigure(encoding='utf-8')`

## 招标文件控标识别方法论

> 来源：Billy Xiao《如何从招标文件判断是否存在控标？》
> 适用场景：政府采购/工程招标/企业采购审计中，判断招标文件是否被控标

### 一、技术参数审查（3类信号）

| 类型 | 具体表现 | 判断方法 |
|------|---------|---------|
| 奇葩参数 | 与核心需求无关的细节（军工防震办公电脑/防盐雾图书馆设备/RGB精确值） | 参数是否必要？是否照抄某品牌说明书？ |
| 独家技术壁垒 | 非国家强制的独家专利、私有协议、特定功能 | 市场调研：只有1-2家能满足？ |
| 系统授权排他 | 要求接入现有系统/提供特定接口授权 | 授权是否掌握在原有供应商手中？ |

**操作模板**：招标文件核心参数 → 扔到搜索引擎比对 → 判断是否为某品牌独有

### 二、资质业绩审查（3类信号）

| 类型 | 具体表现 | 判断方法 |
|------|---------|---------|
| 资质要求异常 | 小型项目要国家级资质/同时要求跨度极大的多项资质/不接受联合体 | 是否只有某家大型企业资质结构匹配？ |
| 业绩精准画像 | 精确到时间段+特定金额+特定行业+特定地区 | 条件组合后全行业只有1-2家满足？ |
| 本地化陷阱 | 强制要求分公司/办事处/本地房产/本地社保 | 违反公平竞争原则，多地已明令禁止 |

### 三、评分标准审查（3类信号）

| 类型 | 具体表现 | 判断方法 |
|------|---------|---------|
| 主观分权重过高 | 价格分低于30%，技术/商务主观项占比高 | 评委打分可操纵性分析 |
| 冷门证书加分 | 非国家强制的行业协会证书作为高分加分项 | 证书是否只有内定供应商提前持有？ |
| 样品/演示刁难 | 要求过多样品/演示非核心复杂功能 | 是否故意增加投标成本排除竞争者？ |

### 四、时间商务审查（2类信号）

| 类型 | 具体表现 | 判断方法 |
|------|---------|---------|
| 时间压缩 | 公告到截标时间短于法定/节假日前后发标开标 | 内定供应商是否已提前准备标书？ |
| 付款条件苛刻 | 全额垫资/超长账期/巨额违约罚 | 是否只有已谈好条件的供应商敢接？ |

## 电子招投标串通投标大数据审计（四种方法）

> 来源：常智（审计署驻太原特派办）《中国审计》2023年第4期

### 逻辑链（标准格式）

```
采集电子招投标数据(MAC/IP/标段/投标人/保证金)
→ 方法1: MAC/IP自连接 → 同一电脑编制标书 → 串标疑点
→ 方法2: Neo4j股权穿透(1-4层) → 隐蔽控股关系 → 围标疑点
→ 方法3: FP-growth频繁项集 → 同一批人多次陪标+置信度1.0 → 职业陪标团队
→ 方法4: NLP余弦相似度>0.9 → 标书文本雷同 → 同一人编制标书
→ 证据闭环: MAC登记表+IP查询结果+工商股权图+标书比对报告 → 串通投标认定
```

### 方法一：MAC地址/IP地址自连接比对

**适用场景**：发现同一电脑编制标书、同一地点上传投标文件

**核心SQL**：
```sql
-- 自连接查同标段同MAC或同IP的投标人
SELECT a.标段编号, a.投标人 AS 投标人A, b.投标人 AS 投标人B,
  a.MAC地址, a.IP地址
FROM 投标信息表 a
JOIN 投标信息表 b ON a.标段编号 = b.标段编号
WHERE a.投标人 <> b.投标人
  AND (a.MAC地址 = b.MAC地址 OR a.IP地址 = b.IP地址);
```

**判断标准**：
- MAC相同 = 同一台电脑 = 同一人编制标书
- IP相同 = 同一地点 = 同一人办理投标
- 再查：这些疑点投标人中谁中标了 → 串标+围标完整画像

### 方法二：Neo4j图数据库股权穿透

**适用场景**：发现投标人之间的隐蔽控股关系

**核心查询**（Neo4j Cypher）：
```cypher
-- 1-4层股权穿透，找同标段投标的关联企业
MATCH p=(z:标段)<-[:投标]-(x:企业)-[:持股*1..4]->(y:企业)-[:投标]->(z)
RETURN p;
```

**穿透结果示例**：
```
A → 持股100% B → 持股90% C → 持股90% D
→ A实际控制D = 81% (100%×90%×90%)
→ A和D同时投同一标段 → 围标
```

### 方法三：FP-growth关联规则挖掘

**适用场景**：发现"职业"陪标团队（同一批人每次一同出现）

**Python伪代码**：
```python
from mlxtend.frequent_patterns import fpgrowth

# 投标人名称→数字映射
df_encoded = encode_bidder_names(df)

# FP-growth挖掘频繁项集
frequent_itemsets = fpgrowth(df_encoded, min_support=0.3, use_colnames=True)

# 结果示例：
# frozenset({1867,1862},{1856,1860}) | support=9 | confidence=1.0
# → 4家企业在9个项目中同时出现,1867/1862投标的项目{1856,1860}全部参与
# → 再查: 其中某家每次都中标 → 职业陪标团队
```

### 方法四：NLP标书文本相似度

**适用场景**：发现不同投标人的标书内容雷同

**核心步骤**：
1. 语义编码器训练（抓取相似标书文本）
2. 标书非格式化数据 → 标准化格式
3. 计算余弦相似度（值越接近1越雷同）

```python
from sklearn.metrics.pairwise import cosine_similarity

# 对标书文本进行向量化
vector1 = model.encode(标书A内容)
vector2 = model.encode(标书B内容)

# 计算余弦相似度
similarity = cosine_similarity([vector1], [vector2])[0][0]

# 相似度>0.9 = 高度雷同 = 同一人编制标书
if similarity > 0.9:
    print(f'疑点: 标书A与标书B相似度{similarity:.2%}')
```

### 四种方法对比

| 方法 | 数据源 | 技术 | 发现 | 难度 |
|------|--------|------|------|------|
| MAC/IP自连接 | 电子招投标系统 | SQL self join | 同电脑/同地点 | 低 |
| Neo4j股权穿透 | 工商数据+投标数据 | 图数据库Cypher | 隐蔽控股 | 中 |

| NLP标书比对 | 标书全文 | 语义向量+余弦相似 | 文本雷同 | 高 |
