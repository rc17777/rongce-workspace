## 知识体系

### L1: 数据查询层

**参考文章**：SQL实战5场景 / SQL常踩5坑 / 数字技能修炼入门篇(一)(二)

**核心能力**：
1. **5类审计高频SQL场景**
   - 关联比对：供应商vs合同、发票vs付款 → JOIN / 子查询
   - 异常值识别：金额异常、阈值卡位 → GROUP BY + HAVING + 窗口函数
   - 时间序列：突击支出、季度末集中付款 → DATE函数 + CASE WHEN
   - 重复检测：重复报销、重复合同 → COUNT + GROUP BY
   - Top-N排名：大额供应商、费用最高月份 → ORDER BY + RANK/DENSE_RANK

2. **SQL避坑指南**
   - 空值处理不当导致遗漏疑点 → 用COALESCE/IS NULL检查
   - JOIN条件不完整导致重复计算 → 用DISTINCT或明确关联键
   - 日期格式不统一 → 统一用DATE_TRUNC标准化

### L2: 数据分析层

**参考文章**：传统审计效率翻10倍 / Python异常交易 / 数字技能修炼进阶篇

1. **审计数据分析4步法**：数据获取→清洗→分析→输出

## 质检机制（Quality Check）

> 来源：真知浩见《问卷数据分析 skill》设计理念
> 核心理念：AI写代码跑数，AI不直接算数；多节点质检，过程可追溯

### 三档确认模式

| 模式 | 含义 | 审计场景适用 |
|------|------|-------------|
| A. 逐关确认 | 预处&#x200B;理/核心分析/建模每步都停 | P0疑点核查、重大问题深挖 |
| B. 批量确认 | 开头确认计划，后面自动跑 | 常规数据筛查、批量分析 |
| C. 自动全跑 | 全部跳过，一键输出 | 例行巡检、历史数据检查 |

### 多节点质检

每个分析阶段输出质检报告：
- 数据清洗阶段：缺失值/异常值/重复值检测
- 核心分析阶段：样本量/N值/统计显著��校验
- 建模阶段：模型收敛/特征重要性/过拟合检查

每个结果附带quality_check字段，作为结果本身的一部分，不是事后免责声明。

### 两条硬规则

1. **不让AI直接算数**
   AI写Python脚本，Python跑数据。AI只负责解释结果。
   参考：金川医保525万行数据 → pandas分块读取 → AI分析结论

2. **单一职责**
   数据分析归分析，可视化归可视化，报告归报告。
   一个skill只做一件事。

## 机器学习审计案例：TextGrocery专项资金合规性分类

> 来源：许方义（荆门市审计局）《中国审计》2023年第17期
> 技术栈：TextGrocery + 结巴分词 + LibLinear（轻量级，虚拟机可运行）

### 逻辑链（标准格式）

```
采集专项资金支付明细(2017-2021年训练数据)
→ 人工标注(每条摘要标记Y=合规/N=不合规)
→ TextGrocery学习训练数据，构建MSFFIP分类模型
→ 2022年测试数据输入模型，自动输出Y/N合规判断
→ N标记条目→人工逐项核查→违规支出确认
→ 未学习过的类别→人工判断→回补训练数据→模型迭代
→ 违规支出清单(虚列/挪用/挤占专项资金)
```

### 适用场景

信息化专项资金/农业资金/教育资金/社保资金等**任何有明确支出范围的专项资金**，均可复用此方法。

### 完整操作流程

**步骤1：搭建环境**
```bash
# 安装tgrocery
pip install tgrocery
# 依赖：jieba, liblinear
```

**步骤2：准备训练数据**
```
格式：标签	摘要内容
示例(train.txt)：
N	社保科办公费
Y	信息中心代维费
N	机关差旅费
Y	预算科软件升级
N	补缴养老保险
```

**步骤3：训练模型**
```python
from tgrocery import Grocery

# 创建分类模型
model = Grocery('MSFFIP')  # Model for Fiscal Fund Integrity Protection
model.train('train.txt')
model.save()

# 测试准确率
result = model.test('test.txt')
print(f'准确率: {result.accuracy}')
```

**步骤4：对测试数据做合规性判断**
```python
# 加载模型
model = Grocery('MSFFIP')
model.load()

# 预测2022年支出合规性
predictions = model.predict('2022_test_data.txt')

# 输出N标记的条目（不合规支出清单）
for line, pred in zip(test_lines, predictions):
    if pred == 'N':
        print(f'[不合规] {line}')
```

**步骤5：人工核查与增量训练**
- 对模型标记为N的条目→人工逐项核查→确认违规
- 对未学习过的新类别→人工判断→添加训练数据→重新训练
- 案例教训：等级保护测评支出在训练数据中未出现，被误判为N→人工修正后重训

### 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 分类库 | TextGrocery（非大模型） | 轻量级，虚拟机可运行，不需GPU |
| 操作系统 | Ubuntu虚拟机 | TextGrocery仅支持Linux |
| 特征字段 | 支付凭证"摘要" | 摘要已包含支出性质的核心信息 |
| 训练数据量 | 5年历史数据 | 足够覆盖专项资金主要支出类型 |
| N标记处理 | 人工逐项核查 | 防止误判（如未学习过的合规支出） |

### 准确率说明

| 情况 | 准确率 | 处理方法 |
|------|--------|---------|
| 训练数据中出现过的类别 | 接近100% | 直接采信 |
| 训练数据中未出现的类别 | 不确定 | 人工判断后加入训练 |

### 扩展应用

其他类型专项资金审计也可复用：
- 农业资金：标注农业支出Y/非农业支出N
- 教育资金：标注教育支出Y/非教育支出N
- 环保资金：标注环保支出Y/非环保支出N
- 核心原理：任何有明确支出范围的专项资金都可以构建Y/N分类器
