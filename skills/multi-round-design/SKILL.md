# 多轮迭代设计法

从 paper-framework-figure-studio-pro 项目提炼出的通用方法论，核心：**不要直接出结果，而是先设计、多候选、迭代筛选、显性化专业知识**。

## 核心原则

1. **设计先于执行** — 先搞清楚"这张图/报告/方案要解决什么问题、给谁看"，再动手
2. **多候选优于单方案** — 一次出多个方向，比闷头做一版然后返工更高效
3. **迭代优于完美** — 先有个粗糙版本，再一轮轮优化，而不是第一版就追求 publication-ready
4. **过程比结果更值钱** — 展示推理过程、选择理由，才能建立真正的信任
5. **专业知识要外显** — 把专家脑子里的"我知道该怎么做"变成清单、标准、参考案例

## 标准工作流（8步）

```
S0 启动   → 明确任务边界，不急于输出
S1 输入   → 收集材料、背景、约束条件
S2 诊断   → 判断核心问题、目标受众、交付要求
S3 候选   → 生成多个方案/角度/假设（2-4个方向）
S4 筛选   → 对比候选，确定最佳方向或组合
S5 细化   → 针对选定方向深入打磨
S6 验证   → 交叉检查、查漏补缺
S7 定稿   → 输出最终交付物
```

每一步的输出都是下一步的输入，形成闭环。

## 审计场景应用

详细案例和模板见 [references/audit-patterns.md](references/audit-patterns.md)。

### 快速参考

| 审计环节 | S0-S2 诊断重点 | S3 候选方向 | S4 筛选标准 |
|---------|--------------|-----------|------------|
| 合同审计 | 合同类型、风险等级、历史问题 | 金额异常/履约异常/程序异常/条款模糊 | 问题真实性和影响程度 |
| 财务审计 | 报表重点科目、内控弱点 | 余额异常/趋势异常/结构异常/勾稽异常 | 错报金额和重大性 |
| 合规审计 | 法规依据、被审计单位类型 | 程序合规/权限合规/文档合规/流程合规 | 违规严重性和整改难度 |
| 经济责任审计 | 领导干部职责范围、重大决策 | 决策合规/资产安全/廉洁从政/效益评价 | 问题定性和责任归属 |

### 候选生成提示词模板

```
请从以下X个维度，为[审计对象]生成[N]个候选分析方向：

维度1：[维度名称，如"金额异常"]
维度2：[维度名称，如"时间节点异常"]
...

每个候选方向请说明：
- 核心假设
- 数据支撑点
- 预期发现
- 验证难度（高/中/低）
```

## 报告撰写应用

详细模板见 [references/report-template.md](references/report-template.md)。

关键原则：
- **先列框架，再填内容** — 用 S0-S4 先把报告结构敲定
- **每个发现都要有"推理链"** — 数据→分析→结论→建议，缺一不可
- **多版本比较** — 草稿阶段出 2-3 个版本供选择，比一版改到底效率高

## 知识资产化

把审计经验变成可操作的检查标准。参见 [references/checklist-builder.md](references/checklist-builder.md)。

核心方法：
1. 从具体案例中提取判断规律（不只是结论）
2. 用"如果...那么..."的规则描述
3. 按风险等级排序，形成分层检查清单
4. 定期用新案例更新和迭代

## 与其他技能配合

- 审计大数据分析 → 先用多轮设计法确定分析方向，再用数据分析工具
- 审计报告撰写 → 用 S0-S4 敲定报告结构，再填充内容
- 合同审查 → 用候选+筛选多角度对比合同条款风险
- 制度设计 → 用迭代打磨确保制度逻辑严密无漏洞
