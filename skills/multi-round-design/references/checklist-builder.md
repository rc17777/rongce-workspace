# 检查清单构建方法论

## 从专家经验到可操作标准的路径

### Step 1：经验提取

从具体案例中提取判断规律，不只是提取结论。

❌ 低效做法：把"这个合同有风险"当作知识记录下来
✅ 高效做法：把"当合同金额>50万且对方是关联方，且缺少价格评估报告时，风险等级为高"这类规则提取出来

### Step 2：规则编码

用「如果...那么...否则...」格式描述：

```
合同风险快速判断规则：

规则1：如果[金额>50万] 且 [履约期>1年]，那么[需关注履约监控]
规则2：如果[补充协议金额>原合同10%]，那么[需重新履行审批]
规则3：如果[付款节点滞后合同约定>30天]，那么[需检查欠租风险]
规则4：如果[对方资质过期] 且 [合同金额>20万]，那么[立即暂停执行]
```

### Step 3：分层设计

按风险等级设计不同深度的检查项：

```
【第一层：必查项（所有项目都要查）】
- 合同金额与预算是否匹配
- 合同签批手续是否完整
- 对方营业执照是否有效

【第二层：关注项（满足条件时触发）】
- 当金额>100万：需增加价格合理性分析
- 当合同期跨年：需检查年度决算衔接
- 当对方是关联方：需增加关联交易披露检查

【第三层：延伸项（发现异常时启动）】
- 发现欠款：启动欠款追缴检查
- 发现变更：启动变更合规检查
- 发现异常付款：启动资金流向追踪
```

### Step 4：清单模板

```
[审计类型] 检查清单 v1.0
适用范围：[描述]
上次更新：[日期]

一、程序合规性检查
  □ [ ] 步骤1
  □ [ ] 步骤2
  □ [ ] 步骤3（如发现异常→跳转专项检查）

二、实体合规性检查
  □ [ ] 步骤1
  □ [ ] 步骤2

三、风险信号触发清单
  ⚠️ 如满足以下任一条件，触发深度检查：
    ○ 条件A
    ○ 条件B
```

### Step 5：持续迭代

每次做完审计项目后：
1. 回顾检查清单——哪些项没发现实际问题？删除或降低权重
2. 复盘遗漏案例——这次漏了什么？新增检查项
3. 更新规则描述——用新案例验证和修正既有规则

**关键原则：清单的价值在于持续更新，不用追求第一版完美。**
