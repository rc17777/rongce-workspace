# Agent友好性检查清单（完整版）

## S: 结构友好性 (Structure) — 40分

机器能否正确解析数据结构？

### S1: 无合并单元格 [-10分]
- **检查方法**：打开Excel，检查是否存在跨行/跨列合并
- **为什么重要**：Agent解析时合并单元格会导致行列错位，字段与数据对应关系混乱
- **改造方法**：拆分为独立单元格，重复填充相同值。或用CSV导出（天然不支持合并）
- **例外**：纯展示类Sheet（不用于数据分析）可不改造

### S2: 统一日期格式 [-5分]
- **检查方法**：抽查日期列，是否存在多种格式混用（如2024-01-01和2024/1/1和20240101）
- **为什么重要**：Agent需要猜测日期格式，混用会导致解析失败或错误的日期比较
- **改造方法**：统一为ISO 8601格式（YYYY-MM-DD）
- **扣分规则**：混用3种以上日期格式 -5，1-2种 -2

### S3: 数值字段为数字类型 [-10分]
- **检查方法**：检查金额/数量/比率等数值列是否为文本格式（Excel中靠左对齐通常是文本）
- **为什么重要**：文本格式的数字Agent无法直接进行求和/平均/比较等运算
- **改造方法**：转换为数字格式，去除千分位逗号（保留小数点）
- **常见陷阱**：金额列中有"元"字、"万元"等文本混入

### S4: 无非数据内容 [-10分]
- **检查方法**：检查表头行以上是否有标题/说明/空行；数据行之间是否有小计/合计行
- **为什么重要**：Agent假定第一行是列名，之后全是数据行。标题行/空行/小计行会破坏这个假设
- **改造方法**：
  - 标题 → 移到单独的说明Sheet或文件外部
  - 小计行 → 单独放到汇总Sheet
  - 空行 → 删除
- **扣分规则**：存在标题行 -5，存在小计行 -5

### S5: 编码一致 [-5分]
- **检查方法**：同一字段的值是否存在编码混用（如供应商既有中文全称又有缩写代号）
- **为什么重要**：Agent无法判断"A公司"和"四川A科技有限公司"是否是同一个实体
- **改造方法**：统一使用完整名称或建立编码对照表

## M: 语义友好性 (Semantics) — 35分

Agent能否理解每个字段的含义？

### M1: 字段名自解释 [-10分]
- **检查方法**：检查是否存在缩写/代码/拼音作为字段名，且无注释说明
- **为什么重要**：Agent对"ZJLY"的理解完全靠猜，可能猜错
- **评分**：
  - 存在3个以上无说明缩写 -10
  - 存在1-2个 -5
  - 全中文自解释字段名 +0
- **改造方法**：
  - 优先：改用中文完整字段名
  - 次选：提供数据字典（字段名→说明对照表）

### M2: 有数据字典 [-10分]
- **检查方法**：是否存在字段说明文档（可以是独立Sheet、README、或数据库COMMENT）
- **为什么重要**：这是Agent理解数据语义的最重要来源
- **数据字典最少应包含**：字段名 | 中文说明 | 数据类型 | 单位 | 示例值 | 备注
- **改造方法**：在工作簿中添加"数据字典"Sheet

### M3: 枚举值明确 [-5分]
- **检查方法**：状态/类型等枚举字段是否使用数字代码（如1=正常,2=异常）且无说明
- **为什么重要**：Agent不知道"1"和"2"的含义，容易错误解读
- **改造方法**：
  - 优先：直接使用中文枚举值（"正常"/"异常"）
  - 次选：数据字典中提供枚举映射表

### M4: 单位标注 [-5分]
- **检查方法**：金额/数量/比率字段是否明确标注了单位
- **为什么重要**："金额5000"是元还是万元？解读错误可能导致数量级偏差
- **改造方法**：在数据字典中标注单位，或字段名中体现（如"金额（元）"）

### M5: NULL含义清晰 [-5分]
- **检查方法**：空值是否有统一含义？是0/不适用/数据缺失/拒绝提供？
- **为什么重要**：Agent无法区分"金额为0"和"金额未知"，两种解读可能导致相反的审计结论
- **改造方法**：在数据字典中说明空值含义，或使用明确占位符（如"N/A"）

## I: 接口友好性 (Interface) — 25分

API/数据库接口是否描述清晰？

### I1: API文档完整 [-15分]
- **检查方法**：是否提供完整的API文档，包含：接口URL、请求方法、参数说明（名称/类型/必填/说明/示例）、返回格式说明
- **为什么重要**：Agent需要通过API文档来理解如何调用接口、传什么参数、返回什么数据
- **改造方法**：按OpenAPI/Swagger标准编写接口文档

### I2: 分页/限流说明 [-10分]
- **检查方法**：是否说明分页机制（参数名/每页条数/最大页数）和调用限制（频率/总量）
- **为什么重要**：Agent不知道分页可能导致数据不完整，不知道限流可能触发封禁
- **改造方法**：在API文档中明确分页参数和限流规则

## 快速自检（5分钟版）

打开数据文件，问自己5个问题：

1. 第一行是不是列名、后面全是数据？没有合并单元格？ → S1+S4
2. 日期都是一个格式吗？ → S2
3. 金额列是数字吗？ → S3
4. 每个字段名不看备注我都知道是什么意思吗？ → M1+M2
5. 如果有API，文档里参数说明完整吗？ → I1

5个全"是" → 🟢 Agent友好
3-4个"是" → 🟡 基本可用
<3个"是" → 🔴 需要改造
