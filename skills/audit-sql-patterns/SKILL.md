# 审计SQL分析模板库

内置10+审计常用SQL分析模板 + 4个AI翻凭证Prompt模板：重复支付检测、拆分支付规避招标检测、供应商关联关系分析、资金流向追踪、异常时间模式检测、AI翻凭证（AP/AR/EXP/FA）等。即改即用。

## 适用场景

- 需要用SQL对审计数据进行查询分析
- 需要用AI Prompt对序时账/科目余额表进行翻凭证分析

## 执行步骤

### 步骤 1
选择分析场景：
- **SQL方式**：重复支付/拆分支付/供应商分析/资金流向/时间异常/地址异常
- **AI Prompt方式**：应付账款翻凭证/应收账款回款/费用报销去重/固定资产资本化

### 步骤 2
- SQL方式：根据数据表结构调整模板中的字段名
- AI Prompt方式：上传脱敏后的序时账/余额表，输入Prompt指令

### 步骤 3
执行查询，获得结果

### 步骤 4
对结果进行解读和建议后续审计步骤


## 输出格式

```
-- 【拆分支付检测模板】检测同一供应商、同日、多笔金额之和=整数的记录
SELECT supplier, pay_date, SUM(amount) as total, COUNT(*) as cnt
FROM payments WHERE pay_date='2025-03-15'
GROUP BY supplier, pay_date
HAVING COUNT(*) >= 2 AND SUM(amount) % 10000 = 0
ORDER BY total DESC;

-- 结果：3条疑似拆分支付记录，合计金额XX万元
-- 建议：逐条核查合同约定支付方式与实际情况是否一致
```

## 实战案例库

### 案例1：基层法院经责审计SQL分析

> 来源：黄发斌、曾晶、洪云

#### 逻辑链（标准格式）

```
立案到结案日期SQL计算(DATEDIFF)
→ 超期案件批量筛选(民事一审>180天/简易>90天/刑事>30天)
→ 应收费用vs实收费用差额分析
→ 罚没收入结案>180天未执行
→ 法官文书确认金额vs实际应收金额比对
→ 证据闭环(卷宗抽查+庭审记录+财务凭证)
```
（湖北省荆州市审计局）
> 《基层法院领导干部经济责任审计数据分析方法》

#### 数据来源
- 综合信息管理平台 → 诉讼结案案件明细表
- 执行案件流程信息管理平台 → 执行结案案件明细表
- 法务综合管理平台 → 诉讼/执行案件收退费明细表

#### 分析1：无依据收取诉讼案件受理费
```sql
-- 筛选不应收费的案件类别
SELECT * FROM 诉讼结案案件明细
WHERE 案件文号 LIKE '%民申%'
   OR 案件文号 LIKE '%民监%'
   OR 案件文号 LIKE '%民特%'
   OR 结案方式 IN ('不予受理', '驳回起诉', '驳回上诉');

-- 关联收退费表，查出实际已收费的
SELECT a.*, b.确认的案件受理费
FROM 诉讼结案案件明细 a
LEFT JOIN 诉讼案件收退费明细 b ON a.案件文号 = b.案件文号
WHERE (a.案件文号 LIKE '%民申%' OR a.案件文号 LIKE '%民监%')
  AND b.确认的案件受理费 > 0;
```

#### 分析2：诉讼案件受理费收退费合理性
```sql
-- 按案由分类计算应收费用，与法官确认费用比对
-- 先分类：财产类/离婚类/侵权类
SELECT 案件文号, 立案标的, 案由,
  CASE
    WHEN 案由分类 = '财产类' AND 立案标的 <= 10000 THEN 50
    WHEN 案由分类 = '财产类' AND 立案标的 > 10000 AND 立案标的 <= 100000 THEN 立案标的 * 0.025 - 200
    WHEN 案由分类 = '财产类' AND 立案标的 > 100000 AND 立案标的 <= 200000 THEN 立案标的 * 0.02 + 300
    -- 其他金额区间省略...
    ELSE 0
  END AS 实际应交纳的案件受理费
INTO #审计中间表
FROM 诉讼结案案件明细;

-- 简易程序/调解/撤诉减半
UPDATE #审计中间表
SET 实际应交纳的案件受理费 = 实际应交纳的案件受理费 / 2
WHERE 适用程序 = '简易程序'
   OR 结案方式 IN ('调解', '申请撤诉');

-- 比对差异
SELECT a.*, b.确认的案件受理费,
  a.实际应交纳的案件受理费 - b.确认的案件受理费 AS 差异金额
FROM #审计中间表 a
JOIN 诉讼案件收退费明细 b ON a.案件文号 = b.案件文号
WHERE abs(a.实际应交纳的案件受理费 - b.确认的案件受理费) > 0.01;
```

#### 分析3：申请执行费应收未收/多收
```sql
-- 按执行到位标的计算应收申请执行费
SELECT 案件文号, 执行到位标的,
  CASE
    WHEN 执行到位标的 <= 10000 THEN 50
    WHEN 执行到位标的 > 10000 AND 执行到位标的 <= 500000 THEN 执行到位标的 * 0.015 - 100
    WHEN 执行到位标的 > 500000 THEN 执行到位标的 * 0.01 + 2400
    ELSE 0
  END AS 实际应交纳的申请执行费
INTO #执行费中间表
FROM 执行结案案件明细
WHERE 结案方式 IN ('执行完毕', '自动履行完毕');

-- 比对已收金额
SELECT a.*, b.已收的申请执行费,
  a.实际应交纳的申请执行费 - b.已收的申请执行费 AS 差异金额
FROM #执行费中间表 a
JOIN 执行案件收退费明细 b ON a.案件文号 = b.案件文号
WHERE abs(a.实际应交纳的申请执行费 - b.已收的申请执行费) > 0.01;
```

#### 分析4：审理/执行期限超期
```sql
-- 诉讼案件审理期限超期检测
SELECT 案件文号, 立案日期, 结案日期,
  DATEDIFF(day, 立案日期, 结案日期) AS 实际审理期限,
  CASE
    WHEN 案件文号 LIKE '%民初%' AND 适用程序 = '普通程序' THEN 180
    WHEN 案件文号 LIKE '%民初%' AND 适用程序 = '简易程序' THEN 90
    WHEN 案件文号 LIKE '%刑初%' AND 适用程序 = '普通程序' THEN 30
    WHEN 案件文号 LIKE '%刑初%' AND 适用程序 = '简易程序' THEN 15
    WHEN 案件文号 LIKE '%民特%' THEN 30
    ELSE 180
  END AS 法定审理期限
FROM 诉讼结案案件明细
WHERE DATEDIFF(day, 立案日期, 结案日期) >
  CASE
    WHEN 案件文号 LIKE '%民初%' AND 适用程序 = '普通程序' THEN 180
    WHEN 案件文号 LIKE '%民初%' AND 适用程序 = '简易程序' THEN 90
    WHEN 案件文号 LIKE '%刑初%' AND 适用程序 = '普通程序' THEN 30
    WHEN 案件文号 LIKE '%刑初%' AND 适用程序 = '简易程序' THEN 15
    WHEN 案件文号 LIKE '%民特%' THEN 30
    ELSE 180
  END;
```

#### 分析5：刑事案件罚没收入超期未执行
```sql
-- 查判决超过180天仍未执行到位的罚金
SELECT *, DATEDIFF(day, 结案日期, GETDATE()) AS 结案至今天数,
  (应收金额 - 实收金额) AS 未执行到位金额
FROM 刑事案件收费明细
WHERE 收取方式 = '本院依法收缴'
  AND 应收金额 > 实收金额
  AND DATEDIFF(day, 结案日期, GETDATE()) > 180;
```

#### 审计成效
- 替代传统翻阅案卷方式
- 快速精准发现法院在履行审判职能中的薄弱环节
- 实现以审促改，完善规章制度

## AI Prompt 模板库（翻凭证）

> 来源：AI 审计翻凭证资源包（核心指令版），2026-06-01
> 用法：将序时账/科目余额表上传给AI后，直接复制对应Prompt使用

### 前置配置：持久化会话

**指令**："请记住当前文件的列名和数据格式，并在后续会话中保持此上下文，除非我主动要求重置。"

**防坑提醒**：
- 上传前务必隐藏客户名称、敏感账号（数据脱敏）
- 如果AI开始"胡言乱语"，通常是Session长度超出限制，需重新开启对话并复用初始化指令

### 场景1：应付账款（AP）— 查跨期/核算错误

```
请从序时账中筛选出摘要包含'货款'但借方科目非'库存商品/原材料'的凭证。输出凭证号、日期、摘要、借方科目、贷方科目、金额。
```

**审计关注点**：货款入账科目异常 → 可能跨期计入费用、虚列采购、或通过"应付账款"挂账调节利润

### 场景2：应收账款（AR）— 查异常回款/关联方

```
找出贷方发生额前10名的非银行存款对应科目，并列出其摘要和日期。输出对方科目名称、发生额、对应凭证号、摘要。
```

**审计关注点**：应收账款贷方发生额大且对方科目非常规 → 可能是关联方资金拆借、虚假回款冲账、或体外资金循环

### 场景3：费用报销（EXP）— 查重复报销

```
筛选出同一报销人、同一金额在3天内重复出现的记录，并输出凭证号、日期、报销人、金额、摘要。
```

**审计关注点**：同一人同一金额短时间重复 → 重复报销嫌疑；可进一步查该报销人全部记录、关注整金额凑数特征

### 场景4：固定资产（FA）— 查资本化/费用化误判

```
找出摘要包含'采购/购买/设备'且金额超过5000元，但未计入'固定资产'科目的记录。输出凭证号、日期、金额、实际计入科目、摘要。
```

**审计关注点**：应资本化的支出费用化 → 低估资产、虚增当期费用；应费用化的后续支出资本化 → 虚增资产、粉饰报表

### 进阶：指令组合拳

**分步指令策略**：
1. 第一步："列出所有异常记录"（让AI做初筛）
2. 第二步："针对第X笔异常，详细解释为什么它异常"（让AI做深度分析）
3. 第三步："根据以上异常，生成一份抽样检查表，含凭证号、异常原因、建议进一步核查方向"（生成审计工作底稿）

**验证指令**：
```
请针对你筛选出的第X号凭证，在原文件中找到对应行并完整展示，以核对你的准确性。
```

**提示**：建议将上述Prompt模板存入Notion或Excel快捷表单，审计季直接复制使用。

## 案例2：政策性农业保险审计SQL分析

> 来源：于晓蕾、葛其圣（海阳市审计局）《中国审计》2023年第21期
> 核心方法：潜在关联+风险聚合+信息不对称三种SQL分析法

### 审计发现逻辑链（从数据到违法事实）

#### 逻辑链A：截留赔款（潜在关联分析）

```
赔付周期>6个月 → 同一账号理赔>10次 →
人员核实 → 走访农户(未收到赔款) →
银行流水(款项进入业务员控制账号) →
结论：业务员+镇街人员串通截留赔款
```

**核心SQL1：筛选赔付周期异常**
```sql
SELECT 保单号, 赔案号, 农户名称, 身份证号码, 银行账户,
  DATEDIFF(month, 报案日期, 结案日期) AS 时间差
INTO 赔付周期表
FROM 小麦政策性保险理赔表
WHERE 赔付金额 > 10000;
```

**核心SQL2：筛选理赔频次异常**
```sql
SELECT COUNT(银行账户) AS 理赔次数, 农户名称
FROM 赔付周期表
GROUP BY 农户名称
HAVING COUNT(银行账户) > 10;
```

#### 逻辑链B：虚报面积（风险聚合分析）

```
理赔金额>1万 → 按村汇总>10万 →
气象数据排除(无自然灾害) →
JOIN村干部表(投保>50亩) →
实地丈量(投保面积>实际面积) →
结论：村干部虚报投保面积骗取补贴
```

**核心SQL3：大额赔付按区域汇总**
```sql
SELECT SUM(赔付额) AS 理赔金额, 家庭地址
FROM 个人赔付金额大于10000元审计中间表
GROUP BY 家庭地址
HAVING SUM(赔付额) > 100000;
```

**核心SQL4：筛选村干部大面积投保**
```sql
SELECT a.姓名, a.身份证号码, a.银行账号, a.保险金额,
  a.村名, b.村干部姓名, b.职务
FROM 小麦政策性保险表 a
JOIN 村干部工资发放表 b ON a.身份证号码 = b.身份证号码
WHERE a.投保面积 > 50;
```

#### 逻辑链C：虚假理赔（信息不对称分析）

```
理赔面积 > 直补面积 → 赔付>5亩名单 →
按索赔率排序(赔付/投保) →
走访确认(未发生受灾) →
保险公司承认(人手少未逐户核实) →
结论：虚假理赔、审核失守
```

**核心SQL5：理赔面积大于直补面积**
```sql
SELECT a.姓名, a.身份证号码, a.赔付面积, b.补贴面积, a.家庭地址
FROM 小麦政策性保险理赔表 a
JOIN 小麦直补表 b ON a.身份证号码 = b.身份证号码
WHERE a.赔付面积 > b.补贴面积;
```

**核心SQL6：筛选赔付亩数异常**
```sql
SELECT 保单号, 姓名, 身份证号码, 银行卡号, 赔付金额, 赔付面积
FROM 小麦政策性保险理赔表
WHERE 赔付面积 > 5  -- 约一户口粮地面积数
ORDER BY 赔付面积 DESC;
```

### 三种分析方法的逻辑区别

| 方法 | 起点 | 逻辑路径 | 适用场景 |
|------|------|---------|---------|
| 潜在关联 | 业务流程图→流程节点 | 流程反常→人物关联→资金穿透 | 串通、内外勾结 |
| 风险聚合 | 金额异常→区域集中 | 大额→区域→特定人群 | 虚报、骗保 |
| 信息不对称 | 外部信息 vs 内部数据 | 气象/直补 ≠ 赔付 | 虚假事实、敷衍审核 |

### 本案完整逻辑链（总链）

```
链A(截留赔款): 赔付周期>6月 → 同账号理赔>10次 → 人物核实(业务员) → 农户(未收到) → 流水(进入业务员账号)
链B(虚报面积): 理赔金额>1万 → 按村汇总>10万 → 气象(无灾害) → 村干部投保>50亩 → 实地丈量(虚假)
链C(虚假理赔): 理赔面积>直补面积 → 赔付>5亩 → 索赔率排序 → 走访(无受灾) → 保险公司承认(未逐户核实)
```

### 可复用的审计模型

```
数据异常 → 追问(偶然？集中？) → 节点收敛(区域/人物/资金)
→ 关联穿透(工商/银行/村干部) → 现场核实 → 证据闭环
```

### 与金川医保案的共通逻辑

| 项目 | 金川医保 | 小麦农业保险 |
|------|---------|-------------|
| 数据量 | 525万行×111列 | 全市投保理赔数据 |
| 关键SQL | 分解住院检测/诊疗费虚高 | 赔付周期异常/村干部大面积投保 |
| 突破口 | 同一人频繁住院、诊疗费极低 | 同一账号频繁理赔、投保面积>实际 |
| 逻辑链 | 数据异常→交叉比对→案例锁定→现场核实 | 周期异常→区域收敛→人物关联→实地测量 |

## 案例3：医疗保险基金审计SQL分析

> 来源：何舒莹、陈爱芬、柯昱（泉州市+晋江市审计局）《中国审计》2023年第5期
> 规模：128个数据分析模型

### 逻辑链（标准格式）

```
审前调查(医疗+医保+医药三方向数据)
→ 关联比对("医疗+医保" inner join自连接)
→ 分解收费(同患者同项目重复收费)
→ 超标准收费(SUM汇总,优惠价格vs实际收费)
→ 超限定支付(成人报销儿童药/住院→门诊)
→ 医+药关联(OVER窗口函数逐日累计,带量采购)
→ 耗材加价(同产品进价vs售价,STDDEV标准差穿透)
→ 结论: 分解收费3家医院+偏瘫训练4家医院+耗材中间商层层加价
```

### 分析一：医疗+医保关联——分解收费

**场景**：某个诊疗项目已经包含子项目，但医院对子项目重复收费。

**SQL模板**：inner join自连接，筛选同一患者同项目情况

```sql
-- 麻醉含表面麻醉，同时收费=分解收费
SELECT a.患者ID, a.结算日期, a.项目名称 AS 主项目,
  b.项目名称 AS 子项目, a.金额 AS 主金额, b.金额 AS 子金额
FROM 医保结算明细 a
INNER JOIN 医保结算明细 b
  ON a.患者ID = b.患者ID
  AND a.结算日期 = b.结算日期
WHERE a.项目名称 = '局部浸润麻醉'
  AND b.项目名称 = '表面麻醉';
```

### 分析二：医疗+医保关联——超标准收费

**场景**：多项目同时执行时应打折，但收了全价。

```sql
-- 筛选(数量>=2但单价=原价)的记录
SELECT 单据号, 患者ID, 项目名称, 数量, 总费用,
  ROUND(总费用/数量, 2) AS 实际单价,
  (SELECT 标准单价 FROM 价格表 WHERE 项目名=医保结算.项目名称) AS 标准单价
FROM 医保结算明细
WHERE 项目名称 IN (SELECT 项目名称 FROM 价格表 WHERE 多项目优惠=1)
  AND 数量 >= 2
  AND ROUND(总费用/数量, 2) >= (SELECT 标准单价 FROM 价格表 WHERE 项目名=医保结算.项目名称);
```

### 分析四：中药饮片溢价比对

**场景**：入库价 → 门诊收费价的溢价分析。

```sql
-- Step1: 入库价 GROUP BY
SELECT 药品编码, 单位, 入库时间,
  SUM(数量) AS 入库总量, SUM(金额) AS 入库总金额,
  ROUND(SUM(金额)/SUM(数量), 4) AS 平均入库单价
INTO 药品入库时间表
FROM 药品入库明细
GROUP BY 药品编码, 单位, 入库时间;

-- Step2: OVER窗口函数生成入库价格区间
SELECT 药品编码, 单位, 入库时间 AS 区间开始,
  NVL(LEAD(入库时间) OVER (PARTITION BY 药品名称, 单位 ORDER BY 入库时间),
    TO_DATE('2099-12-31','YYYY-MM-DD')) AS 区间结束,
  平均入库单价
FROM 药品入库时间表;

-- Step3: JOIN门诊明细,比对溢价
SELECT a.药品编码, a.区间开始, a.区间结束, a.平均入库单价,
  b.收费时间, b.单价 AS 门诊单价,
  ROUND((b.单价 - a.平均入库单价)/a.平均入库单价*100, 1) AS 溢价率
FROM 药品入库起始截止表 a
JOIN 门诊费用明细表 b
  ON a.药品编码 = b.药品编码
  AND a.单位 = b.单位
  AND b.收费时间 BETWEEN a.区间开始 AND a.区间结束
WHERE ROUND((b.单价 - a.平均入库单价)/a.平均入库单价*100, 1) > 30;  -- 溢价>30%
```

### 分析五：带量采购使用占比

**场景**：药低报需求量，大量使用非中选品种。

```sql
-- OVER窗口函数逐日累计销售
SELECT 药品名称, 销售日期, 销售数量,
  SUM(销售数量) OVER (PARTITION BY 药品名称 ORDER BY 销售日期 ASC)
    AS 逐日累计销售,
  (SELECT 年需求量 FROM 采购需求清单 WHERE 药品名=销售表.药品名称) AS 年需求量
FROM 药品逐日销售表
ORDER BY 药品名称, 销售日期;
```

### 分析六：耗材中间商加价穿透

**场景**：同一产品进价vs售价差异分析，用STDDEV找异常。

```sql
-- 同一厂家同一产品进价售价对比
SELECT a.产品名称, a.厂家, a.进价 AS 进价, b.售价 AS 售价,
  ROUND((b.售价 - a.进价)/a.进价*100, 1) AS 加价率
FROM 中间商进价表 a
JOIN 中间商售价表 b
  ON UTL_MATCH.JARO_WINKLER_SIMILARITY(a.产品名称, b.产品名称) > 0.85
  AND a.厂家 = b.厂家;

-- STDDEV标准差找异常加价
SELECT 产品名称, AVG(加价率) AS 平均加价率,
  STDDEV(加价率) AS 标准差,
  MAX(加价率) - MIN(加价率) AS 极差
FROM 加价率中间表
GROUP BY 产品名称
HAVING STDDEV(加价率) > 20;  -- 标准差>20%表示某批次异常
```
