# 审计报告写作辅助

## 核心理念

审计报告的价值 = 发现问题的深度 × 表达的精准度。

本技能借鉴Nature期刊写作的严谨性标准，嫁接到审计/咨询报告场景：每一个结论都有依据、每一组数据都可溯源、每一条建议都可执行。

## 触发条件

用户提到以下关键词时自动触发：
- 审计报告、咨询报告、审计建议、整改建议
- 润色报告、修改报告、优化报告
- 审计发现、问题清单、风险提示
- 报告模板、报告结构

## 工作流程

### 12步报告写作工作流

```
1. 审计目标确认   → 这份报告要回答什么问题？
2. 受众识别       → 谁读这份报告？（管理层/监管/被审计单位）
3. 结构选择       → 选模板（见 references/report-templates.md）
4. 事实梳理       → 审计发现 → 证据链 → 结论
5. 风险分级       → 高/中/低，每级有明确标准
6. 语言审计       → 过度声明检测、模糊词消除
7. 数据验证       → 报告中所有数字与底稿交叉核对
8. 法规引用       → 引用准确、条款完整、效力确认
9. 建议可执行性   → 每条建议：谁做/做什么/何时做/如何验证
10. 格式规范      → 编号、字体、页码、签章位置
11. 敏感性审查    → 涉密信息、个人信息脱敏
12. 终稿输出      → Word文档生成
```

## 写作规则（25条审计报告写作铁律）

详见 `references/writing-rules.md`。

核心要点速查：
- **不用** "存在严重问题" → **改用** "发现3项违规，涉及金额XX万元"
- **不用** "据了解" / "据悉" → **改用** "审计抽查发现" / "根据XX文件第X条"
- **不用** "基本合规" → **改用** "除以下事项外，其余均符合规定"
- **不用** "建议加强管理" → **改用** "建议在X月X日前完成XX具体整改，由XX部门验收"
- **结论必须**有数据支撑，有法规依据，有责任主体
- **建议必须**有执行人、有完成时限、有验证方式

## 审计发现写作公式

```
[问题描述] + [涉及金额/范围] + [违反的法规/制度] + [原因分析] + [整改建议]
```

示例：
> 审计发现，2024年度采购项目中，有5个项目的合同签订时间晚于开工时间（涉及金额236万元），违反《政府采购法》第四十六条"中标、成交通知书发出之日起三十日内签订合同"的规定。主要原因为采购部门与业务部门衔接不畅。建议：(1) 采购部门在中标通知发出后15个工作日内完成合同签订；(2) 建立合同签订台账，每月由分管领导核查。

## 数据可视化配色方案

使用审计语义色板（详见 `references/color-palette.md`）：

| 用途 | 色系 | HEX |
|------|------|-----|
| 主审计发现（高风险） | 红色 | #C0392B |
| 中等风险 | 橙色 | #E67E22 |
| 低风险/合规 | 绿色 | #27AE60 |
| 基准/参考数据 | 蓝色 | #2980B9 |
| 背景/中性 | 灰色 | #BDC3C7 |

规则：同一项目在不同图表中使用同一色系；每个子图最多5种颜色；SVG导出时使用 `svg.fonttype = 'none'` 保留文字可编辑。

## 报告类型选择

用户没有明确指定时，按以下逻辑判断：
- 审计对象是领导干部 → 经济责任审计模板
- 审计对象是采购项目/专项资金 → 专项审计模板
- 审计对象是工程项目 → 工程审计模板
- 用户要的是建议方案而非审计结论 → 管理咨询报告模板

## 输出格式

默认输出 Word 文档（.docx），使用 python-docx 生成：
- 封面页：项目名称、委托单位、报告日期、报告编号
- 目录页
- 正文：按模板结构
- 附件：问题清单、整改建议汇总表

## 工具脚本

- `scripts/generate_report.py` — 审计报告Word文档生成器
- `scripts/polish_text.py` — 审计文本润色检查器（标记模糊词、过度声明、缺少依据的结论）
- `scripts/audit_chart.py` — 审计数据可视化（语义色板 + SVG可编辑输出）

## 与其他技能的配合

- 需要合同审查 → 调用 contract-review-revise 技能
- 需要数据分析 → 调用 audit-data-analyst 技能
- 需要抓取法规 → 使用 web-search 或 web-fetch
