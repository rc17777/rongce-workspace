# CoT 提取提示词模板库

本文档提供不同场景下的 CoT 提取提示词模板。使用时选择最适合的模板，将转写文本填入 `{转写稿}` 占位符。

---

## 模板1：标准复盘提取（通用）

**适用**：项目复盘会录音转写、疑点讨论记录。

```
你是一位审计方法论研究员，擅长从审计专家的口述中提取结构化思维链。

请从以下审计复盘讨论的转写稿中，逐段提取专家的推理过程，按标准五步骤格式输出。

## 输出要求

对转写稿中每个独立的审计发现/判断，输出一条CoT记录。格式严格遵循：

{
  "id": "COT-YYYYMMDD-NNN",
  "场景": {
    "审计类型": "从以下选择：绩效评价|资产清查|专项资金审计|采购审计|工程审计|财务审计|其他",
    "具体环节": "具体审计环节描述",
    "背景简述": "一句话上下文"
  },
  "思维链": [
    {
      "步骤": "事实检查",
      "内容": "专家具体做了什么检查、查看了什么数据、发现了什么现象",
      "工具/方法": "使用的方法"
    },
    {
      "步骤": "风险评估",
      "内容": "为什么觉得可疑/异常",
      "风险等级": "高|中|低",
      "判断依据": "凭经验|凭数据|凭政策"
    },
    {
      "步骤": "排除干扰",
      "内容": "考虑了哪些替代解释、为什么被排除",
      "被排除的假设": ["假设及排除理由"]
    },
    {
      "步骤": "专业判断",
      "内容": "综合判断结论",
      "确定性": "确定|很可能|可能"
    },
    {
      "步骤": "问题定性",
      "内容": "归为何种审计问题",
      "问题类型": "违规|管理缺陷|绩效低下|内控缺失|舞弊迹象",
      "严重程度": "重大|重要|一般"
    }
  ],
  "关键发现": "一句话核心洞察",
  "经验教训": "可迁移的经验",
  "适用场景标签": ["标签1", "标签2"],
  "置信度": "高|中|低"
}

## 关键原则

1. 不要编造——只提取转写稿中实际出现的内容。如果某个步骤在转写稿中缺失，标注"转写稿中未体现"
2. 不要过度概括——保留专家的具体措辞和数字细节
3. "排除干扰"步骤特别重要——记录专家提到了"我一开始以为是XX，后来发现不是"这类纠偏过程
4. 一个转写稿可能包含多个独立的CoT记录，分别提取
5. 如果有多个专家讨论一个问题，以主导推理的那位为主

## 转写稿

{转写稿}
```

## 模板2：结构化访谈提取

**适用**：按 interview-protocol 进行的正式访谈转写。

```
你是一位审计方法论研究员。以下是一份按五阶段结构化访谈协议进行的审计专家访谈转写稿。

访谈已经按"场景还原→推理链回溯→方法工具→经验萃取→收尾"的顺序进行，请直接按CoT格式提取。

## 输出要求

与模板1相同。

## 额外处理

1. 访谈中专家可能对同一问题有多次修正——提取最终版本，但在"排除干扰"中记录修正过程
2. "经验萃取"阶段的内容填入"经验教训"字段
3. 如果访谈者追问了"排除了什么"，这个部分的内容优先填入"排除干扰"步骤

## 转写稿

{转写稿}
```

## 模板3：文本直接提取（案例文档）

**适用**：已有的审计案例报告、问题分析文档、审计手记、底稿批注。

```
你是一位审计方法论研究员。请从以下审计案例文档中提取专家的推理过程。

## 注意事项

1. 案例文档通常是"结论"导向的——先有结论再有证据。请还原成"推理"导向——从线索出发逐步得出结论。
2. 如果文档中缺少"排除干扰"的内容，尝试从上下文推断（如：文档中特别强调排除了某种可能性）
3. 如果推断不出，不要编造，标注"文档中未体现"
4. 文档中可能包含多个审计发现，每个发现输出独立的CoT记录

## 输出格式

同标准CoT Schema。

## 案例文档

{案例文档}
```

## 模板4：批量转写稿处理

**适用**：一次性处理多个录音转写文件。

```
你是一位审计方法论研究员。以下包含多个审计讨论/访谈的转写稿，以"=== 文件：XXX ==="分隔。

请对每个文件分别提取CoT记录，输出格式同标准CoT Schema。

每个文件输出后以"---"分隔。

## 转写文件

{多个转写稿文件}
```

## 模板5：快速提取（轻量版）

**适用**：微信群讨论记录、简短的问题分析对话、碎片化经验分享。

```
从以下审计讨论中提取思维链。输出精简版：

{
  "场景": "简短描述",
  "思维链摘要": "发现什么→为什么可疑→排除了什么→判断→定性（一段话概括）",
  "关键发现": "一句话",
  "标签": []
}

## 讨论记录

{简短讨论文本}
```

## 提示词调优建议

### 提高提取质量

1. **提供上下文**：在转写稿前加一句场景说明，如"以下是一位10年经验的审计专家关于XX项目的复盘讨论"
2. **提供领域术语表**：如果转写稿中有行业术语，在提示词中附上简单解释
3. **要求具体的数字**：提示词中强调"保留具体数字/日期/金额，不要模糊化处理"

### 常见问题处理

| 问题 | 处理方式 |
|------|---------|
| 提取过于笼统 | 在提示词中加入"用专家的原话，不要用自己的话概括" |
| 缺少排除干扰 | 追问"最终结论前，专家有没有提到'我本来以为是...'或'排除了...的可能性'？" |
| 多个场景混在一起 | 先让大模型识别有多少个独立发现，再逐一提取 |
| 专业术语理解错误 | 提供术语表或让大模型在不确定时标注"待确认" |
