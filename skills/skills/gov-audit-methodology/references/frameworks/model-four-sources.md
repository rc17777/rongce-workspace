# 审计模型来源四法

> 来源：#74「提升数字化审计模型实效的思考」

## 四源模型

| 来源 | 方法 | 输出物 | 优先级 |
|:--|:-----|:-----|:--:|
| **规章制度** | 从制度条款提取风险点和禁令 | 规则清单 | 🔴 基础 |
| **数据分析** | 数据探索中发现的异常特征模式 | 疑点规则 | 🟡 进阶 |
| **以往问题** | 历年报告/问题清单系统梳理 | 经验规则库 | 🟡 高效 |
| **经验转化** | 经验丰富审计员的预判→数据语言 | 专家模型 | 🟢 稀缺 |

## 各来源操作指南

### 1. 规章制度 → 规则清单
```
制度条款 → 提取"必须"/"禁止"/"不得"/"应当" → 转化为数据校验规则
```
示例：
- 制度："专项资金必须专款专用" → 规则：专项资金账户流出金额 > 0 且收款方非项目方 → 疑点
- 制度："项目资金拨付不超过合同金额的80%" → 规则：累计拨付/合同金额 > 0.8 → 疑点

### 2. 数据分析 → 疑点规则
```
加载数据 → 探索分布 → 发现异常值 → 验证 → 固化为规则
```
示例：
- 同一供应商多次中标且金额刚好低于招标门槛 → 拆分合同规避招标
- 项目支出集中在年底最后一个月 → 突击花钱/虚列支出

### 3. 以往问题 → 经验规则库
```
历年审计报告 → 提取问题清单 → 按类型分类 → 抽象为通用规则
```
融策操作建议：建立Excel规则库，字段包括：
- 规则ID / 规则描述 / 数据源 / 检测逻辑 / 参数阈值 / 来源项目

### 4. 经验转化 → 专家模型
```
资深审计员说："我感觉这个项目有问题" → 追问"为什么" → 显性化判断逻辑 → 编码为模型
```

## 模型生命周期管理

```
创建(规则转化) → 分析(多维判断+参数调优) → 后评估(效果验证) → 退出(失效废弃) / 优化
```

### 模型后评估标准
- 命中率 = 现场确认问题数 / 模型输出疑点数
- 命中率 < 30% → 优化参数
- 命中率 > 80% → 模型成熟，可退出人工复核
- 持续低命中 → 模型失效，废弃

### 模型退出条件
- 制度已变化，规则依据不再成立
- 系统功能已完善，人工操作型问题不再存在
- 命中率持续低于10%
