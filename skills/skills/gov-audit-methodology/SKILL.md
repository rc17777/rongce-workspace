# 政府审计数字化方法论

> 基于「数据化审计」公众号85篇文章提炼的政府审计实战框架。
> 覆盖：绩效评价、资产清查、专项债申报、监督检查、政策跟踪审计。

## 核心原则

**业务是数字化审计之本。** 代码是流淌的检查思路，厘清业务流程和逻辑才能落实在分析中。脱离业务谈数字化审计 = "有吓人的线索，无落地的问题"。

## 五大核心框架

### 框架一：业务穿透三层模型

任何审计项目进场前，按三层穿透，打通"业务→数据"的通道：

1. **制度流程层**：基本规范/业务手册/制度体系/考核体系 → 解决"要查什么"
2. **业务环节层**：人(岗位)/信息(资料)/流程(操作)/系统(工具) → 分解工作流
3. **业务操作层**：交易码/科目/数据/存储位置 → 定位数据源

> 来源：#49「业务是数字化审计之本」

### 框架二：政策跟踪审计三维视角

用于绩效评价和政策跟踪审计，按三维展开分析：

| 维度 | 审计重点 | 对应绩效评价 |
|------|---------|-------------|
| **形式** | 政策文件/会议部署/组织领导/配套制度 | 决策程序合规性 |
| **事实** | 项目进度/资金使用/过程管理 | 产出数量/质量/时效 |
| **价值** | 经济价值+社会价值/是否达预期 | 效益/满意度 |

> 来源：#54「重大政策措施落实情况跟踪审计」

### 框架三：审计问题四步定性法

避免"镜像式"问题（描述现象≠分析根因）：

1. **跳出拟态环境** → 先搞清楚工作流程，不凭印象
2. **从常识和逻辑出发** → 穷举可能原因（不知道/没做/资源不足/系统缺陷）
3. **提出正确的问题** → 区分"现象"和"根因"
4. **数字化思维建议** → 建议要可执行、效果可评估

判断"屡查屡犯"前先确认场景是否变化——系统改进了还出问题，才是真屡查屡犯。

> 来源：#57「如何提出有价值的审计问题」

### 框架四：审计模型来源四法

模型思路从四个方向获取：

1. **向规章制度要思路** → 制度中的风险管理要求和禁令
2. **向数据分析要思路** → 数据探索中发现异常特征
3. **向以往问题要思路** → 历年审计报告/问题清单的沉淀
4. **向经验要思路** → 经验丰富审计员的预判转化为数据语言

模型生命周期：创建(规则转化) → 分析(多维判断) → 后评估(效果验证) → 退出(失效废弃)

> 来源：#74「提升数字化审计模型实效的思考」、#68「孤立点分析」

### 框架五：内控资源承载力

屡查屡犯的根因往往不是执行不力，而是**业务规模超过了内控资源承载力**。

关键判断：梳理业务每个环节需要的资源 → 与机构实际资源对比 → 超越承载力必然偷工减料 → 这些环节才是监控重点。

> 来源：#52「内控资源承载力」

## 审计系统建设避坑

1. **康威定律**：系统会反映开发团队的组织缺陷，业技融合是前提
2. **线性思维做网状需求**：审计工作是网状的，不能用流程化思维设计系统
3. **外延式扩张陷阱**：不停接入新数据源，从不深挖已有数据
4. **可用性 > 超预期**：炫酷仪表盘不如一个准确的疑点推送

> 来源：#60「风控审计系统为什么出道即巅峰」

## 工作流程

```
进场准备 → 业务穿透三层 → 选择分析方法 → 数据采集验证
    → 异常检测/聚类 → 四步法定性问题 → 三维视角写报告
    → 复盘沉淀(更新规则库/经验库)
```
