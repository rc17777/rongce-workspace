# 面向Agent的审计数据标准检查 (Agent Data Standard)

检查审计数据是否"Agent友好"——不是为人类眼睛设计的，而是为机器/AI Agent消费设计的。

## 核心理念

> 文章五大基石之五：过去的数据清洗、指标命名与报表设计，几乎全部以人类可读性为核心导向。当这些数据被直接投喂给AI Agent时，往往导致模型解析崩溃或产生严重幻觉。

**第一服务对象从人类的眼睛转变为机器的接口。**

## 工作流

### 1. 提交数据

```
/agent-data:check [文件路径] [数据描述]
```

支持格式：Excel(.xlsx/.xls)、CSV、数据库表结构、JSON Schema、API文档。

### 2. 自动检查

对数据执行12项Agent友好性检查，分为三个维度：

**结构友好性（Structure）** — 机器能否正确解析数据结构？
**语义友好性（Semantics）** — Agent能否理解每个字段的含义？
**接口友好性（Interface）** — API/数据库接口是否描述清晰？

### 3. 输出报告

生成结构化评估报告：总分 + 分维度得分 + 问题清单 + 改造建议。

## 12项检查清单

详见 [checklist.md](references/checklist.md)。概览：

### 结构友好性（40分）

| # | 检查项 | 扣分条件 |
|---|--------|---------|
| S1 | 无合并单元格 | 存在合并单元格 -10 |
| S2 | 统一日期格式 | 日期格式不统一 -5 |
| S3 | 数值字段为数字类型 | 金额/数量字段为文本 -10 |
| S4 | 无非数据内容 | 表头含标题行/空行/小计行 -10 |
| S5 | 编码一致 | 同一字段存在混用编码 -5 |

### 语义友好性（35分）

| # | 检查项 | 扣分条件 |
|---|--------|---------|
| M1 | 字段名自解释 | 使用无说明的缩写 -10 |
| M2 | 有数据字典 | 缺少字段说明文档 -10 |
| M3 | 枚举值明确 | 状态字段使用数字代码无说明 -5 |
| M4 | 单位标注 | 金额/数量字段无单位 -5 |
| M5 | NULL含义清晰 | 空值含义不明（是0/不适用/缺失？）-5 |

### 接口友好性（25分）

| # | 检查项 | 扣分条件 |
|---|--------|---------|
| I1 | API文档完整 | 缺少参数说明/返回示例 -15 |
| I2 | 分页/限流说明 | 无分页机制说明 -10 |

## 评分等级

| 分数 | 等级 | 含义 |
|------|------|------|
| 90-100 | 🟢 Agent友好 | 可直接投喂给AI Agent进行分析 |
| 70-89 | 🟡 基本可用 | 大部分场景可用，个别字段需人工说明 |
| 50-69 | 🟠 需要改造 | 存在明显障碍，建议改造后再投喂 |
| <50 | 🔴 Agent不友好 | 强行投喂会导致解析崩溃或严重幻觉 |

## 输出示例

```markdown
## 数据Agent友好度评估报告

**数据源**：XX项目资金使用明细.xlsx
**检查时间**：2026-05-26
**综合评分**：52/100 🔴 Agent不友好

### 结构友好性：25/40

🔴 严重问题：
- S1 合并单元格：Sheet"资金明细"第3-5行标题合并 → Agent解析会错位
- S3 数值类型：金额列"C"为文本格式 → 无法自动求和
- S4 非数据行：第1-2行为报表标题 → 需跳过

🟢 通过：
- S2 日期格式统一 ✓
- S5 编码一致 ✓

### 语义友好性：17/35

🔴 严重问题：
- M1 字段缩写：字段"ZJLY"无说明 → Agent无法理解语义
- M2 数据字典：整个工作簿缺少字段说明Sheet

🟡 建议改进：
- M4 单位标注：金额字段未标注单位（元/万元？）

### 接口友好性：10/25

🔴 严重问题：
- I1 无API文档（非接口类数据，部分适用）

### 改造建议（优先级排序）

1. 🔴 拆分合并单元格，表头占一行
2. 🔴 添加"数据字典"Sheet（字段名→中文说明→数据类型→单位）
3. 🔴 金额列转为数字格式
4. 🟡 将字段名"ZJLY"改为"资金来源"或添加注释
5. 🟡 非数据标题行移到单独的说明Sheet

### 改造后预估评分：88/100 🟢
```

## 与 audit-plugin 的集成

数据通过 agent-data-standard 检查改造后，可直接作为 `multi-source-analysis` 的输入，Agent解析准确率显著提升。
