# Reflection — Pre-Delivery Checklist & Session Review Templates

## 🔍 交付前自检清单

### 信息完整性
- [ ] 用户的所有问题/需求是否都已回答？
- [ ] 有没有用户提了但忘记回应的点？
- [ ] 是否覆盖了显性需求 + 潜在的隐性需求？
- [ ] 答复是否包含"下一步建议"？

### 数据准确性
- [ ] 引用数字是否精确（而不是"大约""一些"）？
- [ ] 数字是否有单位（万元/条/%）？
- [ ] 事实来源是否明确（"方案原文""数据清洗结果"）？
- [ ] 没有编造不存在的数据或案例？

### 逻辑清晰度
- [ ] 结论是否放在开头/摘要里？
- [ ] 结构是否按"结论→依据→建议"排列？
- [ ] 有没有不必要的重复或废话？
- [ ] 中英文混排是否规范（中文全角、英文半角、空格）？

### 可行性与实用性
- [ ] 交付物能否被对方直接使用？
- [ ] 文件格式是否通用（.md/.docx/.csv/.png）？
- [ ] 是否需要额外步骤或工具才能用？
- [ ] 是否给出了具体的执行建议？

### 语气与专业度
- [ ] 语气是否匹配对方身份和场景？
- [ ] 有没有不该在正式场合用的表述？
- [ ] 有没有滥用感叹号/表情符号？
- [ ] 如果是客户沟通，是否保持了专业距离？

## ⏱ 快速反思问题集

| 时机 | 问自己 |
|:----|:-------|
| 交付前30秒 | "用户拿到这个，能直接用来做决策/执行吗？" |
| 收到模糊需求时 | "我知道用户真正想要什么吗？要不要先confirm？" |
| 遇到卡住时 | "我试过几种方案了？有没有遗漏的工具或角度？" |
| 数据异常时 | "是我搞错了还是数据本身就异常？怎么验证？" |
| 长对话中途 | "现在还跟得上用户的真实意图吗？有没有跑偏？" |
| 一天结束时 | "今天最有价值的产出是什么？最大的遗憾是什么？" |

## 复盘示例（审计场景）

```
## 工作复盘 2026-04-28

### 今天做了什么
- 停车数据审计佐证提取（62,035条 → 10,330异常 + 7辆超长停车）
- 审计业务合作协议分析（结论：不建议签）
- C盘清理（两轮累计释放 5GB）
- 中银证券脑机接口研报分析（排版工具推断）
- 创建7个skill（illustration-analysis / arch-diagrammer / brainstorming 等）

### 做得好
1. 停车数据清洗逻辑严谨，3分钟出异常清单 → 效率高
2. 合作协议分析有理有据，给出3条具体修改底线 → 实操价值
3. C盘清理分两轮执行，桌面全部恢复整洁

### 能更好
1. PDF解析时花太多时间尝试兼容性方案（pdf2json/pdfjs-dist/pdf-parse都失败了）
   → 下次应该更早切换到binary扫描方案
2. skill创建是集中做的，但brainstorming和reflection缺了配套reference文件
   → 今天补上

### 学到的东西
- @napi-rs/canvas比matplotlib在Windows上更可靠（避开numpy DLL问题）
- ClawHub有429限速，本地创建skill更快
- scheme-chart-analyzer → illustration-analysis 改名体现了更精准的职责

### 待办
- [ ] 补brainstorming和reflection的reference文件
```
