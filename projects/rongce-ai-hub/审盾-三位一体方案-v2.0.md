## 背景

- **公司**：四川融策会计师事务所 + 四川融策工程咨询公司
- **规模**：50-60人
- **业务**：政府审计（绩效评价/经责审计/资产清查/专项债/招投标等12大类）+ 工程咨询
- **现有资产**：RAG审计知识库（17,912 chunks / 3,153文档）、15模型路由体系、79个AI Skills、7Agent审计平台框架
- **战略定位**：融策·审盾 —— 用AI武装的政府财政资金安全与绩效智能守门人
- **一期主责人**：融策平头哥（亲自下场，无Plan B）
- **一期实战场景**：若尔盖审计局"校园餐" + "医保资金"审计项目
- **一期唯一用户**：审计项目经理（B类用户 —— 报告复核）

## 阶段1B：规则引擎验证（第15-60天）

**投入：¥0（仅现有DeepSeek API费用），硬件用现有工作站**

| 维度 | 内容 | 说明 |
|:--|:--|:--|
| **验证范围** | 格式检查（日期/金额/单位一致性）、合计校验、法规引用完整性、附表交叉比对 | 只做规则层面，不碰语义判断 |
| **测试报告** | 10份（5份校园餐+5份医保资金），覆盖不同年份、不同客户格式 | 必须含至少3个不同客户来源 |
| **评估方式** | 人工标注所有AI检出项 → 统计准确率/误报率/漏报率 | 标注人：平头哥本人 |
| **通过标准** | 规则引擎准确率≥95%，误报率≤10% | 未达标：延长至Day 90重测 |
| **数据积累** | 每条人工修正diff存入PostgreSQL + Label Studio | 每天哪怕10条也攒 |
| **Prompt管理** | 建立评估表：每次改prompt记录"改了什么→预期改善什么→实际结果" | 防止调参死循环 |

**每周节奏**：
- **周一**：跑本周new reports的AI复核
- **周三**：人工标注 + 修正prompt
- **周五**：输出周报（采纳率趋势图 + 失效模式变化）
- **每日**：早8点打卡"今日计划"，晚8点打卡"今日完成"

**里程碑M1（Day 60）交付物**：
- ✅ 10份报告的规则引擎盲测结果（准确率≥95%）
- ✅ 至少200条高质量标注数据
- ✅ Prompt改进日志（至少6轮迭代记录）

## 阶段2B：3条业务线深度打磨（第4-9个月）

# 关键管理机制

## 验证节点与决策门

```
Day 0 ── Day 14 ── Day 60 ── Day 90 ──── Day 180 ──── Month 18
  │        │         │         │            │              │
  │    M0:白皮书  M1:规则    M2:语义     M3:3线实战    Phase 2
  │    +基线     引擎95%    三指标       ≥10人用       通过验收
  │              准确率     达标         效率+30%
  │
  └── 每日打卡（永不间断）──┘
```

## 止损机制

| 节点 | 如果未达标 | 执行动作 |
|:--|:--|:--|
| Day 90 三指标不达标 | 延长30天 | 不招人，继续优化prompt |
| Day 180 3线不达标 | **不进入Phase 2** | 维持1人+API，作为"AI辅助工具集"低成本运行，不扩团队不买硬件 |
| Phase 2 第3月 采纳率未涨 | 缩减为2条线 | 砍掉效果最差的那条 |
| Phase 2 第12月 私测失败 | **不进入Phase 3** | 仅维持对内使用，放弃对外输出 |

## 每条评审线必须满足的合规底线

1. **AI输出分级**：L1格式检查（自动通过）/ L2内容建议（需人确认）/ L3结论性意见（双人复核）
2. **溯源水印**：每份AI处理底稿附带模型版本+Prompt哈希+处理时间+置信度
3. **人工签字**：审计人员签字确认时需同时确认"已审阅AI辅助内容"
4. **回滚机制**：AI辅助结论可一键撤销并标记
