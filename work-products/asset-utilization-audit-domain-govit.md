## 一、政务信息化资产类型与数据源映射

### 1.1 资产全景

```
┌─────────────────────────────────────────────────────────────────┐
│                    政务信息化资产地图                              │
├──────────────────┬──────────────────┬───────────────────────────┤

├──────────────────┼──────────────────┼───────────────────────────┤

│ OA协同办公系统     │ 电子证照库         │ 机房/UPS/动环              │

│ 政务APP/小程序    │                   │                           │
└──────────────────┴──────────────────┴───────────────────────────┘
```

### 1.2 关键特点

政务信息化的资产使用率审计有三个独特难度（也是三个机会）：

1. **没有"物理产品"**——不像教育有课表、医疗有病人，政务系统的"使用"需要从系统日志、办件量、用户活跃度中间接推断
2. **建设方和运营方分离**——系统是厂商建的，但用不用、怎么用是政府部门的事——闲置的责任归属需要分清
3. **审计署已经开了路**——2026年审计署公告对"系统闲置"的定性从"使用效率不高"升级为"财政资金损失浪费"，标准已经在那里了

## 二、政务信息化数据生态——一张图看懂

政务信息化系统的数据可采性取决于**它处于什么位置**：

```
                互联网端（外部用户）
                      │
              ┌───────┴────────┐
              │  政务服务网     │
              │  (办件入口)     │
              │  政务APP/小程序  │
              └───────┬────────┘
                      │
              ┌───────┴────────┐
              │  统一身份认证    │  ← 所有外部用户的统一入口
              │  (IAM/单点登录) │    登录日志=所有系统的用户基数
              └───────┬────────┘
                      │
        ┌─────────────┼─────────────┐
        │             │             │
  ┌─────┴─────┐ ┌─────┴─────┐ ┌─────┴─────┐
  │ 行政审批  │ │ 公共服务  │ │ 监管执法  │
  │ 系统      │ │ 系统      │ │ 系统      │
  └─────┬─────┘ └─────┬─────┘ └─────┬─────┘
        │             │             │
        └─────────────┼─────────────┘
                      │
              ┌───────┴────────┐
              │  数据共享交换    │  ← 系统间数据流通的管道
              │  平台(ESB/API)  │    调用量=系统是否在"被人用"
              └───────┬────────┘
                      │
              ┌───────┴────────┐
              │  政务云平台      │  ← 资源使用率
              │  (IaaS/PaaS)   │    CPU/内存/存储/带宽
              └────────────────┘

                政务外网（内部用户）
                      │
              ┌───────┴────────┐
              │  统一身份认证    │
              │  (内部用户)     │
              └───────┬────────┘
                      │
        ┌─────────────┼─────────────┐
        │             │             │
  ┌─────┴─────┐ ┌─────┴─────┐ ┌─────┴─────┐
  │ OA办公    │ │ 业务系统  │ │ 数据中台  │
  │ 系统      │ │ (内部)    │ │ BI/报表   │
  └───────────┘ └───────────┘ └───────────┘
```

**核心数据入口优先级：统一身份认证日志（覆盖所有系统）> 政务服务网办件量（外部使用）> 数据共享交换调用量（系统间调用）> 各系统自身日志 > 政务云资源使用率**

## 三、分资产类型的硬数据采集方案

### 3.1 政务服务一体化平台/行政审批系统

> 这是政务信息化的"门面系统"，也是审计署公告中高频出现的闲置重灾区。

| 数据源 | 采集方式 | 关键字段 | 分析要点 |
|--------|---------|---------|---------|
| **办件量统计**（最核心）| 政务服务网后台/电子监察系统 | 事项名称、申请时间、办结时间、办理部门、办件状态 | 办件量=系统存在价值的直接证据。零办件量=零使用价值 |
| **统一身份认证登录日志** | IAM/单点登录系统 | 登录时间、用户ID、用户类型（个人/法人）、登录IP、登录方式 | 实名认证的自然人/法人登录量——排除测试账号和运维账号后的真实用户数 |
| **Web服务器访问日志** | Nginx/Apache/网关 | 时间戳、URL、HTTP方法、状态码、客户端IP | 区分机器人流量和真实用户：User-Agent分析、请求间隔分析 |
| **电子证照调用量** | 电子证照库→调用统计 | 证照类型、调证次数、用证部门、用证事项 | 政务服务网的核心产出之一是证照调用——调用量低=整个平台没在跑 |

**判定标准：**

| 指标 | 🟢 正常 | 🟡 关注 | 🟠 预警 | 🔴 严重 |
|------|---------|---------|---------|---------|
| 月均办件量（vs 同地区同级平台）| ≥中位数的80% | 60-79% | 30-59% | <30% |
| 月活跃用户数（排除运维/测试账号）| ≥户籍人口的5% | 2-4.9% | 0.5-1.9% | <0.5% |
| 事项覆盖率（已上线事项÷应上线事项）| ≥95% | 80-94% | 50-79% | <50% |
| 网上办理率（网办件÷总办件）| ≥80% | 60-79% | 30-59% | <30%（系统建了，人还是跑线下大厅）|
| 好差评覆盖率 | ≥90% | — | — | <50%（系统好不好用，用户说了算）|

**交叉验证重点：** 政务服务网办件量（平台统计）× 统一身份认证登录量（独立于平台）× 电子证照调用量（独立于平台）→ 办件量只存在于平台自身统计但IAM无对应登录 = 数据造假嫌疑

### 3.2 OA协同办公系统

| 数据源 | 采集方式 | 关键字段 |
|--------|---------|---------|
| OA后台统计 | OA管理后台→使用统计 | 日活用户数、月活用户数、发文量、收文量、流程发起数、流程办结数 |
| 统一身份认证（内部）| IAM→内部用户登录日志 | 用户账号、登录时间、登录IP |
| 数据库审计日志 | 数据库→连接/查询日志 | 业务表的SELECT/INSERT/UPDATE频率（非系统表）|

**判定标准：**

| 指标 | 🟢 正常 | 🟡 关注 | 🔴 严重 |
|------|---------|---------|---------|
| 日活用户数/编制人数 | ≥60% | 30-59% | <30% |
| 月均流程发起数（vs 同规模单位）| ≥中位数 | — | <中位数的30% |
| 发文量（vs 如果"纸质发文量依然很大"）| 电子≥纸质 | 电子≈纸质 | 电子<<纸质（系统有，不用=双轨运行=浪费）|
| 功能模块使用覆盖率 | ≥80% | 50-79% | <50%（审计署公告："部分功能从未启用"）|

**交叉验证重点：** OA统计（活跃用户）× IAM登录日志（真实登录）× 数据库查询日志（后台操作）→ OA统计的用户活跃度是否与IAM和数据库记录一致

### 3.3 数据共享交换平台

> 这恰恰是审计署公告中容易忽视的盲区——平台本身"在运行"（一直通着电），但上面跑的数据量趋近于零。

| 数据源 | 采集方式 | 关键字段 |
|--------|---------|---------|
| 交换平台管理后台 | ESB/API网关→调用统计 | 接口名称、调用次数、调用方、提供方、数据量、响应时间 |
| API网关日志 | 网关→访问日志 | API路径、调用方式、请求/响应、状态码 |
| 数据库连接池监控 | 数据库→连接会话数 | 活跃连接数、等待连接数 |

**判定标准：**

| 指标 | 🟢 正常 | 🟡 关注 | 🔴 严重 |
|------|---------|---------|---------|
| 日均接口调用次数 | ≥1000次 | 100-999次 | <100次 |
| 有调用的接口数 ÷ 已注册接口数 | ≥60% | 20-59% | <20% |
| 日均数据交换量 | ≥1GB | 10MB-1GB | <10MB |
| 有数据更新的数据源 ÷ 已接入数据源 | ≥80% | 40-79% | <40% |

**交叉验证重点：** 交换平台调用量（平台层）× 调用方的业务日志（应用层）→ 同一个接口被调用的记录在两个系统里是否一致

### 3.4 视频会议系统

| 数据源 | 采集方式 | 关键字段 |
|--------|---------|---------|
| MCU/视频会议控制平台 | 管理后台→会议统计 | 会议ID、会议主题、主持人、参会方数、开始时间、结束时间、会议时长 |
| 会议室预订系统 | 预订系统→预订记录 | 预订人、预订时间、会议室、会议主题 |
| 终端设备在线记录 | 终端管理→在线状态日志 | 终端型号、在线时间段、呼叫记录 |

**判定标准：**

| 指标 | 🟢 正常 | 🔴 严重 |
|------|---------|---------|
| 月均会议场次（vs 机构层级/人员规模）| 地市级≥20场/月 | <5场/月 |
| 终端在线率 | ≥90% | <50% |
| 会议室预订率 | ≥50% | <10%（预订记录与MCU会议记录应该一致）|

### 3.5 大屏/指挥中心

> 审计署公告里"内蒙古政务大厅48块大屏花227万只给领导参观"的典型。大屏是政务信息化中最容易出"面子工程"的品类。

| 数据源 | 采集方式 | 关键字段 |
|--------|---------|---------|
| 大屏控制系统日志 | 拼接控制器→开关机记录 | 开机时间、关机时间、信号源 |
| 大屏内容管理系统 | 后台→内容发布记录 | 内容更新频率、展示内容类型 |
| 指挥中心值班记录 | 纸质/电子值班记录 | 值班日期、值班人员、事件记录 |

**判定标准：**

| 指标 | 🔴 严重（直接定性）|
|------|-------------------|
| 大屏日均开机时长 < 1小时 | 仅用于领导参观 |
| 展示内容超过30天未更新 | 内容无人维护 |
| 零值班事件记录 + 零实操调度 | 形式化存在 |

**交叉验证重点：** 大屏开机日志（物理通电）× 内容更新记录（有人维护）× 指挥中心事件记录（有指挥场景）→ 缺任何一环=面子工程

### 3.6 政务云资源（IaaS/PaaS）

> 政务信息化特有的浪费形式：云资源买多了、配大了、不用也不释放——按需付费变成按量付费，弹性伸缩变成固定预留。

| 数据源 | 采集方式 | 关键字段 |
|--------|---------|---------|
| 云管平台资源使用统计 | 云管后台→资源监控 | CPU使用率、内存使用率、磁盘IO、网络带宽 |
| 云费用账单 | 云服务商→月度账单 | 各资源规格、使用时长、费用 |
| CMDB/资产清单 | CMDB系统→资源清单 | 虚拟机清单、配置规格、所属系统/项目 |

**判定标准：**

| 指标 | 🟢 正常 | 🟡 关注 | 🔴 严重 |
|------|---------|---------|---------|
| CPU平均使用率 | 30-70% | 10-29% | <10%（超配严重）|
| 内存平均使用率 | 30-70% | 10-29% | <10% |
| 磁盘使用率 | 30-70% | — | <5%（买500G只用了20G）|
| 持续低负载的资源数占比 | <10% | 10-30% | >30%（大量资源闲置）|
| 存在但无任何流量的IP/域名数 | 0 | — | >0（资源分配了但从未使用）|

### 3.7 政务信息化特有的闲置高发区

| 高发类型 | 闲置原因（行业通病）| 审计切入点 |
|---------|------------------|-----------|
| **"一锅端"大平台** | 一次性建成所有子系统→业务部门没准备好→部分模块从未启用 | 分模块统计使用率→已上线功能 vs 合同约定功能对比 |
| **上级要求建，下级不想用** | 省级统建、市县推广→基层业务流程不匹配→用不起来 | 查看各级使用率差异→使用率为零的层级→远程访谈原因 |
| **系统验收后断崖式衰退** | 厂商验收走人→政府没运维能力→系统逐渐瘫痪 | 验收后第1个月 vs 第6个月 vs 第12个月的使用率趋势 |
| **重复建设** | A部门建了B部门又建→功能重叠→总有一个没人用 | 对比多个系统的功能清单→重叠功能→使用率低的一方判定为重复建设 |
| **僵尸APP/小程序** | 花几十万开发APP，发布后再没更新过→日活趋近于零 | 应用商店最后更新时间→月活/日活数据→版本迭代记录 |
| **培训不到位导致"软闲置"** | 系统功能齐全但办事人员只用其中最简单的功能 | 功能模块级使用率→高级功能零调用→系统价值未充分释放 |

## 四、政务信息化三层交叉验证矩阵（领域适配版）

在原版8种判定模式基础上，政务信息化新增4种专用验证模式：

| 编号 | 办件量/业务量 | IAM登录/认证 | 数据交换/API调用 | 判定结论 |
|------|------------|------------|----------------|---------|
| L | ❌ 零办件 | ❌ 零真实用户登录 | ❌ 零API调用 | 🔴 **系统完全闲置**——最严重，等同于"没上线" |
| M | ✅ 有办件 | ❌ 零IAM登录 | ❌ 零API调用 | 🔍 **办件量造假嫌疑**——如果用户不登录怎么办的件？|
| N | ❌ 零办件 | ✅ 有IAM登录 | ✅ 有API调用 | 🟠 **系统在运行但无业务产出**——可能是内部测试/巡检脚本 |
| O | ✅ 办件量断崖下降（验收后）| ✅ IAM登录同步下降 | ✅ API调用同步下降 | 🔴 **验收后闲置**——典型模式：上线→验收→无人管→逐渐废弃 |

## 五、"活用户 vs 假活跃"识别方法

政务信息化系统最常见的误导：运维脚本定期登录、数据同步进程一直跑着 → 系统看起来"有登录、有流量" → 实际上是机器在用，不是人在用。

### 5.1 识别清单

| 识别维度 | "假活跃"信号 | 验证方法 |
|---------|------------|---------|
| 登录时段 | 凌晨2:00-4:00、周末固定时间 | 核对是否为定时任务/备份/巡检 |
| 登录IP | 固定1-2个IP（内网运维段）| 排除已知运维IP和设备IP |
| 操作类型 | 只有"登录→查看→退出"、从未提交实质性操作 | 日志深度分析：有POST/PUT请求吗？没有=浏览型 |
| 会话时长 | 固定时长（如恰好30分钟）| 人的操作随机波动，机器固定 |
| User-Agent | 脚本类UA（curl/python-requests/go-http）| 排除所有非浏览器客户端 |
| 用户账号后缀 | admin/test/devops/root | 排除运维和技术类账号 |
| 数据变动 | 数据库有SELECT无INSERT/UPDATE | 只读不写=没有业务操作 |

### 5.2 真实用户判定公式

```
真实用户活跃度 = 排除以下后的活跃账号数：
  - 运维/管理账号（admin/devops/root/system后缀）
  - 非工作时间活跃但持续时长<1分钟的账号
  - 同一IP登录>10个账号的IP
  - 固定IP+固定时长+无实质性操作的账号
  - User-Agent非浏览器的请求
```

## 六、政务信息化审计数据采集清单（速查版）

```
□ 1. 项目立项批复、可行性研究报告、初步设计（含系统功能清单）
□ 2. 软件开发/集成采购合同、验收报告
□ 3. 统一身份认证(IAM)系统登录日志（至少1年，区分内外部用户）
□ 4. 政务服务网/各业务系统后台办件量统计（至少1年，按事项和部门分）
□ 5. 各系统Web/应用服务器访问日志（至少6个月原始日志）
□ 6. 数据共享交换平台/API网关调用统计（至少1年）
□ 7. 电子证照库调用量统计
□ 8. 政务云平台资源使用率监控数据（CPU/内存/磁盘/带宽，至少6个月）
□ 9. OA系统使用统计（日活/月活/流程量/发文量）
□ 10. 视频会议MCU会议统计
□ 11. 大屏/指挥中心开关机日志、值班记录
□ 12. IT运维工单系统记录（故障报修、变更、巡检）
□ 13. 系统运维费/云服务费年度账单
□ 14. 驻场运维人员考勤/工作日志
□ 15. 应用商店/小程序后台用户统计（日活/月活/版本历史）
□ 16. 好差评系统数据
□ 17. 网络安全等保测评报告（含系统资产清单）
□ 18. 数据库审计日志（业务表操作频率）
□ 19. "僵尸"账号清单（连续>90天未登录的账号数）
□ 20. 上级统建系统的推广使用通知/督办文件
```

## 七、政务信息化领域的审计报告措辞参考

基于2026年审计署公告的口径升级，以下表述可直接使用或适配：

```
【系统完全闲置】
"XX系统自XXXX年XX月验收以来，办件量为零，月均活跃用户数
为零，实际处于闲置状态。该项目合同金额XXX万元，财政资金
```
