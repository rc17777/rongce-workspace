# 资产使用率审计检查清单（硬数据驱动版）

> **版本：** v1.0 | **日期：** 2026-07-22 | **适用场景：** 政府采购设备/信息化系统绩效审计、资产专项审计、财政资金使用效益评价

---

## 一、总则

### 1.1 适用范围

| 资产类别 | 典型示例 |
|---------|---------|
| 信息化软件平台 | 政务服务平台、OA系统、业务管理系统、数据中台 |
| IT硬件设备 | 服务器、存储、网络设备、安全设备 |
| 智慧城市设施 | 大屏显示系统、视频监控、物联网传感器 |
| 通用办公设备 | 打印机/复印机、投影仪、会议一体机 |
| 专用设备 | 实验室仪器、医疗设备、检测设备、特种车辆 |

### 1.2 审计依据

- 《中华人民共和国审计法》及其实施条例
- 《行政事业性国有资产管理条例》
- 审计署年度审计公告（2026年发布口径："财政资金面临损失浪费风险"）
- 《政府会计准则——固定资产》
- 项目立项批复、采购合同、验收报告

### 1.3 核心审计逻辑

```
验收 ≠ 资产发挥作用
资产发挥作用 = 被实际使用 + 产生预期效益

硬数据驱动逻辑：
系统日志 + 电力数据 + 网络流量 → 三源交叉验证 → 不可抵赖的使用状态判定
```

### 2.1 系统/设备运行日志

#### 采集清单

| 序号 | 资产类型 | 目标日志源 | 必采字段 | 采集方式 | 责任人 |
|------|---------|-----------|---------|---------|--------|
| 1.1 | 信息化系统（Web类） | Web服务器access log（Nginx/Apache/IIS） | 时间戳、URL路径、HTTP方法、响应状态码、客户端IP、User-Agent、会话ID | 要求被审计单位IT部门导出原始日志文件（.log/.gz），指定起止时间范围 | |
| 1.2 | 信息化系统（应用层） | 应用服务器操作日志/审计日志 | 用户ID、登录时间、退出时间、操作类型、操作对象、结果状态 | 通过应用后台"审计日志"模块导出CSV/Excel | |
| 1.3 | 数据库系统 | 数据库审计日志/Slow Query Log | 连接时间、用户名、SQL类型（SELECT/INSERT/UPDATE/DELETE）、执行次数 | 数据库管理员导出，重点查看业务表（非系统表）的查询记录 | |
| 1.4 | 智慧教室/会议系统 | 中控系统日志 | 设备ID、开机时间、关机时间、信号源选择、音量调节 | 中控管理后台 → 历史记录导出 | |
| 1.5 | 服务器/云主机 | 操作系统syslog（Linux: /var/log/; Windows: 事件查看器） | 启动时间、关机时间、用户登录事件、进程启动/停止 | SSH/RDP登录后导出，或通过堡垒机审计日志间接获取 | |
| 1.6 | 监控摄像/大屏 | 控制器/NVR日志 | 录像开关、通道状态、画面显示记录 | NVR管理界面 → 日志导出 | |
| 1.7 | 安全/网络设备 | 设备自身syslog/SNMP Trap | 接口UP/DOWN、流量统计、配置变更时间 | 网管平台或设备CLI导出 | |

#### 采集注意事项

- ⚠️ **优先取服务器端日志，不取客户端日志**——客户端日志易被清除或篡改
- ⚠️ **指定精确时间范围**：从资产验收日期至审计基准日，覆盖完整周期
- ⚠️ **保留原始文件**——不接收截图或二次加工后的Excel
- ⚠️ **核对日志时间是否与NTP同步**——时间偏差可能导致误判

### 2.2 电力消耗数据

#### 采集清单

| 序号 | 数据来源 | 必采字段 | 粒度要求 | 采集方式 |
|------|---------|---------|---------|---------|
| 2.1 | 智能电表分路数据 | 回路编号、对应区域/设备、时间戳、电压(V)、电流(A)、功率(kW)、电量(kWh) | 小时级（最低）；天级可接受 | 能源管理系统导出CSV |
| 2.2 | 机房UPS输出日志 | 输出功率、负载率(%)、电池状态、输入/输出电压 | 分钟级（理想）；小时级可接受 | UPS管理卡Web界面或SNMP采集 |
| 2.3 | 机房动环监控 | 机柜/区域温度、湿度、电流、功率 | 小时级 | 动环系统历史数据导出 |
| 2.4 | 配电柜接线图 | 各回路对应的物理区域和设备清单 | — | 物业/后勤部门提供，现场核对 |
| 2.5 | 电费缴纳记录 | 每月总用电量、电费金额 | 月级 | 财务部门提供电费发票/缴纳凭证副本 |

#### 分析方法

```
步骤1：建立设备功耗基线
  → 查询设备铭牌额定功率 / 技术规格书的典型功耗
  → 区分"满载功耗""典型功耗""待机功耗"三档

步骤2：反推通电时长
  → 对应回路日用电量 ÷ 设备额定功率 ≈ 日均通电小时数

步骤3：异常判定
  → 日均功耗 ≤ 待机功耗 × 1.2 → 设备从未进入工作状态 → 直接定性"闲置"
  → 日均功耗在待机与满载之间波动 → 属于正常使用状态
  → 日均功耗 > 满载功耗 × 1.5 → 数据异常，需核对计量回路是否包含其他设备
```

#### 采集注意事项

- ⚠️ **先要配电柜接线图**——确认回路和设备对应关系，防止"回路串了"
- ⚠️ **排除非目标设备**——同一回路可能接了空调、照明等，需现场核实
- ⚠️ **注意季节性差异**——空调、采暖等季节性负载会干扰判断，取全年均值
- ⚠️ **关注异常断电**——月度电量为零 → 设备根本没通电

### 2.3 运维工单系统

#### 采集清单

| 序号 | 数据项 | 必采字段 | 采集方式 |
|------|--------|---------|---------|
| 3.1 | 报修/故障工单 | 工单编号、创建时间、故障设备/系统名称、故障描述、处理状态、处理人、关闭时间 | ITSM/工单系统导出全部工单（不限状态） |
| 3.2 | 巡检记录 | 巡检时间、巡检对象、巡检人、巡检结果、异常描述 | 运维部门巡检台账或ITSM定时任务记录 |
| 3.3 | 系统变更记录 | 变更时间、变更内容、变更原因、审批人、执行人 | ITIL变更管理模块导出 |
| 3.4 | 资产报废/处置申请 | 申请时间、资产编号、报废原因、审批状态 | 资产管理系统导出 |

#### 分析维度

| 分析项 | 计算公式/方法 | 异常信号 |
|--------|-------------|---------|
| 工单密度 | 工单总数 ÷ 资产在用月数 | 同类资产排名后20% → 疑点 |
| 零工单资产 | 上线≥12个月，工单数=0 | 🔴 重点核查 |
| 工单关键词扫描 | 热词提取："闲置""不用""没培训""启动不了""密码忘了" | 每条包含关键词的工单 → 逐个追溯 |
| 工单平均处理时长 | 关闭时间 - 创建时间 | 平均处理时长异常长 → 运维不到位，间接影响使用 |
| 巡检覆盖率 | 实际巡检次数 ÷ 应巡检次数 | <50% → 运维失控，资产状态不明 |

### 2.4 网络流量日志

#### 采集清单

| 序号 | 数据来源 | 必采字段 | 采集方式 |
|------|---------|---------|---------|
| 4.1 | 防火墙/核心交换机流量日志 | 时间戳、源IP、目标IP、协议、上行流量(bytes)、下行流量(bytes)、会话数 | NetFlow/sFlow/netflow采集器导出 |
| 4.2 | 无线AP/AC日志 | MAC地址、关联时间、解除关联时间、SSID、信号强度 | AC管理界面 → 客户端统计导出 |
| 4.3 | DNS查询日志 | 查询时间、查询域名、客户端IP、解析结果 | DNS服务器日志导出 |
| 4.4 | 堡垒机/运维审计日志 | 登录时间、用户、目标服务器IP、操作指令、会话时长 | 堡垒机管理界面 → 审计日志导出 |

#### 分析指标

| 指标 | 计算方式 | 正常区间参考 |
|------|---------|------------|
| 日均活跃IP数 | 每日有网络请求的唯一源IP数量 | 业务系统 ≥ 用户数的10% |
| 日均请求量 | 每日HTTP请求总数（GET+POST） | 同类系统横向对比 ±50% |
| 活跃时段分布 | 按小时统计请求量 | 应与工作时间一致；凌晨大量请求 → 爬虫/脚本 |
| 内部 vs 外部流量比 | 内网IP流量 ÷ 外网IP流量 | 政务系统外部流量应占主体 |
| 流量断崖检测 | 连续N天流量 < 基准流量的5% | N ≥ 30天 → 闲置信号 |

## 三、三层交叉验证矩阵

### 3.1 核心原理

```
单一数据源 → 可信度 50%
双数据源交叉 → 可信度 75%
三数据源交叉（日志+电力+流量）→ 可信度 95%+
```

三源交叉意味着：被审计单位想要掩盖"闲置"，必须同时伪造三个独立系统的数据——这在技术和管理上成本极高，绝大多数情况下不可行。

### 3.2 判定矩阵

| 编号 | 系统日志（登陆/操作）| 电力数据（功耗）| 网络数据（流量）| 判定结论 | 审计行动 |
|------|-------------------|---------------|---------------|---------|---------|
| A | ✅ 持续活跃 | ✅ 典型功耗 | ✅ 持续流量 | **正常使用** | 通过 |
| B | ❌ 零活跃 | ✅ 待机功耗 | ❌ 零流量 | **闲置（通电未用）** | 取证→确认→计算损失 |
| C | ❌ 零活跃 | ❌ 零功耗 | ❌ 零流量 | **闲置（物理断电/搬迁）** | 🔴 立即现场核查资产实物 |
| D | ❌ 零活跃 | ✅ 典型功耗 | ✅ 持续流量 | **疑似日志缺失或卸载** | 进一步排查：是否系统升级后日志模块未配置 |
| E | ✅ 活跃记录 | ❌ 待机功耗 | ❌ 零流量 | **疑似日志造假** | 🔴 重点核查：疑似脚本模拟登录 |
| F | ✅ 活跃记录 | ✅ 典型功耗 | ❌ 零流量 | **离线系统/内网隔离** | 确认网络架构：是否纯内网运行不走网关 |
| G | ⚠️ 间歇活跃（前3月有/后清零）| ⚠️ 功耗断崖下降 | ⚠️ 流量断崖下降 | **上线后闲置（断崖式）** | 🔴 直接定性："验收后即闲置" |
| H | ⚠️ 仅工作日9:00有1次登录 | ✅ 待机功耗 | ⚠️ 极小流量 | **"做给审计看"式假活跃** | 🔴 重点核查：自动化维护脚本 |

### 3.3 交叉验证流程

```
步骤1：采集三源数据
  → 对每一台/套目标资产，至少获取日志+电力+流量三类数据中的两类
  → 如仅能获取一类 → 在审计底稿中标注"证据不足，结论受限"

步骤2：时间轴对齐
  → 三类数据统一到同一时间粒度（推荐"天"级）
  → 对齐时区、处理缺失值

步骤3：匹配判定矩阵
  → 逐日、逐周匹配3.2矩阵
  → 自动标记异常模式（使用融策"时间序列异常检测"工具）

步骤4：生成疑点清单
  → 异常天数占比 > 评估阈值的资产列入疑点清单
  → 按金额从大到小排序，优先核查高价资产

步骤5：现场验证
  → 携带疑点清单进行实地盘点
  → 核对实物位置、物理状态、操作人员访谈
```

## 四、判定标准与分级

### 4.1 使用率分级标准

| 等级 | 月活跃天数占比 | 深度使用率 | 功能模块覆盖率 | 审计评价 |
|------|-------------|-----------|-------------|---------|
| 🟢 正常 | ≥ 80% | ≥ 70% | ≥ 80% | 资产有效利用 |
| 🟡 关注 | 50%–79% | 40%–69% | 50%–79% | 使用率偏低，建议优化 |
| 🟠 预警 | 10%–49% | 10%–39% | 20%–49% | 存在闲置风险，建议核查原因 |
| 🔴 严重 | < 10% | < 10% | < 20% | 判定为闲置，构成"未发挥效益"→ "财政资金损失浪费"|

### 4.2 金额分级标准

| 等级 | 单资产/系统合同金额 | 处置建议 |
|------|-------------------|---------|
| 🔴 重大 | ≥ 1000万元 | 必须出具专项审计意见，建议追责 |
| 🟠 较大 | 100万–999万元 | 列入审计报告重点问题 |
| 🟡 一般 | 10万–99万元 | 列入管理建议书 |
| 🟢 关注 | < 10万元 | 汇总分析，作为趋势判断依据 |

### 4.3 闲置时长分级

| 等级 | 连续无活跃天数 | 审计评价 |
|------|-------------|---------|
| 🔴 极端 | ≥ 365天（1年以上）| 构成事实闲置，按合同金额全额或高比例认定损失 |
| 🟠 严重 | 180–364天（半年至1年）| 高度疑似闲置，建议核实是否已搬迁/处置 |
| 🟡 一般 | 90–179天（3–6个月）| 阶段性闲置，需了解原因（如项目建设期中断） |
| 🟢 正常 | < 90天 | 在项目建设的正常间歇期内 |

## 附录B：常见问题与应对

| 问题 | 被审计单位可能说 | 应对策略 |
|------|----------------|---------|
| 没有日志 | "系统没有开日志功能" | ① 检查操作系统级syslog（独立于应用）；② 用电力数据替代；③ 记录为"审计范围受限" |
| 日志被清除 | "日志只保留3个月" | ① 从备份服务器/归档存储调取；② 核实日志清除策略是否符合《网络安全法》21条（要求≥6个月） |
| 电表没分路 | "电表是总的，没分到设备" | ① 现场加装临时分路计量；② 用UPS日志替代（如适用）；③ 用网络流量数据替代 |
| 系统已经关了 | "那个系统早就不用了，服务器都关机了" | ① 这就是你要的证据——直接确认为闲置；② 追问何时停用、谁决定停用 |
| 数据"涉密"不可提供 | "日志涉及安全，不能给" | ① 要求在不含敏感字段的前提下提供脱敏版本；② 在现场环境下进行分析，数据不带走 |
| 外包运维，数据在供应商那 | "系统是XX公司运维的，我们没有权限" | ① 要求乙方配合提供（合同里通常有配合审计条款）；② 查看合同原件确认权责 |
