## 一、先懂核心：大数据审计SQL核心原则

审计用SQL和普通数据查询不一样，核心是"找异常、抓疑点、留痕迹"，牢记3个原则：

- 只查需要字段，不滥用SELECT * ：大数据量下全表查询极慢，精准筛选字段，提升运行速度，避免冗余数据干扰；
- **先清洗后分析**：提前剔除空值、异常测试数据（如手机号12345678901、金额为负无效数据），保证结果准确；
- **分组聚合+多表关联优先**：审计疑点多藏在关联关系和统计异常中，少逐行遍历，多用分组、关联、窗口函数定位。

## 二、5大实战技巧+完整代码案例（直接套用）

### 技巧1：重复数据筛查——揪出重复报销、重复发放、重复入账

**适用场景**：差旅费重复报销、补贴重复发放、费用重复入账、供应商重复付款等高频违规问题，是审计入门必查项。

**核心逻辑**：通过 **GROUP BY+ HAVING**，对"同一人+同金额+同日期+同摘要"等关键维度分组，统计出现次数大于1的记录。

#### 实操代码（差旅费重复报销筛查）

```sql
-- 数据清洗：先剔除无效、作废凭证
WITH clean_voucher AS (
  SELECT * FROM 凭证明细表
  WHERE 作废标识 ='否'
    AND 借方金额 >0
    AND 人员姓名 IS NOT NULL
)
-- 筛查重复报销疑点：同一人、同日、同金额、同差旅事由重复记录
SELECT
  人员姓名,
  凭证日期,
  借方金额 AS 报销金额,
  摘要,
  凭证号,
  COUNT(*) AS 重复次数
FROM clean_voucher
WHERE 摘要 LIKE '%差旅费%' OR 摘要 LIKE '%住宿%' OR 摘要 LIKE '%交通%'
GROUP BY 人员姓名, 凭证日期, 借方金额, 摘要
HAVING COUNT(*) >1
ORDER BY 重复次数 DESC, 报销金额 DESC;
```

**疑点解读**：查询结果中，重复次数越多、金额越大，违规嫌疑越高，重点核查是否存在一笔差旅多次报销、虚假报销的情况，后续可关联原始凭证和出差审批单核实。

### 技巧2：多表关联比对——跨数据源找利益输送、账实不符

**适用场景**：招标采购审计（供应商与内部员工关联）、财务业务比对（账上支出与实际业务不符）、医保审计（结算数据与进销存不符）。

**核心逻辑**：通过身份证号、供应商名称、员工编号等关键字段，打通多张数据表，挖掘隐藏关联关系。

#### 实操代码（招标围标串标+员工关联供应商筛查）

```sql
-- 步骤1：关联分包采购表、供应商联系人表、员工信息表
WITH supplier_emp AS (
  SELECT
    a.招标方案名称,
    a.招标金额,
    a.中标金额,
    b.单位名称 AS 中标供应商,
    b.现场负责人姓名,
    b.现场负责人身份证号,
    c.员工姓名 AS 内部员工,
    c.所在部门 AS 员工部门
  FROM 分包采购信息表 a
  LEFT JOIN 供应商联系人表 b
    ON a.参与供应商名称 = b.单位名称
  LEFT JOIN 员工信息表 c
    ON b.现场负责人身份证号 = c.身份证号
  WHERE a.是否中标 = '是'
)
-- 步骤2：筛查同一项目多个供应商为同一人、供应商负责人为内部员工的疑点
SELECT
  招标方案名称,
  中标供应商,
  现场负责人姓名,
  内部员工,
  员工部门,
  中标金额
FROM supplier_emp
-- 条件1：供应商负责人为单位内部员工（利益输送疑点）
WHERE 内部员工 IS NOT NULL
-- 条件2：同一项目多个供应商共用同一负责人（围标串标疑点）
   OR 现场负责人身份证号 IN (
     SELECT 现场负责人身份证号
     FROM supplier_emp
     GROUP BY 招标方案名称, 现场负责人身份证号
     HAVING COUNT(DISTINCT 中标供应商) >1
   )
ORDER BY 中标金额 DESC;
```

**疑点解读**：中标供应商负责人是内部员工，大概率存在利益输送；同一项目多个供应商为同一人操控，基本锁定围标串标嫌疑，直接延伸核查投标文件、评标记录。

### 技巧3：异常数值筛查——锁定大额、超标准、偏离常规数据

**适用场景**：超标准发放补贴、大额现金支出、异常大额采购、费用突增突减等问题。

**核心逻辑**：设定合规阈值，筛选超出标准、远超平均值、极端数值的记录，避免大海捞针。

#### 实操代码（超标准补贴发放+异常大额支出筛查）

```sql
-- 计算补贴发放平均值，筛选超均值3倍及超标准上限的疑点
WITH avg_subsidy AS (
  SELECT AVG(发放金额) AS 平均补贴金额
  FROM 补贴发放表
  WHERE 发放状态 = '正常'
)
SELECT
  人员姓名,
  发放部门,
  发放日期,
  发放金额,
  补贴类型,
  平均补贴金额,
  -- 标记异常类型
  CASE
    WHEN 发放金额 > 5000 THEN '超标准上限（合规上限5000元）'
    WHEN 发放金额 > 平均补贴金额*3 THEN '远超平均水平'
    ELSE '正常'
  END AS 异常类型
FROM 补贴发放表, avg_subsidy
WHERE 发放状态 = '正常'
  AND (发放金额 > 5000 OR 发放金额 > 平均补贴金额*3)
ORDER BY 发放金额 DESC;
```

拓展：筛查大额现金支出，重点关注现金支付超限额、无合理事由的记录，替换WHERE条件即可适配。

### 技巧4：窗口函数实战——同比环比、连续异常、排名筛查

**适用场景**：费用月度波动异常、员工连续多月异常报销、供应商中标排名异常、医保分解住院筛查。

**核心逻辑**：用LAG()、LEAD()、ROW_NUMBER()窗口函数，实现同维度数据的前后对比、分组排名，不用复杂子查询，高效定位连续异常。

#### 实操代码（医保分解住院疑点筛查）

```sql
-- 按参保人分组，按住院时间排序，计算本次住院与上次出院间隔
WITH patient_hospital AS (
  SELECT
    身份证号,
    患者姓名,
    入院日期,
    出院日期,
    住院天数,
    -- 获取上一次出院日期
    LAG(出院日期) OVER (PARTITION BY 身份证号 ORDER BY 入院日期) AS 上次出院日期
  FROM 住院结算表
  WHERE 医疗付款方式 NOT LIKE '%全自费%'
)
-- 筛查间隔小于15天的分解住院疑点（违规分解住院套取医保基金）
SELECT
  身份证号,
  患者姓名,
  上次出院日期,
  入院日期 AS 本次入院日期,
  DATEDIFF(入院日期, 上次出院日期) AS 间隔天数,
  住院天数
FROM patient_hospital
WHERE 上次出院日期 IS NOT NULL
  AND DATEDIFF(入院日期, 上次出院日期) < 15
ORDER BY 间隔天数 ASC, 身份证号;
```

**疑点解读**：医保审计中，患者出院后15天内再次入院，且无合理转院、急症证明，属于典型分解住院，套取医保基金，直接关联医院诊疗记录核实。

### 技巧5：模糊匹配+文本筛查——隐蔽违规、串换项目精准定位

**适用场景**：医保药店串换药品（生活用品换医保药）、费用摘要篡改、虚假列支等隐蔽违规行为。

**核心逻辑**：通过LIKE模糊匹配，锁定违规关键词，结合多表比对，找出"表里不一"的记录。

#### 实操代码（医保药店串换物品筛查）

```sql
-- 关联药店销售表和医保结算表，筛查串换医保项目疑点
SELECT
  a.结算单号,
  a.参保人身份证号,
  a.收费项目名称 AS 医保结算项目,
  b.商品名称 AS 实际销售商品,
  a.结算金额,
  b.销售日期
FROM 医保结算表 a
LEFT JOIN 药店销售表 b
  ON a.参保人身份证号 = b.会员身份证号
  AND a.结算日期 = b.销售日期
  AND a.结算金额 = b.销售金额
WHERE
  -- 实际销售非医保商品，却按医保项目结算
  (b.商品名称 LIKE '%大米%'
   OR b.商品名称 LIKE '%食用油%'
   OR b.商品名称 LIKE '%洗衣液%')
  AND a.收费项目名称 LIKE '%药品%'
ORDER BY a.结算金额 DESC;
```

该案例也是多地医保审计实战案例，通过SQL快速锁定串换疑点，再结合原始小票和库存台账，快速固定证据。

## 三、大数据审计SQL避坑指南

- 1. **大数据量必加索引**：对身份证号、凭证号、日期、供应商名称等查询字段提前建索引，避免查询超时；
- 2. **保留查询语句**：审计工作留痕，所有SQL语句分类存档，方便后续复核和追溯；
- 3. **数据脱敏优先**：涉及个人隐私、商业秘密的数据，查询时屏蔽敏感信息，合规审计；
- 4. **先小批量测试**：千万级数据先取1000条测试语句，无误后再全量运行，避免资源占用。

### 模板1：重复报销/重复入账筛查SQL

```sql
-- 审计场景：差旅费/补贴/费用重复报销、重复入账 通用模板
WITH clean_voucher AS (
  SELECT * FROM 【替换为你的凭证明细表名】
  WHERE 作废标识 = '否'
    AND 借方金额 > 0
    AND 人员姓名 IS NOT NULL
)
SELECT
  人员姓名,
  凭证日期,
  借方金额 AS 报销金额,
  摘要,
  凭证号,
  COUNT(*) AS 重复次数
FROM clean_voucher
WHERE 摘要 LIKE '%差旅费%'
   OR 摘要 LIKE '%住宿%'
   OR 摘要 LIKE '%交通%'
   OR 摘要 LIKE '%补贴%'
GROUP BY 人员姓名, 凭证日期, 借方金额, 摘要
HAVING COUNT(*) > 1
ORDER BY 重复次数 DESC, 报销金额 DESC;
```

### 模板3：超标准补贴+异常大额支出筛查SQL

```sql
-- 审计场景：超标准补贴发放、异常大额费用、违规现金支出 通用模板
-- 可自行修改合规上限金额（默认5000元）和异常倍数（默认3倍均值）
WITH avg_subsidy AS (
  SELECT AVG(发放金额) AS 平均补贴金额
  FROM 【替换为补贴/费用表名】
  WHERE 发放状态 = '正常'
)
SELECT
  人员姓名,
  发放部门,
  发放日期,
  发放金额,
  补贴类型,
  平均补贴金额,
  CASE
    WHEN 发放金额 > 5000 THEN '超标准上限'
    WHEN 发放金额 > 平均补贴金额*3 THEN '远超平均水平'
    ELSE '正常'
  END AS 异常类型
FROM 【替换为补贴/费用表名】, avg_subsidy
WHERE 发放状态 = '正常'
  AND (发放金额 > 5000 OR 发放金额 > 平均补贴金额*3)
ORDER BY 发放金额 DESC;
```

### 模板5：医保药店串换物品筛查SQL
