## 二、核心发现

### ✅ 适用的数据源（列表页）

web_fetch markdown 模式对以下类型页面效果极佳：

1. **财政部新闻页** — 直接返回结构化新闻列表
   - URL: `https://www.mof.gov.cn/zhengwuxinxi/caizhengxinwen/`
   - 可采集：国债发行、转移支付、会计监督、绩效评价等政策动态
   
2. **审计署报告列表** — 返回审计报告目录
   - URL: `https://www.audit.gov.cn/n5/n26/index.html`
   - 可采集：年度审计工作报告、整改报告、审计公告

### ⚠️ 受限的数据源（详情页）

政务网站的详情页普遍存在问题：
- **正文在 PDF 附件中**（审计署报告的正文是 PDF 链接）
- **JS 动态渲染**（React/Vue 框架的内容需浏览器执行）
- **反爬措施**（部分网站检测非浏览器请求）

### 🔧 解决方案矩阵

```
列表页采集    → web_fetch markdown 模式（省钱省Token）
                         ↓
            提取详情页 URL
                         ↓
          ┌──────────────┴──────────────┐
          ↓                              ↓
    HTML正文页                      PDF附件页
    web_fetch                       pdf工具
    直接提取                        提取文本
```

## 六、关键技术细节

### web_fetch vs browser 的选取策略

| 指标 | web_fetch | browser |
|---|---|---|
| Token 消耗 | 低（html2text 压缩 60-70%） | 高（完整 DOM） |
| 速度 | 2-6秒 | 8-20秒 |
| 反爬穿透 | 差 | 强（真实浏览器） |
| JS 渲染 | 不支持 | 完整支持 |
| 适用场景 | 列表页、简单新闻页 | SPA、反爬强、验证码 |
| 成本 | ~200 Token/次 | ~2000 Token/次 |

**经验法则**：先用 web_fetch 试，失败再降级到 browser。

### html2text 节省 Token 的原理

```
原始 HTML:  <div class="article"><p>财政监管需要<strong>数智赋能</strong></p></div>
             ↑ 约 70 字符

Markdown 后: 财政监管需要**数智赋能**
             ↑ 约 15 字符，节省 78%
```

对政务网站常见的 table/div 嵌套布局，压缩率可达 80%+。
