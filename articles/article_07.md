## 二、数据采集与准备

### 2.1 数据表结构

我们从ERP系统导出了以下数据表：

```sql
-- 1. 费用报销主表
CREATE TABLE expense_reimburse (
    reimburse_id VARCHAR(32) PRIMARY KEY,  -- 报销单号
    employee_id VARCHAR(16),               -- 员工编号
    employee_name VARCHAR(64),             -- 员工姓名
    dept_id VARCHAR(16),                   -- 部门编号
    dept_name VARCHAR(64),                 -- 部门名称
    expense_type VARCHAR(32),              -- 费用类型
    amount DECIMAL(12,2),                  -- 报销金额
    invoice_count INT,                     -- 发票数量
    submit_date DATE,                      -- 提交日期
    approve_date DATE,                     -- 审批日期
    approver VARCHAR(64),                  -- 审批人
    status VARCHAR(16),                    -- 单据状态
    create_time DATETIME                   -- 创建时间
);

-- 2. 差旅明细表
CREATE TABLE travel_detail (
    detail_id VARCHAR(32) PRIMARY KEY,     -- 明细ID
    reimburse_id VARCHAR(32),              -- 报销单号
    travel_date DATE,                      -- 出行日期
    departure VARCHAR(64),                 -- 出发地
    destination VARCHAR(64),               -- 目的地
    transportation VARCHAR(32),            -- 交通方式
    fare DECIMAL(10,2),                    -- 交通费用
    hotel_name VARCHAR(128),               -- 酒店名称
    hotel_fee DECIMAL(10,2),               -- 住宿费用
    meal_fee DECIMAL(10,2),                -- 餐饮费用
    city_allowance DECIMAL(10,2)           -- 差旅补贴
);

-- 3. 发票信息表
CREATE TABLE invoice_info (
    invoice_id VARCHAR(32) PRIMARY KEY,    -- 发票号
    reimburse_id VARCHAR(32),              -- 报销单号
    invoice_date DATE,                     -- 开票日期
    invoice_amount DECIMAL(12,2),          -- 发票金额
    invoice_code VARCHAR(32),              -- 发票代码
    invoice_number VARCHAR(32),            -- 发票号码
    seller_name VARCHAR(128),              -- 销售方名称
    tax_amount DECIMAL(10,2),              -- 税额
    status VARCHAR(16)                     -- 发票状态
);

-- 4. 员工信息表
CREATE TABLE employee_info (
    employee_id VARCHAR(16) PRIMARY KEY,   -- 员工编号
    employee_name VARCHAR(64),             -- 员工姓名
    id_card VARCHAR(18),                   -- 身份证号
    dept_id VARCHAR(16),                   -- 部门编号
    position VARCHAR(32),                  -- 职位
    entry_date DATE,                       -- 入职日期
    salary_level VARCHAR(8)                -- 薪资等级
);
```

## 三、SQL分析实操

### 3.1 审计点一：单笔大额异常报销分析

**审计思路：** 单笔报销金额超过正常业务范围，可能是异常交易。

```sql
-- 审计SQL：筛查单笔报销金额超过10000元的记录
SELECT
    reimburse_id AS "报销单号",
    employee_name AS "员工姓名",
    dept_name AS "部门",
    expense_type AS "费用类型",
    amount AS "报销金额",
    invoice_count AS "发票数量",
    submit_date AS "提交日期",
    approve_date AS "审批日期",
    approver AS "审批人"
FROM expense_reimburse
WHERE amount > 10000
ORDER BY amount DESC;
```

**审计结果：**

| 报销单号 | 员工姓名 | 部门 | 费用类型 | 报销金额 | 发票数量 |
|----------|----------|------|----------|----------|----------|
| REI20240009 | 吴十 | 采购部 | 物料费 | 28,900.00 | 15 |
| REI20240006 | 钱七 | 市场部 | 差旅费 | 15,230.00 | 18 |

**审计发现：**

- 采购部吴十报销物料费28,900元，需进一步核实采购流程
- 市场部钱七差旅费15,230元，金额较大且发票数量偏多

### 3.2 审计点二：同一地点重复报销分析

**审计思路：** 同一天同一出发地和目的地存在多次报销，可能存在重复报销。

```sql
-- 审计SQL：筛查同一员工、同一天、同一路线重复报销的情况
SELECT
    t1.reimburse_id AS "报销单号1",
    t2.reimburse_id AS "报销单号2",
    t1.employee_id AS "员工编号",
    t1.departure AS "出发地",
    t1.destination AS "目的地",
    t1.travel_date AS "出行日期",
    t1.fare AS "费用1",
    t2.fare AS "费用2",
    t1.reimburse_id AS "关联报销单"
FROM travel_detail t1
JOIN travel_detail t2 ON
    t1.employee_id = t2.employee_id
    AND t1.travel_date = t2.travel_date
    AND t1.departure = t2.departure
    AND t1.destination = t2.destination
    AND t1.detail_id < t2.detail_id
ORDER BY t1.employee_id, t1.travel_date;
```

**审计结果：**

| 报销单号1 | 报销单号2 | 员工编号 | 出发地 | 目的地 | 出行日期 | 费用1 | 费用2 |
|-----------|-----------|----------|--------|--------|----------|-------|-------|
| REI20240001 | REI20240004 | E001 | 北京 | 上海 | 2024-03-10 | 553.00 | 553.00 |

**审计发现：**

- 员工张三（E001）在2024-03-10从北京到上海，产生了2笔完全相同的报销记录
- 涉及金额：553元 × 2 = 1106元（仅交通费）
- 疑点：同一天同一路线不应该有两次报销，疑似重复报销

### 3.3 审计点三：发票重复使用分析

**审计思路：** 同一发票号码被多次使用，属于明显违规。

```sql
-- 审计SQL：筛查发票号码重复的记录
SELECT
    i1.invoice_id AS "发票ID1",
    i2.invoice_id AS "发票ID2",
    i1.reimburse_id AS "报销单号1",
    i2.reimburse_id AS "报销单号2",
    i1.invoice_number AS "发票号码",
    i1.invoice_amount AS "发票金额",
    i1.seller_name AS "销售方",
    i1.invoice_date AS "开票日期"
FROM invoice_info i1
JOIN invoice_info i2 ON
    i1.invoice_number = i2.invoice_number
    AND i1.invoice_id < i2.invoice_id
ORDER BY i1.invoice_number;
```

**审计结果：**

| 发票ID1 | 发票ID2 | 报销单号1 | 报销单号2 | 发票号码 | 发票金额 | 销售方 |
|---------|---------|-----------|-----------|----------|----------|--------|
| INV20240001 | INV20240006 | REI20240001 | REI20240004 | 12345678 | 623.90 | 上海铁路局 |
| INV20240002 | INV20240007 | REI20240001 | REI20240004 | 12345679 | 748.00 | 上海外滩酒店 |

**审计发现：**

- **严重违规：** 发票号码12345678和12345679被两个不同的报销单使用
- 涉及金额：623.90 + 748.00 = 1371.90元
- 关联报销单：REI20240001和REI20240004
- 涉案人员：张三（E001）
- **结论：张三使用同一发票重复报销，构成虚假报销**

### 3.4 审计点四：费用归集错误分析

**审计思路：** 检查费用类型与实际明细是否匹配。

```sql
-- 审计SQL：分析各费用类型的金额分布
SELECT
    expense_type AS "费用类型",
    COUNT(*) AS "单据数量",
    SUM(amount) AS "总金额",
    AVG(amount) AS "平均金额",
    MAX(amount) AS "最大金额",
    MIN(amount) AS "最小金额"
FROM expense_reimburse
GROUP BY expense_type
ORDER BY SUM(amount) DESC;
```

**审计结果：**

| 费用类型 | 单据数量 | 总金额 | 平均金额 | 最大金额 | 最小金额 |
|----------|----------|--------|----------|----------|----------|
| 差旅费 | 5 | 37,280.50 | 7,456.10 | 15,230.00 | 4,250.00 |
| 物料费 | 1 | 28,900.00 | 28,900.00 | 28,900.00 | 28,900.00 |
| 招待费 | 1 | 3,500.00 | 3,500.00 | 3,500.00 | 3,500.00 |
| 办公费 | 1 | 1,280.00 | 1,280.00 | 1,280.00 | 1,280.00 |

### 3.5 审计点五：报销频率异常分析

**审计思路：** 短时间内频繁报销可能存在异常。

```sql
-- 审计SQL：统计每个员工的报销频次
SELECT
    employee_id AS "员工编号",
    employee_name AS "员工姓名",
    dept_name AS "部门",
    COUNT(*) AS "报销次数",
    SUM(amount) AS "报销总额",
    AVG(amount) AS "平均金额",
    MIN(submit_date) AS "首次报销",
    MAX(submit_date) AS "最近报销"
FROM expense_reimburse
GROUP BY employee_id, employee_name, dept_name
HAVING COUNT(*) > 1
ORDER BY COUNT(*) DESC, SUM(amount) DESC;
```

**审计结果：**

| 员工编号 | 员工姓名 | 部门 | 报销次数 | 报销总额 | 平均金额 | 首次报销 | 最近报销 |
|----------|----------|------|----------|----------|----------|----------|----------|
| E001 | 张三 | 销售部 | 2 | 11,360.00 | 5,680.00 | 2024-03-15 | 2024-03-20 |
| E002 | 李四 | 销售部 | 2 | 13,120.50 | 6,560.25 | 2024-03-16 | 2024-04-18 |

**审计发现：**

- 员工张三在5天内报销2次，频率较高
- 结合前面的重复报销发现，张三的问题较为严重

## 四、综合分析

### 4.1 风险等级汇总

```sql
-- 综合风险评分SQL
SELECT
    r.employee_id AS "员工编号",
    r.employee_name AS "员工姓名",
    r.dept_name AS "部门",
    COUNT(DISTINCT r.reimburse_id) AS "报销单数",
    SUM(r.amount) AS "报销总额",
    COUNT(DISTINCT i.invoice_number) AS "使用发票数",
    COUNT(DISTINCT CASE WHEN i1.invoice_number = i2.invoice_number
        THEN i1.invoice_number END) AS "重复发票数",
    CASE
        WHEN COUNT(DISTINCT CASE WHEN i1.invoice_number = i2.invoice_number
            THEN i1.invoice_number END) > 0 THEN '🔴 高风险'
        WHEN SUM(r.amount) > 10000 THEN '🟡 中风险'
        ELSE '🟢 低风险'
    END AS "风险等级"
FROM expense_reimburse r
LEFT JOIN invoice_info i ON r.reimburse_id = i.reimburse_id
LEFT JOIN invoice_info i1 ON r.reimburse_id = i1.reimburse_id
LEFT JOIN invoice_info i2 ON i1.invoice_number = i2.invoice_number
    AND i1.invoice_id < i2.invoice_id
GROUP BY r.employee_id, r.employee_name, r.dept_name
ORDER BY "重复发票数" DESC, "报销总额" DESC;
```
