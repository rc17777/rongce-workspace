## 一、招投标审计在12条业务线中的定位

招投标审计不是孤立业务——它是**7条业务线的通用交叉能力**：

```
                    ┌── 预算执行审计 ── 政府采购合规
                    ├── 专项资金审计 ── 资金项目招采
        独立项目 ──┤── 工程审计 ──── 施工/监理/设计招标
                    ├── 经济责任审计 ── 重大采购决策合规
        交叉能力 ──┤── 国企审计 ──── 企业采购/工程项目招标
                    ├── 收支审计 ──── 大额支出采购程序
                    └── 两新补贴 ──── 补贴项目招采合规
```

| 业务线 | 招投标审计角色 | 触发条件 | 重点维度 |
|:--|:--|:--|:--|
| **预算执行** | 政府采购合规审查 | 涉及政府采购的预算项目 | 标前（招标方式）+ 标后（履约） |
| **专项资金** | 资金使用合规 | 专项资金涉及工程建设/货物采购 | 标前到标后全流程 |
| **工程审计** | 核心组成 | 所有工程项目 | 全流程 + 物理坐标系（工程量反推） |
| **经济责任** | 重大决策合规 | 领导任期内重大采购/招标决策 | 标前（决策程序）+ 社会关系 |
| **国企审计** | 采购合规 + 关联交易 | 企业采购/工程项目 | 全流程 + 社会关系（关联穿透） |
| **收支审计** | 大额支出程序 | 单笔超10万采购支出 | 标前（招标方式） |
| **两新补贴** | 供应商遴选合规 | 补贴涉及招采环节 | 标中（投标真实性） |
| **招投标审计(独立)** | 全量 | 专项招投标审计项目 | ⭐全流程全坐标系 |

### 2.2 三阶段审计流水线

```
DATA IN ──→ 标前审计 ──→ 标中审计 ──→ 标后审计 ──→ FINDINGS OUT
             (3天)        (5天)        (3天)
```

#### 阶段一：标前审计「查该不该招、能不能招」

**目标**：在招标公告发出一刻就埋下的问题，后续环节只是放大。

**执行步骤**：

| 步骤 | 动作 | 方法 | E规则 | 输出 |
|:--|:--|:--|:--|:--|
| **1.1** | 核对立项审批 | 项目可研/初设/概算批复 × 招标时间 | — | 标前审批问题清单 |
| **1.2** | 检查招标方式 | 公开/邀请/竞争性谈判/单一来源→是否符合法定条件 | **E26** | 招标方式异常清单 |
| **1.3** | 排查拆分招标 | 同一采购人同一时期同类项目 → 是否拆分成多个限额以下项目 | **E26** | 拆分嫌疑清单 |
| **1.4** | 审查招标文件排他性 | 注册资金≥X / N个以上案例 / 本系统优先 / 特定品牌指定 | **E25** | 排他性条款清单 |
| **1.5** | 验证评分标准合规 | 评分项是否量化？是否存在"酌情给分"等模糊项？ | — | 评分标准合规报告 |
| **1.6** | 核查标底/限价合理性 | 限价与预算/概算/市场价的偏差 | — | 限价异常清单 |
| **1.7** | 检查等标期 | 招标文件发出日→开标日间隔≥20天？ | — | 等标期违规清单 |

**阶段一常见发现**：
- "注册资金≥2000万 + 3个省级案例 + 本系统优先" → **E25命中** → 度身招标
- "同一采购人12月密集发出3个邀请招标" → **E26命中** → 规避公开招标
- "3个同类项目分别招标，合计金额超过公开招标限额" → **E26命中** → 拆分招标

#### 阶段二：标中审计「防围标串标、程序违规」

**目标**：这是发现围标串标的主战场——大部分E规则在此阶段执行。

**执行步骤**：

| 步骤 | 动作 | 方法 | E规则 | 自动化 |
|:--|:--|:--|:--|:--|
| **2.1** | 投标文件元数据同源检测 | 提取全部投标文件core.xml的创建时间/修改时间/保存者/修订号 | **E05** | ✅ `e05_bid_metadata_homology.py` |
| **2.2** | 报价规律异常检测 | 全部报价的分布（极端一致/等差数列/接近限价） | **E20** | 待实现 |
| **2.3** | IP/MAC地址比对 | 投标文件上传IP/MAC是否相同 | **E05** | 需代理数据 |
| **2.4** | 标书撰写时间矛盾 | 标书创建时间 < 招标文件发布时间？ | **E27** | ✅ E05脚本可扩展 |
| **2.5** | 评委构成合规检查 | 专家≥2/3？采购人代表≤1/3？是否有回避义务人？ | **L10** | 人工 |
| **2.6** | 评标打分偏差检测 | 某个评委打分与最终排名高度相关 / 与其他评分离散度过大 | **L10** | 待实现 |
| **2.7** | 关键人员资质核验 | 建造师/造价师/安全工程师证书号批量对接四库一平台 | **E29** | 待实现 |
| **2.8** | 社保公积金核验 | 投标文件所列关键岗位人员社保缴纳单位是否为投标人 | — | 需社保数据 |
| **2.9** | 投标文件内容雷同 | TF-IDF文本相似度 + 图片感知哈希 | **L3+L4** | 可调用23层体系 |
| **2.10** | 轮流中标模式检测 | 同一批投标人3年内在多个项目轮流中标 | **E21** | 待实现 |
| **2.11** | 中标价×合同价×结算价预测 | 中标价是否显著低于合同价（后续会改） | **E31** | 待实现 |

**阶段二常见发现**：
- "3家投标文件创建时间相隔2分钟，修订号连续" → **E05命中** → 同一台电脑制作标书
- "6家投标报价全部在控制价97%-99%之间" → **E20命中** → 报价异常一致
- "5人评委会中3人是采购人代表" → **L10命中** → 评委会构成违规
- "A公司/B公司/C公司在4个项目上轮流做第一中标候选人" → **E21命中** → 围标联盟
- "中标人报价398万，签约价448万（涨10%）" → **E31命中** → 低价中标高价签约

#### 阶段三：标后审计「防阴阳合同、履约失控」

**目标**：中标只是开始——合同的每一分钱都可能是实施腐败的载体。

**执行步骤**：

| 步骤 | 动作 | 方法 | E规则 | 自动化 |
|:--|:--|:--|:--|:--|
| **3.1** | 合同×招标文件比对 | 价款/工期/质量标准是否与招标文件一致 | — | 人工 |
| **3.2** | 中标价×合同价×结算价追踪 | 三价是否递增？递增幅度≥5%？ | **E31** | 待实现 |
| **3.3** | 转包/挂靠检测 | 现场施工人员社保归属 / 实际施工方≠中标人 | **E30** | 需现场数据 |
| **3.4** | 分包合规检查 | 分包方资质核验 + 分包金额是否超比例 | **E30** | 人工 |
| **3.5** | 变更签证合规 | 变更理由合理性 + 变更是否在审计后追加 | — | 人工 |
| **3.6** | 资金支付合规 | 是否按合同节点支付 / 有无提前付/超额付 | **E31** | Excel比对 |
| **3.7** | 验收真实性 | 验收单×现场实物×出入库记录三向比对 | **E32** | 需现场 |
| **3.8** | 交货/验收时间矛盾 | 验收日期 < 合同签署日期？ | **E27** | ✅ E23脚本可适配 |

**阶段三常见发现**：
- "中标价500万→合同价550万→结算价680万" → **E31命中** → 层层加码
- "验收单签字日期早于合同签订日期" → **E27命中** → 时间矛盾
- "现场施工人员全部来自XX劳务公司，非中标人" → **E30命中** → 转包
- "合同约定质保期3年，验收6个月后设备停用" → **E32命中** → 验收造假

### 2.3 5坐标系并行穿透（与三阶段叠合）

三阶段是纵向时间线，5坐标系是横向覆盖。每个阶段内部同时执行：

```
标前                         标中                         标后
───────────────────────────────────────────────────────────────→ 时间
│
├ 时空: 招标时间/地点合规        时空: IP/MAC同源, 标书时间矛盾   时空: 验收时间矛盾
├ 物理: 标底/限价物理合理性      物理: 报价规律, 资质真实性       物理: 转包, 履约物量验证
├ 社会关系: 评委/代理选聘合规     社会关系: 投标人关联, 评委关联   社会关系: 分包方关联
├ 行为: 招标方式行为模式         行为: 打分行为, 投标行为模式     行为: 变更签证行为模式
└ 时间序列: 招标时间分布         时间序列: 报价序列, 中标序列     时间序列: 支付节奏
```

**跨坐标系碰撞规则**（v3.0引擎）：
- 同一实体被2+个坐标系标记 → 置信度大幅提升
- 典型高价值碰撞：时空(E05 IP同源) + 行为(E20 报价异常) = 围标铁证
- 典型高价值碰撞：社会关系(E15 经办人关联) + 时间序列(E23 年末突击) = 利益输送+套取资金
- 典型高价值碰撞：物理(E13 进销存不匹配) + 行为(E19 审批异常) = 虚构交易

## 四、跨业务线调用规则

### 如何在不同业务线中嵌入招投标审计

#### 1. 预算执行审计

```
触发条件: 预算项目中存在"政府采购"标记
嵌入深度: 浅度（标前为主）
执行步骤: 1.1 → 1.2 → 1.3 → 1.4(十必审) → 跳过标中标后（除非有异常信号）
重点E规则: E26（招标方式）, E25（排他性条件）, E34（政策功能）, E35（评审标准）
```

#### 2. 专项资金审计

```
触发条件: 专项资金涉及工程建设/货物/服务采购
嵌入深度: 中度（标前+标后）
执行步骤: 阶段一全量(含1.4十必审) → 阶段三全量 → 阶段二仅L10+E29
重点E规则: E26, E31, E30, E34, E35
```

#### 3. 工程审计

```
触发条件: 所有工程项目
嵌入深度: 深度（全流程）
执行步骤: 三个阶段全量 + 物理坐标系增强（E12商砼反推等）
重点E规则: 全部 + 工程专用E12等
特殊数据: 商砼站供货记录、施工日志、监理日志
```

#### 4. 经济责任审计

```
触发条件: 领导任期内有重大采购/招标决策
嵌入深度: 中度（标前+社会关系+标后）
执行步骤: 1.4(十必审) → 2.5 → 2.6 → 3.1 → 3.2 + E28（评委关联）+ E17（亲属经商）
重点E规则: E25, L10, E31, E28, E17, E35
特殊关注: 决策程序合规、是否存在领导打招呼（E28）、评审标准是否量化(E35)
```

#### 5. 国企审计

```
触发条件: 企业采购/工程项目
嵌入深度: 深度（全流程+关联交易）
执行步骤: 三阶段全量 + E16（股权穿透）+ E33（联合体关联）
重点E规则: E25, E20, E21, E31, E16, E33
特殊关注: 内部人控制、关联交易、利益输送
```

#### 6. 收支审计

```
触发条件: 单笔大于10万的采购/服务支出
嵌入深度: 浅度（标前检查）
执行步骤: 1.1 → 1.2 → 跳过（除非异常）
重点E规则: E26
```

#### 7. 两新补贴审计

```
触发条件: 补贴涉及遴选供应商/服务商
嵌入深度: 中度（标中+标后）
执行步骤: 阶段二（重点查投标真实性）→ 阶段三（查履约）
重点E规则: E20, E29, E30, E31
```

## 五、审计发现标准化输出

### 5.1 发现分级

| 级别 | 定义 | 案例 |
|:--|:--|:--|
| **P0 铁证** | 多坐标系交叉，有物理证据 | IP同源(E05) + 报价异常(E20) + 评委关联(E28) → 围标铁证 |
| **P1 强信号** | 单一坐标系高置信度 | 标书创建时间早于招标文件(E27) → 内幕信息泄露 |
| **P1 强信号** | 程序性违规 | 评审标准用"优/良"等模糊表述(E35) + 价格分权重不足(E34) → 招标文件违规 |
| **P2 需要验证** | 异常信号，需补充证据 | 中标价<合同价5%以上(E31) → 需要核验变更理由 |
