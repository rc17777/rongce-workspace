# 四川融策制度发布与版本管理规范

> **制度编号**：RC-GOV-004  
> **版本**：V1.0  
> **编制日期**：2026年7月22日  
> **适用范围**：四川融策会计师事务所有限公司、四川融策工程咨询有限公司全部规章制度  
> **优先级**：P1  
> **审核人**：________ | **批准人**：________

---

## 第一章 总则

**第一条** 为规范公司制度的起草、审核、发布和管理工作，确保制度体系的统一性、有效性和可追溯性，制定本规范。

**第二条** 本规范适用于公司全部管理制度的全生命周期管理，包括：制定、修订、发布、执行、废止。

**第三条** 制度管理原则：
1. **统一管理**：制度编号、格式、发布流程统一规范
2. **权责清晰**：起草、审核、批准各环节责任明确
3. **版本可控**：每次修改有记录，新旧版本可追溯
4. **定期审视**：定期评估制度有效性，及时修订或废止

---

## 第二章 制度编号规则

**第四条** 制度编号格式：

```
RC - [类别码] - [序号]

RC        = 融策（RongCe）
类别码：
  GOV  = 公司治理（Governance）
  HR   = 人力资源（Human Resources）
  FIN  = 财务管理（Finance）
  BIZ  = 业务运营（Business）
  QC   = 质量控制（Quality Control）
  ADM  = 行政管理（Administration）
  SPL  = 专项制度（Special）
序号：
  001~999，按类别内编制顺序递增
```

**第五条** 编号分配：
1. 新制度编号由人力资源部（或制度归口管理部门）统一分配
2. 编号一经分配，即使制度废止也不再重复使用
3. 制度类别调整时，编号不变（避免混乱）

## 第三章 版本号规则

**第六条** 版本号格式：

```
V[主版本号].[次版本号]

主版本号：重大修订（制度框架性调整、核心条款变更）
次版本号：小幅修订（个别条款调整、文字修正）
```

**第七条** 版本号递增规则：

| 变更类型 | 版本号变化 | 示例 |
|---------|----------|------|
| 新制定 | V1.0 | 首次发布 |
| 个别条款修正（错别字、格式） | V1.1, V1.2... | 文字修正 |
| 部分条款修订（不涉及框架） | V1.x → V2.0 | 核心条款变更 |
| 重大修订（制度重构） | V2.0 → V3.0 | 框架性调整 |

**第八条** 修订记录：
每份制度文件首页应包含修订记录表：

```
| 版本 | 修订日期 | 修订内容摘要 | 修订人 | 审批人 |
|------|---------|------------|--------|--------|
| V1.0 | 2026-07-22 | 首次发布 | XXX | XXX |
| V1.1 | 2026-10-15 | 修正第16条病假工资标准 | XXX | XXX |
| V2.0 | 2027-04-01 | 增加远程办公条款、调整考勤规则 | XXX | XXX |
```

## 第四章 组织角色与审批替代规则

**第九条** 公司制度中的组织角色按实际组织架构执行：总经理、部门负责人、项目负责人、财务负责人、质控负责人等可根据公司规模一人多岗，但审批人不得审批本人经办事项，也不得对本人编制的成果进行最终独立复核。

**第十条** 制度中出现“分管副总”“质量控制部”“人力资源部”等角色，而公司当期未设置相应岗位或部门的，由总经理指定的同级或上一级负责人履行职责，并在年度组织架构表中公布。指定应保留书面记录；涉及员工切身利益的制度，不得由利益相关人员单独决定。

## 第五章 制度起草/审核/会签/批准/发布流程

**第十一条** 制度制定流程：

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  需求提出  │ →  │  起草草案  │ →  │  征求意见  │ →  │  审核会签  │ →  │  批准发布  │
│ (各部门)   │    │ (归口部门) │    │ (相关部门) │    │ (管理层)   │    │ (执行董事)  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 4.1 需求提出

**第十二条** 以下情形应提出制度制定/修订需求：
1. 新业务领域需要制度规范
2. 法律法规变化导致现有制度不合规
3. 管理实践中发现制度空白或不合理
4. 年度制度审视计划中列入的修订任务
5. 审计/检查中发现制度缺陷

**第十三条** 需求提出方式：
- 各部门填写《制度制定/修订需求表》，提交人力资源部
- 人力资源部汇总后报管理层审批立项

### 4.2 起草草案

**第十四条** 起草责任部门（归口部门）：

| 制度类别 | 归口部门 |
|---------|---------|
| 公司治理（GOV） | 综合管理部/总经理办公室 |
| 人力资源（HR） | 人力资源部 |
| 财务管理（FIN） | 财务部 |
| 业务运营（BIZ） | 业务管理部 |
| 质量控制（QC） | 质量控制部 |
| 行政管理（ADM） | 行政部 |
| 专项制度（SPL） | 按内容确定归口部门 |

**第十五条** 起草要求：
1. 格式统一：使用公司制度模板（见附件）
2. 内容完整：总则、正文、附则、签署页缺一不可
3. 条款明确：每条制度应可操作、可检验，避免模糊表述
4. 合法合规：不得与法律法规冲突
5. 引用清晰：引用其他制度的，标注制度编号

### 4.3 征求意见

**第十六条** 草案完成后，应征求相关部门意见：
1. 涉及多部门的制度，归口部门将草案发相关部门征求意见
2. 征求意见期限：一般制度5个工作日，重要制度10个工作日
3. 反馈意见应书面记录，归口部门逐条回应（采纳/不采纳及理由）
4. 涉及员工切身利益的制度（薪酬、考核、考勤、奖惩等），应征求员工代表意见

### 4.4 审核会签

**第十七条** 审核层级：

| 审核环节 | 审核人 | 审核内容 |
|---------|--------|---------|
| 合规审核 | 人力资源部/法务 | 是否符合法律法规 |
| 专业审核 | 归口部门负责人 | 内容是否专业、合理、可操作 |
| 关联审核 | 相关部门负责人 | 与其他制度是否冲突、是否协调 |
| 综合审核 | 管理层 | 是否符合公司整体管理方向 |

**第十八条** 会签要求：
1. 会签部门在收到草案后5个工作日内签署意见
2. 会签意见不一致的，由管理层协调决定
3. 会签通过后，提交批准

### 4.5 批准发布

**第十九条** 批准权限：

| 制度级别 | 批准人 |
|---------|--------|
| P0制度（核心制度） | 执行董事/股东会 |
| P1制度（重要制度） | 总经理 |
| P2制度（一般制度） | 分管副总经理 |

**第二十条** 发布方式：
1. 制度批准后3个工作日内发布
2. 发布渠道：
   - 公司OA系统/内部群发布电子版
   - 纸质版由行政部统一印制发放
3. 发布通知应包含：制度编号、名称、版本号、生效日期、替代的旧制度（如有）

## 第五章 制度宣贯要求

**第十九条** 新制度发布后必须进行宣贯：

| 制度级别 | 宣贯要求 |
|---------|---------|
| P0制度 | 全员宣贯会（由制度起草人主讲），考核确认 |
| P1制度 | 相关部门宣贯会，邮件通知+签收确认 |
| P2制度 | 邮件通知+签收确认 |

**第二十条** 宣贯内容：
1. 制度制定的背景和目的
2. 核心条款解读
3. 与旧制度的变化对比（修订时）
4. 实际操作中的注意事项
5. 答疑环节

**第二十一条** 宣贯记录：
1. 宣贯会签到表（参会人员签字）
2. 宣贯材料（PPT/讲义）存档
3. 员工签收确认表（确认已阅读并理解制度内容）

**第二十二条** 新员工制度培训：
1. 入职培训中必须包含核心制度（P0）培训
2. 培训内容包括：员工手册、薪酬制度、考勤制度、项目管理制度
3. 培训后员工签字确认

---

## 第六章 制度定期审视

**第二十三条** 定期审视机制：

| 审视类型 | 频率 | 范围 | 责任人 |
|---------|------|------|--------|
| 年度审视 | 每年4月 | 全部制度 | 人力资源部牵头 |
| 专项审视 | 不定期 | 特定类别制度 | 归口部门 |
| 触发式审视 | 即时 | 相关制度 | 发现问题的部门 |

**第二十四条** 年度审视内容：
1. 制度是否仍然适用（业务变化、组织变化）
2. 制度是否与最新法律法规一致
3. 制度执行中是否存在问题或矛盾
4. 是否有制度空白需要补充
5. 是否有制度需要合并或简化

**第二十五条** 年度审视输出：
- 《年度制度审视报告》，包含：
  - 需修订的制度清单及修订理由
  - 需新增的制度清单及必要性说明
  - 需废止的制度清单及原因
  - 下一年度制度建设计划

## 第七章 制度废止管理

**第二十六条** 制度废止情形：
1. 制度已被新版本替代
2. 制度规范的事项已不存在
3. 制度与法律法规冲突且无法修订
4. 制度已不适用且无修订价值

**第二十七条** 废止流程：
1. 归口部门提出废止建议，说明理由
2. 人力资源部审核
3. 按原审批权限批准废止
4. 发布废止通知

**第二十八条** 废止处理：
1. 废止通知中明确：废止制度编号、名称、废止日期、替代制度（如有）
2. 废止制度从公司制度库中移除，标注"已废止"存档
3. 废止制度不再具有约束力，但废止前依据该制度做出的处理决定继续有效
4. 纸质版废止制度由行政部收回销毁或标注"作废"存档

## 第八章 制度文件管理

**第二十九条** 制度文件存储：
1. 电子版：公司OA系统/共享文件夹，按类别分类存储
2. 纸质版：行政部统一保管，各部门留存与本部门相关的制度
3. 制度总目录由人力资源部维护，定期更新

**第三十条** 制度文件命名规则：

```
[编号]_[制度名称]_V[版本号].md

示例：
RC-HR-001_薪酬管理制度_V1.0.md
RC-HR-002_绩效考核管理制度_V1.0.md
RC-BIZ-001_项目管理规范_V1.0.md
```

**第三十一条** 制度查阅：
1. 全体员工有权查阅与公司管理相关的全部制度
2. 制度不应设置不合理的查阅障碍
3. 制度归口部门负责解答制度内容疑问
