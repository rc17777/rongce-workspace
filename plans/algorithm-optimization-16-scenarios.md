# 融策审计智析 — 16场景算法全覆盖落地路线图

> 基于 2026-07-22 业务场景 × 算法覆盖矩阵分析
> 总工期：73天（P0: 20d + P1: 24d + P2: 29d）
> 目标：16个场景平均覆盖率从 35% → 65%+

---

## 总体架构设计原则

### 新算法三层架构

```
┌─────────────────────────────────────────────┐
│  场景专用规则层（16个场景的专属规则包）        │
│  预算规则 / 三重一大 / 内控五要素 / 任期指标... │
├─────────────────────────────────────────────┤
│  通用算法增强层（现有28个算法的参数化扩展）     │
│  多层级分组对标 / 四阶段穿透 / 语义对齐...     │
├─────────────────────────────────────────────┤
│  基础设施层（不改动，复用现有）               │
│  MCP Server / LangGraph / 三级复核 / RAG     │
└─────────────────────────────────────────────┘
```

### 关键设计约束

1. **所有新算法通过 MCP Server 注册**，不改动现有 19 个模块
2. **规则化优先，语义化补充** — 80% 规则 + 20% NLP，不追求完美
3. **每个场景的算法输出统一为三级标记**：P0(高风险) / P1(中风险) / P2(低风险)
4. **与三级复核引擎联动** — 所有算法输出经 L1→L2→L3 复核

## P0 阶段：三大高频场景攻坚（20天）

### 场景1：预算执行情况审计（5天）

**目标覆盖率：25% → 75%**

#### 新增算法

| 算法 | 核心逻辑 | 输入 | 输出 |
|:---|:---|:---|:---|
| **预算执行偏差引擎** `budget_deviation_engine` | 预算批复数 vs 实际执行数 → 偏差率计算 → 分级预警（>10%黄/>20%橙/>30%红）。按支出功能分类/经济分类/部门三维度分别计算 | 预算批复表 + 执行报表 | 偏差热力图 + 异常科目清单 + 预警级别 |
| **无预算支出检测器** `no_budget_detector` | 实际支出科目 × 预算批复科目 → 差集 = 无预算支出清单。结合金额阈值过滤小额合理支出 | 预算批复表 + 执行报表 | 无预算支出清单 + 金额 + 疑似科目 |
| **结转结余合规判定** `carryover_compliance` | 按《预算法》第四十二条：连续两年未用完的结转资金→收回财政。自动计算各项目资金结转年限+标记超期 | 项目台账 + 年度结转表 | 超期结转清单 + 应收回金额 |
| **预算调整程序合规** `budget_adjustment_check` | 检测预算调整是否经过法定审批：调整报告存在性 + 审批时间在调整执行之前 + 调整幅度 vs 审批权限匹配 | 预算调整文件 + 审批记录 | 程序违规清单 |

#### 集成方式

```
预算数据 → budget_deviation_engine → P0/P1/P2
         → no_budget_detector      → P0/P1/P2
         → carryover_compliance    → P0/P1/P2
         → budget_adjustment_check → P0/P1/P2
         → 综合评分 → 审计问题底稿(问题描述+法规引用+证据索引)
```

#### 交付物
- 4 个 MCP 工具（~1500行 Python）
- 1 个场景编排配置文件（LangGraph 节点定义）
- 预算法规 RAG 知识库扩展（《预算法》核心条款 15条）

### 场景2：国有企业审计（7天）

**目标覆盖率：35% → 75%**

#### 新增算法

| 算法 | 核心逻辑 | 输入 | 输出 |
|:---|:---|:---|:---|
| **"三重一大"决策合规检测** `triple_one_detector` | 四检测器并行：① 重大决策：党委会/董事会纪要存在性+签字齐备性；② 重要人事：任免程序（动议→民主推荐→考察→讨论决定→任职）节点完整性；③ 重大项目：可研批复→立项→招标→签约的时间逻辑链（后一节点必须在上一节点之后）；④ 大额资金：金额×审批层级映射表（如>500万需董事会+国资委备案）| 决策文件库 + 审批记录 + 金额台账 | 四维合规评分 + 程序缺失项 + 疑似越权审批项 |
| **国有资产保值增值预警** `asset_preservation_alert` | 三维检测：① 资产减值信号（公允价值持续下跌/技术淘汰/闲置/终止使用）；② 低价处置检测（处置价 vs 评估价 vs 账面净值 三维比价，差异>20%标记）；③ 无偿划转合规（接收方是否为国企/是否经国资委批准）| 资产台账 + 评估报告 + 处置记录 | 风险清单 + 估值差异 + 合规缺口 |
| **履职待遇合规校验** `executive_perks_check` | 薪酬/用车/住房/通讯/兼职/培训六维限额对标（基于《国有企业负责人履职待遇和业务支出管理办法》），实际 vs 限额 → 超标项自动标记引法条 | 薪酬明细 + 费用报销 + 限额标准表 | 超标清单 + 超标金额 + 法规引用 |
| **混合所有制改革资产流失检测** `mixed_reform_asset_check` | 混改进程中的资产定价公允性：评估价 vs 成交价偏差率 / 评估基准日到成交日的资产变化（利润是否被隐藏）/ 受让方与原管理层的关联关系扫描 | 混改方案 + 评估报告 + 成交文件 + 关联方图谱 | 定价偏离清单 + 疑似隐藏利润 + 关联受让方 |

#### 集成方式

```
企业数据 → triple_one_detector      → 决策合规评分
         → asset_preservation_alert  → 资产风险清单
         → executive_perks_check     → 待遇超标清单
         → mixed_reform_asset_check  → 混改风险清单
         → 综合 → 国有企业审计综合风险报告
```

#### 交付物
- 4 个 MCP 工具（~2000行 Python）
- 1 套限额标准参数文件（可配置）
- 国资委法规 RAG 知识库扩展（15条核心条款）

### 场景3：内控制度审计（8天）

**目标覆盖率：10% → 70%**

#### 新增算法

| 算法 | 核心逻辑 | 输入 | 输出 |
|:---|:---|:---|:---|
| **内控五要素对标引擎** `coso_five_elements` | 基于 COSO 框架五要素（控制环境/风险评估/控制活动/信息沟通/监督）→ 18项原则 → 80+关注点。通过制度文本关键词匹配+语义相似度，判断每个关注点的制度覆盖度 | 内控制度文件集 | 五要素雷达图 + 制度空白清单 + 关注点覆盖率 |
| **不相容职务分离检测** `segregation_duties_check` | 六大不相容职务对（申请/审批/执行/记录/保管/检查）→ 提取实际授权矩阵 → 检测同一人对同一业务的"申请+审批"或"执行+记录"等冲突组合 | 授权表 + 用户权限表 + 业务日志 | 冲突矩阵 + 高风险岗位 + 具体证据(谁在何时同时做了哪两件冲突的事) |
| **穿行测试自动化** `walkthrough_test_engine` | 选取典型交易样本，沿全流程逐步验证：① 控制节点是否存在 ② 控制是否执行（留痕证据）③ 执行人是否合规。每个节点输出"存在且有效/存在但无效/不存在"三级判定 | 业务流程定义 + 交易样本 + 控制证据文件 | 每一步的判定结果 + 断裂点标注 + 全流程健康度评分 |
| **内控缺陷分级模型** `ic_deficiency_grading` | 定量维度（涉及金额/影响范围/发生频率）+ 定性维度（是否系统性/是否故意/是否已造成损失）→ 加权评分 → 重大/重要/一般三级输出 | 缺陷清单 + 业务数据 | 缺陷分级报告 + 每个缺陷的评分明细 + 建议整改优先级 |

#### 集成方式

```
制度文件 → coso_five_elements      → 制度健全度评分
授权数据 → segregation_duties_check → 不相容职务冲突清单
交易样本 → walkthrough_test_engine  → 控制执行有效性
缺陷清单 → ic_deficiency_grading    → 缺陷分级 + 整改建议
         → 综合 → 内控审计综合报告
```

#### 交付物
- 4 个 MCP 工具（~2200行 Python）
- 1 套 COSO 关注点标准模板（80+条目）
- 1 套不相容职务对照表模板

### 场景6：绩效评价（7天）

**目标覆盖率：50% → 80%**

#### 新增算法

| 算法 | 核心逻辑 | 输入 | 输出 |
|:---|:---|:---|:---|
| **绩效指标体系自动构建** `kpi_auto_construct` | 从政策文件/实施方案中提取：绩效目标→量化指标→权重→评分标准→数据来源。基于NLP的指标提取+人工确认。存量指标库积累后逐步降低人工占比 | 政策文件 + 项目方案 | 绩效指标体系草案（含指标/权重/标准/来源）+ 待确认项 |
| **多源数据融合评分** `multi_source_scoring` | 财政执行数据（权重40%）+ 业务产出数据（30%）+ 第三方评价（15%）+ 满意度（15%）→ 加权归一化 → 综合绩效评分。各数据源的缺失值/异常值自动标记 | 多来源绩效数据 | 综合评分 + 分维度评分 + 数据质量标注 |
| **绩效对比分析** `performance_benchmark` | 同类项目（同类型/同金额段/同地区）的多维绩效对比：投入产出比/完成时效/质量达标率/满意度。自动生成"标杆项目"和"异常项目"两组 | 同类项目绩效数据 | 绩效排名 + 标杆识别 + 异常项目清单 + 偏差分析 |

#### 集成方式
与 v12 绩效评价引擎（~45条规则）形成分工：
- v12 做**算术正确性校验**（权重闭合/加权递推等机械计算）
- 新增算法做**指标构建** + **多源融合** + **横向对比**

#### 交付物
- 3 个 MCP 工具（~1500行 Python）
- 绩效评价法规 RAG 扩展（《项目支出绩效评价管理办法》核心条款 12条）

### 场景7：专项债申报和审计（5天）

**目标覆盖率：20% → 70%**

#### 新增算法

| 算法 | 核心逻辑 | 输入 | 输出 |
|:---|:---|:---|:---|
| **收益覆盖率测算** `revenue_coverage_calc` | 提取专项债项目可研报告中的预期收益流 → 按折现率折现 → 计算收益覆盖率（当期+累计）→ 自动检测是否<1.1（监管底线）。区分政府性基金收入/专项收入两类偿债来源 | 可研报告 + 收益测算表 | 收益覆盖率 + 测算参数合理性评估（折现率/增长率/收费标准） |
| **负面清单自动扫描** `negative_list_scanner` | 基于《专项债资金使用负面清单》的 20+ 禁止项：楼堂馆所/形象工程/经常性支出/置换存量债务/商业化项目等 → 自动匹配资金支出用途 → 命中则标记 | 资金支出明细 + 项目批复 | 负面清单命中项 + 金额 + 合规判定 |
| **进度-拨付匹配** `progress_disbursement_match` | 项目形象进度（完工百分比） vs 资金拨付进度（拨付率）→ 偏差率计算 → 超标自动预警（进度慢于拨付→资金沉淀风险；拨付慢于进度→工程延误风险）| 进度报告 + 拨付台账 | 偏差分析表 + 风险分类（沉淀/延误）+ 金额 |
| **偿债备付金监测** `debt_service_monitor` | 偿债备付金账户余额 vs 到期应偿还本息 → 覆盖率自动计算 + 余额变化趋势预测（基于未来6个月的收入/支出计划）| 备付金账户 + 偿债计划 | 当期覆盖率 + 趋势预警（未来3/6个月缺口） |

#### 交付物
- 4 个 MCP 工具（~1200行 Python）
- 专项债法规 RAG 扩展（《地方政府专项债券发行管理暂行办法》核心条款 8条）

## P2 阶段：六场景深度增强（29天）

### 场景8：司法审计（8天）

**目标覆盖率：35% → 75%**

#### 新增算法

| 算法 | 核心逻辑 | 输入 | 输出 |
|:---|:---|:---|:---|
| **资金追踪可视化（司法标准）** `fund_trace_visualizer` | 从目标账户出发，沿资金流向逐级追踪（入账/出账/中转账户/最终去向），生成完整的资金链路图 + 每个节点的金额/时间/摘要。支持多层嵌套（最多5层）追踪。输出格式满足司法鉴定要求 | 银行流水 + 关联账户信息 | 资金链路图 + 每层金额汇总 + 关键节点标注 |
| **资产流向还原** `asset_flow_reconstruction` | 特定时间段内目标主体（个人/企业）的全部资产变化：购置/处置/转让/抵押/赠与 → 时间线还原 + 对价公允性判断 + 关联交易标记 | 资产台账 + 工商变更 + 不动产登记 + 股权转让 | 资产变化时间线 + 异常交易（低价/关联/突击） |
| **损失金额计算模型** `loss_quantification_model` | 四种损失计算模式：① 虚增成本型 = 虚增额 × (1+合理利润率) ② 虚减收入型 = 应确认而未确认收入 ③ 关联非公允型 = (市场公允价-实际成交价) × 交易量 ④ 资产侵占型 = 资产账面价值 - 可追回价值。每分钟自动引用法条依据 | 交易数据 + 市场价格参考 | 损失金额 + 计算过程 + 法条依据 |
| **电子数据取证合规链** `e_discovery_compliance` | 审计数据→司法证据的转化：自动生成时间戳/数据哈希/来源追溯/操作日志，符合《电子签名法》和司法鉴定电子数据规范 | 审计数据文件 | 合规证据包（含完整性证明 + 来源证明 + 操作日志） |

### 场景9：监督检查（5天）

**目标覆盖率：20% → 65%**

#### 新增算法

## 实施约束与风险

### 技术风险
1. **NLP 语义对齐精度**：绩效指标提取、政策文本对标等依赖NLP的环节，初期准确率预计在70-80%，需要人机确认环节
2. **数据可获得性**：部分场景（经责审计的跨部门数据/财政评审的行业造价指数）依赖外部数据，需要提前协调
3. **规则库维护**：80+条新法规注入后，需要场景3（内控制度审计）中设计的六步更新闭环来保鲜

### 业务风险
1. **场景覆盖 ≠ 场景有效**：算法能"跑到"不代表"跑对了"，每个场景需要配套3-5个标准测试案例
2. **用户期望管理**：74%是算法可自动化处理的比例，剩余26%仍需人工专业判断

### 组织风险
1. **73天为纯开发时间**，不含需求确认/测试/培训，实际交付需加30%-40%缓冲
2. **8个场景的法规RAG注入**需要审计专业人员参与核对（~15天专业工时）
