# 项目闭环检查表

> 适用：每个项目必须勾完才算“管理上结项”。目标是“项目落地有措施，项目结束有反馈修复”。

## 一、立项阶段：有方法

- [ ] 已创建项目目录：`projects/<项目名>/`
- [ ] 已生成项目作战包
- [ ] 已明确项目类型和适用技能包
- [ ] 已形成取数清单
- [ ] 已列出重点风险点
- [ ] 已检索相关法规/案例/历史项目

## 二、执行阶段：有措施

- [ ] 资料完整性检查已完成
- [ ] 数据质量检查已完成
- [ ] 关键数据已结构化到 Excel/CSV/数据库
- [ ] 已按业务类型运行对应分析方法
- [ ] 招投标项目已运行串标检测（如适用）
- [ ] 会议/合同/纪要已运行文本审阅（如适用）
- [ ] 疑点均形成核查任务
- [ ] 核查结果已回填到底稿

## 三、报告阶段：有卡点

- [ ] 报告初稿已完成
- [ ] 问题、依据、证据、建议四要素完整
- [ ] 报告金额与附表一致
- [ ] 取证单/底稿/报告三方闭环
- [ ] 已运行 15维报告复核
- [ ] P0 重大矛盾已清零
- [ ] P1 重大遗漏已清零
- [ ] 用户/项目负责人确认可出所

## 四、结项阶段：有反馈修复

- [ ] 已完成结项复盘四问
- [ ] 好用方法已写回对应 Skill 或模板
- [ ] 新发现的故障/坑已写入 TROUBLESHOOTING.md
- [ ] 新审计规则已写入 rule-library 草稿
- [ ] 取数清单/playbook 已更新
- [ ] 最终成果已归档
- [ ] 中间文件/缓存已按规则清理或保留

## 五、结项复盘四问

1. 本项目哪个方法最有效？
2. 哪里出现了漏项、误判、低效或故障？
3. 有没有可以沉淀的新审计规则？
4. 下一次同类项目，取数清单和作战包要怎么改？

## 六、结项结论

- 项目是否允许管理结项：是 / 否
- 未完成事项：
- 责任人：
- 截止时间：
