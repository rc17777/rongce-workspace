# 融策审计规则库

## 定位

审计规则库不是关键词合集，而是把已经验证过的审计经验、案例、底稿、法规要求，转化为可执行、可复核、可沉淀的规则资产。

核心目标：

```text
案例/底稿/法规
  ↓
问题表现
  ↓
资料要求
  ↓
命中特征
  ↓
检测逻辑
  ↓
核查动作
  ↓
证据链
  ↓
底稿/报告表述
```

## 目录

| 文件 | 用途 |
|---|---|
| `rule-template.md` | 单条规则标准颗粒度模板 |
| `rule-schema.json` | 规则结构化字段定义，供脚本和工具读取 |
| `first-50-extraction-tasks.md` | 首批 50 条规则抽取任务表 |
| `case-to-rule-workflow.md` | 从 Obsidian/资料库案例提炼规则的流程 |

## 一期建设原则

1. 先从已验证案例提炼，不凭空编规则。
2. 每条规则必须绑定案例来源或法规依据。
3. 每条规则必须说明能否进入底稿，不能只输出“可疑”。
4. 规则按提示级、疑点级、底稿级分层。
5. 首批规则覆盖五个模块：会议纪要、合同、凭证、人员、文本相似度。
6. 规则运行后必须记录命中、确认、排除、形成问题情况。

## 规则分级

| 等级 | 名称 | 含义 | 使用位置 |
|---|---|---|---|
| A | 底稿级规则 | 证据链明确，补齐资料后可支撑底稿或报告问题 | 底稿、取证单、报告问题 |
| B | 疑点级规则 | 有明确核查价值，但需进一步取证 | 现场核查清单 |
| C | 提示级规则 | 只提示方向，不能直接作为疑点 | 审前调查、扩展检查 |

## 五个模块

| 模块 | 目标 |
|---|---|
| M1 会议纪要重点事项分析 | 识别重大事项、异常决策、反复研究、高风险议题 |
| M2 合同条款抽取与付款异常比对 | 识别提前付款、超合同付款、履约超期、变更无依据 |
| M3 凭证摘要合规关键词筛查 | 识别高危支出、专项资金用途偏离、摘要模糊、规避痕迹 |
| M4 人员名单身份碰撞 | 识别财政供养人员、死亡人员、重复领取、干部亲属等异常 |
| M5 投标/报告/验收文本相似度比对 | 识别投标雷同、报告套模板、验收材料复制等线索 |
