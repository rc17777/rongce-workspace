# 审计数据安全分级与AI调用策略 v1.0

> 2026-07-17 | 三模型联合评审驱动
> 核心原则：不是不用AI，而是分清楚什么数据能过什么AI

---

## 数据分级标准（L0-L4）

### L0 — 公开资料
| 示例 | 处理方式 |
|:--|------|
| 公开法规、政策文件 | ✅ 可任意云端LLM |
| 公开审计案例（脱敏后） | ✅ 可任意云端LLM |
| 政府采购网公告 | ✅ 可任意云端LLM |
| 行业标准、定额 | ✅ 可任意云端LLM |

### L1 — 非敏感业务资料
| 示例 | 处理方式 |
|:--|------|
| 经脱敏的项目实施方案 | ✅ 国内合规云平台（阿里云百炼/华为云） |
| 不含金额的合同模板 | ✅ 国内合规云平台 |
| 制度文件（公开颁布的） | ✅ 国内合规云平台 |
| 审计方法论文档 | ✅ 国内合规云平台 |

### L2 — 业务敏感资料（需脱敏后上云）
| 示例 | 原始 | 脱敏后 | 可用模型 |
|:--|:--|:--|:--|
| 合同（含金额、甲乙方） | ❌ 禁止上云 | 企业名→"甲方"、金额→区间 | DeepSeek V4/Pro (国内) |
| 招投标文件 | ❌ 禁止上云 | 投标人名称→编号、报价→比例 | DeepSeek V4/Pro (国内) |
| 验收报告 | ❌ 禁止上云 | 项目名→"XX项目" | DeepSeek V4/Pro (国内) |
| 会议纪要（非涉密） | ❌ 禁止上云 | 人名→角色、金额→区间 | Qwen3.7 (阿里云国内) |

**脱敏规则**：
- 企业名称 → "企业A/企业B"
- 个人姓名 → "XX职务"
- 具体金额 → "约XX万元"（四舍五入到万）
- 身份证/统一社会信用代码 → "XXXX...XXXX"
- 银行账号 → "XXXX...XXXX"
- 手机号 → "138XXXXXXXX"

### L3 — 个人隐私/敏感财政数据（仅本地处理）
| 示例 | 处理方式 |
|:--|------|
| 含身份证号的社保数据 | ❌ 禁止上云，仅本地Pandas/SQL分析 |
| 含银行账号的流水 | ❌ 禁止上云，仅本地OCR+Pandas处理 |
| 含个人工资的薪酬数据 | ❌ 禁止上云，仅本地处理 |
| 补贴发放明细（含姓名+金额+身份证） | ❌ 禁止上云，仅本地处理 |

**允许的本地处理**：
- PaddleOCR → 本地文本识别 ✅
- Pandas/SQL → 本地数据分析 ✅
- 本地规则引擎 → 异常检测 ✅
- 本地部署Qwen2.5 → 文本理解 ✅（后续建设）

### L4 — 涉密资料
| 示例 | 处理方式 |
|:--|------|
| 明确标注密级的文件 | ❌ 不进AI系统，按涉密流程人工处理 |
| 涉军/涉国家安全项目 | ❌ 不进AI系统 |
| 上级领导批示件 | ❌ 不进AI系统 |
