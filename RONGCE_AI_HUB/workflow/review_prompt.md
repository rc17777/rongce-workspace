# 审计工作流评审任务

你是资深审计信息化顾问。请以"挑剔的实务专家"视角，审查以下审计工作流设计，找出**任何**可以优化、遗漏、过度设计或不切实际的地方。

## 背景

四川融策会计师事务所（政府审计为主），老板正在用AI Agent改造审计全流程。

## 当前工作流（7阶段）

```
①a 项目初始化 → ①b OCR预处理 → ①c 智能分类 → ② 实施方案+资料清单 → ③ 多Agent并行分析 → ④ 现场核实+取证底稿 → ⑤ 报告撰写+15维复核 → ⑥ 反馈闭环归档
```

### ①b OCR预处理（核心创新）
- 扫描PDF/图片→PaddleOCR本地识别
- 发票→提取发票号/金额/购销方→invoices.csv
- 合同→提取合同号/甲乙方/金额/违约条款→contracts.csv
- 招投标文件→提取报价/得分/投标人→bids.csv
- 银行单据→提取交易日期/金额/对方户名→bank_transactions.csv
- 发票识别用qwen-vl-max（图片直接识别），合同提取用qwen3.7-plus（中文理解）

### ③ 多Agent分析
13个专业Agent按业务线自动选配，并行spawn：
- data_scout: 财务数据异常扫描（v4-pro）
- contract_hound: 合同条款审查（sonnet-5）
- bid_hunter: 围标串标23层检测（v4-pro）
- law_inspector: 法规遵从检查（qwen3.7-plus）
- workpaper_crafter: 取证单+底稿生成（v4-pro）
- report_writer: 报告撰写（v4-pro）
- review_sentinel: 15维复核（sonnet-5）
- 等7个工程/绩效专用Agent

### ⑥ 反馈闭环
确认的问题→案例化→规则化（A/B/C级）→RAG索引更新→下次同类项目自动调取

## 12大业务线
经济责任/收支/预算执行/专项资金/往来款/招投标/国企/成本效益/能源/工程竣工决算/绩效管理/政府补贴
+ 工程咨询4线（预算编制/财政评审/全过程咨询/工程结算）

## 已知但未解决的问题（详见validation_report）
- 会议纪要Agent未接入
- "三重一大"跨Agent全链条追踪缺失
- 实施方案→实际执行覆盖率无勾稽检查
- 底稿层复核前置未实现
- 客户多批次资料回溯
- 图纸/OFD/压缩包支持

## 审查要求

请从以下视角逐条点评：

1. **架构合理性**：7阶段划分是否合理？阶段之间衔接逻辑有无断点？
2. **实务匹配度**：这个流程跟真实审计（特别是中国政府审计）的实务吻合度如何？有无"技术很酷但实际用不上"的过度设计？
3. **风险遗漏**：有没有在真实审计中一定会发生、但这个流程完全没考虑的情况？
4. **效率瓶颈**：哪一步最可能成为瓶颈？OCR全部本地PaddleOCR跑500页要多久？
5. **Agent协作**：13个Agent并行分析后，结果如何碰撞合并？当前设计够不够？
6. **人的位置**：审计人员的专业判断在哪一步介入？AI会不会过度替代人工判断？
7. **安全合规**：客户数据通过AI/LLM处理，在中国政府审计的合规框架下有什么风险？
8. **最值得做的改进**：如果只能做一个改进，做什么？

请务实、具体、挑刺。不要说"这个设计很棒"，说"这个地方有问题"。
